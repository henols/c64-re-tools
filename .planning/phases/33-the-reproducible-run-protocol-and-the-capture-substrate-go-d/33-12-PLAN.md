<objective>
Derive the verdict by walking the recorded input values through the rules
committed in `33-01`, record it as machine-readable frontmatter, bind it to the
five phases it has authority over, and close the three folded todos.

Purpose: a gate is only a gate if its verdict is derived. Phase 9's `R4` returned
`degrade` and Phase 23's `R1` returned `no-go`, both correctly, both against rules
that predated the measurements. This document is what makes the third instance
checkable by a reader who trusts nothing: the rule is reproduced verbatim, the
five input values are transcribed from named files with their paths, and the walk
through the rules is written out so the verdict can be re-derived from the
document alone — without a plan file surviving and without trusting any summary.

`could-not-run` is not an emittable value here. `R9` carries no antecedent and the
rule set is total over all 108 tuples, so a rule evaluator that cannot resolve to
one of the three verdicts is a bug in the rules rather than an outcome. That is
the specific defect Phase 23's gate carried, and removing it is what the ROADMAP
names as this gate's distinguishing property.

Output: the verdict document, the ROADMAP and STATE bindings, and three closed
todos.

**Worktree carve-out:** this plan delivers `.planning/STATE.md` and
`.planning/ROADMAP.md` content, so it takes the stock per-plan
`USE_WORKTREES_FOR_PLAN=false` carve-out. It also moves three files with `git mv`,
which a worktree wave-cleanup refuses unconditionally — another reason the
carve-out applies rather than being worked around.
</objective>
