<objective>
Settle, by measurement on a real autostarted cracked release, the one unknown that
can turn `C0_CAPTURE_PAIR` into `fail` — and record the wall-clock-anchoring
negative control red while doing it.

Purpose: the ROADMAP says the opening task of this phase is a **measurement, not
an implementation**, because every probe behind `REPRO-*` ran at the KERNAL
`READY` prompt over the now-excluded text channel. `33-RESEARCH.md` § *Open
Questions* Q2 is the residue: `AUTOSTART` (0xdd) is itself a power cycle
(`mon_autostart` → `reboot_for_autostart` → `machine_trigger_reset(POWER_CYCLE)`),
so a separate `RESET 1` afterwards undoes the autostart, and one attempt at
*arm-while-halted → `RESET 1` → `AUTOSTART` → count hits* produced no usable stop
(both runs ended at `PC=$FD75`/`$FD70`, `LIN=0`, `hits=0`, inside the KERNAL reset
routine). That is design work for `runReproducible()`, and doing it here — before
the procedure is written — is what stops 33-09 from encoding a guess.

Output: two committed transcripts under the phase evidence directory plus the
named repeatable script that produced them. `AUTOSTART_FRAME_EXACT` is recorded
with a value either way: a non-achievement is a recorded fact with the sequences
tried, never a silent omission.

This is the phase's first live plan. Every other wave-2 plan (33-04, 33-05) is
emulator-free, so nothing contends for the emulator — stock's binary monitor
services exactly one client, and a second connect sits unserviced in the backlog
looking exactly like a wedge.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.d64` release image → `AUTOSTART` (0xdd) | Untrusted, operator-supplied binary input, never committed; drives a real drive emulation |
| binary monitor socket → emulator | Unauthenticated by design; grants full memory read/write plus process control |
| this plan's probe script → `execve(/usr/bin/x64sc, argv)` | argv is assembled in the probe script rather than by the broker, so the broker's own argv discipline does not protect it |
| the emulator's drive CPU → `default_memspace` | A drive checkpoint hit contaminates it and nothing over the binary monitor resets it |
