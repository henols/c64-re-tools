<objective>
Commit the binding go / degrade / no-go decision rules for `GATE-01` **before any
measurement in this phase exists**, so the verdict is derived rather than judged.

Purpose: Phase 9's `R4` and Phase 23's `R1` both fired correctly, five-plus plans
before the measurements they gated existed. This is the third use of that pattern
and the first with an input domain designed so the gate **cannot abstain** —
Phase 23's gate could return `could-not-run` because every one of its inputs
needed a corpus, and the ROADMAP names removing that defect as this gate's
distinguishing property.

Output: three committed files under the phase evidence directory — the rules, the
outcome-line schema, and the evidence conventions plus the banked ordering proof.
This plan touches **nothing else** (D-01): git history is the whole mechanism, and
a plan that also shipped code would make the ordering claim ambiguous.

**Ordering contract:** every other plan in this phase depends on this one. The
`33-02` reconciliation plan runs concurrently in wave 1 but writes nothing under
`evidence/`, so it cannot disturb the proof.
</objective>

- **R1 → `no-go`.** `SLICER` is `failed`. The flat-64K substrate every downstream
  number is measured on does not exist, so Phases 35-38 would measure
  hand-transcribed hex again — the exact error source `CAP-01` removes (one 32 KB

  to `$7871`). Corpus-free.
- **R2 → `no-go`.** `SEED_EFFECT` is `unpinned`. Launch nondeterminism dominates
  every comparison — worth roughly a thousand false-divergence addresses per
  capture pair, with `RAMInitRandomChance` shipping at 10 (0.1% of all RAM bits
  flipped at power-up) — so no capture pair can be trusted. Corpus-free.
- **R3 → `no-go`.** `JITTER_IMMUNITY` is `not-immune`. The reset protocol does not
  reproduce, so there is no frame-exact stop for anything downstream to stand on
  and the milestone's premise fails. Corpus-free.
- **R4 → `degrade`.** `C0_CAPTURE_PAIR` is `fail`. Narrowing authored at verdict
  time against the evidence — deliberately not pre-mapped (D-04), because a
  `fail` whose recorded cause is "the stop was not frame-exact" and a `fail` whose
  recorded cause is "the derivation overflowed the committed cap of 64" narrow in
  different directions.
- **R5 → `degrade`.** `C0_CAPTURE_PAIR` is `not-obtained`. **Pre-mapped narrowing

  was measured without a corpus.
- **R6 → `degrade`.** `ORACLE_NECESSITY` is `unproven`. **Pre-mapped narrowing

  frame term **recorded but not asserted**, and every downstream capture pair
  carries that weakening in its own record.
- **R7 → `degrade`.** `SEED_EFFECT` is `partial`. Narrowing authored at verdict

- **R8 → `degrade`.** `JITTER_IMMUNITY` is `partial`. Narrowing authored at

- **R9 → `go`.** Reached only when `SLICER: validated`, `SEED_EFFECT: pinned`,

**File 2 — `evidence/SCHEMA.md`.** Declare, for each of the five outcome lines:
the exact line name at column 0, its complete value domain, its single source
file, and the derivation rule that produces the value from raw measurements —
so no measuring plan can invent a favourable definition. The derivations:

- `SEED_EFFECT: pinned` iff, over the untouched `$C000-$CFEF` window (4080
  addresses), two cold boots WITH the determinism block differ at **0**
  addresses AND two cold boots WITHOUT it differ at more than 0; `partial` iff
  the with-block count is greater than 0 but strictly less than the without-block
  count; `unpinned` iff the with-block count is greater than or equal to the
  without-block count. Research reproduced 59 -> 0 on this host (M3).
- `JITTER_IMMUNITY: immune` iff three runs at pre-protocol jitter 0 / 1500 /
  4000 ms produce one identical 64K sha256 AND identical `(PC, hit_count, LIN,
  CYC)`; `partial` iff the four-term stop identity matches on all three runs but
  the sha256 does not; `not-immune` iff any of the four stop-identity terms
  differs. Research measured `immune` at the READY prompt (M4).
- `ORACLE_NECESSITY: proven` iff a committed control shows `(LIN, CYC)` **alone
  PASSING** on two stops exactly one frame apart while the full triple correctly
  reports them different; `unproven` otherwise, including when no such pair was
  produced.
- `SLICER: validated` iff both `node --test vsf-slice.test.ts` and `node --test
  capture-predicate.test.ts capture-seam.test.ts` report `fail 0`, with both
  transcripts appended to the source file; `failed` otherwise.
- `C0_CAPTURE_PAIR: pass` iff one real cracked release, autostarted with true
  drive emulation in the loop, was captured twice and the pair compares
  equivalent under `CAP-02`'s predicate with an allow-list at or under the
  committed cap of 64; `fail` iff two captures were obtained and the pair does
  not compare equivalent, or the derivation exceeded the cap; `not-obtained` iff
  fewer than two usable captures were obtained, with the reason named.

Also declare the transcript line conventions the README binds, and the

**File 3 — `evidence/README.md`.** A file table (one row per artifact this phase
will produce under `evidence/`, with "what it proves"), then numbered

`## Ordering proof`. The conventions, copied in kind from Phase 23 and extended
with this phase's two live-run rules:

1. **Transcript convention.** Before running a command, append a line reading
   `$ <the exact command line>` to the named evidence file; then append its real
   stdout and stderr immediately below. A summary written in place of output is
   not evidence. Never reconstruct a transcript afterwards from memory.
2. **Worktree-independent probe directory.** Cross-wave working artifacts live at
   `PROBE_DIR=$HOME/.cache/c64-re-tools/phase33` — never inside the checkout and
   never under `/tmp`, which is tmpfs on this host (16 GB, emptied only on
   reboot) and has already cost this project a build. Record absolute `PROBE_DIR`
   paths in the evidence file.
3. **Broker stopped, recorded (D-11).** Every live run in this phase is taken
   with the VICE broker stopped, and each transcript records `BROKER_STATE:
   inactive` alongside the `TEST_AUTOMATED_BASELINE:` line it was taken against.
   A live broker reddens the `BACK-05` assertion deterministically, so a
   measurement taken against a live-broker run reads a false baseline and every
   number in it is suspect. Such a measurement is **discarded and re-run**, never
   repaired.
4. **Baseline stated, never re-derived (33-RESEARCH.md P8).** The measured
   `test:automated` baseline on this tree is **5 failing tests in 3 files**
   (`anno-register.test.ts`, `docs-deferred-ledger.test.ts`,
   `audit-integrity.test.ts`) from two root causes Phase 33 did not create. Plan
   `33-02` repairs one of them, after which the expected baseline is **2 failing
   tests in `anno-register.test.ts` only**. Every transcript records the count it
   observed and the file names; no transcript writes "clean" or "0 failures".
5. **Voided runs are recorded, not discarded.** A run that produced no usable
   stop is written into the evidence file with its reason. The reported capture
   pair is the pair taken, in the order taken — never the two most similar of N.
6. **Final occurrence wins.** Where an outcome line appears more than once in one
   file, the last occurrence is the value.
7. **Values are transcribed, never remembered.** Every value in the findings
   document comes from a literal outcome line at column 0 of a named evidence
   file, cited by path. Nothing is taken from a plan SUMMARY's paraphrase.
