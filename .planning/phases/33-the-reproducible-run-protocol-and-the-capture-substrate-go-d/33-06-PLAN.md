<objective>
Thread the warp/headless launch profile from the container-side broker client,
through the control plane, into the pool's warm-instance eligibility rule, and out
to `buildViceArgs()` — additively, with an absent profile behaving byte-identically
to today.

Purpose: warp is a **per-instance** property fixed at spawn. That puts it inside
the warm-instance-eligibility problem: a pre-warmed interactive instance cannot be
retro-warped. Of the three available answers, two are wrong in ways a caller
cannot detect — refusing the acquire makes warp unusable whenever a warm floor
exists, and serving it unwarped makes the knob a lie. The third is what this plan
builds, and it is D-16: an instance whose profile does not match is
**ineligible**, and the broker launches a dedicated instance for that grant and
never retro-warps.

Output: an eighth field on an existing control op — not an eighth op — validated
at the boundary, carried on the instance record, honoured by the pool, and
emitted into argv by the builder 33-05 already widened.

**Note on where `D-18` lives.** `D-18` asks for `probeReady`'s real-time timeouts
to be re-checked under warp "in the same plan that adds the profile". That
re-check is a **live, broker-stopped measurement**, and every live measurement in
this phase is governed by `D-10`/`D-11` and lives in a measuring plan. It is
therefore placed in `33-11` — still inside this phase, never deferred out of it —
and widened there to cover `-console` as well as `-warp`, because research
observed one `-console` launch not yet bound at 3000 ms and bound at 5000 ms.
`33-11` cites this paragraph.
</objective>

**`broker-state.mts`.** Add `profile?: LaunchProfile` to `InstanceRecord`,
importing the type from `broker-launch.mts`. Document it in the register the
existing "Plan 03" block uses: optional, because a record created through a path

**`broker-control.mts`.** `ControlRequestKind` stays at seven kinds: this is a
field on an existing op, not an eighth op, and `ControlRequest` already carries an
index signature so an added field parses today without a schema change. Add
`normaliseLaunchProfile(raw: unknown)` returning
`{ ok: true; profile: LaunchProfile | undefined } | { ok: false; message: string }`.
It is the one narrowing site — do not re-derive this check anywhere else. Rules:
`undefined` and `null` return `ok` with `undefined`; a plain object whose keys are
a subset of `{warp, headless}` and whose present values are booleans returns `ok`
with that object; anything else returns `ok: false` with a message naming the
offending value and the accepted shape. Reject unknown keys **by name**, matching
the by-name unexpected-argument discipline the tool handlers already use — a typo
accepted silently means a caller asked for warp and got an unwarped instance with
a confident answer. In the `req.op === "acquire"` handler, call
`normaliseLaunchProfile(req.profile)` before `attemptAcquire`; on `ok: false`,
`writeLine` the existing error shape with code `bad_request` and the returned
message, and do not enqueue the request.

Widen the `onAcquire` dependency to
`(requestId: string, profile?: LaunchProfile) => Promise<AcquireOutcome>` — an
optional second parameter, so every pre-existing one-argument implementation and
test stub keeps satisfying the type and behaving identically. Thread the
normalised profile through `attemptAcquire(requestId, profile)` and through the
`enqueueAcquire` retry closure, so a queued request retried later still carries
the profile it was made with.

**`vice-broker-client.ts`.** Add an optional `profile` to the acquire options and
include it in the request object at **both** write sites. Missing either one means
the profile silently never arrives — the same defect class as a tool argument that
is accepted and dropped. Omit the key entirely when no profile was requested, so
the wire line is byte-identical to today's for a profile-less acquire.

**`vice-broker.mts`.** Add a module-level `profileEligible(record, requested)`
returning a boolean: true when the record's effective profile (absent treated as
`{}`) matches the requested one (absent treated as `{}`) on both `warp` and
`headless`, comparing `=== true` on each side so `undefined` and `false` are the
same request. Add the call as a **synchronous `continue` filter immediately beside

cold-launch path and pass it to `buildViceArgs`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| container-side MCP server → broker control plane (newline-delimited JSON over TCP) | `ControlRequest` carries an index signature, so *anything* parses; this is where the `profile` field enters the host side |
| broker control plane → `buildViceArgs()` → `execve(x64sc, argv)` | An unvalidated `profile` is an argv-construction surface on the host |
| the instance pool's warm floor → a grant | A grant that does not match what the caller asked for is undetectable by the caller |
| a state-directory record written by an older broker → the running pool | Records predating the `profile` field are read at every broker restart |
