<objective>
Build the equivalence predicate `CAP-02` requires, the three-term stop-identity
oracle `REPRO-03` requires, and the structural bar `CAP-03` requires — and prove
the predicate can fail, on a one-bit plant, in CI, on any machine.

Purpose: the existing `compare.mjs` is a **vocabulary analog only**. Its volatile
set is four *ranges* covering 4866 addresses and its drift rule lets any
single-bit difference pass anywhere. A predicate inheriting either makes the
planted-byte control vacuous: plant one bit, the predicate says PASS, and the
fail-ability guard has proven nothing. `CAP-02` requires an enumerated list, never
a range, and a planted byte outside it to fail.

`CAP-03` is the other half: the captured 64K is the **dependent variable** the
oracle certifies, and a predicate that used the capture to certify its own stop
would be circular. Asserting that structurally — by import census and by function
signature — is what stops the next edit from reintroducing it.

Output: two pure byte modules that cannot reach each other, a census test with
planted positive controls, and the `SLICER` gate input derived from both suites by
the rule `SCHEMA.md` states.

**These are the only two things in this phase that become automated tests, per
D-09** — `CAP-03`'s structural bar and `CAP-02`'s fail-ability over a synthetic
pair. They qualify because they are corpus-free and must not regress. Everything
else in this phase's evidence is a committed transcript, so `MANUAL_ONLY_TESTS`
stays at exactly nine files with zero new entries (D-08).

This plan is emulator-free and runs concurrently with 33-06's broker work.
</objective>

Exports:

- `TRANSIENT_ALLOW_LIST_CAP = 64`. Document the reasoning inline so a later reader
  can weigh it rather than trust it: the only measurement in hand is 3 transients
  out of 1024 addresses at the `READY` prompt, itself an upper bound taken under
  frame-divergent conditions; 64 sits an order of magnitude above it and at a
  quarter of the page the requirement names as over-wide. Record that exceeding
  the cap **voids the derivation** — it means the stop is not frame-exact, which
  is a fact the gate must hear rather than a threshold to raise.
- `parseAllowList(json: unknown): TransientAllowList` — accepts the committed
  per-release artifact shape: a release identifier, and an array of entries each
  carrying an `address` (integer 0..65535), the run pairs it differed in, and an
  optional one-line attribution. Refuse: a non-integer or out-of-range address; a
  duplicated address; any range-shaped notation (a `start`/`end` pair, or an
  address written as a two-element span) — refuse it **by name**, stating that the
  list is enumerated and never a range; and a list longer than
  `TRANSIENT_ALLOW_LIST_CAP`, naming the count and the cap.
- `normalisePorts(image, { dirRead, dataRead })` — returns a **copy** with
  `image[0x0000]` set to `dirRead` and `image[0x0001]` set to `dataRead`. Note the
  address order explicitly in a comment: `$0000` is the direction register and
  `$0001` is data, and the CPU-visible values come from the 3-byte suffix after
  the RAM array, not from the 4-byte prefix — measured `prefix=[231,47,0,0]`
  against `suffix3=[39,55,47]` with live registers `$00=47 $01=55`, so a
  prefix-over-RAM copy is wrong by 176 at `$0000`. Explain why these two bytes
  need normalising at all rather than allow-listing: every store to `$00`/`$01`
  overwrites `mem_ram[0]`/`mem_ram[1]` with the VIC's phi1 bus value at that
  instant, so those two RAM bytes are a raster-position artefact rather than
  program state — which is why they are the one legitimate divergence pair, and
  why spending two of the cap's 64 slots on them would hide a real difference.
  This is the ONE normalisation site; do not re-derive it in a caller.
- `compareCaptures(a, b, allowList)` — refuse unless both images are exactly 65536
  bytes, naming the offending length. Compare byte by byte. An address whose bytes
  differ and which is **on** the allow-list is counted and reported as `allowed`;
  any other differing address is a `divergence` and **fails**, whatever the bit
  count. Return
  `{ verdict: "equivalent" | "not-equivalent", differing: number[], allowed: number[], cap: number, allowListSize: number }`
  with `differing` and `allowed` **ascending by address**. Keep `compare.mjs`'s
  report vocabulary in the returned record's field names and in any formatted
  output, and copy its `hex4`/`hex2`/`bin8`/`popcount` helpers in kind — but do
  not import them across the package boundary.
- `argvDigest(argv: string[])` — sha256 via `node:crypto` over the exact argv
  array joined by a single NUL byte (0x00), returned lowercase hex. Refuse an
  empty array by name rather than digesting the empty string. Order-sensitive by
  construction, which is the whole point of `REPRO-04`'s key.
- `CaptureComparisonError` extending `Error`, carrying the offending value.

**The cap boundary.** `parseAllowList` accepts a list of exactly 64 entries and
refuses one of 65, with a message containing both `65` and `64`. Assert the
refusal is a throw with no artifact returned — the cap **voids** the derivation
rather than warning and continuing.

**Range refusal.** `parseAllowList` refuses a range-shaped entry (a `start`/`end`
object, and a two-element array used as a span) with a message stating the list is
enumerated. Pair it with the clean control: the same list with those entries
written as individual addresses parses.

**Adjacency.** With an allow-list containing exactly `0x1000`, assert: a
difference at `0x1000` is allowed; a difference at `0x0FFF` fails; a difference at
`0x1001` fails. Three assertions in one test, so the boundary reads as a boundary.

**Empty and degenerate.** An empty allow-list is legal and two byte-identical
images compare `equivalent` under it. A zero-length image, a 65535-byte image and
a 65537-byte image are each refused naming the length — never reported as
trivially equivalent. A single-address allow-list with a zero-difference pair
compares `equivalent` with empty `differing` and empty `allowed`.

**Ordering / symmetry.** `compareCaptures(a, b, list)` and
`compareCaptures(b, a, list)` produce the same verdict and the same `differing`
array. `differing` is ascending: build a pair differing at `0x8000`, `0x0100` and
`0xC000` and assert the array is exactly those three in ascending order.

**Port normalisation.** Two images identical except at `$0000` and `$0001`,
normalised with the same `{dirRead, dataRead}`, compare `equivalent` — while the
same pair compared **without** normalisation is `not-equivalent`. That pairing is
what proves the normalisation is load-bearing. Also assert `$0000` receives
`dirRead` and `$0001` receives `dataRead`, using two distinguishable values (for
example 47 and 55, the measured live pair), so an address swap reds.

**`argvDigest`.** Order sensitivity (two orderings differ); NUL-joining rather
than space-joining (`["a b"]` and `["a","b"]` produce different digests, which a
space-join would collapse); an empty array throws; the digest is 64 lowercase hex
characters.

invisible to a plain text search, so a shelled-out census silently under-covers —
and has already produced one false decision in this project. Reading files in the
test makes the hazard unreachable rather than merely avoided.

**Assertion 1 — the two modules cannot reach each other.** With literal bodies
