<plan_decision_D-05-18>
**`query` echoes the value the handler actually used, not the caller's raw argument.**

`vice_symbols_lookup` accepts `53280`, `"$d020"` and `"0xd020"` (via `stock-address.ts`'s
`parseAddress()`), and the schema declares one type. Echoing the raw argument makes the
answer's type depend on the caller's formatting choice, which no `outputSchema` in the
supported subset can express (`checkAgainstSchema()` has no `oneOf`). Echoing the **parsed
number** is both schema-conformant and more useful: the agent sees the address the lookup was
performed against.

**Rejected: widening the schema to accept a string.** That would make the schema describe the
defect instead of the contract, and `vice_memory_read`'s own answer already reports parsed
numeric addresses — the two families would disagree about what an echoed address is.

The name branch is unchanged: `query.name` is declared `type:"string"` and the handler already
guards `typeof args.name !== "string"`, so the raw echo is correct there.
</plan_decision_D-05-18>

<plan_decision_D-05-19>
**One canonical path after the containment check: `real` is returned, stat'ed, read and
reported.**

The containment check must apply to the path that is actually opened. Returning `resolved`
while checking `real` means the check and the read can disagree — anything able to replace a
symlink component between them reads a file from outside the workspace, and the answer's
`resolvedPath` names a path that is not what was read.

`realpathSync()` runs **before** `statSync`/`readFileSync`, and all three then operate on the
same fully-resolved string, so the remaining window is narrowed to the kernel's own path
resolution rather than spanning two userspace calls. A stronger guarantee (open-then-fstat on
a held descriptor) is not adopted here: this is a local developer-facing debug bridge reading
a label file inside the developer's own workspace, and the honest mitigation is the canonical
path plus the refusal, not an `O_NOFOLLOW` dance that would change the tool's error surface.
This limit is recorded in the threat register below rather than left implicit.
</plan_decision_D-05-19>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → `path` argument | Model-generated, attacker-influenceable if a prompt or file in the repo suggests a path; resolved against `repoRoot()` and refused unless contained |
| filesystem → MCP server process | `vice_symbols_load` opens a file with `node:fs` **inside the server's own process**, with the server's full privileges — no emulator and no wire involved, so the only guard is the containment check |
| answer → agent reasoning | `query.address` and `resolvedPath` are read by an agent and by downstream schema consumers; a type violation breaks the declared contract for a tool advertised on both backends |
