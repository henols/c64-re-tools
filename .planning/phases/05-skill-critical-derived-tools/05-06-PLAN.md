<plan_decision_D-05-12>
**`hostpath-consumers.test.ts`'s fourth test is vacuous for every multi-word tool name;
this plan fixes it rather than adding four more names it cannot check.**

That test loops `STOCK_DERIVED_TOOLS` and derives a module name with
`stock-${toolName.replace(/^vice_/, "")}.ts`. For `vice_disassemble` that yields
`stock-disassemble.ts`, which is correct. For `vice_memory_search` it yields
`stock-memory_search.ts` with an **underscore**, matching no file that exists or ever
will, so the assertion passes by never testing anything. Adding this phase's eight
multi-word tools to the registry would leave D-02's second enforcement mechanism silently
covering exactly one tool out of nine.

**Decision: replace the derived guess with a declared map plus an existence assertion.**
Add `DERIVED_TOOL_MODULES: Record<string, string>` to the test file, mapping each
`STOCK_DERIVED_TOOLS` member to its real module filename, and assert three things:
1. the map's key set equals `STOCK_DERIVED_TOOLS` exactly, so a new derived tool with no
   mapping fails the test rather than escaping it;
2. every mapped filename **exists on disk** in `.claude/mcp/vice`, so a typo fails loudly
   instead of passing vacuously — this is the assertion whose absence made the original
   guess useless;
3. no mapped filename appears in `hostpath.ts`'s importer set.

Same reasoning 04-CONTEXT's D-02 gives for requiring two mechanisms: CR-07 proved a
structural test can pass while the real violation stands. A guess that cannot match is
worse than no test, because it reads as coverage.
</plan_decision_D-05-12>
