<plan_decision_D-05-22>
**The side-effect claim is downgraded to what the repo can show, in both files that carry it.**

`docs/stock-vice-parity.md` and `observation-hazards.md` both say the stock chip reads are
"**provably** side-effect-free ... a stronger guarantee than 'unverified'". The cited evidence
is a regression test asserting `body[0] === 0x00` — that the client *sends* `sidefx = 0`.
Whether stock VICE's `MEM_GET` honours that flag for `$D01E`/`$D01F`/`$DC0D`/`$DD0D` is an
emulator property with no probe recorded in this repo. The code reviewer's own live probe was
consistent with the claim, but this project's convention is to label claims VERIFIED or
ASSUMED explicitly rather than inherit them from a transcript.

**Decision: downgrade the prose rather than add a probe.** The accurate split is: `sidefx:false`
is hardcoded with no argument able to override it (**VERIFIED** — asserted on the wire body by
a regression test for both chips); whether the emulator's read path honours it for the four
clear-on-read registers is **ASSUMED**, pending a recorded probe. Adding the probe would mean a
new live case in a file three plans in this set already extend, for a claim nothing's
correctness currently depends on. The honest label costs nothing and misleads nobody.
</plan_decision_D-05-22>
