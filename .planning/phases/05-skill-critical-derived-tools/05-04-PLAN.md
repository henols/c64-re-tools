<objective>
Build `vice_cia_get_state` on the stock backend: one `sidefx:false` `MEM_GET` per
requested CIA over its 16-byte register block (`$DC00-$DC0F` for CIA1, `$DD00-$DD0F` for
CIA2), decoded client-side into named bit fields, with every internal-only field
explicitly marked unavailable.

Purpose: the other half of criterion 3. The binary monitor has no CIA command, and the
CIA is the sharpest case of "the register map is not the chip": three of its address
ranges mean **different things on read than on write**, so a naive decoder silently
reports the read side and leaves the caller believing it has the write side.

Output: `stock-cia.ts` exporting `handleCiaGetState`, the pure `decodeCia()` decoder and
the `CIA_UNAVAILABLE_FIELDS` registry, plus `stock-cia.test.ts`.

`stock-derived.ts`, `tools-manifest.stock.json` or `package.json` — 05-07 (wave 3) owns
all four and adds `stock-cia.ts` to `files[]` in the same commit that makes it reachable
(Phase 3 Rule 2).

**Nothing in this plan is host-bound.** No `.mts` file is touched, so `build.ts` runs no
recompile and `resources-sync.test.ts` cannot drift.

<plan_decision_D-05-11>
**The three read-versus-write address collisions are named as unavailable fields, not
silently reported as their read side.**

This is where "never reported as zero" is not enough — the hazard here is a value that
*is* readable but means something **other than what the caller asked for**:

| Address range | Read returns | Write sets | Consequence if conflated |
|---|---|---|---|
| `$xx04-$xx07` | the timer's **current counter** | the timer **latch** (start value) | a caller reading a mid-count value believes it read the configured period |
| `$xx0D` | the interrupt **status** flags | the interrupt **enable mask** | a caller believes it read which interrupts are enabled when it read which have fired |
| `$xx08-$xx0B` | the current **TOD** | the TOD **alarm** time (when CRB bit 7 is set) | a caller believes it read the alarm |

**Decision: report the readable side under a name that says which side it is**
(`timerA.current`, `interruptStatus`, `tod`), **and** declare the write side as an
explicit `{ available: false, reason }` field (`timerALatch`, `timerBLatch`,
`interruptEnableMask`, `todAlarmTime`) whose reason names the sharing address and what
the read actually returns. The two halves of one address therefore appear as two
differently-named answer fields, and the unreadable half is impossible to mistake for
`0`.

Fifth member: `todLatchState` — the internal TOD read-latch/halt flip-flop, not in the
register map at all.
</plan_decision_D-05-11>

**Header comment** (match `stock-memory.ts`'s density). State by name: this is a
**derived** module (DERIV-05) — the binary monitor has no CIA command; it registers
through `withDerivedTool("vice_cia_get_state", { needsSession: true }, ...)`; it must
never import `hostpath.ts` or `vice-proxy.ts`; **`sidefx` is hardcoded `false` with no
argument to override it**, because `$DC0D`/`$DD0D` clear on read in hardware and this
tool exists specifically to read them; it never sends a resume (Phase 3 D-05); the
bit-field names were transcribed once from `memmap.json`'s entries for the addresses
listed in `read_first` and cross-checked at write time, with no automated drift check
(the same posture D-06 of Phase 4 took for the opcode table).

Also state two clarifications that are otherwise easy to get wrong:
- **Port A/B bits are active-low for joysticks and the keyboard matrix**: a *clear* bit
  means pressed. Every joystick field below is therefore computed as `((raw >> bit) & 1) === 0`,
  and the module header says so, so nobody "fixes" the polarity later.
- **This is not a keyboard-matrix read.** `$DC00`/`$DC01` expose the current column
  selection and row result only; the full matrix is `vice_keyboard_matrix`, which is
  provably unrecoverable on stock (`docs/stock-vice-parity.md` §A item 2) and is Phase
  8's business.

**Module constants:**
- `CIA1_BASE = 0xdc00`, `CIA2_BASE = 0xdd00`, `CIA_LENGTH = 0x10` (16).
- `CIA_UNAVAILABLE_FIELDS` — an exported frozen array of `[fieldName, reason]` pairs with
  exactly these five members. Each reason must name the **sharing address** and what the
  read actually returns (see this plan's `plan_decision_D-05-11`):
  - `timerALatch` — the timer A start value written behind `$xx04`/`$xx05`; reading those
    two addresses returns the timer's CURRENT counter, and the binary monitor has no CIA
    command that exposes the latch. The current count IS available as `timerA.current`.
  - `timerBLatch` — the same for `$xx06`/`$xx07`; the current count is `timerB.current`.
  - `interruptEnableMask` — the interrupt-enable mask written to `$xx0D`; a READ of
    `$xx0D` returns the interrupt STATUS flags, not the mask, so the two halves of that
    one address are different data. The status side IS available as `interruptStatus`.
  - `todAlarmTime` — the TOD alarm written behind `$xx08`-`$xx0B` while CRB bit 7 is set;
    reading those addresses always returns the current time of day, never the alarm. The
    current TOD IS available as `tod`.
  - `todLatchState` — the internal TOD read-latch / halt flip-flop; not in the
    memory-mapped register map at all.

**`export function decodeCia(chip: 1 | 2, bytes: Uint8Array): Record<string, unknown>`**
— a **pure** function taking exactly 16 bytes (throw a plain `Error` on any other
length). Index `bytes[n]` for register offset `n`. Decode:

- `chip` (1 or 2), `base` (`CIA1_BASE`/`CIA2_BASE`), `registersHex` (32 lowercase hex
  characters).
- `portA` — `{ raw: bytes[0x00], ... }` plus, **for chip 1 only**,
  `joystick2: { up, down, left, right, fire }` from bits 0-4 **active-low**; and **for
  chip 2 only**, `vicBank` = `3 - (raw & 3)` with `vicBankBase` = `vicBank * 16384`,
  `rs232Txd` (bit 2), `serialAtnOut` (bit 3), `serialClockOut` (bit 4),
  `serialDataOut` (bit 5), `serialClockIn` (bit 6), `serialDataIn` (bit 7).
  Note in a comment that `$DD00`'s bank bits are the INVERSE of the bank number, which is
  why the `3 - (raw & 3)` form is used, matching `dump-artifacts.mjs`'s own verified
  `vicBank()`.
- `portB` — `{ raw: bytes[0x01], ... }` plus, **for chip 1 only**,
  `joystick1: { up, down, left, right, fire }` from bits 0-4 active-low; and **for chip 2
  only**, `rs232Rxd` (bit 0), `ri` (bit 3), `dcd` (bit 4), `userPortH` (bit 5),
  `cts` (bit 6), `dsr` (bit 7).
- `portADirection` — `{ raw: bytes[0x02], outputs: boolean[8] }` (a set bit means the
  corresponding port bit is writable).
- `portBDirection` — the same from `bytes[0x03]`.
- `timerA` — `{ current: bytes[0x04] | (bytes[0x05] << 8) }`.
- `timerB` — `{ current: bytes[0x06] | (bytes[0x07] << 8) }`.
- `tod` — decoded from BCD: `tenths` = `bytes[0x08] & 0x0f`, `seconds` from
  `bytes[0x09]`, `minutes` from `bytes[0x0a]`, `hours` = `bytes[0x0b] & 0x1f` in BCD,
  `pm` = `((bytes[0x0b] >> 7) & 1) === 1`. Provide one private helper
  `function fromBcd(raw: number): number` returning `((raw >> 4) & 0x0f) * 10 + (raw & 0x0f)`
  and use it for `seconds`, `minutes` and `hours`. Also include `rawHex` (the four TOD
  bytes as hex) so a caller can see the undecoded BCD.
- `serialShiftRegister` — `bytes[0x0c]`.
- `interruptStatus` — from `bytes[0x0d]`: `raw`, `timerAUnderflow` (bit 0),
  `timerBUnderflow` (bit 1), `todAlarm` (bit 2), `serialShiftComplete` (bit 3),
  `flagPin` (bit 4), `interruptGenerated` (bit 7), and `interruptKind` — the fixed
  string `"irq"` for chip 1 and `"nmi"` for chip 2, because bit 7 means different things
  on the two chips and the answer should say which.
- `timerAControl` — from `bytes[0x0e]`: `raw`, `started` (bit 0),
  `underflowOnPortB` (bit 1), `underflowPulseMode` (bit 2), `oneShot` (bit 3),
  `forceLoad` (bit 4), `countsCntPin` (bit 5), `serialOutput` (bit 6),
  `todFrequency50Hz` (bit 7).
- `timerBControl` — from `bytes[0x0f]`: `raw`, `started` (bit 0),
  `underflowOnPortB` (bit 1), `underflowPulseMode` (bit 2), `oneShot` (bit 3),
  `forceLoad` (bit 4), `countSource` (bits 5-6, a number 0-3), and
  `countSourceMeaning` — a string from a four-entry lookup: `0` = `"system cycles"`,
  `1` = `"cnt pin positive edges"`, `2` = `"timer a underflows"`,
  `3` = `"timer a underflows with cnt high"`; plus `todWriteSetsAlarm` (bit 7).
- `unavailable` — an object built by mapping `CIA_UNAVAILABLE_FIELDS` to
  `{ available: false, reason }`. Build it from the registry, never as five hand-written
  literals.

**`export const handleCiaGetState: StockSessionHandler`:**
1. `isPlainObject(args)` guard.
2. `cia` — optional. Refuse any key other than `cia`, naming it and listing `cia` as the
   only accepted argument. When present, refuse anything that is not the number `1` or
   the number `2` (or their `"1"`/`"2"` string forms, which `parseByteCount` would accept
   elsewhere — accept both here and normalise), naming the received value. When absent,
   both chips are read.
3. For each requested chip in ascending order: build
   `memGetBody({ sidefx: false, start: base, end: base + CIA_LENGTH - 1, memspace: 0x00, bank: 0x0000 })`
   and send `CommandType.MemoryGet` inside a try/catch →
   `convertWireError("vice_cia_get_state", err)`. Guard
   `response.type !== "memory_get"` and guard
   `response.bytes.length !== CIA_LENGTH`, each refusal naming **which chip** failed and,
   for a short read, both the expected 16 and the received count with the words
   `a short read is a wrong answer, not a partial success`.
4. `stockAnswer(session.client, { requested: <1 | 2 | "both">, cias: [decodeCia(...), ...], count: cias.length })`.
   `cias` is always an array, even for a single chip, so the answer shape does not change
   with the argument. Never a hand-built `{ content, isError: false }` literal.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Tampering | destroying pending interrupt state by reading it (`$DC0D`/`$DD0D` clear on read) | mitigate | `sidefx: false` hardcoded at the single `memGetBody` construction, with no argument to override it. | T-05-04-02 | Repudiation | reporting a readable value under a name that implies the unreadable half | mitigate | D-05-11: the readable side is named for what it is (`timerA.current`, `interruptStatus`, `tod`) and the write side is a separate, explicit `{ available: false, reason }` field naming the sharing address. | T-05-04-03 | Repudiation | an unreadable field reported as `0`, or omitted | mitigate | Five internal/write-side fields in one exported registry, rendered from that registry, pinned by an `enum: [false]` schema declaration (05-07) the conformance harness validates the real answer against, and asserted by a never-zero/never-absent loop (D-05-07's two independent mechanisms). |
