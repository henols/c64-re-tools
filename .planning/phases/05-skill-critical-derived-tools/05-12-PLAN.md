<plan_decision_D-05-20>
**An invalid BCD byte omits the decoded number and names itself; it does not become a
`{available:false}` member of the `unavailable` registry.**

`CIA_UNAVAILABLE_FIELDS` is a **fixed five-member registry** of things stock can *never*
read, pinned in the manifest with `enum:[false]`. An invalid BCD nibble is not that: the
field is readable, and the raw byte is right there — what is missing is a meaningful decimal
interpretation, for this one sample. Injecting dynamic members into `unavailable` would break
the "registry-built, cannot drift" invariant and the schema pin that enforces it.

**Decision:** on an invalid nibble, the `tod` object **omits** `seconds`/`minutes`/`hours` and
lists the omitted names in a new always-present `tod.invalidBcd: string[]` (empty in the
normal case). `tod.rawHex` is already always present, so the caller can always re-derive.
Schema consequence, stated openly: `seconds`/`minutes`/`hours` move **out** of `tod.required`
(they stay declared as `type:"number"`), while `rawHex` and the new `invalidBcd` are
`required`. `checkAgainstSchema()` has no union support, so an "always present, sometimes not a
number" field is not expressible — omit-and-list is the only honest shape inside the supported
subset.

`tenths` keeps its current `raw & 0x0f` decode: a nibble is 0-15 and values 10-15 are not
"invalid BCD" in the same sense; it is reported as the raw nibble it is.
</plan_decision_D-05-20>

<plan_decision_D-05-21>
**Confounded joystick state is reported both machine-readably and in prose.**

Two additions, because the two consumers differ: an agent reads prose, a script reads fields.
- Inside `joystick1`/`joystick2`, a `confounded: boolean` plus a `confoundedReason: string`
  (present only when `confounded` is true).
- On each chip entry, a `notes: string[]` — the shape `stock-sprites.ts` already uses for its
  window hazards, so a caller meets one convention.

The **condition** is derived from data already in the buffer, not guessed:
`chip === 1 && portADirection.raw !== 0x00` — i.e. CIA1 with any port A pin configured as an
output, which is the KERNAL's normal `DDRA = $FF` state and the precondition for a column
being driven. The five booleans keep their current active-low decode; they are annotated,
never deleted, because with `DDRA = $00` (a game that stopped scanning the keyboard) they are
genuinely a joystick reading.
</plan_decision_D-05-21>
