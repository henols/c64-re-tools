<objective>
Migrate the two existing violations off direct external-binary spawning and onto the seam,
without changing a single thing a caller can observe.

Purpose: SEAM-05 states the ordering as a requirement — the whole-tree gate "can only be
written once nothing violates it", and two skill scripts violate it today. This plan is
that clearing. It is also where the migration's real risk lives: `.github/workflows/ci.yml`
invokes `acme.mjs build` on a flat runner with no container and no broker, and
`packer-finding.mjs`'s two functions are contractually never-throw with an absent oracle as
an expected state. A migration that quietly breaks either has removed a working route
rather than moved it.
Output: `mcp-module.mjs` (the one resolution ladder), and both scripts migrated.
</objective>

Planner assumption **A-08 — the resolution ladder is EXTRACTED, not copied.**
`src/skills/c64-ram-capture/scripts/vsf-slice.mjs` already carries the three-rung ladder
(`$VICE_MCP_DIR`, the in-repo relative path, `require.resolve("@henols/vice-mcp/<file>")`)
with a refusal that names every path tried, and its own header records WHY a skill script
invokes an MCP-tree module rather than importing it: the two trees ship in different npm
packages, so a plain cross-package `import` resolves on neither installer route. Rather
than let two more copies appear, extract that ladder into
`src/skills/c64-ram-capture/scripts/mcp-module.mjs` and convert all three production
consumers. Cross-skill relative imports are already established in this tree
(`c64-provenance-diff/scripts/diff-images.mjs` imports four symbols from
`../../c64-ram-capture/scripts/`), and `installer/scripts/sync-skills.mjs` copies whole skill
directories preserving that layout, so the relative path resolves on both distribution
routes. `derive-transients.test.mjs` carries a fourth, TEST-ONLY copy: it is deliberately
left alone (test files ship in neither tarball) and given a pointer comment instead.

`packer-finding.mjs`,** which resolves `34-RESEARCH.md`'s Assumption A4 and Open Question 3.

`packer-finding.mjs` is its colocated `src/skills/c64-program-recon/scripts/packer-finding.test.mjs`,

`command -v unp64` returns nothing), so the oracle route's live path cannot be exercised
here. That is exactly the state `packer-finding.mjs` already treats as an expected,
visible absence, and `packer-finding.test.mjs` already has a named skip plus an
always-runs case that turns the absence into a hard failure under
`VICE_REQUIRE_UNP64`. Preserve both. Do not weaken the always-runs case to accommodate the
migration.
