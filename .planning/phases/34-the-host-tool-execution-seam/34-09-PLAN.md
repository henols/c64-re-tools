<assumption_delta_decision>
**The noun that just lost its monopoly: the host-tool timeout budget.**

The `assumption-delta` detector fired `pluralization` on this phase's scope. Both cited
snippets are prose artifacts, but the genuine transition is here: until this plan there is
ONE number — `DEFAULT_HOST_TOOL_TIMEOUT_MS = 20_000` — bounding every `host_tool`
invocation on the server side, and ONE constant (`CONTROL_CONNECT_TIMEOUT_MS`) bounding
everything on the client side. This plan introduces a second budget for a second tool, and a
second timer for a second phase of the round trip.

- **Primary noun (generalized):** a **per-tool budget**, resolved per tool id, on each side
  of the seam.
- **Decision: `promote`.** The per-tool table becomes the primary representation on both
  sides. `DEFAULT_HOST_TOOL_TIMEOUT_MS` is demoted to the fallback value for a tool id with
  no entry, and a completeness assertion (every `HOST_TOOL_IDS` member has an entry) makes
  that fallback unreachable for the tools that exist today — so the single default cannot
  quietly keep governing a tool whose real cost is different. On the client side,
  `CONTROL_CONNECT_TIMEOUT_MS` is demoted from "the round-trip bound" to what its own header
  comment always said it was: the TCP-connect bound only.
- **Rationale:** adding a second budget alongside a still-primary single default is exactly
  how this defect happened — a number chosen for a stateless assembler silently governed a
  JVM. Promotion makes "which budget governs this tool?" a question with one answer per tool
  rather than one answer per codebase.
- **Deliberately NOT introduced: a wire-supplied timeout.** The review offers "per-tool (or
  wire-supplied and capped)". A wire field would widen the very allowlist this phase exists
  to tighten, and plans `34-07`/`34-08` spent their whole scope removing wire-supplied
  values from privileged positions. Budgets stay host-side configuration, like the ACME
  library directory and (after `34-08`) the oracle's location. The `deps.timeoutMs`
  parameter remains an in-process test seam, not a wire field.
- **Invariant tests accepted (the companion this checkpoint suggests):** the per-tool
  completeness assertion and the cross-seam ordering assertion both go red the instant a
  future phase reintroduces the singular assumption or adds a tool without a budget.
</assumption_delta_decision>
