## Planner assumptions recorded here (no discuss-phase ran for this phase)

Four design questions were genuinely open. Each is decided here, with its reasoning, so the
executor implements a decision rather than re-opening one. Two of them are `34-RESEARCH.md`'s
own Open Questions.

**A-01 — one op with a typed payload, NOT one op per tool** (resolves RESEARCH Open
Question 1). `ControlRequestKind` gains exactly ONE new member, `host_tool`, carrying a
`tool` field naming the namespaced tool id (`acme.build`, `oracle.probe`, `oracle.run`,
`ghidra.analyze`) plus a typed `args` object. The namespacing SEAM-01 asks for lives in the
`tool` field's value; the per-tool typing SEAM-02 asks for lives in the allowlist inside
`host-tool.mts`. Reasoning: `broker-control.mts:39-43`'s own D-15 comment states the
project's most recent decision on exactly this question — "Adding an eighth kind here would
have meant a second acquire path to keep in sync with this one; there is deliberately only
one." One op means one dispatch branch, one narrowing site, and `ControlRequestKind`'s two
byte-exact tests edited exactly once ever, rather than once per tool for the rest of the
project's life. The seed's prose pulls the other way ("prefixed op values slot into that
chain directly"); the prefix survives, as the `tool` value, so the seed's intent is met
without the per-tool cost. Reversibility: reversible — splitting `host_tool` into per-tool
ops later is a change to one branch, one narrowing function and two test literals; the
control protocol is internal to a container-host pair that ships as one package version, so
there is no published contract to break and no data to migrate.

**A-02 — "recorded" means the response plus one broker stderr line, NOT a persistent audit
file** (resolves RESEARCH Open Question 2). SEAM-02's "with the invocation and its exit
status recorded" is satisfied by (a) `exitStatus` on the response object, and (b) one
structured single-line diagnostic on the broker's own stderr per invocation, mirroring the
`process.stderr.write` diagnostics `vice-broker.mts` already emits at startup. Reasoning:
nothing in the existing control plane persists a request log, `incident-record.ts` is scoped
to VICE crash/recycle events rather than arbitrary invocations, and a persistent audit file
is a heavier reading than the requirement's words support. Reversal condition: if a later
phase needs to answer "which host-tool invocations ran during this capture", promote (b) to
a file under the supervisor directory. Reversibility: reversible.

**A-03 — request paths are workspace-relative and resolved server-side; only RESULT paths
cross through `containerpath.ts`.** A `host_tool` request never carries a host-absolute
path. Every path argument is a workspace-relative path, which the executor resolves against
the broker's own `--repo-root` and then re-checks to be inside it, refusing anything that
escapes. Reasoning: three wins at once. It is the path-traversal mitigation (T-34-03); it
avoids importing `hostpath.ts` anywhere in the new family, so
`hostpath-consumers.test.ts`'s five-member `EXPECTED_IMPORTERS` set does not have to be
widened at all — which is the ROADMAP's own preferred shape ("one declared-consumer module
the rest of the family reaches through"), here achieved by construction because
`containerpath.ts` is already in that set; and it keeps the wire shape symmetric with
SEAM-03's mandate that RESULTS cross "through `containerpath.ts`", which is the one
direction the requirement actually names.

**A-04 — `host-tool.test.ts` imports the COMMITTED `resources/host-tool.mjs`, not
`host-tool.mts`.** Reasoning: `host-tool.mts` will (in plan 34-03) value-import a sibling
host-bound module by its `.mjs` specifier, and that specifier only resolves inside
`resources/`, never against the unbuilt source — which is exactly why every other
host-bound module keeps its sibling imports type-only. Testing the emitted artifact is not a
weaker test: `resources-sync.test.ts`'s first case asserts `resources/` is byte-identical to
a fresh build of its TypeScript source, so the artifact and the source are the same code by
guard. The established precedent for this import shape is `broker-state.test.ts:391`
(`await import(new URL("./resources/vice-broker.mjs", import.meta.url).href)` with an
explicit cast), and `tsconfig.json` excludes `resources` so `tsc --noEmit` is satisfied by
the cast. Adopt that shape from the start rather than switching the import in a later plan.
