Planner assumption **A-11 — the discovered set is EXACTLY EMPTY, not a frozen non-empty
record.** `spawn-seam.test.ts`'s `EXPECTED_EMULATOR_SPAWN_SITES` is a frozen one-entry
record because the emulator legitimately has one spawn site. After plan 34-04 no skill
script spawns any external binary at all, so this gate's expected set is the empty set and
its assertion is `deepEqual(discovered, [])`. There is deliberately NO allowlist to add an
entry to — an allowlist is how "no skill script spawns a host binary" becomes "no skill
script spawns a host binary except these", one entry per milestone, which is the decay
pattern the project's own Standing Constraint on repaired guards describes.

Planner assumption **A-12 — the interpreter is not an external binary, and that distinction
is the gate's hardest case.** `vsf-slice.mjs`'s header already records the reasoning in
terms: `process.execPath` is the interpreter already running the script and the target is a
file inside one of this project's own two packages, so no external host binary is reached
and the seam is not involved. Plan 34-04's migrated scripts reach the seam the same way.
The gate must therefore exempt a child process whose command resolves to the interpreter —
directly, or through a local declared from it — and must NOT exempt a bare command name.
That distinction gets a case in both directions, and `vsf-slice.mjs` is the real on-disk
positive proof that the exemption is not vacuous.
