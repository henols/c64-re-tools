<objective>
Close **DIST-03** — the milestone's own stated definition of done — by re-running the
install-to-RAM-capture walkthrough that Phase 8.1 ran and honestly recorded as
`failed`.

The audit's §5 flow table says it plainly: *"Fresh install → `VICE_BACKEND=stock` →
`c64-ram-capture` full 64K RAM capture — ✗ BROKEN. This is the milestone's stated
finish line."* Phase 8.1 drove it, hit `?DEVICE NOT PRESENT ERROR`, root-caused it,
confirmed the one-flag fix live, and then deliberately **declined to apply the fix to
force a pass**, recording `status: failed` instead. That refusal is why this phase can
be specific about what is broken. This plan is the other half: run it again now that
plan 02 has landed the fix and plan 03 has proven the fixed code path live, and record
whatever actually happens.

Two things make this a re-run rather than a repeat. First, the ROADMAP is explicit that
DIST-03 is not satisfied until the capture succeeds **on a broker-launched stock
instance** — so this run must prove the emulator it drove was launched by the host
broker with the fixed argv, not hand-spawned. Second, the recording protocol is
non-negotiable: pass or fail, never pending.

Purpose: item 3 of the ROADMAP's four ordered items. Gated on item 1 (plan 02) and on
plan 03's live proof; plan 05 reads its recorded outcome rather than assuming one.
Output: an evidence document and a recorded Test 1 verdict in `08-HUMAN-UAT.md`.
