## Accomplishments

- **Task 1 (broker-launch.mts, four remaining hops):** Widened `MaintainWarmFloorDeps.spawn`/`spawnFactory` and `SuperviseChildDeps.spawn`/`spawnFactory` to the same optional third `SpawnOptionsWithoutStdio` argument plan 02 established for `TryLaunchDeps`/`AcquirePortAndLaunchDeps`. Widened `withCrashSupervision()` in both its type AND its wrapper body — the call changed from `baseSpawn(cmd, args)` to `baseSpawn(cmd, args, options)`, since a type-only widening would still have silently dropped the value at that exact call site (`grep -c 'baseSpawn(cmd, args)'` now returns `0`). Fixed `launchSupervised()`'s `defaultRealSpawn` to accept and **merge** the caller's options with the per-instance log `stdio`, caller options spread first:
  `return nodeSpawn(cmd, args, { ...options, stdio: ["ignore", fd, fd] });` (`broker-launch.mts:1397`) — so a crash-respawn of an isolated stock instance stays isolated, and the forensic per-instance log (D-23) is never silently redirected.
- **Task 2 (vice-broker.mts, both real spawn-factory closures):** `makeLoggingSpawn()`'s returned `spawn` now merges caller options the same way, log fd winning: `spawn: (cmd, cmdArgs, options) => nodeSpawn(cmd, cmdArgs, { ...options, stdio: ["ignore", logFd, logFd] })` (`vice-broker.mts:270`). Verified (not assumed) that `handleAcquire`'s cold-launch closure needed no body change — it already returns `withCrashSupervision("acquire", port, spawn, ...)` where `spawn` is `makeLoggingSpawn`'s own widened closure, so Task 1 + Task 2's `makeLoggingSpawn` fix alone closes that arm. Fixed the warm-floor arm's own independent dropper, `maintainWarmFloorForRealBroker`'s inner `stashingSpawn`, which previously called `spawn(cmd, args)` (silently dropping options even after `makeLoggingSpawn` was fixed) — now `spawn(cmd, args, options)`.
- **Task 3 (vice-broker-acquire.test.ts, the non-bypassable proof):** Two new automated tests call the real composition with no spawn override at all. Both spawn a throwaway, self-written Node recorder script (never fetched — written by the test itself into its own `mkdtempSync` scratch dir) that records `process.env.XDG_CONFIG_HOME ?? "<unset>"` and blocks until killed. Confirmed: a stock cold-acquire and a stock warm-floor spare launch each produce a real child process whose recorded `XDG_CONFIG_HOME` is non-empty, not `<unset>`, differs from the ambient value, and lives under `os.tmpdir()`; a fork cold-acquire's recorded value stays `<unset>` (BACK-02); and each case's per-instance `logs/` file still exists, proving the stdio-wins merge order end to end rather than assuming it.
