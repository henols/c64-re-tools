<objective>
Make the **I-1** config-isolation fix actually reach the code production runs.

Plan 02 widens `TryLaunchDeps.spawn` / `AcquirePortAndLaunchDeps.spawn` and has
`spawnAndRecordInstance()` compute a scratch `XDG_CONFIG_HOME` and pass it as a third
argument. That is the bottom of the chain and it is necessary — but on its own it is
**dead code in production**, because `deps.spawn` / `deps.spawnFactory` is never
undefined there. The real spawn function is composed in `vice-broker.mts`, and the
third argument is silently dropped at **four** separate hops:

- `makeLoggingSpawn()` (`vice-broker.mts:256`) is hardcoded two-arg and hands
  `nodeSpawn` a fixed `{ stdio: ["ignore", logFd, logFd] }` with no `env` field. It
  structurally ignores any third argument.
- `withCrashSupervision()` (`broker-launch.mts:1228-1240`) has a two-arg type for both
  `baseSpawn` and its returned wrapper, and its body calls `baseSpawn(cmd, args)`.
- `maintainWarmFloorForRealBroker()`'s inner `stashingSpawn` closure
  (`vice-broker.mts:~830`) is a second, independent two-arg dropper on the warm-floor
  arm specifically — fix only `makeLoggingSpawn` and the warm floor still leaks.
- `launchSupervised()`'s `defaultRealSpawn` (`broker-launch.mts:1292-1295`) is the
  respawn path's own spawn, two-arg, with its own fixed `stdio`. Left alone, a
  crash-respawn of an isolated stock instance comes back unisolated.

`grep -rn 'XDG_CONFIG_HOME' --include='*.ts' --include='*.mts' --include='*.mjs'
.claude/mcp/vice/ | grep -v '\.test\.'` returns **zero** hits today. This is genuinely
unimplemented anywhere in non-test code.

**The verification trap this plan exists to avoid.** A stub injected *below* the
composition cannot prove the composition forwards anything. Plan 02's unit tests inject
a three-arg spawn straight into `tryLaunchOne()`. Plan 03's in-process route passes
`spawn: nodeSpawn`, which genuinely takes three arguments. Both would go green with the
production path still broken. `HandleAcquireDeps.buildColdSpawnFactory`'s own doc
comment says the existing test injects it and thereby never spawns a real process — so
the real composition has never been exercised in this project's history. This plan's
test must call `handleAcquire()` with `buildColdSpawnFactory` **omitted**.

Purpose: closes I-1 for real, and is a prerequisite for plan 03's through-the-daemon
live test and for plan 04's tightened `/proc/<pid>/environ` assertion.
Output: a third options argument forwarded end to end, both generated host artifacts
rebuilt, and two composition tests that an injected stub cannot satisfy.
</objective>
