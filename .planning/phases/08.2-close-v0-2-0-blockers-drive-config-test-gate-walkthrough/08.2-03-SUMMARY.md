## Accomplishments

- Closed audit item I-2's mandated coverage clause: `stock-broker-live.test.ts` launches genuine stock VICE through the real spawned `resources/vice-broker.mjs` artifact — so both `buildViceArgs()` and the production `makeLoggingSpawn()` + `withCrashSupervision()` daemon composition are in the call path — reads the granted process's actual argv and `/proc/<pid>/environ` back from the process table (proving `-drive8type 1541` and a scratch `XDG_CONFIG_HOME` genuinely reached the real daemon, not merely the code that computes them), then dispatches `vice_disk_attach` + `vice_autostart` against a synthetic `.d64` and proves the program's bytes landed in memory via a `sidefx:false` read — never trusting the tool's own success report alone.
- Settled the `.prg`-only blast-radius question the audit's §4.2 labelled "reasoned inference, untested either way": with `Drive8Type=1541` (post-fix), a bare `.prg` autostart with no prior `vice_disk_attach` loads cleanly through the real daemon; with `Drive8Type=0` (pre-fix, reproduced via the supported `VICE_ARGS` static override, in-process `tryLaunchOne()`), the AUTOSTART wire command is refused outright (`isError:true`, `CmdFailure`/`0x8f`) and the payload never lands. **Verdict: `all-program-loads`** — a bare `.prg` autostart hits the identical wall a `.d64` load does; it does not bypass the drive.
- Registered `stock-broker-live.test.ts` as the seventh and, per this plan, last `MANUAL_ONLY_TESTS` entry in `test-gate.mjs`, correcting all three stale "six" references to "seven" and updating `test-gate.test.ts`'s own hardcoded drift-guard array in the same wave (a necessary, in-scope consequence — see Deviations).
- Recorded the full live transcript, the machine-readable `blast_radius: all-program-loads` verdict, and an honest read of `08.2-RESEARCH.md`'s Assumptions Log (A1 consistent-with-but-not-confirmed, A3 untouched) in `08.2-BROKER-LIVE-EVIDENCE.md`.
- Discovered and documented two genuine, unplanned live findings during fixture development (neither a source defect, both recorded as FINDING-D1/D2 in the evidence doc): VICE's own BASIC-relink pass overwrites a raw `.prg`'s first two loaded bytes on any LOAD+RUN autostart regardless of content; and the binary monitor halts the CPU on every inbound byte, so a live poll loop must resume-sleep-then-read, never read-immediately-after-resume, or it observes zero real run time.

## Two Unplanned Live Findings (documented in full in `08.2-BROKER-LIVE-EVIDENCE.md`, neither fixed — no fix needed)

- **FINDING-D1:** A raw machine-code `.prg` loaded to `$0801` has its first two bytes overwritten by VICE's own BASIC-relink pass as part of AUTOSTART's simulated RUN keystroke, regardless of payload content (confirmed with two different fixture contents landing on the identical computed override). Genuine, well-known C64 KERNAL/BASIC behaviour, not a defect in `stock-machine.ts`. The fixture and its assertion window were designed around this rather than fighting it.
- **FINDING-D2:** The binary monitor halts the CPU on every inbound byte; a live poll loop that reads memory back-to-back with no resume in between starves the CPU of real run time almost entirely. The correct shape (resume → sleep → read) is what `pollUntilBytesMatch()` implements.
