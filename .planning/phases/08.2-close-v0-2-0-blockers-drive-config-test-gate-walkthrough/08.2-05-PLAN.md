Close audit §7's **E-1 through E-5**, the documentation drift the newly-found defect

it must read it rather than copy a number out of the audit or out of this plan's own
prose.

should say three: the two already named are `vice_sid_get_state` and
`vice_keyboard_matrix`, and the third — found by plan 05-08's skill-versus-manifest
sweep and already recorded as a hard loss in `docs/stock-vice-parity.md` §A — is
`vice_keyboard_restore`. **E-4** is STATE.md, which the audit describes as
`milestone_complete` / 9-phases / 89% — a description that live inspection suggests is

legitimate outcome. **E-5** asks only that Phase 8.1's five orphaned walkthrough
findings get a tracked home; it explicitly does **not** ask anyone to fix them.

`Total plans completed: 76`) in its consistency assertions. This project's own
`phase.complete` and `state.*` SDK commands **recompute** those from disk, so the
assertions broke twice on legitimate advancement — once mid-execution. Every check this
plan writes asserts **self-consistency** (body value equals frontmatter value; coverage
arithmetic adds up) and never a pinned magic number.
