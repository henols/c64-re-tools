Write `evidence/proof02-enumerate-sites.mjs`: the one place in this phase that
decides WHICH addresses are candidate indirect-dispatch sites, and it must reach
that decision without Ghidra having contributed anything. Header modelled on
`capture-pair.mjs`'s, with an explicit section naming the D-06 circularity guard:
this file never opens, parses or reads a Ghidra export, and nothing downstream may
add a site to its output.

It must not import Node's child-process module: the dxa invocation, when the
`--dump` cross-check is requested, goes through `runDxaDisassemble()`, which owns
the host-tool seam.

**Enumeration method** (state it in the header and emit it verbatim as
`PROOF02_SITES_METHOD`): a linear byte scan for opcode `$6C`, the NMOS 6502
`JMP (abs)` — the only indirect control transfer the NMOS 6502 has, since `$7C`
`JMP (abs,X)` is a 65C02 opcode and does not exist here. For each `$6C` site,
read its 16-bit little-endian operand as the pointer address, then walk backwards
a bounded 48-byte window classifying how that pointer was loaded:

- **`immediate-index`** — the pointer's low/high bytes are stored from an indexed
  load (`$BD` `LDA abs,X`, `$B9` `LDA abs,Y`, `$B5` `LDA zp,X`, `$B1` `LDA (zp),Y`)
  whose index register was last set by an immediate load (`$A2` `LDX #imm`,
  `$A0` `LDY #imm`, or `$A9` `LDA #imm` followed by `$AA` `TAX` / `$A8` `TAY`)
  with no intervening write to that register. This is the pivot fixture's own
  shape and is explicitly NOT the case PROOF-02 asks about.
- **`computed-index`** — the same indexed-load-into-pointer shape, but the index
  register was last set from memory or arithmetic (an absolute/zero-page load
  such as `$AD`/`$A5`/`$AE`/`$A6`/`$AC`/`$A4`, or any of `$29` `AND #imm`,
  `$0A` `ASL`, `$4A` `LSR`, `$69` `ADC #imm`, `$E8` `INX`, `$C8` `INY`, `$CA`
  `DEX`, `$88` `DEY` applied after it). This is PROOF-02's case.
- **`vector`** — the pointer operand is a fixed hardware vector address in
  `$FFFA-$FFFF`, or the pointer is never written in the window. Phase 36's
  BRK-trick finding lives in this bucket, and it is a different mechanism from a
  computed-index dispatch table — the enumerator must not merge the two.
- **`unknown`** — none of the above matched. Reported, never dropped.

**Cross-check, never a filter.** When `--dump <path>` is supplied, parse it with
`parseDumpListing()` and annotate each site with whether dxa classified that
address `code`, `data`, `unclassified` or not at all. Report the annotation
beside every site; do NOT remove sites dxa called data — a `$6C` byte inside a
data region is a false site and saying so is part of the record. Report the
per-class counts.

**Output.** `enumerate` prints a deterministic report: the image sha256 and
length first, then `PROOF02_SITES_METHOD` and `PROOF02_CIRCULARITY_GUARD` (a
one-line statement that no Ghidra output was read), then the site table sorted
ascending by address with columns address, pointer operand, classification, dxa
class, and the disassembled backward-window bytes as hex. Then the counts. With
`--json <path>` it also writes the same site list as JSON with keys in a fixed
order, so plan `38-04` and the loader-stage record read one artifact rather than
re-parsing prose.

Both `--prg` and `--flat64k` are supported from the start, because plan `38-04`
runs this identical file against a flat 64K capture; the origin is read from the
`.prg`'s own two-byte header in the first case and is `$0000` in the second,
never hardcoded either way.
