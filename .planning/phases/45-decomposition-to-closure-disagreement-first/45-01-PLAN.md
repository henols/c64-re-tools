The `assumption-delta scan` fired `pluralization` on the phrase "match it
rather than inventing a second convention". The real identity question behind
that signal, answered here once for the whole phase:

- **Primary noun:** the *per-fixture annotation store* (D-01). There is no
  singleton "the store" anywhere in this phase; every verb, every report and
  every committed artifact is scoped to one `--store` path, and the store path
  IS the identity. Nothing needs promoting on that axis.
- **Decision: `promote`** — for the *decline record only*. Today
  `runMemmapJoin()`'s `JoinDecision { outcome: "declined", reason }` is an
  in-memory value returned in one tool call's JSON and never persisted
  (RESEARCH.md §3, MEASURED). This phase promotes the **persisted store
  comment** to the primary, durable decline record and demotes the returned
  `JoinDecision` to a transient view of it. Rationale: criterion 4 asks for a
  *recorded* decline, and a record that vanishes when the tool call returns is
  not one.
- **Not `add-alongside`:** no second decline mechanism is introduced. Three
  distinguishable comment-text prefixes ride the ONE existing
  `anno_set_comment` API (frozen in plan 45-02).
- **Invariant test suggested and accepted:** plan 45-04's report test asserts
  that a declined address is visible to a reader who has only the store — i.e.
  a decline that exists solely in a tool-call response is not counted as
  recorded. That test goes red the moment a future phase reintroduces the
  ephemeral-only shape.
</assumption_delta_decision>
