(a) `scripts/lib/skill-descriptions.mjs` — pure predicates, every export taking content as a

Export: a frontmatter parser returning the name and description; a trigger-clause splitter that
cuts at the first case-insensitive trigger phrase, treating the head as the capability sentence
and splitting the tail on commas, the word "or", full stops and semicolons; a clause normaliser

markers, map both dash forms to a hyphen, drop characters outside a named safe set, split on
whitespace and hyphens, crudely stem tokens longer than four characters, and drop members of two
named stop-lists, one of function words and one of domain words; a token-set builder; a Jaccard
similarity; and a collision detector taking a map of skill name to description and returning an
array of collision records, empty when clean. Each record carries both skill names, the two
colliding clauses verbatim, and the score.
Fix the contention rule as: any pair whose maximum pairwise clause score is greater than OR
EQUAL to the threshold, OR any pair with an identical normalised token set regardless of the
threshold. Ignore clauses with fewer than two surviving tokens. Sort the returned records by
descending score then by the two names alphabetically, and emit each unordered pair once.

it, and the upstream sibling pair that scored above the ceiling — which is why absorbed
descriptions were rewritten rather than carried. State that the value is a measured choice with

never a failing pair).

unordered pairs for the scanned count; or the scanned count is below a floor. On success print
exactly one line beginning with the check's own name and OK, carrying skills scanned, pairs

allowlist size. Use a floor for the scanned count, never an equality — a census assertion pinned
to an exact number goes red on a correct tree, which this project has already paid for once.
