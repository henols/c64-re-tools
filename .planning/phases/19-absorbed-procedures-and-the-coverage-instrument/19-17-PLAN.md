<objective>
Replace "one hand-built fixture per shape" with a property over a COMPOSED corpus and a COMPUTED
oracle. D-03 through D-05 still scale with the number of shapes: they put the suite one round *ahead*
of the defect rather than past it. This plan is the move that ends the loop (D-06).

Two things make it a property rather than a bigger table:

**Generation is compositional.** A fragment alphabet — indexed load × register × table base, zero-page
store × address, `pha`, `txa`/`tya`, `rts`, `jmp (zp)`, `lda (zp),y`, `nop` — is interleaved under a
bounded budget. The generative dimensions are ORDER, INTERLEAVING, GAP PLACEMENT and LENGTH, which is
what lets the corpus contain arrangements nobody enumerated. Hundreds of payloads, not twenty.

**The oracle is computed from composition.** `expectedProvenLink()` implements six numbered structural
rules, stated ONCE, and decides every arrangement's expected verdict from its fragment list. There is
no per-payload human declaration anywhere in the corpus. A boolean typed per template cannot be right
about a case nobody thought of, which is exactly the practice this file exists to replace.

**Why this is a specification and not a second implementation.** The oracle reads the SYMBOLIC fragment
list. The instrument reads BYTES: it decodes, scans a window, reconstructs tables, walks a census. The
two never share a code path and meet only at the final boolean. The oracle has no decoder, no
recursive descent, no advisory-candidate logic and no census. It states what a proven data-flow link IS
— which is D-02's invariant written down as a function — and the set equality asks whether the
instrument agrees.

Purpose: stated this way the property holds for shapes nobody has filed a finding for, which is what
"would have caught all three prior rounds' defects without knowing about any of them" requires.

Output: `src/mcp/vice/r2000-coverage-grammar.test.ts` — the alphabet, the bounded stratified
enumerator, the generator's throws, the computed oracle, the corpus-wide properties, the nine pinned
regression members, and two planted-violation demonstrations that report how many arrangements each
loosening falsely proves.

**Requirement scope.** `ABS-01`…`ABS-04` and `SURF-03` are closed by plans 19-01…19-05 and are out of
scope for this round. `COV-02` is cited because the dispatch gate is the mechanism both requirements
read. The open requirement is `COV-01`.

**Where this file lives, and why.** A new `*.test.ts` directly under `src/mcp/vice/` is picked up
automatically by that package's `node --test '*.test.*'` script, which is cwd-only and non-recursive;
`ci-suite-coverage.test.ts` derives suite DIRECTORIES from the repository and `src/mcp/vice` is already
provably covered by a CI step, so no CI wiring changes. The file is deliberately NOT added to
`package.json`'s `files[]`, so neither published tarball gains a byte and `check-npm-packages.mjs` keeps
its current verdict.

**If the oracle turns out to be infeasible.** The planner judges it feasible: the six rules below are
each one clause of documented behaviour, the arrangement is symbolic, and the data tail is fixed and
known. If the executor nonetheless finds that computing the expectation requires reproducing the scan's
window arithmetic, advisory logic or decoder, it must STOP, record that finding, and report that D-06's
loop-ending claim is NOT delivered this round. Falling back to a hand-declared boolean per template
while keeping D-06's label is forbidden.

Write `expectedProvenLink(arrangement)`: ONE function over the SYMBOLIC fragment list that returns
whether a proven data-flow link exists. It must not decode, must not scan bytes, and must not import
anything from `r2000-coverage.ts` except the shared constants `SPLIT_TABLE_WINDOW` and
`MAX_TABLE_ENTRIES`. Its only contact with bytes is reading the FIXED `DATA_TAIL` to reconstruct target
values, which is arithmetic over a known constant rather than a reimplementation of anything.

Implement it as six numbered rules, each written as its own small helper with a comment naming the
source behaviour it states. Number them in the file so a failure can cite one:

  R1 — PAIRING. Two indexed loads L1 before L2, indexing through the SAME register, with DISTINCT
  table bases, where L2 occurs at most `SPLIT_TABLE_WINDOW` fragments after L1.

  R2 — THE CLASS-4 WINDOW, AND WHEN IT IS CLAIMED. Five consecutive fragments matching indexed load,
  `pha`, indexed load, `pha`, `rts`, with both loads through the same register. The window is CLAIMED
  on shape and register alone — BEFORE any plausibility test — because the source adds every
  instruction of a matched window to `classFourWindow` before it walks and validates the table. Getting
  this ordering wrong is the difference between a correct oracle and one that disagrees with the
  instrument on exactly the interesting arrangements.

  R3 — CLASS-3 AVAILABILITY. A pairing whose LEADING load lies inside a claimed class-4 window is
  unavailable to the class-3 route, whether or not class 4 went on to publish anything.

  R4 — CLASS-3 ORIENTATION. Each of the two paired loads must have a nearest-following zero-page store
  within the window; the two store addresses must differ by exactly one; the load reaching the LOWER
  address holds the low byte. Without a resolvable orientation the pairing is advisory and publishes
  nothing — which is why even the push-idiom route needs the store construction present.

  R5 — CLASS-3 DISPATCH LINK, either of two: the STACK-RETURN link, where the fragment immediately
  after each paired load is `pha` and an `rts` follows the second push within the leading load's
  window; or the ZERO-PAGE-VECTOR link, where an indirect jump within the leading load's window names
  exactly the LOWER of the two store addresses from R4.

  R6 — RECONSTRUCTION AND PLAUSIBILITY. A route publishes only when every reconstructed target is
  inside the image and lands on a `nop` byte of `DATA_TAIL`. Class 4 reconstructs with the FIRST load
  as the hi table and adds one to each pushed value, because `rts` increments before jumping. Class 3
  reconstructs from the R4 orientation and adds nothing. Entry count is the distance between the two
  bases, clamped at `MAX_TABLE_ENTRIES`.

`expectedProvenLink()` is then: a claimed class-4 window whose reconstruction passes R6, OR a pairing
satisfying R1, available under R3, oriented under R4, linked under R5, whose reconstruction passes R6.

Assert the oracle's SCOPE is honest rather than assuming it. Over the whole corpus, every indirect jump
the scan records has a null target and `scan.multiEntryTables` is empty — true because every indirect
jump in the alphabet points through zero page, which lies outside the image. That assertion is what
licenses the oracle to say nothing about classes 1 and 2; if a future alphabet change breaks it, the
oracle becomes incomplete and this assertion reds first.

THE ANTI-COUPLING CHECK, and it is not optional: for each of the nine `PINNED_IDIOMS`, assert that
`expectedProvenLink()` agrees with that member's HAND-DECLARED verdict. The nine declarations were
written by a human reading the shapes; the oracle was written from the rules. If the oracle ever drifts
toward being a copy of the implementation it is checking, it will start agreeing with the instrument
