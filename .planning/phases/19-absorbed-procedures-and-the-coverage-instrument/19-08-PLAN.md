<objective>
Close the second half of GAP 2 (SC4 / COV-02): stop the Class-3 split lo/hi table scan
manufacturing headline structural coverage out of ordinary data, and give it the negative
control it never had.

Purpose: the scan pairs ANY two indexed `ld*` instructions within 8 decoded instructions, with
no dispatch-context gate, reconstructs up to 64 targets out of whatever bytes lie at the two
bases, and feeds them straight back as `extraSeeds` at `anno-coverage.ts:1311`. Reproduced
against shipped code at report level: two 64-byte programs at `$0810`, each with exactly 7 bytes
of real code and 57 bytes of ordinary data, differing ONLY in immediate versus indexed
addressing — a screen-plus-colour copy loop, the single most ordinary shape in C64 code — report
`reached=7 / unreached=57` versus `reached=55 / unreached=9`, with `splitTables=1` and
`discovered=8`. The headline structural measure inflates 8x from ordinary data.

`linearSweepDecodable` is indeed reported beside the census and never summed, so 19-03's literal
truth "Decodability is never counted as evidence of code" holds as written — but the same bad
outcome is reached by the other route: ordinary DATA is classified `reached-as-instruction`,
which the module's own trap 2 defines as REACHED BY RECURSIVE DESCENT FROM A SEED. The
separation the module is built around is worthless if arbitrary data can be injected into the
seed set.

Output: a dispatch-context gate, an advisory class that never seeds a descent, one exported
seam that decides what may, the class-4-first ordering that kills WR-01's byte-swapped twin, and
the four controls that hold all of it down.
</objective>

  <action>
Implement the option selected at the checkpoint. The instructions below assume
`narrow-and-add-sibling`; if a different option was chosen, keep every behavioural requirement
and change only the naming and the version handling accordingly, and say so in the SUMMARY.

**Reorder the scan.** Move the Class-4 stack-return pass so it runs BEFORE the Class-3
split-table pass. As it matches, record each matched window's instruction indices (or the `at`
address of every instruction in the matched five-instruction window) in a `Set`. The Class-3
pass then skips any pairing whose leading load sits inside a window Class 4 already claimed.
This is WR-01's fix and it removes the byte-swapped twin at its source: the stack-return idiom's
hi/lo assignment is justified by push order, the split-table scan's `Math.min`/`Math.max` is not,
so where both match, the justified one wins and the other is not reported at all.

**Add the dispatch-context gate.** A Class-3 pairing is PROVEN only when all of the following
hold; otherwise it is ADVISORY:
  - both loads are indexed through the SAME index register — compare the two instructions'
    `mode` values for the same index suffix rather than merely both being in
    `INDEXED_LOAD_MODES`, so an `absolute_x` paired with an `absolute_y` is not a lo/hi pair;
  - the pairing has a dispatch consumer in evidence. Accept any ONE of: an indirect-jump
    instruction (`0x6c`) within the same `SPLIT_TABLE_WINDOW` reach of the pairing; a
    `pha` … `pha` … `rts` shape in that reach (which, after the reordering above, means the
    window was already claimed by Class 4 and the pairing is therefore skipped, not promoted —
    keep the condition anyway so the gate reads as a complete statement of what counts); or two
    consecutive stores (`sta`/`stx`/`sty`) into consecutive zero-page addresses within reach,
    which is the classic "build a vector then `jmp (vector)`" construction;
  - every reconstructed target lands strictly inside the image, and lands on a byte the census
    could plausibly execute — require the byte at the target to decode as a legal,
    non-truncated instruction via `decode()`. A target pointing at a byte that does not decode
    is not an entry point.

Report ADVISORY pairings in a new `splitTableCandidates: SplitTableFinding[]` field on
`IndirectDispatchScan`, using the same finding shape. An advisory pairing contributes NOTHING to
`discovered` and NOTHING to `tableEntryAddresses` — those two sets are what feed the census, and
an unproven pairing must not move a single byte of it. Document the field with the same
discipline `linearSweepDecodable` carries: it is reported beside the proven classes, never
summed into them, and it exists so a hazard report can see "something indexes two tables here
and we cannot prove what it dispatches to" rather than having that observation discarded.

Where the lo/hi orientation of an advisory pairing is undetermined, do not pick one silently.
Either record both bases without asserting which is which (add a field or a note on the finding
saying the orientation is unresolved) or omit `targets` for advisory findings entirely. Do not
emit byte-swapped values as if they were addresses.

**Add the single proven-target seam.** Export
`provenDispatchTargets(scan: IndirectDispatchScan): number[]` — ascending, deduped, built from
non-null `indirectJumps[].target`, `multiEntryTables[].targets`, `stackReturnDispatch[].targets`
and PROVEN `splitTables[].targets`, and from nothing else. Give it a doc comment stating that it
is the ONE place that decides what may seed a recursive descent, and that adding a source to it
is the decision to treat that source as proof of code. Then:
  - `buildCoverageReport()`'s `extraSeeds` reads `provenDispatchTargets(dispatch)` instead of
    `dispatch.discoveredTargets`;
  - `classFromBytes()` consults `provenDispatchTargets` (compute it once per report and pass it
    in, or drop the branch entirely and rely on the census — either is acceptable, but a bare
    `discoveredTargets.includes(address)` must not remain).

**Fold in IN-04.** In `computeStructuralCensus()`, bound the censused range to the 16-bit
address space: the effective end is `min(safeOrigin + size, 0x10000)`, and `inRange` must use it.
Bytes beyond `$FFFF` are not classified and are not counted. State in a comment why: a payload
whose origin plus length runs past the address space is malformed input, and the module's
contract is to produce a well-formed census on malformed input rather than to wrap.

Update `COVERAGE_SCHEMA_VERSION` per the checkpoint's decision, and update the module header:
the "WHAT THIS IS THE ONE AUTHORITATIVE PLACE FOR" list gains the gate and the proven-target
seam, and the "WHAT NOT TO DO" list gains a named trap — never promote a reconstructed value to
a descent seed without evidence that something dispatches through it, because the census's whole
meaning is that reachability was PROVEN.

Do not change `MAX_TABLE_ENTRIES`, `MAX_WALK_STEPS` or `SPLIT_TABLE_WINDOW`. Do not change any
threshold in `coverageFindings()`. Do not touch the multi-caller rule — 19-06 owns it.
