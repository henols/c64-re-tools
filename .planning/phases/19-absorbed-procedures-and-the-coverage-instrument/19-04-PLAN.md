<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied project path → the coverage verb | untrusted path crosses into a file read |
| the external oracle's configured path and standard output → the finding | an attacker-influenceable executable path and untrusted subprocess output |
| target binary bytes → the oracle subprocess | untrusted binary handed to an external tool |
| the finding's report → downstream provenance work | a fabricated name would poison provenance evidence, which is the asset |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-18 | Tampering | oracle invocation from a configured executable path and a caller-supplied filename | high | mitigate | Spawn with an argument array and never a shell string; never set a shell option; treat a non-existent configured path as oracle-absent rather than interpolating it; asserted at source level by a test that rejects any shell-invoking form |
| T-19-19 | Elevation of Privilege | parsing the oracle's standard output | high | mitigate | A defensive parser with an explicit length cap, no evaluation of any kind, and rejection of truncated or empty input without throwing; the parsed value can only ever reach the name field, never a code path |
| T-19-20 | Repudiation | a fabricated packer name entering provenance evidence | high | mitigate | The name field is assignable only inside the oracle branch from the oracle's own output; the high confidence level is reachable only on that route; the planted-violation test drives an above-threshold entropy input with the oracle forced absent and asserts the name stays null |
| T-19-21 | Tampering | a false SURF-03 pass from an absent oracle | high | mitigate | The live gate skips visibly by default with a stated reason and hard-fails under an opt-in environment variable; the finding itself must emit the unknown verdict with a non-empty reason, never a silent null |
| T-19-22 | Tampering | path traversal via the coverage verb's project argument | medium | mitigate | Validation goes through the one existing authoritative project-path resolver; no second validator is added |
| T-19-23 | Denial of Service | the oracle subprocess hanging | medium | mitigate | Every spawn carries an explicit timeout and the probe treats a timeout as oracle-absent; the scratch output path is created under a temporary directory and cleaned up |
| T-19-24 | Information Disclosure | the oracle's scratch output | low | accept | The scratch path holds a decompressed copy of a file the caller already supplied, under a temporary directory, removed on completion; nothing new is disclosed |
| T-19-25 | Elevation of Privilege | a new child-process spawn site bypassing the session guard | medium | mitigate | The coverage verb adds no spawn site: every store read goes through the existing single-owner session runner, and the enumerated spawn-seam guard already covers the module set |
| T-19-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable this plan — no package-manager install task exists. The external oracle is an optional OS-level tool that is probed and never installed, never added to any dependency block, and its licence therefore attaches to nothing shipped |

Canon-referral breadcrumbs (recorded, deliberately not minted as prohibitions): command
injection through an environment-supplied executable path is canon — covered by
`/gsd-secure-phase` and by the argument-array mitigation above; path traversal on a
caller-supplied path is canon — covered by reusing the existing resolver.
</threat_model>
