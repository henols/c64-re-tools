<objective>
Build the coverage instrument: a derived-from-bytes census that the external analyser's own
bookkeeping cannot move, an Auto-versus-User label measure that a mass rename cannot flatter, a
sampled reproducibility result sealed against retrofit, and six committed controls that prove
the whole thing is not vacuous.

Purpose: this instrument gates Phase 20's decomposition sweep and lends its widened dispatch
scan to Phase 21's hazard report. It has to exist, and be trustworthy, before the work it
measures runs. The one design constraint that makes it trustworthy is that it never reads the
store's own block-type table as its census: upstream's own reachability walk skips bytes that
are not already classified `Code` and requires a pointer to be already classified as an address,
so on an under-classified binary — exactly the state coverage measures — it finds nothing.

Output: `anno-coverage.ts`, its test with six controls, six committed synthetic fixtures, and a
sealed reproducibility answer.
</objective>

  <context>
Phase 20 runs this report repeatedly throughout its decomposition sweep and Phase 21's hazard
report reuses its widened dispatch scan, so two consumers inherit whatever shape lands here.
Retrofitting the shape after Phase 20 has been reading it means rewriting both consumers plus
every recorded run; a version bump does not spare them. COV-01's substance IS the shape — "three
distinct numbers, never one aggregate" — so this is the one place in the phase where the field
set is the requirement rather than an implementation detail.

The measures themselves are fixed by COV-01 and COV-02 and are not being re-opened here: a byte
census of structural completeness, an Auto-versus-User label figure, a sampled
independent-reproducibility result, a divergence sub-report against the external analyser's own block
table, and a comment-vacuity measure. Only their arrangement is being decided.
  </context>
  <options>
    <option id="flat-three">
      <name>Flat sibling objects, one level deep (recommended)</name>
      <pros>Each measure is addressable by a stable top-level key (`structural`, `labels`, `reproducibility`, `divergence`, `commentVacuity`), which makes "never one aggregate" structurally obvious and makes a schema test a plain key-set assertion. Cheapest for a consumer to read a single measure. Matches how the existing verify-output reader is shaped.</pros>
      <cons>Adding a sixth measure later widens the top-level key set, so the schema test has to be edited deliberately (which is the point, but it is friction).</cons>
    </option>
    <option id="measures-array">
      <name>An array of measure records</name>
      <pros>Uniform shape; a new measure is a new array element with no schema-test edit. Each record can carry its own unit and evidence list.</pros>
      <cons>Consumers must search the array by id rather than read a key, which invites a helper that silently returns undefined for a renamed id. Makes it easier, not harder, to compute a combined figure by reducing over the array — the exact thing COV-01 forbids.</cons>
    </option>
    <option id="nested-by-requirement">
      <name>Grouped under requirement keys</name>
      <pros>Traceability to COV-01 and COV-02 is visible in the data itself.</pros>
      <cons>Couples an output format to requirement IDs that retire at the milestone close; a Phase 21 consumer would be reading a v0.5.0 requirement ID as a data path.</cons>
    </option>
  </options>

  <action>
Create `src/mcp/vice/anno-coverage.ts`. Open it with a module header in this repository's
doctrine: why it exists (COV-01 and COV-02, and the concrete reason a store-derived census is
circular), what it is the one place for, and an explicit named list of what not to do — never
derive any measure from the block-type listing; never sum a linear-sweep figure into
completeness; never emit a single combined figure; never define a second confidence vocabulary;
never import from the host-path or container-path modules, which this module family is asserted
absent from.

Shape it as pure functions over already-fetched data plus a thin reader, so every measure is
testable with no child process and no session:

(a) `computeStructuralCensus` takes raw bytes, the origin, and a seed address set, and returns
a census. Seeds are the program origin plus every User-kind label address plus any recorded
entry point. Walk by recursive descent using `decode()`, following `resolvedTarget` for
relative-role operands and for absolute subroutine and jump targets, terminating a trace at
return-from-subroutine, return-from-interrupt, unconditional jump and break. Maintain an
explicit worklist with a visited set; no recursion. Classify every byte in the half-open range
from origin to origin plus size into disjoint classes: reached as instruction, table entry,
referenced as data, unreached. Report a separately named linear-sweep-decodable byte count and
never add it to the reached count. Bound the walk by an explicit maximum step count and return a
truncation flag rather than looping.

(b) `scanIndirectDispatch` takes the decoded instruction stream plus bytes and origin, and
reaches the four classes upstream's own walk misses. Indirect jumps whose pointer lies anywhere
including zero page, not only inside the program image. Multi-entry tables: from a table base,
read successive little-endian sixteen-bit entries while each resolves inside the image, and
record the run length — bounded by an explicit maximum entry count, never "walk while
plausible". Split low and high tables: paired indexed loads whose two bases are a fixed
distance apart, reconstructing that many targets. The stack-return dispatch idiom: a
sliding-window match over the decoded stream for the load-high, push, load-low, push,
return-from-subroutine sequence, which contains no indirect-jump opcode at all and is therefore
completely invisible to the upstream walk. Return each class separately with its discovered
targets, so Phase 21's hazard report can consume the classes it needs without re-deriving them.

(c) `computeLabelRatio` takes the symbol list and returns TWO independent figures, because one
is gameable and the other is not. A kind figure over non-System labels only, carrying the user
count, the auto count and the user fraction — System labels are platform-provided and counting
them would let a large platform symbol set inflate the fraction for free. And a count of labels
whose NAME still matches the auto-name prefix set, regardless of kind, which catches renaming a
label to its own existing auto name so the kind flips to User while the name is unchanged.
Define `AUTO_NAME_PREFIX_RE` from the upstream prefix list, and deliberately EXCLUDE the prefix
that upstream assigns to both predefined and user-defined label types — it cannot distinguish
auto from user and including it would produce false positives. State that exclusion and its
reason in a comment beside the regex.

(d) `computeCommentVacuity` takes the comment list and returns a distinct-comment ratio, a
commented-address count, a graded fraction computed with the existing confidence grades, and the
list of addresses whose comment matched a banned-generic entry. Define `BANNED_GENERIC_COMMENTS`
as a named, non-empty exported set. Normalise exactly as the schema requires: ASCII lowercase,
strip backticks and emphasis markers, collapse whitespace runs to a single space, trim; compare
by exact string equality. Count the same normalised text at N addresses once, not N times.
Return a null ratio with a zero commented-address count when there are no comments, never a
division.

(e) `computeReproducibility` takes the census, the symbol list, the comment list and a
cross-reference lookup, plus a sample size, and returns the sampled independent-reproducibility
result. Sample deterministically: documented labels sorted ascending by address, take every Nth
where N is the ceiling of the population over the sample size; record the rule string AND the
resulting address list in the result so the sample is auditable and reproducible. For each
sampled label, re-derive a classification FROM THE BYTES ALONE using the census and the dispatch
scan — reached-as-instruction versus table-entry versus referenced-as-data versus unreached —
and compare it against the classification the store's own documentation implies, taken from the
label's confidence-grade prefix and its block classification. Report the sampled count, the
agreed count, the disagreed count, the agreement rate, the sample rule and the address list.
Apply the multi-caller rule while doing so: a label with strictly more than one caller counts as
documented only if its line comment exists, is non-vacuous, AND literally names at least one
caller — either as a hexadecimal address matching a caller address, or as the user label name at
a caller address. Otherwise it is reported as multi-caller-undocumented, with its address, and
excluded from the label figure's user tally.

Record in the header, as a named deviation from the research recommendation, that the
independent axis here is bytes-versus-store rather than a second agent session: nested headless
agent sessions stall in this environment, so the independence that matters is that one side
never reads the other's comments. The seal in Task 3 is what prevents retrofit.

(f) `buildCoverageReport` assembles the whole report from a project path plus caller-supplied
symbol, comment, block and cross-reference data. It reads the project file, decodes the raw
payload with the existing decoder, computes each measure, and computes the divergence
sub-report — byte counts where the census and the store's block listing disagree, broken out by
direction — using the block listing ONLY here and nowhere else. Emit an explicit
`COVERAGE_SCHEMA_VERSION` and arrange the measures in the shape selected at this plan's
checkpoint. Add the divergence sub-report's own note recording the systematic bias its store
side carries: adjacent same-type tables merge without a boundary marker, and that marker's
upstream setter is not on this project's curated surface, so an over-merge on the store side is
a known named bias rather than instrument error. Include a generated-at timestamp as the only
field that differs between two runs over the same input. Throw `AnnoCoverageInputError` — a
custom error class in this repository's naming convention — only for a caller contract violation
such as a missing project path; never for malformed bytes, which the decoder already handles by
returning nothing.

Add no write path, no save call, and no session import: this module is read-only over a project
file by construction.
