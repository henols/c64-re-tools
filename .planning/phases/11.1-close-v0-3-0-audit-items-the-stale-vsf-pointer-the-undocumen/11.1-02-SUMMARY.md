# Phase 11.1 Plan 02: Close FLOW-01 -- Document Three Undiscoverable CLI Verbs and Guard Against It Recurring Summary

**Documented `gen-enums`, `export-lbl` and `import-lbl` in the playbooks that own them (the symbol round trip as one closed loop matching Phase 11's live walkthrough), then added a CLI-verb coverage gate that parses the verb list from `r2000-cli.ts`'s own dispatch switch and proved it non-vacuous with a planted 8th verb.**

## Performance

- **Duration:** 55 min
- **Tasks:** 2/2
- **Files modified:** 3 modified, 3 created (one created file, `r2000-cli-verbs.d.mts`, was not in the plan's file list -- see Deviations)

## Accomplishments

- `c64-memory-mapping/SKILL.md`'s § "Feeding the enum generator" now tells a reader the consumer step it was missing before: `r2000 gen-enums <project>` turns register writes into named enum variants, requires an existing `.regen2000proj`, prints paired/unpaired counts and per-enum variant counts, and exits non-zero (naming `--max-results`) when a search pass hits its 10000-row ceiling.
- `c64-program-recon/SKILL.md`'s § "Writing findings into the annotation store" gained a new subsection, "Take names to the running machine, and bring live findings back", documenting the `export-lbl`/`import-lbl` cycle as ONE loop in the order Phase 11 actually proved it: export -> `vice_symbols_load` (exactly once, replace-not-merge) -> live discovery -> `r2000_set_label_name` -> regenerate the whole `.lbl` -> `import-lbl` (disk-verified). Both traps (`export-lbl` is USER-labels-only; both verbs require an existing project) are stated. A single cross-reference line points to `gen-enums` in `c64-memory-mapping`.
- `scripts/lib/r2000-cli-verbs.mjs` is the one definition of `parseR2000CliVerbs()` (a comment-stripping character scanner plus a brace-depth-scoped switch-body extraction -- never a regex-alternation extractor, matching the discipline this repo's `docs-dangling-refs.test.ts` already established after measuring a regex miss), `verbsMissingFromSkills()`, and `R2000_CLI_VERB_FLOOR = 7`. Imported by both `scripts/check-skill-tool-coverage.mjs` (a new fourth section) and the committed test -- one implementation, two callers.
- `.claude/mcp/vice/r2000-verb-coverage.test.ts` (6 tests): real-source parse (exactly the 7 known verbs, never `default`), positive control (no verb missing from the real skill corpus), planted violation (an 8th, genuinely new `case "ghost-verb":` is parsed and reported missing, while a documented verb `export-asm` is not -- with an inline inversion-check assertion), comment hygiene (a case hidden in a block comment and a case hidden in a line comment are both invisible to the parser), a non-vacuity-floor check, and a `spawnSync` run of the live CI script asserting exit 0 with `OK` in stdout.

## Decisions Made

- Round trip documented in the exact order Phase 11's live walkthrough proved it (absence proven first is already established upstream in that walkthrough; this plan's prose starts from "export what the store already knows" through to the disk-verified `import-lbl`, naming `vice_symbols_load`'s replace-not-merge semantics and the literal phrase "exactly once").
- `gen-enums` cross-referenced bidirectionally (documented fully in `c64-memory-mapping`, pointed to by name from `c64-program-recon`) per the plan's instruction to link all three verbs' requirements in both directions.
- The verb-to-requirement map used in the guard's failure messages (`gen-enums` -> `R2000-13`, etc.) lives in `check-skill-tool-coverage.mjs` itself, not in the shared module -- keeps the shared module's vocabulary generic (any future CLI could reuse the parser/predicate pair without inheriting FLOW-01-specific requirement IDs).
- Chose a hand-written character-scanner comment stripper over a regex for the exact reason this repo's own `docs-dangling-refs.test.ts` header already documents (a regex-alternation extractor was measured to miss a literal at the one site that mattered) -- Task 4's comment-hygiene test (block comment AND line comment, in the same synthetic source) is the proof this discipline was followed here too.
