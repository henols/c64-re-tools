<objective>
Close FLOW-02 — the sharpest finding in the v0.3.0 audit — and generalise it into a guard.

`r2000-cli.ts:162-164` (USAGE) and `:256-258` (the live `bootstrap` refusal) both tell a user
that closing the `.vsf` gap "is Phase 11's job". Phase 11 is complete and never touched `.vsf`
bootstrap, and `REQUIREMENTS.md`'s own D-34-corrected `R2000-09` text says explicitly that
`.vsf` is **not** deferred to a later phase. Worse, `r2000-cli.test.ts:237-248` pins the claim
with `assert.match(stderr, /Phase 11/)`, so the falsehood passes green forever.

Purpose: a user-facing diagnostic that points at a remediation path which does not and will not
exist is the one item in this milestone that actively misleads a user. A phase number is a
planning artifact; it has no place in a shipped diagnostic.

Output: both strings reworded to name the backlog file (D-11.1-01); the pinning test retargeted;
and a committed guard that fails if any shipped `.claude/mcp/vice/` module ever again puts a
phase number inside a user-facing string literal.

**This plan does NOT implement `.vsf` bootstrap support.** `.vsf` stays out of the input set and
stays backlog (D-34, scope fence). No requirement is added or re-opened (`requirements: []`).
</objective>

Add a second, independent section to this file: the same defect class (a dangling phase pointer)
one layer down, in **shipped source strings** rather than normative documents.

**Do NOT touch `ASSIGNMENT_RES` or any existing test in this file.** Measured during planning:
extending `ASSIGNMENT_RES` with a `job|responsibility|task|work` noun makes the existing
normative-doc test FAIL on `ROADMAP.md`'s own Phase 11.1 note, which legitimately *quotes* the
defect being fixed. That is the false-positive class this file's header warns about. The new
section gets its own pattern.

**Scope: string literals only, never comments.** Stated as a comment in the new section, with the
reason: the fix's own explanatory comments quote the old wording on purpose (Task 1 adds exactly
such comments), so a comment-scoped guard would be invalidated by the very commit that satisfies
it — the self-invalidating-gate hazard CLAUDE.md's grep-gate hygiene rule names. The cost is
explicit: `r2000-project.ts`'s comment was corrected by hand in Task 1 and is not held by this
guard. Say so in the comment rather than implying full coverage.

**The scanned set is derived, not enumerated:** read `package.json`, take every `files[]` entry
matching `/\.(ts|mts)$/`, and assert each one exists on disk (a missing entry FAILS rather than
silently shrinking the set). A module added to `files[]` by a later phase is therefore scanned
with no edit here — the INT-01 lesson applied preemptively.

**Write a real scanner, not a regex.** A single-pass character state machine over each source
file that tracks: line comment, block comment, single-quoted, double-quoted, template literal
(including `${ … }` interpolation nesting and backslash escapes), and emits the *content* of
every string/template literal it closes. This is required, not stylistic: measured during
planning, a regex-alternation extractor silently failed to capture `r2000-cli.ts`'s `USAGE`
template — the exact site FLOW-02 lived at — and reported only 2 of the 3 literal fragments.
A guard blind at the one site that mattered is worse than no guard.

**The predicate:** a literal is a violation if its content matches `/\bPhase\s+\d/i`. Blanket
inside literals, no exemption list, no verb heuristics — a phase number is a planning artifact
and a string literal is (or may become) user-facing. If a future maintainer genuinely needs one,
the fix is a deliberate, visible edit to this guard, not a silent exemption.
