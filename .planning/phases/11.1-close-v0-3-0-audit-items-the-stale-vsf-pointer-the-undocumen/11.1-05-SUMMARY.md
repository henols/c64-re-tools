## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The bounded drain itself would have introduced an EPIPE crash on a piped invocation whose reader closes early**
- **Found during:** Task 3, while proving the fix by hand against a reader that closes the pipe before the child finishes writing (`node vice-proxy.ts r2000 --help | head -c 10 > /dev/null` with a large fill payload)
- **Issue:** The OLD (pre-fix) dispatch called `process.exit()` immediately after `console.log()`, so an EPIPE from the write raced against the exit and never got the chance to surface — `process.exit()` always won, silently. Adding `drainStdio()`, which explicitly `await`s the write's own callback, gives Node's event loop the chance it never had before to actually deliver that write's error — and with no `'error'` listener registered on `process.stdout`/`process.stderr` at that early point in the file (the file's own later EPIPE-guard, citing `modelcontextprotocol/typescript-sdk#1564`, is registered further down, on the server path only, well after this branch already exits), the error threw uncaught and crashed the process with a stack trace instead of a clean `exit 0`.
- **Fix:** Registered `process.stdout.on("error", () => {})` and `process.stderr.on("error", () => {})` at the top of the `r2000` dispatch branch, before any write or drain.
- **Files modified:** `.claude/mcp/vice/vice-proxy.ts` (same commit as the rest of Task 3)
- **Verification:** `VICE_TEST_R2000_CLI_STDOUT_FILL_BYTES=5000000 node vice-proxy.ts r2000 --help | head -c 10 > /dev/null` exits 0 with no stack trace, both before this specific fix (crashed) and after (clean), manually re-run to confirm.
- **Committed in:** `d5e01a8` (Task 3 commit)

**2. [Rule 3 - Blocking] Neither of the plan's two named payload-generation routes scales to "well above 128 KiB" on this host**
- **Found during:** Task 3, while trying to produce the required test payload
- **Issue:** `--help`'s USAGE text measures 5677 bytes, fixed regardless of invocation. `cmdExportAsm`'s error path (`console.error(result.stderr)`) was fed a 200 KB garbage-JSON `.regen2000proj` (regenerator2000 reported 67 bytes: `Error loading file: missing field 'origin' at line 1 column 200015`) and a 64 KB garbage flat `.raw` capture (221 bytes: a fixed "headless mode requires .regen2000proj" message) — regenerator2000 0.9.20's own diagnostic size does not scale with input size at all, on either route.
- **Fix:** Added a narrow, clearly-labelled test-only env-var hatch (`VICE_TEST_R2000_CLI_STDOUT_FILL_BYTES`) to the `r2000` dispatch branch in `vice-proxy.ts`, gated behind a specific env var name no real caller would ever set, writing a deterministic filler payload through the exact same drained-exit code path a real invocation uses.
- **Files modified:** `.claude/mcp/vice/vice-proxy.ts`, `.claude/mcp/vice/vice-proxy.test.ts`
- **Verification:** see the byte-count measurements below.
- **Committed in:** `d5e01a8` (Task 3 commit)
