<objective>
Three Phase 10 findings on the bootstrap path, all confirmed still live, all dispositioned as fixes
(D-11.1-04).

**WR-09.** `bootstrapProject()`'s own doc comment (`r2000-cli.ts:218-225`) promises it "Never throws
for an expected, user-facing failure — every branch below returns a `{ code }` result with a
one-line message already printed". Two branches break it: `:313`'s `parsePrg(extracted)` on the
`.d64` path is unwrapped while every sibling branch wraps it, and `:352`'s `writeFileSync` is
unguarded. Reproduced live in the review with an entry whose final sector claims one used byte —
the throw escaped to `runR2000Cli()`'s last-resort net, so the diagnostic came out prefixed
`r2000:` instead of `bootstrap:` and named an internal function to a user who supplied a disk image.
`render-memmap`'s write (`:859`) is the same shape and is included here.

**IN-06.** `parseArgs()` returns `out` for every verb; `cmdVerify` destructures only
`{ positional, entry }` and `USAGE` does not list `--out` for `verify`. A caller who passes it gets
no error and no effect — a silent loss of the caller's intent, the same class D-02 exists to forbid.

**WR-12.** `r2000-d64.test.ts`'s `writeChain()` writes `usedByte = payloadLen + 1` and the
implementation reads `payloadLen = usedByte - 1`. Same equation both directions, so the round-trip
test is a tautology with respect to the DOS convention: a systematic off-by-one in both directions
would still pass. The formula is independently correct — this is a test-strength finding, not a
behaviour bug, and plan 10-03 recorded finding and fixing exactly this bug class while writing that
test, which is precisely why the test must not be able to miss it.

Purpose: the `.d64` sector walker and `parsePrg` are this milestone's untrusted-byte parsers. A
never-throw contract that is false on the malformed-input branch is false exactly where it matters.

Output: both unguarded paths wrapped and pinned by a structural assertion; option rejection; and a
literal fixture that does not share the implementation's arithmetic.
</objective>
