<objective>
Close FLOW-01: three CLI verbs — `gen-enums`, `export-lbl`, `import-lbl` — appear in **zero**
skill files. They are the delivery path for `R2000-13`'s enum install, `R2000-14`'s export leg and
`R2000-15`'s import leg. All three are built, tested and live-proven; none is reachable by the
consumer they were built for. This milestone's thesis is that the annotation store is reachable
*from a skill*.

`check-skill-tool-coverage.mjs` validates `r2000_*` MCP tool **names** in prose but never CLI
**verbs**, which is why three verbs reached `main` documented nowhere. So this plan is guard-first:
the documentation is the fix, and a gate that derives the verb list from `r2000-cli.ts` itself is
what stops the next verb from repeating it (D-11.1-02).

Purpose: an undiscoverable feature is an unshipped feature, and a hard-coded list in a guard is how
this class of defect arrives.

Output: `gen-enums` documented in `c64-memory-mapping`; the `export-lbl`/`import-lbl` round trip
documented as one closed loop in `c64-program-recon`; and a CLI-verb coverage gate with a committed
planted-violation proof.

No requirement is added (`requirements: []`) — `R2000-13`/`-14`/`-15` are already satisfied as
worded; this closes their discoverability debt.
</objective>

**Why a shared module and not inline script code:** the predicate must be callable from a committed
test to be proven non-vacuous, and `check-skill-tool-coverage.mjs` executes its whole check at
import time (importing it would run the gate). So the logic gets ONE definition in a small module
both callers import — the same "single seam, two callers" shape `version.ts`/`scripts/version.mjs`
already uses in this repo. `scripts/lib/` is picked deliberately: it is tracked by git (so
`scripts/package.sh`'s `git archive` includes it) and it keeps a CI-only helper out of
`.claude/mcp/vice/`, whose `package.json` `files[]` is a shipped-runtime allow-list.

Create `scripts/lib/r2000-cli-verbs.mjs` exporting exactly three things:

- `parseR2000CliVerbs(src)` — takes `r2000-cli.ts`'s source TEXT and returns the sorted verb list
  parsed from the dispatch switch's `case "<verb>":` labels. Scope the scan to the switch body
  (anchor on `switch (verb)` and stop at its closing brace / the `default:` label) so an unrelated
  `case "x":` elsewhere in the file can never be counted. Strip `//` line comments and `/* */`
  block comments before matching — mandatory grep-gate hygiene per CLAUDE.md; a commented-out
  `case` is not a verb.
- `R2000_CLI_VERB_FLOOR = 7` — the measured true count today, with a comment naming the seven verbs
  and stating the rule: a future phase that adds a verb raises this floor to the new true count and
  never lowers it to make a regression pass (the `extractedR2000.size >= 10` comment in
  `check-skill-tool-coverage.mjs` is the precedent to mirror).
- `verbsMissingFromSkills(verbs, skillTexts)` — returns the verbs for which NO entry of
  `skillTexts` contains the token `r2000 <verb>`. Match the same literal form the audit measured
  (`grep -rl 'r2000 <verb>'`), so the gate and the finding speak the same language.
