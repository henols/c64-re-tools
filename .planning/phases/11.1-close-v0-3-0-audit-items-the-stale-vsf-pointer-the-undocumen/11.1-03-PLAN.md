<objective>
Close INT-01 and Phase 10's IN-02, which are the same defect at two depths: the guard that proves
the r2000 family never imports a host-path module both **enumerates a list that stopped growing**
(10 modules named; 14 exist) and **cannot see two of the three import shapes** it claims to police.

Uncovered today: `r2000-acme-ident.ts`, `r2000-regbits-gen.ts`, `r2000-symbols.ts`,
`r2000-test-gate.ts`. Independently verified during the audit: none of the four imports
`hostpath.ts`/`containerpath.ts`, so `R2000-02`'s runtime guarantee holds today — **by luck, not by
the test**. `r2000-symbols.ts` implements `R2000-14`/`R2000-15` and is the highest-value target for
an accidental host-path import.

This is the phase's organising principle in its purest form: a fix that only edits the list is the
same bug deferred.

Purpose: `R2000-02` is a standing milestone constraint (regenerator2000 runs container-side, D-R4);
its guard should hold by construction, not by coincidence.

Output: a `readdirSync`-derived module set with a floor, an import detector that matches
newline-tolerant static imports and `await import()`, and a planted violation for each.
</objective>

that keeps this guard from counting comments and string literals as imports:

1. **Multi-line named import.** Match against the whole comment-stripped source with a
   newline-tolerant pattern instead of per-line, so
   `import {\n  hostPath,\n} from "./hostpath.ts";` is caught. Keep comment stripping — extend
   `stripCommentLines()` to also strip `/* … */` block comments if it does not already, and update
   its doc comment to state the new contract. `vice-broker-client.ts`'s header literally contains
   the words "MUST NOT import hostpath.ts" and `load-order.test.ts` embeds an import statement as a
   string literal, so the stripped-source-plus-real-import-shape discipline is load-bearing: an
   unfiltered whole-file match would produce exactly the self-invalidating gate CLAUDE.md forbids.
2. **Dynamic import.** Add a second pattern for `import\s*\(\s*["'][^"']*hostpath` (and the
   `containerpath` equivalent if the file already covers that module — check before assuming), kept
   ALONGSIDE the static pattern, never replacing it.

Both patterns feed the same `hostpathImporters()` result, so `EXPECTED_IMPORTERS` and the
exactly-five assertion must still pass unchanged. If widening surfaces a sixth importer, that is a
finding to report, not a number to bump (§5).

**Commit one planted-violation test per shape.** A single test containing three synthetic sources —
(a) multi-line named import of `hostpath.ts`, (b) `await import("./hostpath.ts")`, (c) a control

predicate reports (a) and (b) and does NOT report (c). The control is the half that keeps this
guard trustworthy: it is what proves the widening did not turn the detector into a substring
