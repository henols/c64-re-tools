## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `docs-review-disposition.test.ts`'s own `tech_debt`-block parser was truncating to one line**
- **Found during:** Task 4, first run against the real milestone audit
- **Issue:** `phaseScopedTechDebtText()`'s block-extraction regex used an end-of-block lookahead alternative of bare `$`, which under the `/m` flag matches at the end of *every* line, not just the true end of the `tech_debt:` block — so the lazy match stopped after the very first `- phase:` line, hiding every phase's actual `items:` list from the guard (measured directly: a 43-character block containing only `  - phase: 09-the-assumption-probe-go-no-go`).
- **Fix:** Rewrote as a column-zero line scan (`extractTechDebtBlock()`): walk lines after `tech_debt:` until a line starting at column zero with a letter (the next top-level key) or the closing `---`.
- **Files modified:** `.claude/mcp/vice/docs-review-disposition.test.ts`
- **Verification:** Re-ran the guard; Phase 09's WR-01/WR-02 became correctly dispositioned via the tech_debt block (IN-02 still needed the range-notation fix below).
- **Committed in:** `4122061` (Task 4)

**2. [Rule 1 - Bug] `v0.3.0-MILESTONE-AUDIT.md`'s Phase 09 tech_debt item used range notation invisible to a word-bounded id scan**
- **Found during:** Task 4, after fixing deviation 1
- **Issue:** `"WR-01/WR-02 + IN-01..IN-03 -- ..."` never literally spells "IN-02" as a substring, so a `\bIN-02\b` match against this text fails even though the item is clearly about all three.
- **Fix:** Reworded to `"WR-01/WR-02 + IN-01, IN-02, IN-03 -- ..."` in both the tech_debt YAML block and the matching body prose. Meaning unchanged.
- **Files modified:** `.planning/v0.3.0-MILESTONE-AUDIT.md`
- **Committed in:** `4122061` (Task 4)
