## Residual Debt — Verdict

### 1. `VICE_TEST_R2000_CLI_STDOUT_FILL_BYTES` (new shipped test hatch, `vice-proxy.ts`)

Read directly at the call site today:

```ts
const testFillBytes = process.env.VICE_TEST_R2000_CLI_STDOUT_FILL_BYTES;
if (testFillBytes) {
  process.stdout.write("x".repeat(Number(testFillBytes)));
  await Promise.all([drainStdio(process.stdout), drainStdio(process.stderr)]);
  process.exit(0);
}
```

**Verdict: acceptable test seam, not debt worth filing further.** It writes only a fixed
character repeated N times (no code execution, no file access, no argument passthrough);
it is gated behind an env-var name no real CLI invocation sets; it never appears in
`--help` or any user-facing surface; and whoever can set this process's environment
variables already controls its `argv`/launch options, so it adds no new privilege
boundary. It exists because neither of the plan's two named payload-generation routes
could deterministically clear 128 KiB against the real installed `regenerator2000
0.9.20` (measured directly: `--help`'s USAGE text is a fixed ~5.6 KB string;
`cmdExportAsm`'s error path stayed 67–221 bytes regardless of input size). It is already
disclosed in three independent places (`11.1-05-SUMMARY.md`, the disposition ledger, and
`11.1-VERIFICATION.md`'s Anti-Patterns table) — this ledger adds a fourth, mechanical
one rather than treating it as newly discovered. **Classification: WARNING (disclosed,
narrow, inert)** — not a BLOCKER.

### 2. The phase-pointer guard's string-literal-only scope

`docs-dangling-refs.test.ts`'s `extractStringLiterals()`/`danglingPhaseLiterals()` scans
only string/template literals in shipped `.ts`/`.mts` modules, never comments — by
design, since a comment-scoped guard would be invalidated by its own fix commits (this
repo's fixes routinely name the old, banned wording in a "what NOT to do" comment).
Consequence: `r2000-project.ts`'s header-comment FLOW-02 site is permanently outside the
guard and was fixed by hand. **Verdict: correctly reasoned, permanent, and already
documented in three places** (the guard's own header, `11.1-01-SUMMARY.md`'s Known
Limitations, the disposition ledger's "Found while dispositioning" §2). A future
regression at that one comment site would only be caught by manual review — an honest,
bounded gap, not a defect. **Classification: WARNING (accepted, scope-limited by
design)**.

### 3. Does Phase 11.1 need its own `11.1-SECURITY.md`?

**Verdict: not warranted — reasoned independently, not deferred to the prompt's framing.**

Checked what this phase actually changed against untrusted-input surfaces:

- **WR-09** wraps an *existing* `.d64`-path `parsePrg()` call in the same try/catch shape
  its sibling branches already use, and guards two `writeFileSync` calls — it closes a
  crash-on-malformed-input gap, it does not add a new byte parser. Phase 10 is where the
  `.d64` sector walker and `parsePrg()` themselves were introduced (and where
  `/gsd-secure-phase 10` is separately routed for exactly that reason, per D-11.1-08 —
  correctly kept out of this phase's own commit).
- **WR-10** bounds an existing blocking `spawnSync` with a timeout and `maxBuffer` — this
  *closes* a resource-exhaustion vector (unbounded child hang, unbounded buffer growth),
  it does not open one.
- **WR-12**'s two new fixtures are test-only, not shipped parsing logic.
- The one genuinely new piece of shipped surface, the `VICE_TEST_R2000_CLI_STDOUT_FILL_BYTES`
  hatch (residual-debt item 1 above), takes an operator-controlled env var and writes a
  fixed-character filler string — no parsing, no external input, no privilege crossing.

Net effect: this phase closed security-relevant findings (crash-hardening, resource
bounds) and added no new input-handling surface of its own. A full `11.1-SECURITY.md`
threat model, on the pattern of `11-SECURITY.md` (`status: verified`, `threats_open: 0`),
would be modeling threats against code this phase did not introduce. **Classification:
not warranted.** This matches the plan's own stated assessment; independently re-derived
here from the actual diff rather than accepted on request.
