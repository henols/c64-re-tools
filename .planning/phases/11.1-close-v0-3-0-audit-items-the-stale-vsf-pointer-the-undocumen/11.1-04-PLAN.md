<objective>
Three findings on the regenerator2000 spawn seam, closed together because they are the same seam.

**WR-10 (confirmed still live):** `r2000-launch.ts:209-215` passes `timeout: opts.timeoutMs` with
no default and no caller setting it, and no `maxBuffer`, on a **blocking** `spawnSync`. Mitigated
for the MCP tool surface (which routes through `r2000-mcp-client.ts`'s async spawn with its own 30s
default) but unbounded for all seven CLI verbs. `spawnSync` blocks the entire Node event loop, so a
wedged child means no JSON-RPC and no diagnostics — the state `vice-wedge-triage` teaches users to
distrust.

**INT-02:** `r2000-launch.ts:2,12-15` claims to be "the ONE authoritative place in this repo that
spawns regenerator2000 … No other file may shell out to the `regenerator2000` binary directly."
`r2000-mcp-client.ts:332` is a second spawn site — necessarily, since `withR2000Session()` needs a
long-lived async child while `runR2000()` is blocking. `r2000-mcp-client.ts`'s own header correctly
says "both spawn call sites", so the two files contradict each other. `R2000-01` is **not**
compromised: `r2000-mcp-client.ts:330` calls the shared `assertNoViceFlag(argv)` before every
spawn. The defect is that a maintainer trusting the wrong header would not know to guard a third
site.

**Phase 11 IN-02:** `regenerateAndReload()` — the *named* D-29 live-discovery merge point — has zero
callers outside its own module and test. `R2000-15` is satisfied through the `export-lbl`/`import-lbl`
verbs, so this is durability debt on a convenience wrapper. It must not stay ambiguous.

Purpose: `R2000-01` is the constraint the whole milestone's shape follows from. It deserves a checked
invariant, not a prose promise in a header that is already wrong.

Output: bounded spawn with named errors; a truthful header; a committed spawn-seam guard; and a
recorded decision on `regenerateAndReload()`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `runR2000()` → the regenerator2000 child process | Every CLI verb crosses here. The child's runtime and output volume are outside this repo's control, and the call is synchronous, so an unbounded child owns the whole event loop |
| child stdout/stderr → `acmeVerdict()` / label parsers | A truncated transcript that still parses is a false verdict; a max-buffer overrun must be an error, never silently shortened input |
| any future caller → a regenerator2000 argv | `--vice` reaching the child makes it a second client of stock VICE's single-client binary monitor, indistinguishable from a wedge with no diagnostic (CLAUDE.md Concurrency) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.1-SPAWNHANG | Denial of Service | `runR2000()`'s blocking `spawnSync` | mitigate | Task 1: `R2000_TIMEOUT_MS` (120s default, env-overridable, validated against `NaN`) plus caller override; named `ETIMEDOUT` error carrying the argv; timeout proven real by a slow-child test |
| T-11.1-BUFOVER | Tampering | child stdout/stderr → verdict parsers | mitigate | Task 1: `R2000_MAX_BUFFER` 32 MiB with a named overrun error stating the parsed verdict would be unreliable — never a silently truncated transcript feeding a pass |
