# Phase 11.1 Plan 04: Bound the regenerator2000 spawn, correct its header, and record a dead wrapper's status Summary

**`runR2000()` gets a 120s/32 MiB default bound with named ETIMEDOUT/ENOBUFS errors (WR-10); `r2000-launch.ts`'s header no longer contradicts `r2000-mcp-client.ts`'s; R2000-01's spawn-before-guard invariant is now a checked property over the shipped module set with two planted violations; `regenerateAndReload()` is marked library-only with a bidirectional caller-count guard.**

## Accomplishments

- **WR-10 fixed live**: `runR2000()` now bounds its blocking `spawnSync` with `R2000_TIMEOUT_MS` (120s default, env-overridable, validated by `parseR2000TimeoutMs()` so a bad override can never become `NaN`) and `R2000_MAX_BUFFER` (32 MiB). Both a timeout and a max-buffer overrun are translated into named, argv-naming errors, mirroring the existing `ENOENT` branch. `opts.timeoutMs` still overrides the default per call (D-11.1-04). Proven against real `regenerator2000 0.9.20` under `VICE_REQUIRE_R2000=1 VICE_REQUIRE_ACME=1` (38/38 pass, longest test 742ms) so the new bounds do not regress a real `--verify` run, and proven real by driving the timeout through `runR2000()` in a genuinely separate Node child process.
- **IN-04 fixed**: removed the dead `process.env.R2000_BIN` mutation from `r2000-launch.test.ts` (it could never affect the module-load-time constant it was mutating) and replaced the unfalsifiable `typeof R2000_BIN === "string"` assertion with a real equality check.
- **INT-02 fixed**: `r2000-launch.ts`'s header no longer claims sole authorship of every regenerator2000 spawn. It names `r2000-mcp-client.ts` as the second, asynchronous spawn site and states the checked invariant that makes both safe.
- **R2000-01 is now a checked property**: `r2000-spawn-seam.test.ts` derives the shipped production module set from `package.json`'s `files[]`, strips comments and string/template literal bodies before matching any spawn-call pattern, and asserts the discovered regenerator2000 spawn-site set equals exactly `{ r2000-launch.ts, r2000-mcp-client.ts }` in both directions, with every site proven to guard-before-spawn. Two committed planted-violation tests plus two manual, reverted demonstrations against the real files prove the guard is not vacuous.
- **Phase 11 IN-02 recorded**: `regenerateAndReload()` is marked `LIBRARY-ONLY` in its own doc comment, with a biconditional guard in `r2000-symbol-roundtrip.test.ts` that ties the marker to the real production-caller count (derived across `.claude/mcp/vice/`, `.claude/skills/`, `scripts/`) in both directions.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `r2000-test-gate.ts`'s `probeR2000()` is a genuine `spawnSync(R2000_BIN, ...)` call, over-matched by a naive readdirSync-based discovery scanner**
- **Found during:** Task 2 (building `r2000-spawn-seam.test.ts`)
- **Issue:** The plan's literal instruction ("derived by readdirSync, never enumerated... every `*.ts`/`*.mts` directly under `.claude/mcp/vice/`, excluding `*.test.*`") would discover `r2000-test-gate.ts`'s `probeR2000()` (`spawnSync(R2000_BIN, ["--version"], ...)`) as a third, unguarded regenerator2000 spawn site, since that file's name does not end in `.test.ts` despite being test-only infrastructure (its own header explicitly says so). This would have made the set-equality assertion permanently fail against the two expected sites, or forced a hand-maintained exclusion list — exactly the enumeration-not-derivation anti-pattern this phase's guards exist to avoid.
- **Fix:** Scanned `package.json`'s `files[]` array instead (the SHIPPED production module set, mirroring `docs-dangling-refs.test.ts`'s own `shippedTsModules()` idiom) rather than a raw `readdirSync`-and-exclude-`*.test.*` listing. `r2000-test-gate.ts` is legitimately absent from `files[]` (it is test-only, never published), so it is excluded without any hand-maintained exclusion list — the derivation moved one level up (to *which* set is scanned) rather than being abandoned.
- **Files modified:** `.claude/mcp/vice/r2000-spawn-seam.test.ts`
- **Verification:** `node --test r2000-spawn-seam.test.ts` — set-equality test passes discovering exactly the two expected sites; `r2000-test-gate.ts` confirmed absent from the discovered set.
- **Committed in:** `b208248` (Task 2 commit)
