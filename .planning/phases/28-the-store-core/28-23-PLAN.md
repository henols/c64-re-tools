<objective>
Close CR-10: a partial overwrite of a split table re-pairs every entry it leaves
behind, and the store says nothing. This plan makes the store say it — with both
entry-pair sets — and rewrites the tests that certify the defect.

Purpose. Round-6 verification scored 11/12. One truth failed, and it is the
ROADMAP's own criterion 3, not plan-derived scope: *"A partial overwrite splits
and PRESERVES: the surviving region keeps an annotation whose MEANING is what it
was."* The verifier reproduced CR-10 through production entry points only — two
`setDataType` calls, no hand-edited store, no test-only export — and broadened it
from the review's one case to **five distinct overlap geometries, each preserving
0 of 8 recorded 16-bit targets**, with `changed: true`, `contradictedComments:
[]`, no diagnostic and no field anywhere recording that the table was ever 16
bytes wide.

The mechanism, read out of the source rather than argued. `resolveSplitTargets`
pairs `bytes[i]` with `bytes[n + i]`, so an entry's partner is a function of the
row's START and its LENGTH; changing either end re-pairs EVERY entry.
`assertRangeShape()` knows exactly one rule about split tables — the byte count
must be even. CR-09's gate asks that one rule about each remainder. **So it
refuses the ODD fragment and accepts every EVEN one**, including every even
fragment that destroys the pairing. It refuses the loud case and admits every
silent one.

**The arithmetic is worth stating once, because it settles the design.** A
surviving fragment of `m` entries pairs its own byte `j` with its own byte
`m + j`. For a fragment starting `d` bytes into a row of `n` entries, the pair
that entry `j` of the fragment reads matches an original pair only if `m == n` —
that is, only if the fragment IS the whole row. **No proper fragment of a split
table preserves a single entry pair, at any boundary, the midpoint included.**
Preservation is therefore not something a cleverer boundary rule can recover; the
only two honest answers are to refuse the edit or to disclose its cost.

**THE DESIGN DECISION IS TAKEN — answer (b), return the re-interpretation AS
DATA — and this plan executes it rather than re-litigating it.** The three
reasons, recorded here so a later reader does not have to reconstruct them:

1. **It is the pattern this module already established and that criterion 3
   itself blesses.** Criterion 3's own text: *"A retype that contradicts an
   existing comment returns the contradicted comments **as data**."*
   `setDataType()` already returns a result object with a `contradictedComments`
   data channel; the new disclosure rides alongside it as a sibling field, on a
   SUCCESSFUL result, never as a refusal.
2. **It keeps the capability.** Answer (a) — refuse any partial overlap of a
   split row — makes split tables editable only wholesale, and the verifier is
   explicit that this is *"NOT AN EDGE CASE. Every input is ordinary annotation
   work — correcting a few bytes inside a table, or trimming a table you typed
   one entry too wide."*
3. **Criterion 3's operative failure word is `silently`** — *"Silently
   un-documenting a previously annotated region is the exact failure the store
   exists to prevent."* Disclosure removes the silence, which is the clause that
   is actually falsified.

**Escalation to answer (a) was considered and is NOT taken.** (b) is
implementable without any of the three forbidden moves: no boundary of the
caller's range is rounded outward, no remainder is demoted to `undefined`, and
the parity check is untouched and still runs first. Nothing in the source blocks
it, so the escalation clause does not fire.

**Why the disclosure is a RETURN CHANNEL and not a new column.** The obvious
alternative — record the table's original extent on disk so the pairing can be
reconstructed later — is a `SCHEMA_VERSION` bump. Prohibition 28-10 P4 makes that
a one-way decision requiring the older on-disk shape to refuse by name, and this
milestone's single irreversible decision is already spent on the twelve-member
vocabulary. The return channel gives the caller the same fact at the only moment
it can still act on it, and costs nothing that cannot be reverted. This is also
why the honest reversibility rating for the contract change is **costly, not
one-way**: `setDataType` has ZERO production callers today (measured at plan time
— every reference outside `anno-store.ts` is in a test file), so the field is
revertible in-tree until Phase 29 publishes it on the MCP surface.

**Scope fence, stated because this phase's failure mode is scope growth.** Six
rounds, 22 executed plans, and a denominator that grew because each round's
must-haves were lifted out of that round's own frontmatter. **This is ONE plan.**
Every `must_haves.truths` entry above carries a `TRACE:` prefix naming verifier
truth 3 or the specific `gaps[0].missing` line it discharges; anything that could
not be traced was dropped rather than written. No prohibition is newly minted —
every one is carried forward, and the three the round-6 verifier judged
**violated** (28-19 P2, 28-21 P1, 28-07 P3) are all the same instance this plan
closes. The root cause is fixed — the gate asks a rule that cannot see pairing —
and the five geometries the verifier happened to drive are asserted as evidence,
never special-cased in the code.

**WHY THE SUITE COULD NOT SEE THIS, and what that costs this plan.** 210 green
tests were blind to CR-10 exactly as 169 were blind to CR-09. The control closest
to it CERTIFIES it: `anno-overlap.test.ts:592` pins the corrupted three-row set
BY VALUE and its test name calls that outcome the legal remainder case; four
`SEQUENCE` steps are annotated "both even" and marked accepted; and the
round-trip invariant asks only that every row be re-acceptable and decodable —
**and a re-paired table decodes perfectly.** So two of this plan's three tasks
are test work, and every claim it makes is proven RED-BEFORE-GREEN with a planting
observed on the real tree and reverted to an empty diff. A green suite is not
evidence in this phase; a planted red is.

**Two carried items are NOT in scope and are claimed by nothing here.**
`openStore`'s `integrity_check could not be run at all` throw arm, and 28-17's
`backstop`-tagged host-crash durability bound. Both need host- or SQLite-level
fault injection, both are recorded STILL OPEN by task 3, and neither is promoted.

**Worktree isolation is forbidden for this plan and must not be proposed.**
`workflow.use_worktrees` is `false` in this project, and task 3's deliverable is
`.planning/REQUIREMENTS.md`. Worktree isolation strips `.planning/` paths from
commits, so a plan whose deliverable is `.planning/` content silently CANNOT
DELIVER under it: the task would report success and the file would not move.

Output: a store that tells its caller what a partial overwrite of a split table
cost, in both entry-pair sets; a suite that goes red on the class rather than
pinning it as correct; and a requirement record that quotes the verifier rather
than this executor.
