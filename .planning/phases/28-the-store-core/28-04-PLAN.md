<objective>
Give the store the rest of what `STORE-01` says it holds — labels, comments,
scopes and project enums — plus `STORE-05`'s cross-reference row with its access
kind, and put every argument through a validator that refuses rather than
guesses. Then prove the four split layouts earn their place as separate members
by observing both axes: orientation as a differing resolved-target set, and
address-versus-word as whether cross-references are produced at all.

Purpose: the MCP proxy validates nothing —
`vice-proxy.ts:3224`'s `rawJsonSchemaAsStandardSchema()` returns
`validate: (value) => ({ value })` at `:3230`, by design and documented as such
— so every argument reaches this store unvalidated and validation is this
phase's own responsibility. Two of the refusals are the reason the store exists:
a label collision that sanitises instead of refusing silently merges two names a
human deliberately distinguished, and a cross-reference row holding a derivable
value creates a second on-disk truth that can disagree with the table it came
from.

Output: the complete validator set with a denylist derived from the real opcode
table, five annotation kinds that round-trip by value, an `anno_xref` table that
stays empty after typing, and criterion 1's control with its collapse planting
observed red.
</objective>
