<objective>
Prove `ROADMAP.md` criterion 3 in both halves: a partial overwrite splits and
preserves rather than discarding, and a retype that makes an existing comment
false returns that comment back as data. Both halves get their planted violation
observed red, and the five overlap cases are enumerated with the fully-contained
case named as the one that actually detects the planting.

Purpose: silently un-documenting a previously annotated region is the exact
failure the store exists to prevent, and it has no error message. A
`filter()`-and-insert implementation — delete every overlapping row, insert the
new one — is accidentally correct on the total-typed-bytes metric for four of the
five overlap cases and loses bytes only in the fully-contained case. A five-case
table whose case 3 is written weakly makes the planting green, so this plan
names case 3 explicitly and asserts a second invariant (every previously typed
address is still typed) that catches a hole which happens to balance.

Output: the contradiction check on the retype path, a new test file owning
overlap and adjacency semantics, and two observed reds.
</objective>

The five overlap cases, with existing range `[a, b]` and new range `[c, d]`:

| Case | Predicate | Correct result |
|---|---|---|
| 1. identical | `c === a && d === b` | one row, retyped |
| 2. new fully contains existing | `c <= a && d >= b` | one row, retyped; the existing row is gone |
| 3. new fully INSIDE existing | `a < c && d < b` | **three** rows: `[a, c-1]` old type, `[c, d]` new type, `[d+1, b]` old type |
| 4. overlap at the low end | `c <= a && a <= d && d < b` | `[c, d]` new type, `[d+1, b]` old type |
| 5. overlap at the high end | `a < c && c <= b && d >= b` | `[a, c-1]` old type, `[c, d]` new type |

Case 3's predicate is `a < c && d < b` with BOTH inequalities strict. Written as
`c === a` it is really case 4, and the planting goes green.

<research_corrections_applied>
- **A3 resolved — the contradiction rule is the `CONFIDENCE_GRADES`-derived one,
  and the alternative not taken is recorded.** "Contradicts" in criterion 3 means
  the retype makes the existing comment **false**, not merely that a comment
  exists at the address. The rule: a comment graded `[confirmed-code]` or
  `[probable-code]` is contradicted by a retype to any of the ten non-`code`
  members; a comment graded `[confirmed-data]` or `[probable-data]` is
  contradicted by a retype to `code`; `[unknown]` and an ungraded comment are
  never contradicted. **The alternative not taken:** "any comment at all at a
  retyped address is contradicted". It was rejected because it would make every
  retype of a commented range report, which destroys the signal — the report
  exists so a human notices the one case that matters, and a report that fires
  every time is a report nobody reads. Record both the rule and the rejected
  alternative in the code, so a later reader does not "simplify" the rule back
  into the broad form.
- **The rule is derived from an existing vocabulary, not a new one.**
  `r2000-confidence.ts` already owns the five grades and already parses the
  bracket prefix, and the skills already emit that convention. Reuse it; do not
  invent a second grade vocabulary and do not copy the five brackets into this
  store.
