asserting a guarantee the code does not provide. `ScopeRow`'s doc comment and

confinement is the mitigation for exactly that, and it is opt-in, so it is the
only one of the three a caller can forget. Neither is a blocker, and the verifier
says so for each. Both land in Phase 29 if they do not land here: criterion 5 of
that phase requires a repeated edit to succeed reporting no change, which is false
for scopes today, and it puts `openStore`'s path on a transport whose validator is
`validate: (value) => ({ value })`.

**WR-25 is DECIDED, not accepted.** The planning brief allows recording an
accept-with-reason instead. It is not taken: the fix's shape is small and fully
enumerable (four module-derived opens inside `anno-store.ts`, two deliberate ones
in `anno-store.test.ts`, two in the spawned mutator), the review supplies the
exact mechanism, and `anno-seam.test.ts` already has the pin style that keeps the
enumeration honest. An accept-with-reason for a mitigation this cheap would be
recording a decision not to decide.

**Why this is a separate wave from 28-20.** Same argument as every prior round of
this phase, recorded in the wave 12 and wave 15 dependency notes in `ROADMAP.md`:
concurrent edits to `anno-store.ts` are how the next blocker arrives. 28-20
rewrites `revertTo`, `pruneSnapshots` and `runWriteSequence`; this plan rewrites
`addScope` and `openStore`. Serialised, not parallelised.

**Scope fence.** WR-20, WR-23, IN-07 and IN-08 are ACCEPT-ONLY for this round on
the verifier's own routing and NO CODE is written for them here. In particular:
WR-23's false rationale in `contradictedCommentsFor` is fixed only if some other
task in this round genuinely touches that function, and no task in this plan does.

Output: two doc comments that are true, a scope table that cannot grow without

**The real delta here is a `required -> optional` inversion read backwards.**
`openStore`'s `workspaceRoot` is currently OPTIONAL for a mitigation the module's

it required-unless-explicitly-waived.

**Noun now primary:** the CONFINED open. The unconfined open is demoted from the

**Decision: `promote`.** `add-alongside` was the status quo and is exactly what
the finding is about: the safe form existed alongside the unsafe default, so the
unsafe one won by inertia at every site that forgot. The promotion is enforced by
a runtime refusal plus a seam pin over the shipped module set, so a future site
that forgets is a refusal at run time and a red control at test time.

**Second, smaller delta, recorded rather than left implicit:** `addScope`'s

module's own doc mocks elsewhere ("a field that can only ever answer one value is
a claim the next reader has to falsify by experiment"). Task 1 promotes it to a
real two-valued signal.

**What would force a later change:** a legitimate consumer of the published
package that genuinely has no workspace root — for example a CLI opening an
absolute path a user typed. At that point the escape option becomes a documented
public affordance rather than a module-internal one, and the seam pin's expected
count becomes wrong on purpose. That is the signal to revisit, and the pin is what
would surface it.
