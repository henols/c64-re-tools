<objective>
Close CR-08 — the fourth distinct cause of the goal's REVERTIBLE clause being
false — as a CLASS rather than as one byte pattern, and close WR-17 with it
because it lives in the same function and the same failure.

Purpose: `revertTo` witnesses the snapshot image it is about to install with
`existsSync` and nothing else (`anno-store.ts:1632`), then closes the caller's
handle (`:1647`) and renames that unverified file over the live store (`:1677`).
`retainedRevisions()` publishes retention on the same existence-only witness
(`:605`), so the store advertises a route that destroys it. Reproduced by the
round-4 verifier through production entry points with no hand edit of the store
file: a 69632-byte live store replaced by 0 bytes, no handle returned, and every
later `openStore` refusing.

The class is: **`revertTo` must never close the caller's handle or touch the live
store until it has established, BY OPENING IT, that the replacement is a usable
annotation store.** This plan closes it by ordering — the advertisement, the gate
and the staged copy all read one witness whose answer is an actual `openStore` —
not by adding a check for zero-length files.

Output: one promoted witness, one differently-named question for the sweep, a
`revertTo` whose destructive steps are unreachable until an open has succeeded,
and six tests that pin it.

**Scope discipline.** Truths 1-11 of `28-VERIFICATION.md` are VERIFIED and are
not re-planned. Eight of the ten `prohibition_flags` are `held` and no task works
against them. The UNDER-CLAIM direction of 28-07 P2 (a store opened through a
symlink alias reporting `retained []`) is a deliberately accepted residual with a
recorded rationale at `anno-store.ts:480-521` — **it is not touched, and no task
may attempt to close it**, because doing so requires reading a ring whose
ownership the handle cannot establish, which 28-10 P3 / 28-11 P4 forbid.
</objective>
