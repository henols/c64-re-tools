<objective>
Close verification gap 3 (CR-03): workspace confinement is half-built.

`storePathWithinWorkspace` compares `resolve(path)` against
`resolve(workspaceRoot) + sep`. `resolve()` normalises `..` but does **not**
resolve symbolic links, so a symlinked subdirectory inside the workspace escapes.
The verifier reproduced it: with `workspaceRoot=<ws>` and `<ws>/escape` a symlink
to a sibling directory, `openStore(<ws>/escape/p.annostore)` **succeeded and the
store file was created outside the workspace root**. The `..` half works and is
pinned; the symlink half does not exist and no test plants a symlink, so the gap
is invisible to the suite.

This falsifies `28-01`'s artifact `provides` clause and `anno-store.ts`'s own
trap 7 rather than a ROADMAP criterion — the verifier weighed it against
STORE-01 and said so. It is carried as a gap anyway because the module's own
header premise is that this path arrives **unvalidated from the transport**
(`vice-proxy.ts`'s validator is `(value) => ({ value })`), so a checked-in or
agent-created symlink is sufficient and no privileged access is needed.

Purpose: make the control compare what the filesystem will actually do, and prove
it discriminates — a confinement test that only ever refuses is indistinguishable
from one that works.

Output: real-path comparison on both sides resolved through the deepest existing
ancestor; a new `anno-confinement.test.ts` carrying the symlink refusal, the
inside-pointing-symlink follow, and the two cases most likely to regress; and an
honestly widened import-specifier assertion in `anno-types.test.ts` with the
reversal recorded rather than the old rationale deleted.
</objective>

<architectural_siting_decision>
**Where the real-path resolution lives — decided, not defaulted.**

`28-RESEARCH.md`'s Architectural Responsibility Map justified the validation tier
with "Not in the persistence module, so it is unit-testable with no file on disk."
Task 1 gives `anno-types.ts` `existsSync` and `realpathSync`, which makes that
clause false for one export. Two sitings were available:

- **(a) Keep the resolution in `anno-types.ts`.** The validator answers the
  filesystem question itself. Costs: the map's rationale becomes false and must be
  rewritten; trap 3's purity claim must be narrowed to one named exception; the
  import-specifier pin goes from three entries to four.
- **(b) Move the resolution into `anno-store.ts`** — which the map already pairs
  with "filesystem" — and pass resolved paths into the validator. Preserves the
  map row, trap 3 and the three-entry pin outright. Costs: the exported
  `storePathWithinWorkspace` becomes a string comparison again for any caller that
  does not pre-resolve, so ONE confinement contract is split across two modules
  with the security-relevant half sitting in the module whose header does not
  claim confinement (trap 7 does); and `anno-store.ts` gains a third gap-plan
  writer, pushing this plan to wave 8.

**Decision: (a).** The deciding argument is shape, not cost. Siting (b) recreates
the "two places decide one thing" pattern that plan `28-07` exists to remove from
the snapshot ring, and it does so where the failure is SILENT: a caller that skips
the resolution gets a confinement check that passes and a store file outside the
workspace — CR-03 again, with a new cause and no test watching for it. The module
that declares the confinement contract must be the module that cannot answer it
wrongly. `node:fs` is a Node builtin, not a seam, so nothing in the closed
consumer set moves.

**The rationale that became false is REWRITTEN, not left standing** — leaving it
is `28-03` prohibition P2 territory. Three records, all already in place or owned
by a task here:

1. `28-RESEARCH.md`'s map row was rewritten during the planning revision pass that
   produced this version of the plan. It now names the filesystem as a secondary
   tier for confinement only, names `storePathWithinWorkspace` as the single
   exception, states that every other export is still pure and still unit-testable
   with no file on disk, and records siting (b) as weighed and rejected. **No task
   in this plan edits `28-RESEARCH.md`**, so nothing here depends on a
   planning-artifact write landing during execution.
2. `anno-types.ts`'s trap 3 is narrowed by task 1, keeping the
   module-level-mutable-state half intact.
3. `anno-types.test.ts`'s specifier rationale — and its title — are rewritten by
   task 2, with the widening recorded as a reversal.

**P15 is unaffected and still binds.** The confinement REFUSES a path that
resolves outside the root; it never redirects one. Siting (a) is what keeps that
refusal inside the function that promises it.
</architectural_siting_decision>

**In `anno-types.ts`, resolve real paths on BOTH sides.**

Extend the imports: add `existsSync` and `realpathSync` from `node:fs`, and add
`basename`, `dirname` and `join` to the existing `node:path` import alongside
`resolve` and `sep`.

Add a module-private helper `realpathOfNearestExisting(p: string): string`. It
`resolve`s `p`, then walks up collecting tail segments with `basename` while the
current candidate does not `existsSync`, stopping when `dirname(current) ===
current` (the filesystem root) and returning `resolve(p)` unchanged in that case —
nothing on the path exists, so there is nothing to resolve and a string
comparison is the honest answer. Otherwise it returns
`join(realpathSync(current), ...tail)`. Wrap the `realpathSync` call in a `try`
whose `catch` throws `AnnoStorePathError` naming the path and appending the
underlying message, so a permission failure resolving an ancestor is a named
refusal rather than a bare `Error`.

Its doc comment states the two things a reader needs: that the walk exists so a
**not-yet-created** store file still resolves (the common case — the store is
created on first open), and that the tail is re-joined AFTER the real ancestor so
the returned path is the one the filesystem will actually use.

Rewrite `storePathWithinWorkspace` to run BOTH arguments through
`realpathOfNearestExisting` before comparing. Keep everything else: the identity
check against the root, the `startsWith(resolvedRoot + sep)` boundary-safe
comparison, the `AnnoStorePathError` with `{ path, workspaceRoot }`, and the
existing doc comment's two paragraphs about boundary safety and about
