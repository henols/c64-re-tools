<objective>
Build the guarded launch seam for regenerator2000 and pin both of its guarantees with
tests that fail if either is undone.

This plan delivers phase criterion 1 (`R2000-01`) and criterion 2 (`R2000-02`) —
the adoption boundaries. Per **D-06** the seam is a module under `.claude/mcp/vice/`,
because that is the only directory CI runs tests from (`npm test` in
`.github/workflows/ci.yml` never reaches skill-side `*.test.mjs`), so a guard test
living in a skill script would be green-by-absence. Per **D-07** the `--vice` flag is
denied twice — unreachable by construction and denied by scan — and never stripped
silently. Per **D-08** criterion 2's *absence* of host-path translation is asserted by
extending the existing closed-consumer-set test, not by a new bespoke test file.

Purpose: stock VICE's binary monitor services exactly one client. A regenerator2000
launched with `--vice <host:port>` becomes a second, unserviced client against an
instance the broker owns — behaviourally identical to a wedged emulator, with no
diagnostic. This is the constraint the whole milestone's shape follows from.

Output: `r2000-launch.ts`, `r2000-launch.test.ts`, and three new assertions inside
`hostpath-consumers.test.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `r2000-launch.ts` argv builders | Caller-supplied file paths and entry names cross into a subprocess argv |
| `r2000-launch.ts` → regenerator2000 process | An external CLI binary is executed with those arguments |
| regenerator2000 → stock VICE binary monitor | The connection this phase exists to make impossible |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Denial of Service | `r2000-launch.ts` argv construction | mitigate | A regenerator2000 launched with `--vice <host:port>` becomes a second client on stock VICE's single-client binary monitor, indistinguishable from a wedge. Mitigated twice: fixed per-verb builders with no passthrough parameter (Task 1), plus `assertNoViceFlag()` as the first statement of `runR2000` throwing `R2000ViceFlagError` (Task 1), both pinned by Task 2 |
| T-10-02 | Tampering | `spawnSync` invocation in `r2000-launch.ts` | mitigate | Command injection via a caller-controlled filename is prevented by passing an argv array and never a shell string, and never setting `shell: true` — the established project convention (`acme.mjs:124`, `disasm-roundtrip.test.ts`'s explicit rule). Asserted in Task 1's acceptance criteria |
| T-10-04 | Repudiation | the `--vice` guard's failure mode | mitigate | A silent strip would alter a caller's request without telling them, hiding the bug class the guard exists to catch. D-07 forbids it: the guard throws a named error carrying the offending argv. Task 2 test 3 asserts no filtering path exists |
| T-10-05 | Information Disclosure | host-path leakage into r2000 arguments | mitigate | `r2000-launch.ts` imports no host-path module; the absence is asserted structurally by Task 3's extension of the closed consumer set (D-08). A translated container path would also be wrong at the destination, since regenerator2000 runs container-side (D-R4) |
| T-10-SC | Tampering | npm/cargo installs | accept | This plan adds no npm runtime or dev dependency (`@henols/vice-mcp`'s dependency set stays exactly `@mastra/mcp` + `@mastra/core`, mechanically enforced by `scripts/check-npm-packages.mjs`). regenerator2000 is an already-installed external CLI whose crates.io provenance (publisher `ricardoquesada`, `MIT OR Apache-2.0`, version 0.9.20 published 2026-07-11) was verified in Phase 9; no new install is performed here |
</threat_model>
