<objective>
Prove the replacement disassembly route's output actually reassembles, by running a real
assembler — criterion 4's second half and `ANNO-06`.

Per **D-09** (the user's own decision, with the "this is anno checking its own export"
caveat raised and accepted) the proof is the external analyser's `--verify`, which already
spawns a real assembler and diffs byte for byte. Per **D-10** the check parses the ACME
result line and never trusts the exit code: with ACME absent and ca65 present,
The external analyser prints `✗ ACME — ACME not found in PATH (skipped)` followed by
`✓ All roundtrip verifications passed.` and **exits 0** — a false pass with ACME never
run, observed live. Criterion 4 is specifically about ACME matching this project's
`!cpu 6510` expectations, so a skipped ACME must be a failure. Per **D-11** CI does not
install the external analyser (a 4m48s–5m39s Rust build on every merge contradicts the
"cheapest by far" reason `--verify` was chosen), so the gate is a named SKIP by default
and a hard FAIL only under `VICE_REQUIRE_ANNO`.

Purpose: this is what earns the deletion in plan 10-06. The `toacme` caveats existed
because a flat linear decode cannot produce reassemblable source; the replacement must be
shown to, not claimed to.

Output: `anno-verify.ts`, `anno-verify.test.ts`, the `verify` verb, and a live
transcript recorded in the phase's evidence directory.
</objective>

Create `.claude/mcp/vice/anno-verify.ts` — the ONE place that interprets the external analyser's
`--verify` output.

Header comment: state WHY parsing is required at all, quoting the concrete incident in
prose — with ACME absent and ca65 present, `--verify` reports the ACME line as
`(skipped)` and still prints `✓ All roundtrip verifications passed.` and exits 0. Say
plainly that trusting the exit code here would let the one assembler this project cares
about be silently skipped, and that this is the WHAT-NOT-TO-DO for any future edit.

Exports:
  - `type AssemblerOutcome = "ok" | "skipped" | "failed"`
  - `interface VerifyLine { assembler: string; outcome: AssemblerOutcome; detail: string }`
  - `function parseVerifyOutput(stdout: string): VerifyLine[]` — one entry per
    per-assembler result line. Recognise the success form (a leading `✓` with a
    `byte-identical` detail), the skipped form (a `(skipped)` suffix, typically
    `not found in PATH`), and treat any other non-summary result line as `failed`. The
    aggregate `All roundtrip verifications passed.` line is a summary, not an assembler
    line — exclude it, and say why in a comment. Match the assembler name
    case-insensitively (`ACME`, `ca65`, `64tass`, `KickAssembler`), and tolerate an
    em-dash or hyphen separator, since only the ACME verdict is load-bearing and the
    exact glyph is an upstream formatting detail.
  - `function acmeVerdict(lines: VerifyLine[]): { ok: boolean; reason: string }` — `ok`
    only when an ACME line exists with outcome `ok`. A missing ACME line, an ACME line
    with outcome `skipped`, and an ACME line with outcome `failed` each return
    `ok: false` with a distinct, quotable reason. Never conflate "skipped" with
    "passed" and never fall back to the summary line.
  - `function verifyProject(projectPath: string): { ok: boolean; reason: string; lines: VerifyLine[]; status: number | null; stdout: string; stderr: string }`
    — builds argv with `buildVerifyArgs()` and runs it through `runAnno()` (so the
    `--vice` scan applies here too), parses stdout, and derives `ok` from
    `acmeVerdict()` — deliberately NOT from `status`. Return the raw status and streams
    so a caller can print them, but never let a zero status alone make `ok` true. Do not
    treat a warning on stderr as failure.

Add `"anno-verify.ts"` to `.claude/mcp/vice/package.json`'s `files[]` in the same commit
— it becomes reachable from `vice-proxy.ts` through `anno-cli.ts` in Task 3, and
`scripts/check-npm-packages.mjs`'s transitive-closure walk fails the pack otherwise.

Import nothing from `hostpath.ts`/`containerpath.ts`; plan 10-01's absence assertion
already names `anno-verify.ts`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the external analyser stdout → `parseVerifyOutput` | An external tool's human-formatted output is interpreted as a security-relevant verdict |
| `verifyProject` → the external analyser → ACME | Two nested subprocess layers, both spawned with argv arrays |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-09 | Spoofing | `--verify`'s exit code as a verdict | mitigate | A zero exit with ACME skipped is a false pass observed live. `acmeVerdict()` derives the result only from the parsed ACME line, `grep -c 'status === 0'` is asserted to be 0, and the trap transcript is pinned as a unit test (D-10) |
| T-10-02 | Tampering | subprocess invocation | mitigate | `verifyProject` spawns only through `anno-launch.ts`'s argv builders and `runAnno`, which applies the `--vice` scan first; no shell string anywhere. The nested ACME spawn is the external analyser's own, out of this project's control and accepted as part of D-09's decision |
| T-10-06 | Denial of Service | the gated live tests | mitigate | Explicit subprocess timeouts, `finally`-scoped temp cleanup, and the file stays out of `MANUAL_ONLY_TESTS` so it must terminate. Absent the external analyser produces a named SKIP, never a hang |
| T-10-10 | Repudiation | "verified by running a real assembler" as a claim | mitigate | CI never runs this gate (D-11), so the claim is backed by a committed transcript (`evidence/10-verify-transcript.txt`) carrying raw stdout, exit codes and tool versions, rather than by a green tick nobody can re-read |
| T-10-SC | Tampering | npm/cargo installs | accept | No new dependency; the external analyser stays out of CI by design, and its Phase 9 provenance record (crates.io publisher `the upstream author`, `MIT OR Apache-2.0`) is unchanged |
</threat_model>
