# Phase 10: Code Review Report

**Reviewed:** 2026-08-20T19:45:00Z
**Depth:** standard
**Files Reviewed:** 24
**Status:** issues_found

## Summary

The r2000 seam's *stated* invariants hold where they matter most. I could not break
the `--vice` guard: `regenerator2000 0.9.20 --help` (checked live on this host) has no
short alias, no case-insensitive long form and no second flag that opens a binary-monitor
client, so `assertNoViceFlag()`'s exact-token + `--vice=` check is complete against the
shipped tool; every spawn goes through `spawnSync` with an argv array and no `shell:true`
anywhere; the r2000 family genuinely imports no host-path module and the closed consumer
set is still exactly five; the protected Phase-4 disassembler family is untouched
(`git log` shows no phase-10 commit against `disasm-*.ts` / `stock-disassemble.ts`);
`package.json` `files[]` lists all five modules, correctly spelled; and
`r2000-verify.ts` really does derive `ok` only from the parsed ACME line — I re-proved
the false-pass trap and the opposite-direction case by hand.

What is *not* safe is the CLI layer wrapped around it. The two Critical findings are
both **silent data loss on exit 0**, and I reproduced both live against the real binary:
`export-asm game.prg` overwrote a hand-written `game.a` (the exact filename pairing
`acme-build` itself teaches), and `bootstrap game.regen2000proj` overwrote its own input
with a garbage project whose origin was the first two bytes of the old JSON (`$227b`).
Neither path has an overwrite check, a `--force`, or an input==output comparison.

Below that, a family of "silently guess instead of failing loud" defects contradicts
D-02's own stated contract — a 4096-byte `.raw` is silently reparsed as a `.prg` with a
wrong origin; a truncated `.d64` yields a silently short-read payload (98 bytes where
254 were claimed); a NUL-padded directory name is printed in the listing and then
rejected when the user types it back verbatim. And two of the phase's own guards are one
plausible edit away from going vacuous: `r2000-launch.test.ts`'s comment stripper can
swallow the entire file (demonstrated), and `FORBIDDEN_R2000_FLAGS` is a dead constant
whose comment actively instructs future maintainers to add a flag that will then not be
enforced.

## Critical Issues

### CR-01: `export-asm`'s default output path silently overwrites hand-written ACME source

**File:** `.claude/mcp/vice/r2000-cli.ts:264`
**Issue:** `const outPath = out ?? input.replace(/\.[^./\\]+$/, "") + ".a";` derives the
export target from the input stem with no existence check, no `--force`, and no prompt.
`acme-build`'s entire convention is `foo.a` → `foo.prg` (`acme.mjs build game.a` writes
`game.prg`), so `r2000 export-asm game.prg` — the exact command
`acme-build/SKILL.md:141-146` now tells the reader to run — targets `game.a`: the source
file the user just built from.

**Reproduced live** (regenerator2000 0.9.20, this host):

```
$ ls; head -1 game.a
game.a  game.prg
; MY PRECIOUS HAND-WRITTEN SOURCE
$ node vice-proxy.ts r2000 export-asm game.prg
bootstrap: wrote /tmp/r2000-cli-Gd6x21/bootstrap.regen2000proj (origin $0801)
export-asm: wrote game.a
$ head -3 game.a
;=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-=-
;
; Auto-generated by Regenerator 2000 v0.9.20
```

Exit 0. The original source is unrecoverable.

**Fix:** refuse to clobber an existing file unless the caller opted in explicitly.

```ts
const outPath = out ?? input.replace(/\.[^./\\]+$/, "") + ".a";
if (!out && existsSync(outPath)) {
  console.error(
    `export-asm: refusing to overwrite the existing file ${outPath} with generated source -- ` +
      `pass --out FILE to choose a different target. acme-build's own convention pairs ` +
      `<stem>.a with <stem>.prg, so the default target is very often hand-written source.`,
  );
  return 1;
}
```

Consider defaulting to `<stem>.dis.a` (the name the deleted `disasm` verb used) so the
default target can never collide with hand-written source at all.

### CR-02: `bootstrap` on a `.regen2000proj` destroys that project file and reports success

**File:** `.claude/mcp/vice/r2000-cli.ts:212` (out-path derivation), `:220` (unguarded write), `:200-210` (missing `.regen2000proj` rejection)
**Issue:** `cmdBootstrap` has no `.regen2000proj` branch (unlike `cmdExportAsm:252` and
`cmdVerify:310`, which both special-case it). A project file therefore falls through to
`parsePrg(bytes)`, which happily accepts any input ≥ 3 bytes; the derived out path
(`input` minus its extension, plus `.regen2000proj`) is then **byte-identical to the
input path**, and `writeFileSync` clobbers it.

**Reproduced live:**

```
$ node vice-proxy.ts r2000 bootstrap game.prg
bootstrap: wrote game.regen2000proj (origin $0801)
$ node vice-proxy.ts r2000 bootstrap game.regen2000proj    # plausible re-run / tab-completion slip
bootstrap: wrote game.regen2000proj (origin $227b)         # exit 0
```

`$227b` is `{"` read as a little-endian load address. The project now carries the old
file's JSON text as its gzipped payload and a nonsense origin. Any labels/comments a user
had accumulated in that project are gone, and the message reads as success.

**Fix:** two guards, both cheap.

```ts
// in bootstrapProject(), next to the .vsf refusal:
if (ext === ".regen2000proj") {
  console.error(
    `bootstrap: ${input} is already a .regen2000proj -- bootstrap synthesises project files, it never ` +
      `re-reads one. Use export-asm or verify on it directly.`,
  );
  return { code: 1 };
}
...
const outPath = opts.outPath ?? input.replace(/\.[^./\\]+$/, "") + ".regen2000proj";
if (resolve(outPath) === resolve(input)) {
  console.error(`bootstrap: refusing to write the output over its own input (${outPath})`);
  return { code: 1 };
}
```

## Warnings

### WR-01: `FORBIDDEN_R2000_FLAGS` is dead code, and its comment misdirects the next maintainer

**File:** `.claude/mcp/vice/r2000-launch.ts:45-49` (declaration), `:92-98` (the scan that ignores it)
**Issue:** the constant is exported and documented as "The permanent deny list for
regenerator2000 argv... if a second hazardous flag is ever discovered, it joins this array
rather than spawning a parallel check." `assertNoViceFlag()` never reads it —
`arg === "--vice" || arg.startsWith("--vice=")` is hardcoded. `grep -rn
FORBIDDEN_R2000_FLAGS` across the whole repo returns exactly two hits: the declaration,
and a *string inside an assertion message* in `r2000-launch.test.ts:102`. No code and no
assertion binds the array to the enforcement.

**Failure scenario:** a future session discovers a second hazardous flag (say
`--mcp-server`, which `--help` shows binds a hardcoded port), follows the comment's
instruction, adds it to the array, sees the test suite stay green — and ships a deny list
that denies nothing. This is the classic "seam that looks like the single source of truth
but isn't" failure the rest of this codebase is careful about.

**Fix:** make the scan read the constant, and add a test that proves it does.

```ts
export function assertNoViceFlag(argv: readonly string[]): void {
  for (const arg of argv) {
    for (const flag of FORBIDDEN_R2000_FLAGS) {
      if (arg === flag || arg.startsWith(`${flag}=`)) {
        throw new R2000ViceFlagError(viceFlagRefusalMessage(argv), { argv });
      }
    }
  }
}
```
Then assert `FORBIDDEN_R2000_FLAGS.includes("--vice")` and that every member of the array
throws, so a future addition is enforced by construction.

### WR-02: the deny-by-construction guard test can silently strip the whole file and pass vacuously

**File:** `.claude/mcp/vice/r2000-launch.test.ts:38-55` (`stripCommentLines`), used by `:97-104` and `:142-156`
**Issue:** the block-comment state machine enters `inBlock` for any line whose *trimmed*
text starts with `/*` and does not end with `*/`, and only leaves it on a line whose
trimmed text *ends* with `*/`. A one-line block comment followed by code on the same line
(`/* note */ const X = 1;`) satisfies "starts with `/*`, does not end with `*/`" and
therefore swallows **every remaining line of the file**.

**Demonstrated** with the exact helper, verbatim, against a synthetic source containing a
real reintroduction:

```
input line 2: '/* a one-line block comment that ends with code */ const X = 1;'
input line 3: 'export function runR2000(argv, ...extraArgs: string[]) {'
input line 4: '  return spawnSync("x", [...argv, ...extraArgs].filter(Boolean));'

stripped source: 'import { spawnSync } from "node:child_process";'
rest-param regex hit:  false
forbidden ident hit:   false
filter( hit:           false
```

All three source-text assertions pass while a caller-supplied argv pass-through *and* a
`.filter()` strip are both present. The guard is live against today's file (70 non-blank
lines survive stripping, `export function runR2000` included), so this is latent, not
currently broken — but the guard's whole job is to survive future edits, and the trigger
is an ordinary comment style.

**Fix:** add an anchor assertion so over-stripping fails loudly, and fix the state machine.

```ts
const src = stripCommentLines(readFileSync(join(HERE, "r2000-launch.ts"), "utf8"));
assert.match(
  src,
  /export function runR2000\(/,
  "stripCommentLines() over-stripped: the module's own runR2000 definition is gone, so every " +
    "source-text assertion below would pass vacuously",
);
```

### WR-03: the `disasm` deletion-pin exemption suppresses all three checks on the exempted line, and is not count-bounded

**File:** `scripts/check-skill-fork-honesty.mjs:350` (the literal), `:358` (the `continue`)
**Issue:** `if (line.includes(DISASM_LINE_EXEMPTION)) continue;` is evaluated *before*
the `toacme`, `cmdDisasm` and `\bdisasm\b` checks, so it exempts a line from all three.
A line reading

```
// see acme.mjs cmdDisasm / toacme, evidence: "disasm"
```

passes the guard silently. The exemption is also unbounded: nothing asserts it is used at
most once, or that it appears only in `diff-images.test.mjs`, so N lines anywhere in the
skills tree can carry it. The header comment's claim that scoping "to the LINE, not the
file" means "a real reintroduction elsewhere in that same file is still caught" is true
per-line but says nothing about the same line, which is where the hole is.

**Fix:** scope the exemption to the check it was written for, and bound its use.

```ts
let exemptionHits = 0;
...
  if (line.includes("toacme")) { need(false, ...); }
  if (line.includes("cmdDisasm")) { need(false, ...); }
  if (/\bdisasm\b/.test(line)) {
    if (line.includes(DISASM_LINE_EXEMPTION)) { exemptionHits++; continue; }
    need(false, ...);
  }
...
need(
  exemptionHits === 1,
  `non-vacuity: expected exactly ONE documented "disasm" exemption line, saw ${exemptionHits} -- ` +
    `a second one means the exemption is being used to hide a reintroduction`,
);
```

### WR-04: `acmeVerdict()` trusts the FIRST ACME line, so a mixed transcript is a false pass

**File:** `.claude/mcp/vice/r2000-verify.ts:100`
**Issue:** `lines.find((l) => l.assembler.toLowerCase() === "acme")` returns the first
match and every later ACME line is discarded. The module's own header promises the verdict
"comes ONLY from parsing the per-assembler result lines" and that a non-pass must never
read as a pass; a transcript containing both an ok and a failed ACME line breaks that.

**Demonstrated** against the real module:

```
input:  "  ✓ ACME — byte-identical (3 bytes)\n  ✗ ACME — output differs at offset $0010\n"
parsed: [{ACME, ok, ...}, {ACME, failed, ...}]
verdict: { ok: true, reason: 'ACME reported: byte-identical (3 bytes)' }
```

0.9.20 prints one line per assembler, so no observed transcript triggers this today — but
the transcript is already known to interleave echoed child-assembler output (see the pinned
ca65 fixture at `r2000-verify.test.ts:122-132`, which carries raw `stdout:`/`stderr:` echo
lines), and this parser is explicitly meant to be defensive against an unexpected shape.

**Fix:** require unanimity and pin the count.

```ts
const acmeLines = lines.filter((l) => l.assembler.toLowerCase() === "acme");
if (acmeLines.length === 0) { /* existing "never invoked" branch */ }
const bad = acmeLines.find((l) => l.outcome !== "ok");
if (bad) { /* existing skipped / failed branches, driven by `bad` */ }
if (acmeLines.length > 1) {
  return { ok: false, reason: `--verify printed ${acmeLines.length} ACME result lines -- refusing to guess which one is the verdict` };
}
```
Add the two-ACME-lines transcript to `r2000-verify.test.ts` as a pinned fixture.

### WR-05: the `.d64` walker bound-checks disk geometry but never the buffer, so a truncated image short-reads silently

**File:** `.claude/mcp/vice/r2000-d64.ts:79-83` (`isInImage`), `:225` and `:241` (the reads), `:262-268` (`assertPlainImage`, opt-in)
**Issue:** `isInImage(track, sector)` validates only against the 35-track geometry; it
never receives the image and never compares `tsToOffset(...) + 256` against
`image.length`. `image.subarray(off, off + 256)` then clamps silently, and
`chunks.push(sec.subarray(2, 256))` contributes however many bytes happened to exist.
`assertPlainImage()` — which the file header describes as the thing that "enforces the
174848-byte length" — is a separate exported function that neither `listEntries()` nor
`extractEntry()` calls. Today only `r2000-cli.ts:163` happens to call it, on the `.d64`
branch only; the module's exported API is unprotected, and Phase 11 plans an MCP surface
over exactly these functions.

**Demonstrated** against a valid image truncated 100 bytes into the file's own sector:

```
truncated image length: 148580
entries: [ 'GAME/PRG' ]
extracted length (expected 254): 98   -> SILENT SHORT READ
```

No throw, no warning; the caller synthesises a project from a 98-byte payload and
disassembles garbage.

**Fix:** make the bound check part of the walk rather than a separate opt-in.

```ts
function sectorSlice(image: Uint8Array, track: number, sector: number, what: string): Uint8Array {
  const off = tsToOffset(track, sector);
  if (off + 256 > image.length) {
    throw new Error(
      `${what}: sector ${track}/${sector} needs bytes ${off}..${off + 255} but the image is only ` +
        `${image.length} bytes -- truncated or non-plain image`,
    );
  }
  return image.subarray(off, off + 256);
}
```
Use it at both call sites. Also consider throwing (rather than the `Math.max(2, …)` clamp
at `:237`) when a final sector's `usedByte < 2`: today a corrupt `usedByte` of 0 or 1
yields a zero-length payload, which surfaces downstream as the confusing
`parsePrg: input is 0 byte(s)` (see WR-09).

### WR-06: NUL-padded directory names are printed but cannot be selected

**File:** `.claude/mcp/vice/r2000-d64.ts:93-97` (`petsciiName` strips only `$A0`), `:148-151` (`isEmptySlot` treats `$00` as padding)
**Issue:** the module is internally inconsistent about padding: the empty-slot test accepts
`0xa0 || 0x00` as name filler, but `petsciiName()` only trims trailing `0xa0`. A directory
entry padded with `$00` (produced by several disk-writing tools, and by any image where the
slot was partially rewritten) therefore yields a name containing embedded NULs, which the
listing prints and no user can retype.

**Reproduced live:**

```
$ node vice-proxy.ts r2000 bootstrap zeropad.d64 | cat -A
  ZEROPAD^@^@^@^@^@^@^@^@^@^IPRG^I1 block(s)$
$ node vice-proxy.ts r2000 bootstrap zeropad.d64 --entry ZEROPAD
bootstrap: extractEntry: no entry named "ZEROPAD" found. Available entries: ZEROPAD
```

The error message contradicts itself, and D-02's whole value proposition ("print the
listing, the human picks one") is a dead end for that disk.

**Fix:** strip both padding bytes, matching `isEmptySlot`'s own definition.

```ts
function petsciiName(bytes: Uint8Array): string {
  let end = bytes.length;
  while (end > 0 && (bytes[end - 1] === 0xa0 || bytes[end - 1] === 0x00)) end--;
  return Buffer.from(bytes.subarray(0, end)).toString("latin1");
}
```
Add a fixture with a `$00`-padded name to `r2000-d64.test.ts` — every current fixture pads
with `0xa0` (`Buffer.alloc(16, 0xa0)`), which is why this is untested.

### WR-07: a flat capture that is not exactly 65536 bytes is silently reinterpreted as a `.prg`

**File:** `.claude/mcp/vice/r2000-cli.ts:200-210`
**Issue:** the flat-image branch is selected by `bytes.length === 65536`, never by
extension, so `flatImageOrigin()`'s size check (which exists precisely to throw with a
named reason) is unreachable for any `.raw`/`.bin` of the wrong size. Such a file falls
through to `parsePrg()`, whose first two bytes become the load address. `USAGE:63-66`
advertises "a flat 64K `.raw`/`.bin` capture" as a first-class input, and a truncated or
partial capture is exactly the artifact `c64-ram-capture` can leave behind.

**Reproduced live** on a 4096-byte `capture.raw`:

```
bootstrap: wrote capture.regen2000proj (origin $62c5)   # exit 0
first two bytes of capture.raw: c5 62
```

Wrong origin, first two payload bytes eaten, no diagnostic — every downstream address in
the disassembly is wrong, and nothing says so. This is the "silently guess" behaviour D-02
was written to forbid.

**Fix:** dispatch flat captures by extension so the size check actually runs.

```ts
} else if (ext === ".raw" || ext === ".bin") {
  try {
    origin = flatImageOrigin(bytes);   // throws, naming the actual length, for anything != 65536
  } catch (err) {
    console.error(`bootstrap: ${errMsg(err)}`);
    return { code: 1 };
  }
  body = bytes;
} else if (bytes.length === 65536) { ... }
```

### WR-08: option parsing accepts a missing or flag-shaped value and silently loses the caller's intent

**File:** `.claude/mcp/vice/r2000-cli.ts:107-118`
**Issue:** `if (a === "--entry") entry = rest[++i];` never validates that a value exists or
that it is not itself an option. Two demonstrated consequences:

```
$ node vice-proxy.ts r2000 bootstrap game.prg --out
bootstrap: wrote game.regen2000proj (origin $0801)      # --out silently ignored, default used

$ node vice-proxy.ts r2000 bootstrap game.prg --out --entry FOO
bootstrap: wrote --entry (origin $0801)                 # file literally named "--entry"
$ ls
--entry  game.a  game.prg  game.regen2000proj
```

In the second case `--entry FOO` is also silently dropped — on a `.d64` that turns a
"extract this entry" invocation into a directory listing, and it leaves a dash-prefixed
filename in the user's tree (a hazard for any later shell glob).

**Fix:** validate at parse time.

```ts
function takeValue(rest: string[], i: number, flag: string): string {
  const v = rest[i];
  if (v === undefined || v.startsWith("-")) {
    throw new Error(`${flag} needs a value (got ${v === undefined ? "end of arguments" : `"${v}"`})`);
  }
  return v;
}
```
Report unrecognised `--flags` and extra positionals as errors too, rather than letting them
surface later as "input file not found".

### WR-09: `bootstrapProject()`'s documented never-throw contract is broken on two paths

**File:** `.claude/mcp/vice/r2000-cli.ts:199` (unguarded `parsePrg` on the `.d64` path), `:220` (unguarded `writeFileSync`)
**Issue:** the function's own doc comment (`:125-132`) states "Never throws for an
expected, user-facing failure -- every branch below returns a `{ code }` result with a
one-line message already printed". Every other `parsePrg` call is wrapped
(`:204-209`) but the `.d64` one at `:199` is not, and the write at `:220` is not wrapped at
all. Both failures are ordinary user-facing ones: a zero-length or 1-byte disk entry, and
an `--out` path in a directory that does not exist.

**Reproduced live** with an entry whose final sector claims one used byte:

```
$ node vice-proxy.ts r2000 bootstrap empty.d64 --entry EMPTY
r2000: parsePrg: input is 0 byte(s) -- a .prg needs at least 3 bytes (...)
```

Note the `r2000:` prefix instead of `bootstrap:` — the throw escaped to
`runR2000Cli()`'s last-resort net (`:370-381`), which the header describes as being for
*unexpected* throws only, so the diagnostic loses its provenance and mentions an internal
function name to a user who supplied a disk image.

**Fix:** wrap both in the same `try { ... } catch (err) { console.error(\`bootstrap: ${errMsg(err)}\`); return { code: 1 }; }`
shape the sibling branches already use, and give the `.d64` case a message in the
caller's vocabulary (`entry "EMPTY" holds 0 bytes -- not a loadable program`).

### WR-10: `runR2000()` has no default timeout and no `maxBuffer`, on a synchronous spawn

**File:** `.claude/mcp/vice/r2000-launch.ts:142-158`
**Issue:** `RunR2000Options.timeoutMs` exists but no caller sets it
(`r2000-cli.ts:266`, `r2000-verify.ts:149` both call `runR2000(argv)`), and `spawnSync`
has no default timeout. `maxBuffer` is likewise unset, so it defaults to 1 MiB; exceeding
it sets `r.error`, which `:156` re-throws raw — turning a *successful* verify with a
verbose child transcript into an opaque `ENOBUFS`/`ERR_CHILD_PROCESS_STDIO_MAXBUFFER`
stack rather than the parsed verdict this module exists to produce.

The hang risk matters more than it looks: `spawnSync` blocks the entire Node event loop,
and Phase 11 plans an `r2000_*` MCP surface in this same directory. An `r2000_*` tool
built on this function would freeze the stdio proxy — no JSON-RPC, no diagnostics —
which is exactly the state `vice-wedge-triage` teaches users to distrust.

**Fix:** give the seam defaults and a named error, keeping the caller override.

```ts
export const R2000_TIMEOUT_MS = Number(process.env.R2000_TIMEOUT_MS ?? 120_000);
const R2000_MAX_BUFFER = 32 * 1024 * 1024;
...
const r = spawnSync(R2000_BIN, [...argv], {
  encoding: "utf8",
  cwd: opts.cwd,
  timeout: opts.timeoutMs ?? R2000_TIMEOUT_MS,
  maxBuffer: R2000_MAX_BUFFER,
});
```
and translate `ETIMEDOUT` / max-buffer errors into messages that name the argv and the
limit, the way the ENOENT branch already does.

### WR-12: the `.d64` round-trip tests encode the implementation's used-byte formula in their own fixture writer

**File:** `.claude/mcp/vice/r2000-d64.test.ts:50-76` (`writeChain`, `buf[off+1] = remaining + 1`), and the duplicate at `.claude/mcp/vice/r2000-cli.test.ts:87-92`
**Issue:** the fixture writes `usedByte = payloadLen + 1`; the implementation reads
`payloadLen = usedByte - 1`. Those are the same equation, so the round-trip test at
`r2000-d64.test.ts:125-133` is a tautology with respect to the DOS convention: a
*systematic* off-by-one in both directions would still pass. Plan 10-03 records finding and
fixing exactly this bug class while writing this test, which is precisely why the test
should not be able to miss it. (I checked the formula independently and it is correct — a
1-byte file has `00 02 <byte>`, giving `2 - 1 = 1` — so this is a test-strength finding,
not a behaviour bug.)

### IN-01: `process.exit()` immediately after `console.log` can truncate piped output

**File:** `.claude/mcp/vice/vice-proxy.ts:217-221`
**Issue:** the dispatch ends the process the instant `runR2000Cli()` resolves. On a pipe,
`console.log`/`console.error` writes are asynchronous, and `process.exit()` discards
whatever has not drained. Verified on this host's Node 22.22.0:
`node -e 'console.log("x".repeat(500000)); process.exit(0)' | wc -c` → `131072`
(truncated at 128 KiB). The reachable trigger is `cmdExportAsm`'s `console.error(result.stderr)`
(`r2000-cli.ts:269`), which can carry up to `maxBuffer` of child output — so the one case
where the user most needs the diagnostic is the one where a piped invocation can lose it.
Directory listings are bounded to ~144 entries and are safe.
**Fix:** `process.exitCode = code;` plus an explicit drain
(`await new Promise((r) => process.stdout.write("", r))`) before exiting, or exit from a
`process.stdout` `drain` continuation.

### IN-02: the host-path absence assertion the r2000 family relies on is single-line and static-import-only

**File:** `.claude/mcp/vice/hostpath-consumers.test.ts:43` (`HOSTPATH_IMPORT_RE`), `:106-118` (the new r2000 test)
**Issue:** the regex is applied per line, so a multi-line named import
(`import {\n  hostPath,\n} from "./hostpath.ts";`) never matches, and a dynamic
`await import("./hostpath.ts")` never matches either. The new r2000 assertion inherits
both blind spots — notably in a phase that itself introduced the dynamic-import route
(`vice-proxy.ts:218`). Pre-existing infrastructure, not a regression, but the new test's
stated guarantee ("must not import hostpath.ts, whether or not it exists yet") is weaker
than it reads.
**Fix:** match against the whole comment-stripped source with an `m`-flagged, newline-tolerant
pattern, and add a `\bimport\s*\(\s*["'][^"']*hostpath` dynamic-import check.

### IN-03: the `\bdisasm\b` deletion pin will false-positive on the protected Phase-4 module names

**File:** `scripts/check-skill-fork-honesty.mjs:373`
**Issue:** `-` is a non-word character, so `\bdisasm\b` matches `disasm-decoder.ts`,
`disasm-opcodes.ts` and `disasm-renderer.ts`. Any future skill doc that legitimately names
the stock live-RAM disassembler's modules fails CI with a message about a deleted `toacme`
verb. Worth a narrowing (e.g. require the token not be followed by `-[a-z]`) or an
explicit note in the failure text so the next maintainer is not misled.

### IN-04: two near-vacuous assertions in `r2000-launch.test.ts`

**Issue:** the test sets `process.env.R2000_BIN` at test time, but `R2000_BIN` is resolved

title's "with a binary name guaranteed not to exist" clause describes something that does

asserts only `typeof R2000_BIN === "string"` and `.length > 0`, which the `?? "regenerator2000"`
default makes unfalsifiable.
**Fix:** delete the env mutation (or move the override to a child-process test), and assert
`R2000_BIN === "regenerator2000"` when the env var is absent.

### IN-06: `verify` accepts `--out` and silently ignores it
