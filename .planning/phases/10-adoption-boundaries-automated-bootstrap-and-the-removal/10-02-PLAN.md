<objective>
Turn a raw binary into an analysed regenerator2000 project with no human in the loop
(criterion 3, `R2000-09`), by synthesising the `.regen2000proj` file directly in Node.

Per **D-01** this does not drive the TUI: `ProjectState` has exactly three fields
without `#[serde(default)]` and the project file is plain JSON with only the
`raw_data_base64` *value* gzip-then-base64 encoded. Per **D-04** the file we write is
minimal by design — every field we omit is a field a future regenerator2000 can change
without breaking us — and the compatibility proof is running the real binary once, not
consulting a version table. Per **D-05** `settings.use_illegal_opcodes` is forced true
and `settings.system` is set explicitly, with no flag to disable either.

Purpose: this is the bootstrap the whole phase's ordering hangs on — criterion 4's
`--verify` proof (plan 10-05) needs a project file to exist first, because `--verify`
implies `--headless` and headless refuses any non-`.regen2000proj` input.

Output: `.claude/mcp/vice/r2000-project.ts`, `.claude/mcp/vice/r2000-project.test.ts`,
and an execution-time environment re-check recorded as evidence.
</objective>

detect a schema break within a permitted version.

Exports:
  - `const R2000_SYSTEM_C64 = "Commodore 64"` — the exact literal from the crate's
    `System::C64` constant. `System` is `#[serde(transparent)]` over `String`, so the
    JSON value is a bare string.
  - `interface SynthesizeOptions { origin: number; system?: string }` — `origin` is the
    load address as a plain number (`Addr` is `#[serde(transparent)]` over `u16`);
    `system` defaults to `R2000_SYSTEM_C64` and is ALWAYS written, never omitted (D-05).
  - `function synthesizeProject(bytes: Uint8Array, opts: SynthesizeOptions): string`
    returning the project file's JSON text. The object written is exactly:
    `origin`, `raw_data_base64` (`gzipSync(bytes).toString("base64")` from `node:zlib`),
    `blocks` as an empty array, and `settings` containing exactly
    `use_illegal_opcodes: true` and `system`. Write NO other field — every other
    `ProjectState` member carries `#[serde(default)]`, and omission is the
    forward-compatibility strategy (D-04). Do not write `version`; it defaults.
    Do not write `settings.assembler`; the assembler is chosen per-invocation with
    `--assembler acme` by `r2000-launch.ts`.
  - `function parsePrg(bytes: Uint8Array): { origin: number; body: Uint8Array }` — a
    `.prg` carries a little-endian 2-byte load address followed by the payload. Reject a

  - `function flatImageOrigin(bytes: Uint8Array): number` — returns 0 for a flat 64K
    capture and throws if the length is not exactly 65536, naming the actual length.
    Flat 64K is in scope because `R2000-06` names it and it is what `c64-ram-capture`
    already produces (D-03).
  - `function decodeRawData(base64: string): Uint8Array` — the inverse (gunzip + base64
    decode), exported so the tests can prove the payload round-trips rather than
    asserting on an opaque blob.

Validation and range rules: `origin` must be an integer in `0..0xffff` — throw naming
the offending value and the valid range, following this project's existing range-error
message convention. Reject a zero-length payload.

State inline, as a comment beside the settings object, that `use_illegal_opcodes` and
`system` are deliberately not configurable: illegal-opcode-correct decoding is the entire
reason the `toacme` caveats existed, so making it optional would reintroduce the defect
as a configuration choice (D-05); and an explicit `system` is what makes Phase 9's
`.vsf` machine-type limit unreachable rather than merely mitigated.

`.vsf` is NOT an input to this module (D-03) — say so in the header, and name Phase 11

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied binary bytes → `synthesizeProject` | Untrusted file content is base64-embedded in a JSON document |
| test harness → regenerator2000 subprocess | An external CLI is executed with temp-file paths |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02 | Tampering | the gated subprocess run in `r2000-project.test.ts` | mitigate | Argv array to `spawnSync`, never a shell string and never `shell: true`; temp paths are generated by `node:fs.mkdtempSync`, never interpolated into a command line — the standing rule stated in `disasm-roundtrip.test.ts`'s own header |
| T-10-03 | Tampering | `synthesizeProject` input validation | mitigate | `origin` is range-checked to `0..0xffff` and a zero-length payload is rejected, both with the offending value in the message (ASVS V5, the only category RESEARCH.md marks `yes` for this phase). The module never loads an externally-supplied `.regen2000proj` — it only writes files it synthesised itself, so the malformed-project-ingest threat is not introduced by this phase |
| T-10-06 | Denial of Service | the gated integration test | mitigate | An explicit subprocess timeout plus `finally`-scoped temp cleanup, so a hung or missing regenerator2000 can never stall the automated gate. The file is deliberately NOT added to `MANUAL_ONLY_TESTS` |
| T-10-01 | Denial of Service | regenerator2000 invocation | transfer | This plan spawns regenerator2000 only through the argv arrays it builds inline for the gated test, and never passes `--vice`; the general guarantee is owned by plan 10-01's `assertNoViceFlag` seam, which plan 10-04 routes all production invocations through |
| T-10-SC | Tampering | npm/cargo installs | accept | No npm dependency is added; regenerator2000 is already installed and was provenance-verified in Phase 9 (crates.io publisher `ricardoquesada`, `MIT OR Apache-2.0`, 0.9.20). Task 1 re-checks the installed version rather than installing anything |
</threat_model>
