<objective>
Make the guarded seam reachable from a skill, from every install route, and give it the
two verbs the bootstrap needs (`ANNO-09`, and `ANNO-02` extended to the new module).

**This plan resolves RESEARCH.md Open Question #1 / Assumption A2 by adopting the
researcher's recommendation as the design.** The chosen mechanism is an argv subcommand
on the existing published `vice-mcp` bin. Rationale, from the traced facts rather than
preference: `.claude/mcp/vice/*.ts` files exist as plain files on disk ONLY under the
Claude Code plugin route — `installer/bin/cli.mjs`'s `viceServerEntry()` launches the
server via `npx` in BOTH npm-installer modes (`--vendor` only pre-resolves the package,
it does not change the launch), so any design resolving a filesystem path to the seam
silently fails to resolve for npm-installed users. The bin is the one surface proven to
resolve identically in all three routes. A second `bin` entry was rejected: it changes
the published package's bin contract and needs `npx --package=…` ergonomics, while a
subcommand needs neither. The recommendation was flagged as unverified end-to-end, so
Task 3 verifies it by spawning the bin exactly as a consumer would.

Purpose: without this, criterion 3's bootstrap exists but nothing can call it, and
criterion 4's replacement route would have nothing to point at.

Output: `anno-cli.ts`, its test, the dispatch in `vice-proxy.ts`, and the `files[]`
entries `scripts/check-npm-packages.mjs`'s transitive-closure walk requires.
</objective>

Create `.claude/mcp/vice/anno-cli.ts` exporting
`async function runAnnoCli(argv: string[]): Promise<number>` — it returns an exit code

Header comment: state that this is the thin CLI ergonomics layer over the guarded seam

Verbs:
  - `bootstrap <input> [--entry NAME] [--out PROJECT]` — accepts `.prg`, `.d64` and flat
    64K `.raw`/`.bin` (D-03; `.vsf` is explicitly refused with a message naming Phase 11
    as its home). Dispatch by extension AND by content check: `.prg` via
    `parsePrg()`, a 174848-byte `.d64` via `assertPlainImage()`/`extractEntry()` then
    `parsePrg()` on the extracted bytes, and an exactly-65536-byte image via
    `flatImageOrigin()`. Writes the synthesised project text from `synthesizeProject()`
    to `--out`, defaulting to the input path with its extension replaced by
    `.regen2000proj`. Prints the written path and the chosen origin in hex.
  - `export-asm <input-or-project> [--out FILE]` — if given a `.regen2000proj` it uses it
    directly; otherwise it bootstraps to a temp project first, so a user gets ACME source
    from a bare `.prg` in one command. It then calls `buildExportAsmArgs()` and
    `runAnno()` from `anno-launch.ts`, defaults `--out` to the input stem plus `.a`,
    and on a non-zero child status prints the child's stderr and returns that status.
  - `--help` / no verb / unknown verb: print the usage block (both invocation forms —
    `npx -y @henols/vice-mcp anno <verb>` for npm installs, and
    `node <plugin-root>/.claude/mcp/vice/vice-proxy.ts anno <verb>` in-repo/plugin) and
    return 0 for an explicit `--help`, 1 for an unknown verb, matching `acme.mjs`'s
    convention.

D-02's fail-loud contract, implemented here and nowhere else: for a `.d64` input with no
`--entry`, print the directory listing from `listEntries()` — one line per entry with
name, type and block count — then print a line telling the user to re-run with
`--entry NAME`, and return exit code 2. Never pick an entry. Say in a comment WHY: a
silent auto-pick would happily analyse a cracktro or loader stub instead of the game,
which is the exact failure `c64-provenance-diff` exists to prevent.

Error handling: a missing input file, an unreadable file, an unknown `.d64` entry name and
a `.vsf` input each produce a one-line actionable message on stderr and a non-zero return,
never a stack trace. An `AnnoViceFlagError` from the seam must be re-thrown or reported
verbatim, never swallowed — the loud failure is the point.

Import nothing from `hostpath.ts` or `containerpath.ts`. Every path this CLI handles is
already container-side: The external analyser runs on the MCP proxy's side of the boundary
(D-R4), and translating any of these arguments would be the mirror image of the DERIV-07
screenshot-path trap. Plan 10-01's `hostpath-consumers.test.ts` extension already names
`anno-cli.ts` on the absence side.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user shell → `vice-mcp anno …` argv | User-supplied paths and entry names enter the process |
| `anno-cli.ts` → `anno-launch.ts` → the external analyser | The only path from user input to a child process |
| CLI branch → MCP server path | A CLI invocation must never become a server invocation, or vice versa |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Denial of Service | argv reaching the external analyser | mitigate | The CLI exposes no passthrough for extra flags: it calls only `buildExportAsmArgs()`/`buildVerifyArgs()`, and every spawn runs `assertNoViceFlag()` first (plan 10-01). A `--vice` reaching the child would make the external analyser a second client on stock VICE's single-client binary monitor |
| T-10-02 | Tampering | user-controlled filename reaching `spawnSync` | mitigate | `anno-cli.ts` never spawns anything itself (asserted by grep in Task 1's criteria); `anno-launch.ts` passes an argv array with no shell. ASVS V5: input paths are existence-checked before use and never interpolated into a command string |
| T-10-07 | Spoofing | `.d64` entry selection | mitigate | No `--entry` means a listing and exit code 2, never a guess (D-02). Task 3 test 4 asserts no project file is written in that case |
| T-10-08 | Tampering | the bin's dual role | mitigate | The dispatch is the first executable statement, above the backend probe and the server construction, and Task 3 test 1 asserts no JSON-RPC frame is emitted on the CLI path. A fall-through would hang, which test 3's timeout catches |
| T-10-05 | Information Disclosure | host-path leakage into anno arguments | mitigate | `anno-cli.ts` imports no host-path module; plan 10-01's closed-consumer-set extension names it explicitly on the absence side (D-08, ANNO-02) |
| T-10-SC | Tampering | npm publish surface | mitigate | The four new modules are declared in `files[]` and validated by `scripts/check-npm-packages.mjs`'s transitive-closure walk; the runtime dependency set is asserted unchanged, so no new package enters the published tarball |
</threat_model>
