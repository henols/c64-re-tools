<assumption_delta_decision>
**The detector fired, and this plan is where the real question lives.**

**Primary noun: the neutral block class.** Before this plan there is exactly one
answer to "what class is this address, according to the store" — upstream's Rust
`Display` string, compared inline by the census. This plan introduces a second
possible answer (the store this project is about to own), so the singular
assumption loses its monopoly.

**Decision: `promote`.** The generalised representation — the neutral
three-valued class returned by `blockClassAt()` — becomes primary, and upstream's
`Display` vocabulary is demoted to a detail of **one** variant, owned solely
inside `block-class.ts`. Rationale: the census must never keep a second, direct
path to the raw block-type string beside the adapter. That is exactly why all
three comparison sites and both lookup sites route through the boundary and why
the site at `:1983-1986` cannot be left behind — an add-alongside shape would let
the census still read upstream's vocabulary directly, and a later variant that
does not speak it could be stored but never compared.

**Not `add-alongside`, and not `no-change`.** Add-alongside is what D-10 rejected
in its "injected default-argument mapping" form: a caller that forgets the
mapping silently gets upstream's vocabulary back, which is the failure that
should be loud. No-change is not available: the whole of SEAM-03 is this
transition.

**Companion invariant test, accepted:** D-13's substitutability test with a
**zero-overlap** second vocabulary (Task 3). It goes red the instant a future
phase reintroduces a direct comparison against an upstream literal, because a
left-behind comparison would then move a census byte count.

The other three plans in this phase record `no-change` for their own scope with
their rationale; this is the one identity-model transition in Phase 27.
</assumption_delta_decision>

<design_note_recorded>
**How the second implementation reaches the census, and why this is not the shape
D-10 rejected.** D-10 rejected "an injected default-argument mapping" because a
caller that forgets it silently gets upstream's vocabulary back. RESEARCH.md V-3
explicitly names "a parameter on `ReproducibilityInput`" as an acceptable
injection seam. Both are honoured as follows, and the choice is recorded here
rather than left to be discovered in the diff:

- The **boundary is the module**. `block-class.ts` holds the one production
  implementation. Phase 28 swaps the module, never an argument.
- The two **internal** shapes take the classifier as a **required** field or
  parameter with **no default**, so an internal site that forgets it is a
  typecheck error — loud, exactly as D-10 asks.
- `CoverageOptions`, the public entry, takes an **optional** classifier whose
  default is the real module's function. A forgetful caller therefore gets the
  one correct production adapter, not upstream's raw vocabulary — the failure
  D-10 named cannot occur. Its doc comment states it is the substitutability
  proof's seam, that production must not pass it, and that a store change is made
  by editing `block-class.ts`.
- An acceptance criterion asserts **no production module passes it** — only the
  test does.
</design_note_recorded>
