<objective>
Give the emulator's observations a durable home, and give the existing stores
in the field a decided fate rather than a default.

Purpose: EVID-01 wants observations to survive the session so a later session
queries them instead of re-running the program. EVID-02 wants the schema bump
that enables it to carry a recorded, fact-checked decision -- because the
justification the last bump recorded ("no store file exists yet") is very
likely stale after two milestones of real store use, and the current mechanism
refuses on mismatch rather than migrating.

Output: `SCHEMA_VERSION` 4 with its decision paragraph; one new table in
`anno-store.ts`'s single `DDL`; the store-side write and read functions for
it; and a durability proof across a real process death.

## The DDL column set is selected by plan 43-01's verdict, not chosen here

`docs/phase43-instrumentation-perturbation-ab.md`'s decision section marks
exactly one row of the assumption-delta table as selected. Read it before
writing a single `create table` line.

* Selected row `no-change` (verdict `no-perturbation`): the run-identity
  columns are `image_sha256`, `argv_digest`, `seed`. There is **no**
  `run_class` column, and none is invented "for later".
* Selected row `promote` (verdict `perturbation` or `not-exercised`): the
  run-identity columns are `image_sha256`, `argv_digest`, `seed`,
  `run_class`, and `run_class` participates in the uniqueness constraint. The
  four-part composite is primary and the v0.8.0 triple is a projection of it,
  never a second identity scheme kept alongside.

Both branches are spelled out in Task 2's action. Neither is assumed.

## Edge coverage authored from the deterministic probe

* **EVID-02 idempotency (explicit).** Applying the bump twice is a no-op:
  `openStore` runs the `DDL` only on a fresh file, and an already-version-4
  store opens without re-running it and without rewriting `anno_meta`.
  Re-ingesting the identical observation set reports `changed: false`.
* **EVID-02 concurrency (explicit).** Two parallel opens of a version-3 store
  both refuse by name, and neither writes `anno_meta.schema_version` -- the
  refusal is a read followed by a close, with no mutation on the path.
* **EVID-01 (unclassified, unresolved -- flagged, not auto-resolved).** The
  probe could not classify what EVID-01's edges are. Reviewed manually here:
  the requirement's own hazard is a second notion of run identity, which is a
  *structural* property (which columns exist) rather than a boundary or a
  precision question. It is covered by the DDL selection rule above and by
  plan 43-01's assumption-delta decision, and is surfaced here rather than
  silently dropped.
