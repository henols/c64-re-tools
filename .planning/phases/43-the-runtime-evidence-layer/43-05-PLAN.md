<objective>
Turn an observation into a durable row. One `memmapshow` reply plus one run
identity becomes rows in `.annostore` that outlive the session.

Purpose: EVID-01 wants a later session to query the evidence instead of
re-running the program, keyed by the run identity v0.8.0 already established
rather than a second notion of sameness. EVID-04 wants the write path unable
to record `data` from absence -- which is settled here, at the one place where
a parsed access map becomes rows.

Output: `evid-ingest.ts`, the pure transform from a parsed access map to
observations; and `anno_evid_ingest`, the write verb that carries it into the
store.

## The one positive fact this layer is licensed to assert

A row is written if and only if an address's `ram.execute`, `rom.execute` or
`io.execute` flag is true in the parsed reply. Nothing else produces a row.

That resolves `43-RESEARCH.md`'s Open Question 1 deliberately rather than by
default. The consequence is stated here so a later reader does not have to
re-derive it: an address `memmapshow` mentioned with read or write access but
no execute produces no row, and an address absent from the sparse `entries`
array produces no row either. Those are two DIFFERENT facts about the world,
and neither is recoverable from the store's row set alone -- only from the
reply. That is correct and is the point: the store holds observed execution,
and the absence of a row is not a fact the store asserts about the address.
It is the absence of an assertion.

Read-and-write-only observations are deliberately NOT stored. The schema can
gain a separate table for them later without a migration, because it would be
a wholly new table -- which is the store's existing additive discipline.

All three source banks are stored, not just RAM. Each is an independent
execute bit in `AccessFlags`, and dropping ROM or IO execution would discard
a positive observation this layer is licensed to make.

## Why the verb takes an argv array and not a digest

`anno_evid_ingest` requires `argv`, the exact launch argument vector, and
computes `argv_digest` itself through `argvDigest()`. It accepts no
caller-supplied digest at all.

The reason is EVID-01's own hazard: a verb accepting a pre-computed digest
would let a caller invent a run identity, which is a second notion of
sameness sitting beside the first. Requiring the argv and digesting it in one
place means the identity is always derived by the shipped function from the
launch that produced the observation. `argvDigest` also refuses an empty
array by name, because the sha256 of nothing is a stable value that would
look identified.

`image_sha256` is supplied as a 64-lowercase-hex string and validated, not
computed: the program image is named by its bytes, and the digest of those
bytes is already recorded by the capture route that produced the run. This
verb does not read the image, and deliberately takes no path to it -- an
emulator binary or a `.d64` release lives outside the workspace, and the
store's confinement seam would refuse it.
</objective>
