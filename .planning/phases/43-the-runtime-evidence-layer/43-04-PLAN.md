<objective>
Make disagreement queryable. Where the byte-derived block table says `data`
and the emulator was observed executing, that address is the highest-value
output of the whole design -- and the two classifiers' independence is the
asset that produces it.

Purpose: EVID-03 wants the disagreements first, agreement as a count, and the
block table left byte-derived and never overwritten. EVID-04 wants the layer
structurally unable to state `data` from absence, with every summary carrying
its denominator. Both are properties of the join, so both are settled in one
pure module before any verb can reach it.

Output: `evid-reconcile.ts`, shaped exactly like `dxa-proof01-compare.ts` --
two already-fetched classifications in, buckets with an explicit denominator
and a named third bucket out, nothing fetched and nothing mutated.

## Three buckets, and why the third one is not optional

For each address the byte-derived block table covers:

  1. **disagreement** -- the block class is `data` and the evidence holds at
     least one observed-execute row. Reported FIRST, as rows.
  2. **agreement** -- the block class is `code` and the evidence holds at
     least one observed-execute row. Reported as a COUNT. A wall of rows here
     buries bucket 1, which is the whole point of the query.
  3. **block-covered, never observed** -- the block table classifies the
     address and no run ever observed it executing. This is NEITHER agreement
     NOR disagreement, and folding it into either is the soundness violation
     EVID-04 forbids: absence proves nothing. It gets its own count and its
     own name.

A fourth population exists and is also reported by count: an address with an
observed-execute row that NO block covers (`blockClassAt` returns `null`).
That is evidence about an unclassified address -- again neither agreement nor
disagreement -- and it is named rather than dropped, because dropping it
would make the denominator lie.

The block class `undefined` deserves its own note: an address the block table
explicitly marks undefined, with an observed-execute row, is not a
disagreement (nothing was claimed to disagree with) and not agreement. It
joins bucket 3's sibling count under its own name.

## Edge coverage authored from the deterministic probe

* **EVID-03 boundary (explicit).** Both range ends are inclusive, matching
  `blockClassAt`'s own contract. A block ending exactly at an observed
  address covers it; the address one past that end is covered only by its own
  block, never by adjacency. Addresses 0x0000 and 0xffff are ordinary, and a
  block starting at 0x0000 or ending at 0xffff is exercised directly.
* **EVID-03 precision (explicit).** There is no rounding site: this module
  returns integers and an explicit `denominator`, and returns no percentage,
  rate, ratio or score. A consumer that wants a rate forms it from the
  numerator and denominator it was handed. Stated as a contract rather than
  a convention, and asserted by a source census for `toFixed` and by a
  banned-key walk over the returned object.
* **EVID-04 (unclassified, unresolved -- flagged, not auto-resolved).** The
  probe could not classify EVID-04's edges. Reviewed manually: EVID-04 is not
  an edge case but a set of four structural controls, and each gets its own
  control rather than one blanket assertion -- the runtime union has no
  `data` member (plan 43-02), "no row" and "observed not executing" cannot
  collide because a row exists only for an observed execute (plan 43-05),
  every summary carries its denominator (this plan and plan 43-02), and a
  union across runs is never rendered as exhaustive (this plan's third and
  fourth buckets plus plan 43-07's banned-key guard). Surfaced here rather
  than dropped.
