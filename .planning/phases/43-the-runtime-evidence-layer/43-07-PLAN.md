## Why the structural guard is derived and not a list

`anno-coverage.test.ts`'s COV-01 walks one report and refuses a
combined-figure key. This guard does the same thing over four answers, but
its SCOPE is derived from `ANNO_TOOL_DEFINITIONS` rather than written down:
every definition whose name begins with the evidence family's own segment
must have an entry in the guard's fixture table, and the guard fails by name
when one does not. That is the difference between a test that pins today's
four verbs and a test that catches the fifth.

The non-vacuity direction matters as much as the prohibition. A key walk that
stops at the top level passes trivially, and this repository has already been
bitten once by a census that under-covered while reporting success. So the
guard asserts the walk visited more keys than the top level holds, and that
it visited at least one key inside a nested disagreement row.

## Why the concurrent planting is not a second sequential run

A bracket is valid only if nothing else wrote into it. Two sequential
ingests prove ordering; they do not prove isolation. The planted scenario
therefore runs TWO distinct run identities writing into ONE store file
concurrently, kills one mid-ingest with `SIGKILL` and no clean close, and
asserts from a FRESH process that the survivor's rows are complete and the
killed identity left either its whole set or nothing -- never a partial set.

The mutator gains no second harness: it gains one more mode, taking the run
identity from argv, and the committing and no-commit plantings stay one code
path differing in one parameter. That is the property that makes the planting
evidence about the real write sequence rather than about a copy of it.
