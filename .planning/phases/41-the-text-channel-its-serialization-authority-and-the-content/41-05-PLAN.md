<objective>
Make the text port mandatory on every stock launch, and retire the warm floor
that would otherwise need the same change at a second launch call site.

Purpose: `broker-launch.mts`'s `acquirePortAndLaunch()` currently degrades — a
failed second-port allocation launches without the text-monitor flag rather than
failing the acquire. Owner direction is verbatim and unambiguous: it should not
be possible; VICE must be started with the text channel. That converts a
survivable degradation into a hard acquire failure, and every caller and test
that tolerated a portless stock instance changes with it. The folded todo fits
here because the warm-floor call site is the *second* launch call site that
would otherwise need the identical change — and it is the one the todo shows is
structurally useless: `profileEligible()` compares `warp` and `headless` on both
sides while the warm call site passes no profile at all, so every spare is
unwarped and windowed, and any acquire asking for warp skips it and cold-launches
anyway. The floor helps exactly the requests that care least about boot latency.

Output: a stock acquire that fails rather than degrades; the promotion step
relocated out of the warm floor; the floor removed; every comment describing the
removed behaviour corrected.
</objective>

  <decision>Remove `acquirePortAndLaunch()`'s text-port degrade path, so a stock launch that cannot bind a second port fails the whole acquire.</decision>
  <context>
`D-16` is the one decision in this phase rated **one-way in effect**, and
`41-CONTEXT.md` itself flags its blast radius as worth a second look before the
first plan is committed. The outcome was chosen by owner direction, verbatim:
*"it should not be possible, vice must be started witht the text channel"*. What
was NOT enumerated at the time is what changes with it, so this checkpoint
presents the enumerated radius rather than re-asking the decision.

**What the change is.** Today a failed second-port allocation logs a degrade
line and launches without the text-monitor flag. After this change that
allocation failure returns a typed acquire failure and no process is spawned.

**What changes with it, enumerated:**

1. **A new acquire failure mode on a healthy host.** A host whose port band is
   nearly exhausted can now fail an acquire that would previously have succeeded
   with a text-portless instance. The failure surfaces as an ordinary acquire
   error on the control plane, queued and retried by the existing
   `enqueueAcquire()` / `drainPendingAcquires()` machinery like any other, so it
   is not a new refusal *shape* — but it is a new refusal *cause*.
2. **The fork is unaffected.** The second allocation is only ever attempted for
   `backend === "stock"` and only when the caller provided the allocator. No
   `-remotemonitor` is appended to a fork launch before or after.
3. **`remoteMonitorPort` becomes required on a stock grant.** Downstream, that
   removes a whole case rather than adding one: there is no missing-port refusal
   path to design, and no optional-absence branch for any later consumer.
4. **Two shipped comments become false and must be corrected in the same
   commit** — the degrade log line and its comment in `broker-launch.mts`, and
   the absent-request comment beside the record's own field. Plan 41-03 already
   corrected `broker-state.mts`'s ownership banner.
5. **Tests that tolerated a portless stock instance change with it.** The
   affected files are `broker-launch.test.ts`, `vice-broker-acquire.test.ts` and
   `broker-e2e.test.ts`.
6. **It composes with the warm-floor removal in Task 3.** The warm-floor call
   site is the second launch call site that would otherwise need the identical
   mandatory-port change; removing the floor removes that duplicate rather than
   changing it twice.

**Undo cost if this is wrong:** restoring the degrade means restoring the
degrade branch, re-adding an optional-absence branch to every consumer of
`remoteMonitorPort` that this phase wrote as required (`HeldLease`,
`textConnect()`, and any later plan built on the guarantee), and re-loosening
the tests. That is a coordinated change across the phase's output, not a local
revert — which is why this door is rated one-way in effect and is presented here
before it is walked through.

**Alternative that was declined on the spot** (recorded so this checkpoint is a
confirmation and not a re-litigation): a graceful refusal path for a portless
instance, i.e. keep the degrade and refuse text-channel operations by name on
instances that lack a port. Declined by owner direction — the refusal path is
not to be built, and the state it would handle is designed out.
