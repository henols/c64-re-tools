<assumption_delta_decision>
**Noun now primary:** *the monitor clients of an instance, keyed by channel*.

**Decision: `promote`** — `InstanceRecord.monitorClient` (one holder, implicitly
scoped to the binary socket) is replaced by `monitorClients`, a per-channel map,
with the binary socket demoted to one variant of it. The old singular field is
not kept alongside the new one: a single holder slot cannot represent a binary
holder and a text holder simultaneously, so "add-alongside" would leave the
generalized intent expressible but never confirmable. Clean break, no alias and
no dual-read, matching this project's own D-33 precedent.

**Rationale:** `D-14` requires the broker to refuse a *second text client* by
name on a working control socket. That refusal needs a text holder record that
is independent of the binary one; a `channel` tag inside the existing single
field cannot hold both.

**Against the recorded verdict's constraint:** Phase 39 returned `go` (rule
`R15`), under which the `channel` discriminator is **bookkeeping, never
enforcement** for cross-channel serialization. This promotion does not change
that: cross-channel halt serialization stays entirely the in-process mutex's job
(`channel-lock.ts`, plan 41-02). What the discriminator enforces is
*one-text-client-per-instance* — a distinct ownership concern `D-14` names
explicitly, and the same concern the single field already enforced for the
binary socket. No halting operation consults `monitorClients`.

**Where it lands:** plan 41-03, with an invariant test (its Task 2) that goes red
the instant a future phase reintroduces a single-channel-scoped holder.
</assumption_delta_decision>

Layer 5 — NEW `src/mcp/vice/text-protocol.ts`. Header comment declaring this is
the ONE place the text wire's bytes are framed, what not to do (never

command string. Exports:
`TextMonitorClient` (a `net.Socket`-wrapping `EventEmitter` mirroring
`ViceMonitorClient`'s private-field shape — `#socket`, `#buffer`, bound
`#onData`/`#onClose`/`#onError`, a `connected` getter — and deliberately
DROPPING the request-id multiplexing fields `#pending` / `#nextRequestId` /
`#settledRing` / `#settledSet`, because the text protocol is not multiplexed);
`PROMPT_RE` as `/\(C:\$[0-9A-Fa-f]{4}\)\s*$/`; `TEXT_COMMAND_ALLOWLIST` as a
frozen array of the exact verb strings this project may send, namely
`device c:`, `warp on`, `warp off`, `memmapshow`, `prof flat`, `chis`, `bt`, `io`

per D-02); `isAllowlistedTextCommand()`; `TextFramingError`;
`TEXT_MAX_BUFFERED_LEN`; `TEXT_QUIESCENCE_MS`.
`connect(host, port)` connects and returns immediately — it must never read or
wait for a connect banner (stock's text monitor sends zero bytes on connect;
waiting would hang for the full timeout on every connection). `command(cmd)`
refuses any argument that is not in the allowlist, and refuses any argument
containing a carriage return, a line feed, or any C0 control character, by name,
before a byte is written. It then writes the command plus a single `\n`,
accumulates every inbound chunk with `Buffer.concat([this.#buffer, chunk])`,
never decodes per chunk, and resolves once `PROMPT_RE` matches the tail of the
accumulated buffer — decoding with `.toString("utf8")` exactly once, on the
assembled buffer, after the match. `disconnect()` tears down the socket and
removes the bound listeners; a second `connect()` over a live socket is routed
through `disconnect()` first rather than silently leaking the previous socket and
its listeners. For this task the happy path is real and complete; the
quiescence window, the banner drain and the accumulation cap are Task 2's.
