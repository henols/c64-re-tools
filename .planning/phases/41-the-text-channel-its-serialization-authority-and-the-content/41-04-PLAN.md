<objective>
Make a contended instance report as contended, and fix the playbook that would
otherwise destroy it — both in this same phase.

Purpose: the regression is specific and this milestone would otherwise introduce
it into shipped software. `vice-wedge-triage`'s verdict vocabulary has no entry
for two-channel contention, and a text-channel hold the binary side cannot see
reads as exactly the `wedged` signature — two cycle brackets reading zero —
whose recommended remedy is a destructive recycle of a healthy instance.
`CHAN-05` may not slip past the text-channel code: between the two, a shipped
playbook actively recommends destroying a healthy machine.

structural guard making `wedged` unreachable while contended, the manifest's
`required` array extended, and `vice-wedge-triage`'s verdict table, evidence
section and provenance table updated with a live-reproduced signature graded
MEDIUM on a stated single-binary basis.

`stock-diagnose.ts`:

Export `StockChannelContention` as
`{ held: boolean; channel: "binary" | "text" | null; operation: string | null; grantId: string | null; heldMs: number | null }`
and a `channelContentionFor(nowMs: number, self: ChannelLockHandle | null)`
helper that turns `currentChannelLockHolder()` into it. Rules, each of which is a
requirement:

- Always present. When nothing holds the lock, or when the only holder is this
  diagnose call's own handle, the value is
  `{ held: false, channel: null, operation: null, grantId: null, heldMs: null }`
  — never an omitted field, and `heldMs` is `null` rather than `0`, so "not held"
  and "held for under a millisecond" are distinguishable.
- `grantId` is the holder's own grant id, or the literal string `unknown` when
  the holder carries none — never fabricated as a plausible id, matching
  `claimMonitor()`'s established posture.
- `heldMs` is `Math.max(0, Math.trunc(nowMs - holder.heldSince))`, so it is a
  whole-millisecond integer and can never be negative if a clock reading goes
  backwards.

Derive it in `diagnoseVerdictResult()` exactly where `jamObserved` is derived —
computed once per call, spread unconditionally into `evidence` as
`{ ...evidence, jamObserved, channelContention }`. Add a report note in the
`JAM_OBSERVED_NOTE` register, appended when `channelContention.held` is true,
which states that the other channel holds halt authority, names the channel, the
operation and the hold duration, says the instance is healthy and responsive, and
says explicitly that this is never a reason to recycle. The note must not contain
the words wedge, wedged, hang, hung, frozen, stuck or unresponsive.

Then the guard, in `handleDiagnoseStock()`, placed immediately before step 4's
first `runStockLivenessBracket()` call — that is, before the only step that
resumes the machine, and therefore before any path that can reach the `wedged`
return:

- Call `tryAcquireChannelLock({ channel: "binary", operation: "vice_diagnose" })`.
  This is the synchronous, non-blocking entry point, chosen deliberately: a
  diagnostic that queued on `acquireChannelLock()` would block behind the exact
  holder it exists to report, and one that peeked at the holder record without
  taking the lock could still have a foreign hold begin during its own bracket.
  Record that reasoning in a comment at the call site.
- On `null` — a foreign hold is live — return
  `diagnoseVerdictResult(session, "live", { bracketsRun: 0, channelContentionHolder: … }, renderStockContendedReport(holder))`
  with no bracket run at all. `bracketsRun: 0` is the honest count: the machine
  was never resumed, so liveness was not measured; the contention evidence is
  what explains that. This is D-11's verdict choice — `live`, because the
  instance is healthy and responsive rather than wedged — and it is exactly
  parallel to how `jamObserved` already qualifies `live`, since `machinePaused`
  is never false for a verdict that was reached and `live` has therefore never
  meant "advancing".
- On a handle, hold it across both brackets and release it in a `finally` that
  covers every return from step 4 onward, so a thrown bracket still releases.
- With the handle held, the two-bracket path is unchanged and a genuine
  double-zero still returns `wedged`. `wedged` is now unreachable while
  contended by construction: the only route to it is through a bracket, and a
  bracket only runs when the lock was taken.

Add a `renderStockContendedReport(holder)` renderer beside the existing report
builders, in their register.

Also add a short comment, at the `channelContention` derivation, recording the
deliberate asymmetry with `jamObserved`: `jamObserved` guards in the skill's
prose and lets `wedged` still return, while contention guards in code and makes
it unreachable. The reason is the cost of being wrong — a destructive recycle of
a healthy instance — and a later reader must not "fix" the inconsistency by
demoting this guard to prose.
