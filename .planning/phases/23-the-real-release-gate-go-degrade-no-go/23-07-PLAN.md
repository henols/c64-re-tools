<objective>
Measure dxa on real cracked code and print the number beside the fixture's own, under one
definition, with the window and the adjudicated fraction stated as first-class facts.

Purpose: PROOF-01 exists because every number behind the dxa+Ghidra pivot came from one
279-byte fixture written by the same person testing it. D-11 requires the fixture's claim
printed beside the new one rather than replaced by it, and the ROADMAP requires the error
*direction* re-measured too — 0 false positives against 28% false negatives is what decides
whether Phase 26's graphics-feedback containment is a safety net or load-bearing.

This plan is a vertical slice of criterion 1: derive dxa's inputs from the inventory, run
it both ways, parse the listing byte-exactly, cross against the certain sets, print the
side-by-side, and emit the outcome lines.

Output: `C1_DATA_RECOVERY_PCT`, `C1_FALSE_POSITIVES`, `C1_ADJUDICATED_FRACTION` — rules R2
through R5's inputs — plus everything a reader needs to recompute them.
</objective>

  <action>
Run the pinned dxa against the canonical release's flat 64K capture and turn its listing
into a byte-exact classification.

**The primary run.** Use the flag set fixed in 23-01, verbatim, with the two input files
from Task 1: `-g 0000` (without it dxa reads the capture's first two bytes as a
little-endian load address and re-bases the whole image, discarding roughly 50K),
`-p all-nmos6502`, `-d skip-scanning`, `-t detect-internal`, `-R` the entry-point file,
`-B` the data-block file, `-a dump`. Redirect stdout to a listing file and **stderr to its
own file, kept** — the load-address warning lives there and is the cheapest possible guard
against a mis-based run. Record the exact command line on `C1_DXA_FLAGS:` and paste the
stderr contents into the evidence file even when empty. Assert the listing's first
address-bearing line is at `$0000`, not at some re-based address; a listing far shorter
than 65536 bytes' worth is the warning sign.

**The second run.** Identical except `-t detect-all`. On a flat 64K image every 16-bit
value is inside the program, so address-table detection widens to everywhere and the two
modes may collapse; whether they diverge on real code with real tables is unknown, which
is why both are run and both printed rather than one being chosen. Record
`C1_DETECT_INTERNAL_DATA_BYTES:` and `C1_DETECT_ALL_DATA_BYTES:`. `detect-internal` is the
declared primary and is what the rule inputs are computed from.

**Parse byte-exactly.** Run `evidence/dxa-listing-parse.mjs` over the primary listing with
the image size given explicitly as 65536. It classifies by whether a line's text begins
`.byt` or `.word`, adds one address per emitted byte, and throws when the accounted total
does not equal the image size. Record its output and `C1_PARSE_ACCOUNTED_BYTES:`. If it
throws, that is criterion 1's honest outcome for this run: record the refusal in full,
write the outcome lines it blocks as `could-not-run`, and do not hand-patch the listing to
make it parse.

**Cross against the certain sets.** Restrict to the window `W`. Subtract the cracker-patch
ranges from both the certain-code set `C` and the certain-data set `D` when
`PROV_HOLDOUT: available`; when it is `unavailable`, use the sets unchanged and write
`C1_CRACKER_HELD_OUT: no`. Then compute, as exact integer ratios over byte counts:
data-recovery rate as bytes in `D` typed data over the size of `D`; false positives as the
count of bytes in `C` typed data; false negatives as the count of bytes in `D` typed code;
adjudicated fraction as the certain-set total over the window byte count. Bytes in the
intersection of `C` and `D` enter neither ratio and are counted on
`C1_CODE_DATA_OVERLAP:` — that is a finding, not an error, because self-modifying code and
jump tables legitimately produce such bytes. Display every percentage rounded half-up to
two decimal places with its raw numerator and denominator printed beside it, and evaluate
nothing on the rounded value.

Emit at column 0: `C1_WINDOW`, `C1_WINDOW_BYTES`, `C1_DXA_FLAGS`, `C1_DENOMINATOR_BYTES`,
`C1_DATA_RECOVERY_PCT`, `C1_FALSE_POSITIVES`, `C1_FALSE_NEGATIVES`,
`C1_ADJUDICATED_FRACTION`, `C1_CRACKER_HELD_OUT`, `C1_CODE_DATA_OVERLAP`,
`C1_PARSE_ACCOUNTED_BYTES`, `C1_DETECT_INTERNAL_DATA_BYTES`, `C1_DETECT_ALL_DATA_BYTES`.
Then recompute the same four quantities **without** the cracker hold-out and emit
`C1_DATA_RECOVERY_PCT_WITH_CRACKER:` and `C1_FALSE_POSITIVES_WITH_CRACKER:` beside them,
with a sentence stating what the difference between the two says about how far a naive
measurement would have been distorted. Those two lines never gate; the file says so.

Record the canonical release id and its capture sha256 at the top of the file, so the
numbers are attributable without cross-referencing.

| dxa's listing → the parser | Third-party tool output is parsed as text and turned into a gating number |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-23-16 | Tampering | A mis-based dxa run silently discarding most of the image | high | mitigate | `-g 0000` is mandatory and recorded on `C1_DXA_FLAGS`; stderr is captured and pasted because the load-address warning lives there; an acceptance criterion requires the listing to start at `$0000` and the parser to account for all 65536 bytes |
| T-23-17 | Tampering | An unseen listing line shape silently under-counting | high | mitigate | The parser's byte-total assertion converts an unseen shape into a refusal; a refusal is recorded as `could-not-run` and the listing is never hand-patched to make it parse |
