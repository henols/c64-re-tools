<objective>
Establish the point at which a single forward-carried `$01` value stops being correct — by
observing a real access site executing under two distinct bank values that resolve to
different memory-map entries — or record the absence of such an address as a fact about
this corpus rather than about the model.

Purpose: the ROADMAP names this "the highest-risk item on the pivot's own record". Phase
26's `AUTO-04` carries bank state per program point and `AUTO-05` declines where that state
is path-dependent; both ship unvalidated against real code unless this is established here.
D-06 chose runtime observation over static inference on the merits as well as for
non-circularity: "the point at which a single forward-carried `$01` value stops being
correct" is a question about execution paths, and a watchpoint answers it directly where
static inference only guesses.

This plan is a vertical slice of criterion 3: find the candidate access sites → checkpoint
each and read the live bank value → resolve each address under each observed value →
compare the resolutions → emit the outcome.

Output: `C3_BANK_DIVERGENCE` — rule R7's only input — with its address, its two values and
its two resolutions, or its pre-declared absence.
</objective>

instruction alignment by disassembling at that address. Paste both transcripts. Every
candidate is an address where the meaning of the operand depends on the bank state, which

stated number rather than an impression.

read `$0001` and the registers. Poll on the checkpoint's hit count, never on paused state.

bank value, hit count at that value. Sites observed under exactly one bank value are kept
in the table and labelled as single-value — they are the honest majority case and they are
what makes a `not-exercised` outcome earned rather than assumed.

only its enumeration as proof that none remain. Resume the machine exactly once. If the
emulator stops responding, work the wedge-triage decision tree before concluding anything

Write the join, resolve every site under every value it was observed under, and record where

**The join script.** `evidence/bank-join.mjs` is throwaway evidence. Its header comment
declares that, cites `.planning/notes/auto-annotation-from-ghidra-xrefs.md` as the source of
the two selection rules it implements, and states that it deliberately does not import from
any `src/` module because this phase adds nothing to the product. It takes an address, a
`$01` value and the loaded-image range list, and returns the resolved entry. Its rules, in
order: an address inside the loaded image returns a program-address marker and is **never**
looked up in the map at all; otherwise decode the `$01` low three bits into the bank state,
select every map entry whose range contains the address and whose bank applicability
matches, and take the **narrowest** such range; break an exact-width tie toward the entry
carrying a symbol. Selecting the first match or the longest description yields the useless
wide entry and fails silently, which is precisely the failure this criterion exists to
detect. Record the memmap file's sha256 with the project's own hashing seam and emit
`C3_MEMMAP_SHA256:` so a later reader resolves against the same table.

Give the script a small self-check it runs and prints before doing any real work: a handful
of addresses whose narrowest entry is unambiguous, asserted against their expected entries,
so a broken selection rule fails loudly rather than producing plausible wrong labels
throughout. Paste that output into the evidence file.

**Resolve and compare.** For each site in the table, resolve its operand address under each
distinct bank value it was observed executing under. Record the resolved entry for each. The
model **breaks at address A** when a program address that accesses A is observed executing
under two distinct `$01` values whose narrowest resolved entries differ. Two distinct bank
values that resolve to the *same* entry are **not** a divergence: record that row explicitly
as same-resolution, because it is the case a careless test would count and it is the reason
the divergence test is on the resolved entry rather than on the bank value.

ascending by accessed address. Emit `C3_DIVERGENT_SITES:` as the count — a measurement,

measurement, and the file says so with that reason.
