<plan_decisions>
**The cold-profiler string lives in `textmon-profile.ts`, not in the handler.** PARSE-03's
structural guard asserts that nothing outside a format's owning module reads that format's raw
text, and `textmon-seam.test.ts` enforces it with a measured-equals-declared consumer census.
Recognising VICE's own sentence inside the handler would be exactly the seam violation this
phase spent a whole plan proving does not happen. So the owning module gains the literal and a
named refusal code, and the handler branches on the code — which is the module's exported
contract, not its text.

**A new refusal code, not a reuse of `missing-header`.** `missing-header` means "the two-line
header VICE always prints was absent or different" — a drift claim about the format. The cold
state is not drift: the format is fine, the subsystem has nothing to report yet. Reporting it
as a header problem is how the misleading message arose in the first place.

**`textCapabilityRefusalMessage()`'s contract is deliberately NOT widened, and 42-REVIEW.md's
suggested fix is diverged from on this point.** WR-01 proposes rendering the disagreement from
that function regardless of outcome. That function is what `handleIoRegisters` treats as
"is there something that blocks this call" — a non-empty return makes it refuse. Rendering an
advisory there would silently convert an identity disagreement into a hard refusal of an
otherwise-working call, which is a heavier behaviour change than the gap warrants and is not
what WR-01 asks for. Instead the module gains a second, separately-named exported renderer, and
the handlers compose the two. WR-01's stated test — a `capable` verdict carrying a disagreement
must produce a non-empty user-facing message — is satisfied, and is written.

**The renderer takes the two identities, not a verdict, and that is strictly better than the
review's shape.** Four of the five handlers never construct a verdict on the happy path: they
classify, and only probe when the classification is not `capable`. A verdict-shaped renderer
would therefore still surface nothing on the success path for four of five tools — the gap
would look closed and would not be. Both identities are already in hand in every handler from
its own `capabilityIdentityFor(deps)` call, before the dial, so a renderer over those two values
covers every path at zero extra cost and with no extra dial. The existing internal
`identityDisagreementText()` is reimplemented in terms of the new exported function so there is
exactly one wording, in one place.

**IN-02: the documentation half is taken, the behavioural half is deliberately not.** Task 1
already edits `textmon-profile.ts`'s type-and-doc region, so correcting
`FlatProfile.decimalSeparator`'s doc comment to say it records the FIRST data row's separator is
free and removes the misreading. Adding a per-row validation that refuses on a mismatch is NOT
taken: it changes refusal behaviour for a payload neither committed capture exhibits and which
VICE is not known to emit, and it was scored Info, not a gap. Recorded here as a deliberate
partial disposition rather than left unmentioned.

**Window #55 stays open.** This plan changes how the cold state is described. It does not teach
any handler to issue `prof on`, and no wording added here may imply that `vice_profile_flat`
can now produce real rows against a freshly launched instance. That capability gap is separate,
recorded, and out of this round's scope.

**Canon-referral drop (prohibition probe, stage 2):** OWASP/injection-class constraints on the
command path are owned by `TEXT_COMMAND_ALLOWLIST` and `buildTextCommand()`. Not minted here.
</plan_decisions>
