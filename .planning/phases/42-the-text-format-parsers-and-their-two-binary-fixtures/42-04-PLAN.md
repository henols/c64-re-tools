<objective>
Give `chis`, `prof flat` and `io` a parameter, without giving the text channel a free-text
command field. `TEXT_COMMAND_ALLOWLIST` is a frozen set of eight exact literals today, and
the committed fixtures were captured with parameterized forms that are not members of it —
so three of the five tools cannot dial anything but VICE's defaults until this lands.

D-42-1 fixes where the validation lives: here, in the transport, not in the five parser
modules. A parser's whole contract is text in, typed values out, so it cannot be the thing
that decides what may be sent; and five modules each able to mint a dialable command string
would invert the single-seam discipline this phase exists to establish.

Purpose: one place, still, decides what may cross to an unauthenticated monitor.
Output: a per-verb spec table, a builder, a widened dialability check, and the controls that
prove a byte never leaves early.
</objective>

<plan_decisions>
**D-42-1 (locked, orchestrator): parameter validation lives in `text-protocol.ts`.** This
plan implements it, in the shape below. The shape itself is this plan's own decision and is
constrained by two things already on disk: the file's header states as a hard rule that no
caller-supplied, free-text command string may appear anywhere in its public surface, and an
existing test asserts `TEXT_COMMAND_ALLOWLIST` is exactly the eight named verbs. So:

- The eight-literal array is **not** widened. It stays exactly as it is, and its existing
  assertion keeps passing on its own terms rather than being edited to accommodate this work.
- A sibling frozen table, `TEXT_COMMAND_PARAM_SPECS`, maps each parameterized verb to a
  typed, bounded parameter kind and to the renderer that turns a validated value into the
  canonical command string.
- `buildTextCommand(verb, value)` is the ONE place a parameterized command string is ever
  constructed. It returns a discriminated result, matching D-42-3's return-rather-than-throw
  discipline for the same reason: a refusal is a value the caller renders to the user, not an
  exception whose meaning a catch block has to guess.
- `isAllowlistedTextCommand(cmd)` stays the ONE dialability predicate `command()` consults —
  widened to accept, in addition to an exact literal member, a string that is byte-identical
  to what the spec table's own renderer produces for that verb. Re-rendering rather than
  pattern-matching is what makes the accepted set exactly the canonical forms: a string with
  extra spacing, different case, or a second parameter cannot pass, because it is not what
  the renderer would have written.

Reversibility: `costly`, not one-way. It changes a security seam two earlier phases built
and tested, but no shipped data or external contract depends on the new shape, and reverting
is deleting one table, one function and one branch.
</plan_decisions>

    spec's inclusive bounds. Refuse a string that merely looks numeric: the parameter's type

    field. Return the discriminated result — on success the rendered command, on refusal a
