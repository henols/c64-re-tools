<objective>
PARSE-03's third clause is the one that cannot be satisfied by any amount of parser quality:
each format has exactly one owning module and nothing outside it reads the raw text,
"asserted structurally rather than left to convention". This plan writes that assertion.

The tree already has the machinery: a family floor with a pinned-equals-measured companion,
a declared map asserted against disk, a named-absence-before-existence pattern, and a
planted-violation control run through the real predicate. This is a fifth family adopting
those four mechanisms, in its own file, next to the store's own seam guard.

Purpose: make the single-seam claim mechanical.
Output: `textmon-seam.test.ts`.
</objective>

<plan_decisions>
**Why a new file rather than an extension of the host-path consumer guard.** That file owns
a different subject — which modules may import the host-path seam, and which module
implements each derived tool — and this tree already has a precedent for a second seam guard
living in its own file next to the seam it polices. A separate file also keeps this phase's
guard out of the way of plan 42-07, which edits the host-path consumer file in the same wave
to register four tools; two plans editing one file in one wave is a collision this split
avoids by construction.

**Why the census keys on structural literals rather than command verbs.** Two of the five
verbs are two-letter strings that occur as substrings of ordinary English and ordinary
identifiers, so a verb census would be noise. Each format instead gets one distinctive
literal drawn from its own OUTPUT — the access map's header text, the CPU history's
flag-order string, the backtrace's stack-pointer field opener, the profile's narrow
no-break-space escape, and the register dump's row marker. Four of the five are absent from
the entire tree today, and the fifth appears in exactly one existing place with a legitimate
reason, so each census starts from a known state and the constraint is asserted rather than
discovered.

**Why the census must read bytes.** One shipped module in this tree contains a NUL byte,
which makes an ordinary text scan treat it as binary and skip it. A census that silently
skipped a module would be a guard incapable of failing, so the reader is byte-oriented and
one case asserts that specific module is present in the scanned set by name.
</plan_decisions>
