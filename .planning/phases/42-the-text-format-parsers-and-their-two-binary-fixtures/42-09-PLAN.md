<plan_decisions>
**Stock-only, by construction, and stated as a bound rather than an omission.** The broker
appends the text-channel launch flags on its stock branch only — a fork instance it leases
has no text channel at all — so a live run through the broker can exercise exactly one of the
two binaries. That does not weaken PARSE-03's two-binary requirement: the requirement is
about FIXTURES, and both binaries' fixtures are committed, captured by launching each binary
directly rather than through the broker. This plan records that division explicitly so a
later reader does not mistake a stock-only live run for a stock-only defence.

**A live shortfall is recorded, not smoothed.** The committed access-map captures contain no
RAM-execute entry because the machine was idle in a ROM loop. A live run may or may not
produce one, depending on what the emulator happens to execute in its window. Both outcomes
are planned for: an entry found is recorded as the first hardware evidence for criterion 1's
RAM half, alongside the declared-synthetic case that already covers it; no entry found is
recorded as a shortfall naming what was searched and over how many addresses. Neither outcome
changes the phase's completion, and neither is allowed to be silent.

**No new evidence document.** This phase already has one record, written in plan 42-06. The
live section is appended to it, matching the previous phase's single-record convention.
</plan_decisions>
