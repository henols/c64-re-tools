<objective>
Close G5. 42-09-PLAN.md carries the prohibition "a live run must not leave a broker daemon or
an emulator process alive — teardown is verified afterwards", marked `status: resolved`. It was
measured NOT met: a `resources/vice-broker.mjs` process was found alive twenty-five minutes
after the run, with a leaked scratch directory, and the orchestrator killed it by hand.

Neither of the two things that claimed to have verified teardown could ever have caught it. The
SUMMARY's manual check probed a `systemctl --user` unit the test never starts — it spawns the
broker directly with `spawn(process.execPath, [BROKER_ARTIFACT, ...])` — and grepped only for
`x64sc`, never for the broker. The test's own `pidsAliveAfterTeardown` assertion tracks only
pids passed to `recordPid()`, which is called exactly once per case, with the emulator's pid.
The broker child it spawns itself is never in that set.

Purpose: make the assertion observe the process it is responsible for, and prove the assertion
can fail.
Output: a harness whose teardown claim is earned, and a control that goes red when it is not.
</objective>

<plan_decisions>
**The sweep is scoped to the harness's own scratch path, and that is the whole trick.** A
tree-wide `pgrep` for `vice-broker` would report a developer's unrelated broker as this
harness's leak, which is both wrong and the kind of false positive that gets a guard disabled.
The harness already creates a unique `mkdtempSync` directory and passes it as `--repo-root`, so
that string appears in the command line of every process the harness is responsible for and in
no other. Matching on it gives a check with no false positives and one that catches a
grandchild the harness never recorded a pid for — the exact shape of the leak that was found.

**The broker pid joins the existing report field rather than getting its own assertion.** Seven
live cases already assert `report.pidsAliveAfterTeardown` deep-equals the empty array. Pushing
a surviving broker pid onto that same array makes all seven cover the broker at once, with no
seven-way edit and no chance of a new case being written that forgets the new assertion. The
stray-sweep result and the scratch-dir-removal flag are separate fields precisely because they
answer different questions and should fail with different messages.

**The planted control must not need an emulator, and must not be skipped.** This file is in
`test-gate.mjs`'s manual-only list, so it never runs in the automated gate either way — but a
control gated behind `VICE_LIVE_STOCK_BIN` would only ever run on the same rare occasions as
the thing it protects, and the developer would have no cheap way to ask "is the teardown guard
still real?". An unskipped control makes `node --test text-monitor-live.test.ts`, with no
environment variable at all, a five-second answer to that question.

**The control reaps its own planted process, and asserts the reap.** A control that proves a
leak detector works by leaking is self-refuting. The dummy is spawned, observed, killed, and
observed gone, all inside one try-and-finally, and `/tmp` on this host is a RAM-backed
filesystem with aging disabled — a leak there is a leak until reboot.

**IN-02 is not addressed here.** It lives in `textmon-profile.ts`; plan 42-13 takes its
documentation half and records why it does not take the behavioural half. Named here so it is
not simply unmentioned.

**Canon-referral drop (prohibition probe, stage 2):** OWASP/injection-class constraints on the
spawned command line are owned by the project's existing broker-launch discipline. Not minted
here.
</plan_decisions>
