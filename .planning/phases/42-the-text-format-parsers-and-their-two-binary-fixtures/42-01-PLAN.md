<plan_decisions>
Three design decisions this plan is executing. Two were locked at the orchestrator seat;
the third is decided here, for all five parsers, and every later plan in this phase
inherits it rather than re-deciding it per module.

**D-42-1 (locked, orchestrator).** Parameter validation lives in `text-protocol.ts`, not in
the parser modules. This plan does not touch it: `memmapshow` takes no parameter and its
bare verb is already a `TEXT_COMMAND_ALLOWLIST` member. The tool's `startAddress`,
`endAddress` and `maxRanges` arguments are **client-side projection filters applied after
parsing** — none of the three ever reaches the socket, and the command string this handler
dials is the frozen literal, never a built string.

**D-42-2 (locked, orchestrator).** The PARSE-04 capability cache is in-process. Not this
plan's concern; plan 42-05 owns it.

**D-42-3 (decided here, applies to all five parsers): a parser refuses by RETURNING a
discriminated refusal, never by throwing.** Each module exports
`parse<Format>(text): { ok: true; value: T } | { ok: false; refusal: TextParseRefusal }`
where `TextParseRefusal` is `{ code, message, line, lineNumber }` and `code` is that
module's own closed string union. Three reasons, in order of weight:

1. `withTextTool()` wraps the handler body in a `try/catch` that converts anything thrown
   into `convertWireError(toolName, err)`. A thrown parse refusal would therefore be
   reported to the user as a **transport** error — laundering a format-drift refusal into
   a wire message, which is precisely the "absorbed into a plausible-looking wrong answer"
   failure mode PARSE-03 exists to prevent.
2. `disasm-decoder.ts`'s documented never-throw discipline is this tree's established shape
   for a pure parser, and a returned refusal keeps it while adding the slot
   `DisasmNote` lacks: "I do not understand this input at all", as distinct from
   "I understood it and it looks unusual".
3. The refusal is data the handler must render to the user; a return type carries it,
   an exception makes it the catch block's guess.

Reversibility: `costly`, not one-way — reversing it is a mechanical edit across five
modules and five handlers, with no shipped-data migration and no external contract broken.
</plan_decisions>
