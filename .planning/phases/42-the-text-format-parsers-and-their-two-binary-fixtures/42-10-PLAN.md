<plan_decisions>
**A new refusal code, not a reuse of `unparseable-value` (recorded, because 42-REVIEW.md's
suggested fix left the choice open).** `unparseable-value` means "a recognised label was
present and its value could not be read" — a per-line fact that always has a real offending
line to name. The new condition is "a required field was never observed at all" — a per-block
fact with no offending line, whose whole content is the SET of names that did not arrive.
Collapsing the two would make the closed refusal set lie about which drift shape occurred, and
the discipline this phase's five parsers share is that a refusal names what was actually wrong.
So the union gains `incomplete-decoded-state`, and the two codes stay distinguishable by a
caller and by a test.

**The check is unconditional, and a transient consequence is named rather than discovered.**
Until plan 42-11 lands the chip gate, a non-VIC-II chip section (a CIA or SID address, all
in-schema) will now refuse `incomplete-decoded-state` with all nineteen names instead of
`sprite-column-count`. Both messages are wrong for that input; 42-11 replaces both with a
refusal that names the chip. **Do not write a test in this plan that pins a non-VIC-II chip to
`incomplete-decoded-state`** — 42-11 changes that behaviour deliberately, and such a test would
have to be deleted one wave later. A gate that skipped the check when zero fields were
recognised would reintroduce the hole for the worst case (every line renamed), so it is not an
option.

**No handler change is needed for this gap, and that is proven rather than assumed.**
`handleIoRegisters`'s existing parse-refusal branch already renders any refusal code by name.
The tracer's end-to-end assertion is a handler-level test, not a handler edit.

**New imports into `text-tools.test.ts` are avoided on purpose.** `textmon-seam.test.ts`
asserts a closed, measured-equals-declared import-consumer set per format. The handler-level
case builds its drifted reply by string-mutating the fixture `loadTextFixture()` already
returns and asserts on the code as a plain string, so no consumer set changes. The only seam
file edit in this plan is the stale line-number citation in its own comments.

**Canon-referral drop (prohibition probe, stage 2):** injection / path-traversal / OWASP-class
constraints on the text-monitor command path are already owned by `TEXT_COMMAND_ALLOWLIST` and
`buildTextCommand()`'s bounded builder, plus the project's security canon. Not minted here.
</plan_decisions>
