**Tool ids and accepted argument keys** (`HOST_TOOL_ARG_KEYS`):

| id | accepted keys | path-bearing keys | non-path remainder |
|---|---|---|---|
| `c1541.bam` | `image`, `outDir` | `image`, `outDir` | — |
| `c1541.dir` | `image`, `outDir` | `image`, `outDir` | — |
| `c1541.entry` | `image`, `name`, `outDir` | `image`, `outDir` | `name` |
| `c1541.chain` | `image`, `name`, `outDir` | `image`, `outDir` | `name` |
| `c1541.read` | `image`, `name`, `outDir` | `image`, `outDir` | `name` |

`outDir` is optional on every id and defaults to `dirname(imagePath)`, exactly as
`dxa.disassemble`'s own default already does. `name` is required on `entry`,
`chain` and `read`, and is a CBM filename or glob pattern — never a path, never
resolved through `resolveWorkspacePath()`.

**argv** (built only in `buildHostToolArgv()`):
`c1541.bam` → `-attach <imagePath> -bam`;
`c1541.dir` → `-attach <imagePath> -dir`;
`c1541.entry` → `-attach <imagePath> -entry <name>`;
`c1541.chain` → `-attach <imagePath> -chain <name>`;
`c1541.read` → `-attach <imagePath> -read <name> <outputs[0]>`.

**`outputs[0]`** — `imageStem` is `basename(imagePath)` with its extension
stripped; `slug` is the `name` argument with every character outside
`[A-Za-z0-9]` replaced by `_`, truncated to 32 characters:
`bam` → `<outDir>/<imageStem>.bam.txt`;
`dir` → `<outDir>/<imageStem>.dir.txt`;
`entry` → `<outDir>/<imageStem>.<slug>.entry.txt`;
`chain` → `<outDir>/<imageStem>.<slug>.chain.txt`;
`read` → `<outDir>/<imageStem>.<slug>.bin`.

**Which ids capture stdout into `outputs[0]`:** `bam`, `dir`, `entry`, `chain`
(and, in 40-03, `petcat.decode`). `c1541.read` does NOT — the child writes that
file itself.

**Classifier contract:** `type HostToolOutputClassifier = (ctx: { stdout: string; stderr: string; results: readonly HostToolFileResult[] }) => { ok: true } | { ok: false; reason: string }`.
`HOST_TOOL_OUTPUT_CLASSIFIERS` is a **total** `Readonly<Record<HostToolId, HostToolOutputClassifier | null>>`
built with the `Object.freeze(Object.assign(Object.create(null), ...))` idiom the
other four tables use. Pre-existing ids map to `null`, meaning "no declared
shape, behaviour unchanged" — never absent, so no id falls through to an implicit
success.

**Declared success shapes** (`D-09`, MEASURED shapes in `40-RESEARCH.md`):
`c1541.dir` → a `<N> blocks free` trailer;
`c1541.chain` → at least one `(track,sector) -> (track,sector)` arrow pair;
`c1541.entry` → a `T/S: <t>/<s>, <n> blocks` line;
`c1541.bam` → at least one per-sector allocation row (a run of `*` and `.`
characters on a track-labelled line);
`c1541.read` → `results` contains exactly one entry whose `byteLength` is
greater than zero.

**Response shape is unchanged for these five ids:**
`{ ok, tool, exitStatus, results, stderrTail }` — no new field. (40-03 adds two
fields present ONLY on `petcat.decode` responses.)

**Skill:** directory `src/skills/c64-disk-access/`, script
`scripts/c1541.mjs`, subcommands `bam | dir | entry | chain | read`, flags
`--image <path>`, `--name <cbm-name>` (entry/chain/read), `--out-dir <path>`,
`--json`.
