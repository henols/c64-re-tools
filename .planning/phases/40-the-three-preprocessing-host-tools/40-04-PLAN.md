<objective>
Prove `PREP-04` per tool id with a control that cannot be satisfied vacuously,
and carry `d64-parse.mjs`'s load-bearing fakery detector across onto the seam's
inputs before the file that owns it is deleted in 40-06.

Purpose: `PREP-04` says a failure is reported as a failure. Two of the phase's
measured facts make that non-trivial — the disk utility exits zero on error, and
the converter's non-zero exit covers exactly one failure class. A test that
merely asserts "the oracle refused" proves nothing about whether the oracle is
doing work an exit check would not already do; the control that makes it real is
showing the exit check *passing* on the same input.

`PREP-01` rides along because the detector port is the part of the replaced
parser that must survive: signature 3 cross-references the directory's CLAIM
against the allocation map's ACCOUNTING, which is how a filename a cracker put in
a directory for a file never written is caught. On a cracked release that is a
load-bearing provenance signal, and the port makes it SHARPER — the per-sector
map lets the check test the exact first sector rather than only whether its whole
track is free.

Output: one dedicated oracle test file with six two-directional controls, three
committed planted-failure fixtures, the ported detector with its named-reason
output shape and a chain guard, and one live-gated assertion against a real
release image.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a disk image's own bytes → the detector | Directory entries and the allocation map are attacker-authored on a cracked release; the detector exists because they lie. |
| test-local predicate → production code | A deliberately-wrong oracle lives in the test tree and must not leak into production. |
