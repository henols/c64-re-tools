<objective>
Delete the hand-written disk-image parser and its MCP-side duplicate, and
re-point every consumer onto the single seam route — the largest irreversible
step in the phase, taken last so everything it depends on is already proven.

Purpose: `D-04` and `D-08` promote the seam to the ONE disk-image route. Keeping
either module alongside it leaves two sources of truth that can disagree about a
provenance signal, which is exactly the failure the promotion removes. The three
costs were measured and accepted during the phase discussion: the seam route
needs the broker on the container route where the pure-Node parser did not; the
fakery detector had to be ported (done in 40-04); and the duplicate's blast
radius reaches three live tests, a module registration with a pinned
symbol-and-line reference, a packaged file set, a packaged-import set, and four
prose citations — one of which a committed test asserts the presence of.

Output: four files deleted, every named consumer re-pointed, and one committed
invariant test that goes red if a second parser ever reappears.
</objective>

<merge_protocol>
**This plan's branch is merged BY HAND.** The automated wave cleanup refuses any
branch whose diff contains a deletion, unconditionally. That is stock behaviour,
not a local policy, and it is not a reason to disable worktree isolation for this
phase. Verify this plan's scope against its file list, confirm the deletions are
exactly the four named files and nothing else, then merge the branch directly.

Order within the plan matters and is not negotiable: the two re-point tasks land
BEFORE the deletion task. A deletion committed first leaves the suite red between
commits, and the module registration's pinned line reference in particular is a
guard that must be updated in the same commit as what it points at.
</merge_protocol>
