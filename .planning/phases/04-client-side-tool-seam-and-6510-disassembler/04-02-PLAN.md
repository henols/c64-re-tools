computed **client-side** is registered, guaranteed to run before
`forwardToVice()`'s `rewriteArguments()` and structurally incapable of reaching
`hostpath.ts`.

seam with no user and a seam retrofitted under three consumers at once.

Output: `stock-derived.ts` (the leaf that owns the container-path discipline),
`withDerivedTool()` in `stock-dispatch.ts` beside `withStockSession()`, and D-02's
**two independent enforcement mechanisms**.

This plan has no dependency on the disassembler and runs in wave 1 in parallel
with 04-01.

<plan_decision_module_split>
**Decision (exercising 04-CONTEXT.md's "Claude's Discretion: module naming and
file split for the derived layer"): the derived layer is TWO files, because a
single-file `withDerivedTool()` would create a runtime import cycle.**

`withDerivedTool()` must delegate to `ensureStockSession()` and must never
re-implement any part of session acquisition (D-04; 04-RESEARCH.md Pitfall 3;
`ensureStockSession()`'s own header comment: it must be the only thing that ever
reaches `openBrokerControl()`/`session.acquire()`/`adoptGrant()`).
`ensureStockSession()` lives in `stock-dispatch.ts`. `stock-dispatch.ts` must
import the derived tool's handler in order to register it in
`STOCK_DISPATCH_TABLE` (D-03: the SAME table, never a second one). Any placement
of `withDerivedTool()` in a module that `stock-dispatch.ts` imports therefore
closes a runtime cycle `stock-dispatch.ts -> ... -> stock-dispatch.ts`, which this
codebase forbids ("module-cycle avoidance is deliberate and documented" —
CLAUDE.md; `stock-handler.ts`'s header: "Never import stock-dispatch.ts at
RUNTIME from this file — only a type-only import").

Split:
- **`stock-derived.ts` — the leaf.** Owns the one thing `stock-dispatch.ts` does
  not: the **container-path discipline** (D-01). Holds `STOCK_DERIVED_TOOLS` (the
  data-only registry, D-03), `derivedContainerPath()`, `DerivedToolError` and the
  `DerivedPureHandler` type. Imports **only** `stock-handler.ts` (result types)
  and `vice.ts` (`ViceError`). **Never imports `hostpath.ts`, never imports
  `stock-dispatch.ts`, never imports `vice-proxy.ts`.** This is the module D-02's
  asserted-absence test names.
- **`withDerivedTool()` in `stock-dispatch.ts`**, immediately beside
  `withStockSession()` — literally D-01's own words, "sitting alongside
  `withStockSession()`". `stock-dispatch.ts` is a sibling module of
  `vice-proxy.ts`, so D-01's load-bearing clause ("never appended to
  `vice-proxy.ts`", ROADMAP Standing Constraints) is satisfied. It imports
  `STOCK_DERIVED_TOOLS` from the leaf — one direction only, no cycle.

**Rejected: extracting `ensureStockSession()` into a new `stock-session.ts` leaf**
so `withDerivedTool()` could live in `stock-derived.ts`. It would be more literal
to D-01's "adapter in a sibling module", but it moves ~200 lines of the single
load-bearing acquisition seam — the only acquisition path all 25 shipped Phase 3
tools have — for a file-placement preference, against a standing per-phase
regression gate that says the existing suite must pass unchanged.
</plan_decision_module_split>

```
export function withDerivedTool(toolName: string, opts: { needsSession: true }, handler: StockSessionHandler): StockHandler;
export function withDerivedTool(toolName: string, opts: { needsSession: false }, handler: DerivedPureHandler): StockHandler;
```

Implementation rules — no deviation:
  - **First**, refuse if `!STOCK_DERIVED_TOOLS.has(toolName)`: return a handler
    that answers `isErrorText(...)` naming `toolName` and `STOCK_DERIVED_TOOLS`.
    Do this at call time inside the returned handler (never `throw` at module
    scope — the table literal is evaluated at import time and a throw there would
    kill the whole stdio server before it starts).
  - `needsSession: true` — the returned handler runs the EXACT same three-step
    preamble `withStockSession()` runs: `ensureStockSession(deps)` inside its own
    try/catch → `convertHandshakeError(toolName, err)`; `{ ok: false }` →
    `isErrorText(outcome.message)` verbatim, never re-worded; otherwise
    `handler(args, outcome.session, deps)` inside a SECOND try/catch →
    `convertWireError(toolName, err)`. Reuse the imported functions; **do not
    write a third error converter** (`stock-handler.ts`'s standing rule).
  - `needsSession: false` — the returned handler **never calls
    `ensureStockSession()` at all** (not a lighter-weight variant of it —
    04-RESEARCH.md Pitfall 3), and invokes `handler(args, deps)` inside a single
    try/catch → `convertWireError(toolName, err)` so the never-throw boundary
    still holds.
