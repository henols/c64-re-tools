**Assembling helper — the command-injection control (T-04-06-01):**
`function assemble(source: string): { ok: boolean; bytes: Buffer; stderr: string }`
writes `source` to a file inside a `mkdtempSync(join(tmpdir(), "disasm-roundtrip-"))`
directory and runs
`spawnSync(ACME_BIN, ["-f", "plain", "-o", outPath, srcPath], { encoding: "utf8" })`.
**An argv array, never a shell string, and the rendered listing is never
interpolated into a command** — it only ever reaches the assembler as file
contents. `-f plain` emits raw bytes with no load-address header, which is what
makes the byte comparison direct. Remove the temp directory in an `after()`.

**Suite A — the full-256 round-trip through the tool's own output (D-13).**
1. Build a corpus: for every opcode `0x00..0xff` in ascending order, append the
   opcode byte followed by `OPCODES[op].length - 1` deterministic filler bytes.
   Choose filler that exercises the interesting cases — include at least one
   absolute operand below `$0100` and at least one `$6C` with a low byte of `$ff`
   (adjust the specific fillers for `$6C`, `$AD` and the branches rather than
   using a single constant).
2. Place it at `$1000`. Drive `dispatchStock("vice_disassemble", { address: "$1000", end: "$XXXX" }, deps)`
   against a stubbed session whose `MemoryGet` reply serves the corpus, exactly as
   `stock-dispatch.test.ts`'s conformance harness does. Because the answer is
   capped at 100 instructions (D-13), **loop**: follow `nextAddress` while
   `limitReached` is true, collecting each answer's `listing`. This exercises the
   bound as well as the round-trip.
3. Concatenate the listings (each carries its own `!cpu 6510` and `* = $XXXX`;
   repeated directives are legal ACME and each origin keeps the following block at
   the right address).
4. `assemble()` the concatenation. Assert `ok === true`, printing ACME's stderr in
   the failure message so a rejection is diagnosable without re-running.
5. Assert the produced bytes **equal the corpus exactly**
   (`assert.deepEqual(Buffer.from(produced), Buffer.from(corpus))`). Zero
   exclusions, byte-exact by construction (D-09).
6. Assert the corpus really covered all 256 opcode values (a set of the leading
   bytes has size 256) — so the round-trip can never quietly under-cover.

**Suite B — a realistic fragment.** Round-trip a hand-built byte sequence
containing: a forward and a backward branch, a branch that crosses a page
boundary, `lda $0080` (the D-11 shrink hazard), `jmp ($10ff)` (the page-wrap
note), `jsr $ffd2`, and at least three illegal-but-ACME-expressible opcodes
(`lax`, `dcp`, `anc`). Byte-exact.

**Suite C — substitution membership, BOTH directions (D-09, criterion 4).**
Drive this from `OPCODES`, never from a hardcoded list:
- For every entry with `acmeExpressible === false`: build a one-instruction source
  `!cpu 6510` + `* = $1000` + the mnemonic rendered in that addressing mode, and
  assert `assemble()` returns `ok === false` — i.e. **ACME genuinely rejects it**.
  A candidate ACME actually accepts is a **false** entry that must be flipped to
  `true` in `disasm-opcodes.ts` (D-09: "the exact set is determined by the
  assertion test against the installed ACME, not by this list"). Report the
  offending opcode and mnemonic in the assertion message so the fix is mechanical.
- For every entry with `acmeExpressible === true` and `illegal === true`: assert
  `assemble()` returns `ok === true` **and** the produced bytes' first byte equals
  the opcode value — this is the **over-substitution guard**. A `true` entry that
  ACME rejects, or that assembles to a different opcode, must be flipped to
  `false`. Without this direction the table could silently mark everything
  unassemblable and the round-trip would still pass while producing `!byte` soup.
- Emit the resulting membership set (the list of opcodes rendered as `!byte`) via
  `console.log` in a stable, greppable form, so 04-07 can copy it into
  `docs/stock-vice-parity.md`.

**Suite D — the D-11 size-force spelling.** Assert directly that
`lda+2 $0080` assembles to 3 bytes starting `ad`, and that `lda $0080` without the
force assembles to 2 bytes — proving both that the force is necessary and that the
spelling the renderer emits is the one ACME understands.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| rendered listing -> `acme` subprocess | Disassembler output crosses into an external process. It travels as **file contents**, never as command-line text |
| CI runner -> Debian/Ubuntu archive | `apt-get install acme` pulls a binary from the distribution archive into the job |
| test -> temp filesystem | Sources and objects are written under `mkdtempSync(tmpdir())` and removed afterwards |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06-01 | Tampering | command injection via the ACME subprocess | mitigate | `spawnSync(ACME_BIN, ["-f","plain","-o",outPath,srcPath], { encoding: "utf8" })` — argv array, never a shell string, and disassembler output is **never** interpolated into a command; it reaches ACME only as file contents. `acme-build/scripts/acme.mjs` is the in-repo precedent. Asserted by grep in task 2. |
| T-04-06-02 | Tampering | a gate that passes while proving nothing | mitigate | Three independent non-vacuity controls: suite A asserts the corpus covers exactly 256 distinct opcodes; suite C asserts **both** directions of the substitution table (an over-substituted table fails); suite D proves the size-force is actually necessary by showing the unforced form assembles to fewer bytes. |
| T-04-06-03 | Denial of Service | a silently skipped CI gate | mitigate | Two layers: the install step ends in `grep -qi acme` under `set -euo pipefail`, so a wrong package name fails the job; and `VICE_REQUIRE_ACME=1` turns the test's skip into a hard failure. Criterion 4's "rather than skipped" is enforced, not hoped for. |
| T-04-06-04 | Tampering | temp-file path escape | mitigate | All paths come from `mkdtempSync(join(tmpdir(), "disasm-roundtrip-"))`; no test input contributes to a path. |
| T-04-06-05 | Tampering | supply chain -- the `acme` apt package | mitigate | Installed from the distribution's own archive over HTTPS by `apt-get`, then verified to be the ACME cross-assembler by running it and grepping its banner.
