Exports, by these exact names:

- `type DisasmNote = "nmos-page-wrap" | "truncated" | "acme-unassemblable" | "illegal-opcode"`
  — D-10's structured note vocabulary. A closed union, not a free string, so the
  renderer (04-04) and Phase 5's backtrace can switch on it exhaustively.

- `interface DecodedOperand { role: "immediate" | "zeropage" | "absolute" | "relative" | "indirect"; value: number; width: 1 | 2 }`
  — `role` and `width` together are what DISASM-06's substitution rule (D-11)
  reads to decide whether a symbol can safely replace a literal. `value` is the
  operand as encoded (for `relative`, the **raw signed offset**; the resolved
  address lives in `resolvedTarget`). `width` is the operand's byte width (1 or 2),
  which always equals `entry.length - 1`.

- `interface Instruction { address: number; bytes: number[]; opcode: number; mnemonic: string; mode: AddressingMode; illegal: boolean; acmeExpressible: boolean; operand?: DecodedOperand; resolvedTarget?: number; notes: DisasmNote[] }`
  — `notes` is always present (empty array when there is nothing to say), never
  `undefined`. `bytes` holds every byte the instruction consumed, including a
  partial instruction's bytes.

- `interface DecodeOptions { count?: number; end?: number }`

- `function decode(bytes: Uint8Array, startAddress: number, opts: DecodeOptions = {}): Instruction[]`

Decoding rules — implement exactly:

1. **Bounded by construction (T-04-03-01).** A single `while` loop over a byte
   cursor. Every iteration consumes at least one byte, so termination is
   structural. No recursion anywhere in this file. Cap the iteration count at
   `opts.count` when supplied. Narrow `opts` with a local `isPlainObject()`
   (this tree's convention: the one-line predicate is repeated per file, never
   centrally imported). A non-integer, negative or absurd `count`/`end` is
   **ignored** (treated as absent) rather than thrown on — argument validation
   with user-facing refusal text is the tool's job (04-05), not this module's.

2. **Address arithmetic wraps at 16 bits.** `address = (startAddress + offset) & 0xffff`.

3. **Per instruction:** read the opcode byte, look up `OPCODES[opcode]`, and
   require `entry.length` bytes.
   - If fewer than `entry.length` bytes remain in `bytes`, emit a **truncated**
     instruction (DISASM-05, criterion 3): `bytes` holds only the bytes that
     actually exist, `operand` and `resolvedTarget` are **omitted**,
     `notes` includes `"truncated"`, and the loop **stops**. Never fabricate the
     missing operand bytes and never guess a value.
   - Otherwise build the full instruction.

4. **Operand extraction by mode:**
   - `implicit`, `accumulator` — no `operand`.
   - `immediate` — `{ role: "immediate", value: b1, width: 1 }`.
   - `zeropage`, `zeropage_x`, `zeropage_y`, `indirect_x`, `indirect_y` —
     `{ role: "zeropage", value: b1, width: 1 }`.
   - `relative` — `{ role: "relative", value: b1, width: 1 }` where `value` is the
     **raw byte**; see rule 5.
   - `absolute`, `absolute_x`, `absolute_y` — `{ role: "absolute", value: b1 | (b2 << 8), width: 2 }` (little-endian).
   - `indirect` — `{ role: "indirect", value: b1 | (b2 << 8), width: 2 }`.

5. **DISASM-04, resolved branch targets (criterion 3).** For `mode === "relative"`,
   set `resolvedTarget = (address + 2 + signed8(b1)) & 0xffff`, where
   `signed8(b) = b < 0x80 ? b : b - 0x100`. The `& 0xffff` mask is required: a
   backward branch near `$0000` and a forward branch near `$ffff` both wrap on
   real hardware.

6. **Absolute jump targets.** For `jmp` absolute and `jsr` absolute, also set
   `resolvedTarget` to the operand value, so a consumer never has to special-case
   which operand is a control-flow target.

7. **NMOS page-wrap (criterion 3, D-10).** For opcode `$6C` (`jmp` indirect), if
   `(operandValue & 0x00ff) === 0x00ff`, push `"nmos-page-wrap"` into `notes`. On
   the original NMOS 6502/6510 the high byte of the pointer is fetched from
   `pointer & 0xff00`, not the next page. Do not emit this note for any other
   opcode.

8. **`notes` carries the table's own flags:** push `"illegal-opcode"` when
   `entry.illegal`, and `"acme-unassemblable"` when `entry.acmeExpressible === false`
   (the renderer reads the latter to decide the `!byte` substitution, D-09).
   Order the notes deterministically (the order listed here) so the renderer's
   output and the round-trip test are stable.

9. **`opts.end` -- the roadmap's drop-past-end rule.** When `opts.end` is supplied,
   **drop** any instruction whose `address > opts.end` (do not emit it at all) and
   stop. Decoding a byte or two past `end` is expected — 04-05 deliberately
   over-reads by two bytes so the last instruction's full length is available —
   and instructions starting past `end` are discarded rather than returned. An
   instruction that *starts* at or before `end` is emitted in full even if its
   last byte lies past `end`.

10. **Never throws.** A malformed `bytes` argument (not a `Uint8Array`), a
    negative `startAddress`, or anything else returns `[]` rather than throwing —
    matching this module tree's never-throw ethic and `disasm-decoder.ts`'s role
    as a leaf several consumers import.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| emulator memory -> decoder | The `bytes` argument is attacker-controlled in the meaningful sense: it is whatever program is loaded in the emulated C64, which for this project is routinely an unknown cracked release |
| (no path, no socket, no filesystem) | `disasm-decoder.ts` has no I/O of any kind |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Denial of Service | `decode()` over untrusted memory bytes | mitigate | Bounded by construction: one `while` loop whose cursor advances at least one byte per iteration, an optional `count` cap, and **no recursion**. The byte budget itself is capped upstream by `count`'s max of 100 and the over-read-by-two rule (D-13, enforced in 04-05). Task 1's acceptance criteria assert no self-calling function and no bound read from `bytes`. |
| T-04-03-02 | Tampering | fabricated operand bytes presented as decoded data | mitigate | DISASM-05 is exactly this control: a partial instruction emits only the bytes that exist, omits `operand`/`resolvedTarget`, and carries `notes: ["truncated"]`. Suite 2 deep-checks that no numeric field holds a byte absent from the input. |
| T-04-03-03 | Information Disclosure | a wrong branch target sending a reverse engineer to the wrong address | mitigate | DISASM-04's resolution is asserted at both signed extremes and at both 16-bit wrap boundaries (suite 1); the raw offset is preserved in `operand.value` so a consumer can always recompute. |
| T-04-03-04 | Tampering | an exception escaping into a consumer | mitigate | `decode()` never throws; suite 7 fuzzes 200 deterministic inputs plus the degenerate cases. |

## ASVS L1 applicability
V5 Input Validation applies in its "fail safe on malformed input" form only:
`decode()` narrows `opts` defensively and ignores nonsense rather than throwing;
the user-facing refusal text for `address`/`count`/`end` belongs to 04-05's tool
handler through `stock-address.ts`. **V2 Authentication, V3 Session Management,
V4 Access Control and V6 Cryptography do not apply** — this module adds no auth
surface, no session, no access-control decision and no cryptography.
</threat_model>
