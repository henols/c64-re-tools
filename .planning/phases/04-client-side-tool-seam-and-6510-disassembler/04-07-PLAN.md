**Correction 4 — the notices file's placement (RESEARCH Pitfall 2 / Open Question 2).**
D-07 says "`THIRD-PARTY-NOTICES.md` at the repo root, gated by the packaging
check". Research found this cannot work as stated: npm's `files` array is resolved
relative to the directory holding `package.json` (`.claude/mcp/vice/`) and cannot
reach a repo-root file. The repo's own root `LICENSE` demonstrates the gap today —
a live `npm pack --dry-run --json` confirmed it is **absent from the tarball**.

**Decision — Option 2 with a root pointer, chosen explicitly as this plan's
decision:**
- The **canonical** notices file lives at `.claude/mcp/vice/THIRD-PARTY-NOTICES.md`
  and is added to that package's `files[]`. No copy step, no `prepack`, no moving
  parts, nothing that can drift.
- A **repo-root `THIRD-PARTY-NOTICES.md`** is created as a short pointer (a title,
  one sentence, and a relative link) so D-07's "at the repo root" and GitHub's
  repo-page convention are both satisfied. It contains **no licence text**, so
  there is nothing for it to drift from.
- `scripts/check-npm-packages.mjs` asserts the canonical file is present in the
  **packed tarball's own file list** (`vice.files.includes(...)`), never
  `existsSync()` against the repo-root path — that would pass while the published
  package silently omits it, which is exactly the CR-07-shaped failure this repo
  has a named aversion to (RESEARCH Pitfall 2's stated warning sign).

**Rejected — Option 1, a `prepack` script copying the root file into the package
dir** (mirroring `installer/package.json`'s `"prepack": "node scripts/sync-skills.mjs"`).
It is more literal to D-07's "at the repo root", but it creates a duplicated file
in the working tree at pack time that must then be gitignored, and a moving part
that can fail silently. D-07's load-bearing clause is the **gate**, not the
directory.

**Correction 2 (continued from 04-01) — `fluffy-6502`.** The notices file records
it as a source that **could not be located and is therefore not a source of this
table**, rather than citing it. A notices entry naming a project with a URL that
404s overstates what was checked.
</research_corrections_resolved_here>
