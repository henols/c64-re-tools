<plan_decision_reverse_symbol_lookup>
**Gap this plan closes, not visible in CONTEXT.md or RESEARCH.md.** D-14 says
`show_symbols` calls through `stock-address.ts`'s `setSymbolResolver()` extension
point. That hook's `SymbolResolver` interface has exactly one method,
`resolve(name: string): number | undefined` — a **name → address** lookup, built
for `parseAddress()`. Disassembly needs the **inverse**: address → name.

**Decision: widen the existing interface; do not add a second seam.** Add an
**optional** `nameFor?(address: number): string | undefined` to `SymbolResolver`
and export `symbolNameFor(address: number): string | undefined` from
`stock-address.ts`, returning `undefined` when no resolver is installed or the
installed resolver has no `nameFor`. One holder, one hook, one seam — preserving
D-04 of Phase 3 ("one `parseAddress()` with the pluggable symbol hook") exactly
as written. Phase 5's DERIV-04 store implements both directions.

**Rejected:** a separate reverse-resolver holder in `stock-disassemble.ts` or a
new `stock-symbols.ts` seam. Two holders for one concept is this codebase's own
named anti-pattern ("re-deriving a cross-cutting seam locally"), and Phase 5 would
then have to install its store twice.

The renderer stays **pure**: it never imports `stock-address.ts`. This handler
passes `symbolNameFor` in as `RenderOptions.symbolFor` (D-05).
</plan_decision_reverse_symbol_lookup>

**Bounded memory read (Phase 3 D-05: this halts the machine; never resume):**
- `end` form: `readEnd = Math.min(end + 2, 0xffff)` — the roadmap's **over-read by
  two bytes** rule, so the last instruction that *starts* at or before `end` has
  its full length available and truncation only ever happens at a genuine memspace
  boundary.
- `count` form: `readEnd = Math.min(address + count * 3 - 1, 0xffff)` — three is
  the maximum instruction length, so `count` instructions can always be decoded.
- Send `memGetBody({ sidefx: false, start: address, end: readEnd, memspace: 0x00, bank: 0x0000 })`
  with `CommandType.MemoryGet`. **`sidefx` is always `false` and there is no
  argument for it** — disassembly must never trigger I/O side effects such as
  clearing `$D019`.
- Wrap `session.client.send(...)` in try/catch → `convertWireError("vice_disassemble", err)`.
- Guard `response.type !== "memory_get"` and guard a short read
  (`response.bytes.length !== readEnd - address + 1`) with the same
  "a short read is a wrong answer, not a partial success" framing `handleMemoryRead`
  uses.
- Never send `EXIT`/resume (Phase 3 D-05).

**Decode and render:**
- `const decoded = decode(response.bytes, address, end !== undefined ? { end } : { count })`
- **Bound the answer (D-13, T-04-05-03):** if `decoded.length > 100`, keep the
  first 100 and set `limitReached: true` plus
  `nextAddress: <address of the first dropped instruction>`. Otherwise
  `limitReached: false` and no `nextAddress`. This applies to **both** forms —
  the `end` form has no natural cap, and an unbounded answer is the DoS surface.
- `const symbolsAvailable = show_symbols && hasSymbolStore()`
- `const listing = render(kept, { showSymbols: symbolsAvailable, symbolFor: symbolNameFor, origin: address })`

**Answer (D-13), built with `stockAnswer(session.client, payload)` and never a
hand-built `{ content, isError }` literal:**

```
{
  address,                 // number
  end,                     // number, present only when the end form was used
  count: kept.length,      // number -- instructions actually returned
  instructions: [ { address, bytes, mnemonic, operand, resolvedTarget, notes } ],
  listing,                 // string -- the ACME-ready text
  symbolsApplied,          // boolean
  symbolNote,              // string, present only when show_symbols was true but no store is installed
  limitReached,            // boolean
  nextAddress              // number, present only when limitReached
}
```
Per-instruction field rules:
- `bytes` — `number[]`
- `mnemonic` — the decoded mnemonic string; for a **truncated** instruction use
  `""` (the operand is unknown, so no mnemonic is claimed)
- `operand` — the **rendered operand text** (`"#$0f"`, `"$d020,x"`, `"($10ff)"`),
  or `""` when the mode has none. A string, so `checkAgainstSchema()` can type it.
- `resolvedTarget` — number, omitted when the instruction has none
- `notes` — `string[]`, always present (possibly empty)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> `vice_disassemble` | `address`, `count`, `end`, `show_symbols` are untrusted input crossing into the handler |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05-01 | Tampering | `address`/`count`/`end` argument validation (ASVS V5) | mitigate | Every value routes through `stock-address.ts`'s `parseAddress()`/`parseByteCount()` — the one parser, already enforcing `0..0xffff` and refusing malformed input. `count` is capped at 100. `readEnd` is clamped at `$ffff` before the request is built, so a crafted `address`+`count` cannot request past the 16-bit space. |
