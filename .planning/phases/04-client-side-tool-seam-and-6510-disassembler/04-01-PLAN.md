<objective>
Land the committed 256-entry 6502/6510 opcode table (`disasm-opcodes.ts`) and the
independent bit-pattern derivation test that pins it (`disasm-opcodes.test.ts`).

instruction after it in every one of those consumers.

derived-tool seam (04-02) and depends on nothing from Phase 3.

**Correction 1 — "twelve NOP variants" is factually wrong.** ROADMAP.md criterion 2
and 04-CONTEXT.md D-09 both say "twelve". The real 6502/6510 illegal-NOP set is
**27 opcodes across 6 addressing-mode groups** (verified by 04-RESEARCH.md against
cc65's live `opc6502x.c`, masswerk.at and oxyron.de):

| Group | Length | Opcodes | Count |
|-------|--------|---------|-------|
| implied | 1 | `1A 3A 5A 7A DA FA` | 6 |
| immediate | 2 | `80 82 89 C2 E2` | 5 |
| zeropage | 2 | `04 44 64` | 3 |
| zeropage,X | 2 | `14 34 54 74 D4 F4` | 6 |
| absolute | 3 | `0C` | 1 |
| absolute,X | 3 | `1C 3C 5C 7C DC FC` | 6 |

Task 2 therefore writes the length check as **exhaustive over all 256 opcodes**
with per-addressing-mode length assertions — a strict superset of whatever
"twelve" meant — plus the explicit 27-opcode/6-group enumeration above. **Do not
write a test with twelve hardcoded NOP cases.** The correction is recorded in the
test file's own header comment so the ROADMAP wording can be fixed later.

D-06 name it as an MIT cross-check source; 04-RESEARCH.md searched GitHub and the

- `AddressingMode` — a string-literal union with exactly these 13 members:
  `"implicit" | "accumulator" | "immediate" | "zeropage" | "zeropage_x" | "zeropage_y" | "absolute" | "absolute_x" | "absolute_y" | "indirect" | "indirect_x" | "indirect_y" | "relative"`.

  instruction length per mode: `implicit`/`accumulator` = 1; `immediate`,
  `zeropage`, `zeropage_x`, `zeropage_y`, `indirect_x`, `indirect_y`, `relative`
  = 2; `absolute`, `absolute_x`, `absolute_y`, `indirect` = 3. Every entry's own
  `length` field must equal `LENGTH_FOR_MODE[entry.mode]`; task 2 asserts it.
- `OpcodeEntry` — an interface with exactly these fields:
  - `mnemonic: string` — lowercase three-letter canonical 6502/6510 mnemonic
    (`"lda"`, `"lax"`, `"ane"`, `"lxa"`, `"nop"`, `"jam"`, `"sbc"`, ...). Lowercase
    because ACME source is lowercase and the renderer (04-04) emits this verbatim.

  - `length: 1 | 2 | 3`
  - `illegal: boolean` — `true` for every opcode outside the documented NMOS set.

    this addressing mode. **Seed** it: `true` for every legal opcode and for every
    illegal opcode whose mnemonic is in the 18 verified names from

    its authority** (D-09: "the exact set is determined by the assertion test
    against the installed ACME, not by this list"). 04-06 corrects any entry ACME
    disagrees with.
- `OPCODES: readonly OpcodeEntry[]` — exactly 256 entries, **array index equals the
  opcode byte** (so `OPCODES[0xa9]` is `lda #`). No sparse holes, no `undefined`.

Create `.claude/mcp/vice/disasm-opcodes.test.ts` using Node's built-in
`node:test` + `node:assert/strict` (the project's only runner; no framework
install).

This test's entire value is that it is **independent of the source the table came
from** (D-06, and the codebase's own "a green suite written by the same pass that
wrote the code proves less than it looks like it does" lesson from Phase 2's
post-mortem and Phase 3's `sizeBits` blocker). It derives the expected addressing
mode and length from the 6502's own `aaabbbcc` opcode bit structure and compares
against the table, so a transcription typo fails here.

Write these suites:

1. **Shape:** `OPCODES.length === 256`; every entry's `length === LENGTH_FOR_MODE[entry.mode]`;
   every `mnemonic` matches `/^[a-z]{3}$/`.

2. **Bit-pattern derivation, exhaustive over all 256.** Implement
   `deriveMode(opcode): AddressingMode | null` from the `aaabbbcc` decomposition
   (`cc = opcode & 0b11`, `bbb = (opcode >> 2) & 0b111`, `aaa = opcode >> 5`) for
   the three regular groups (`cc === 0b01`, `cc === 0b10`, `cc === 0b00`), plus the
   `cc === 0b11` illegal group, returning `null` where the rule does not apply.
   Then loop `0..255`: if `deriveMode(op)` is non-null, assert it equals
   `OPCODES[op].mode`; otherwise assert `op` is present in an explicit
   `IRREGULARS: Record<number, { mode: AddressingMode; length: 1|2|3 }>` literal
   in this test file and assert the table matches that literal.
   **The irregular list must be kept honest in both directions:** a second
   assertion loops `IRREGULARS` and fails if any listed opcode's derived mode
   would in fact have matched the bit rule (a dead entry hiding a real defect).
   Genuine irregulars to expect: `$00` BRK, `$20` JSR, `$40` RTI, `$60` RTS,
   `$6C` JMP indirect, the eight `xxy10000` branches, `$A2` LDX #, the
   `zeropage_y`/`absolute_y` LDX/STX/LAX/SAX family (`$96 $97 $B6 $B7 $9E $9F $BE $BF`),
   `$8B`, `$AB`, `$EB`, the 12 JAMs, and the NOP class.

3. **NOP class -- exhaustive, per the corrections block, NOT "twelve".** Assert
   the exact 27 opcodes across 6 groups, as a data table in the test:
   implied/1-byte `1A 3A 5A 7A DA FA`; immediate/2-byte `80 82 89 C2 E2`;
   zeropage/2-byte `04 44 64`; zeropage_x/2-byte `14 34 54 74 D4 F4`;
   absolute/3-byte `0C`; absolute_x/3-byte `1C 3C 5C 7C DC FC`. For each: assert
   `mnemonic === "nop"`, the stated `mode`, the stated `length`, and
   `illegal === true`. Assert the total count of illegal `nop` entries in `OPCODES`
   is exactly 27, and that `$EA` is the only legal `nop`. Put the correction
   ("ROADMAP.md criterion 2 and D-09 say twelve; the real set is 27 across 6
   groups -- see 04-RESEARCH.md Common Pitfalls 1") in this suite's own comment.

4. **JAM class:** exactly the 12 opcodes `02 12 22 32 42 52 62 72 92 B2 D2 F2`,
   each `mnemonic === "jam"`, `length === 1`, `illegal === true`,
   `acmeExpressible === true` (`jam` is in `acme-build/SKILL.md`'s verified list).
   Assert the count of `jam` entries in `OPCODES` is exactly 12.

5. **`acmeExpressible` seed sanity:** every `illegal === false` entry has
   `acmeExpressible === true`; every entry whose `acmeExpressible === false` is
   `illegal === true`. Assert `$8B`, `$AB`, `$EB` and all 21 multi-byte NOP-class
   opcodes are seeded `false`, and the 6 implied 1-byte NOPs are seeded... assert
   whatever the table states and add an inline comment that 04-06's real-ACME
