Create `.claude/mcp/vice/disasm-renderer.ts`.

**Imports allowed: `./disasm-decoder.ts` (types) and `./disasm-opcodes.ts` only.**
No `stock-*.ts`, no `vice*.ts`, no `node:` builtin. In particular the renderer must
**not** import `stock-address.ts` — DISASM-06's symbol lookup arrives as an
injected function so this module stays importable by anything (D-05). 04-05 wires
the real resolver in.

Exports, by these exact names:

- `interface RenderOptions { showSymbols?: boolean; symbolFor?: (address: number) => string | undefined; origin?: number }`
- `function renderLine(instruction: Instruction, opts?: RenderOptions): string` — one instruction, no header.
- `function render(instructions: Instruction[], opts?: RenderOptions): string` — the full self-contained listing.

**Listing structure produced by `render()` (this is what must reassemble):**
1. `!cpu 6510` — required; without it ACME rejects every illegal mnemonic
   (`acme-build/SKILL.md`'s own troubleshooting row says so).
2. Zero or more symbol definitions, one per line, `name = $XXXX`, for **every**
   symbol actually substituted below, sorted by address. Without these the
   listing references undefined labels and does not assemble at all — which would
   defeat criterion 4. Emit none when no substitution happened.
3. `* = $XXXX` — the origin, taken from `opts.origin ?? instructions[0].address`.
4. One line per instruction.

**Operand rendering by mode** (lowercase mnemonic, hex with `$`, ACME syntax):

| mode | form |
|------|------|
| implicit, accumulator | `mnemonic` |
| immediate | `mnemonic #$XX` |
| zeropage | `mnemonic $XX` |
| zeropage_x / zeropage_y | `mnemonic $XX,x` / `,y` |
| absolute | `mnemonic $XXXX` |
| absolute_x / absolute_y | `mnemonic $XXXX,x` / `,y` |
| indirect | `mnemonic ($XXXX)` |
| indirect_x | `mnemonic ($XX,x)` |
| indirect_y | `mnemonic ($XX),y` |
| relative | `mnemonic $XXXX` where `$XXXX` is `instruction.resolvedTarget` (DISASM-04 -- the resolved target, never the raw offset) |

**D-11 — the width invariant, the rule everything else falls out of.**
The rendered operand's width must equal the decoded instruction's width. The one
case where it can shrink: an `absolute` / `absolute_x` / `absolute_y` operand
whose effective value is below `$0100` (`lda $0080`), which ACME re-encodes to
zero page, turning 3 bytes into 2 and breaking the round-trip — **whether or not
a symbol is involved**. Render those with ACME's size-forcing postfix on the
mnemonic: `lda+2 $0080`. Apply the same force when a substituted symbol resolves
below `$0100`.

> **Verification note for the executor:** ACME's documented size-forcing syntax is
> `mnemonic+1` / `+2` / `+3`. ACME is not installed in this environment, so this
> plan cannot prove the spelling. Write it as `+2` and record the assumption in
> the module header. **04-06's real-ACME round-trip is the proof**; if ACME
> rejects `+2`, 04-06 corrects this file (it lists `disasm-renderer.ts` in its
> `files_modified` for exactly that reason). Do not invent a different mechanism
> (e.g. padding with `!byte`) to dodge the uncertainty.

**DISASM-06 — symbol substitution, gated by role and width (D-11).**
Only when `opts.showSymbols === true` **and** `opts.symbolFor` is supplied **and**
it returns a name for the relevant address. Then, by operand role:

| role | substitute? | why |
|------|-------------|-----|
| `absolute` (incl. `_x`/`_y`) | **yes**, with the `+2` force applied when the resolved value `< $0100` | width is pinned by the force, so the encoding cannot change |
| `indirect` | **yes** | `jmp ($xxxx)` has exactly one encoding |
| `relative` (branch targets) | **yes** | a branch is always 2 bytes; ACME computes the offset from the label, so the encoding cannot change |
| `immediate` | **never** | the `#<` / `#>` high/low-byte ambiguity — D-11 names this explicitly |
| `zeropage`, `zeropage_x`, `zeropage_y`, `indirect_x`, `indirect_y` | **never** | a symbol whose value is `>= $0100` would force ACME to widen the instruction. Rendering these numerically is the conservative choice this plan takes; it costs nothing a reverse engineer needs, since the interesting addresses (`$d020`, `$ffd2`) are all absolute |

Every substituted name is collected and emitted as a `name = $XXXX` definition in
the listing header (structure item 2 above).

**D-09 — every opcode ACME cannot express renders as `!byte`.**
When `instruction.acmeExpressible === false` (equivalently, `notes` contains
`"acme-unassemblable"`): emit **all** the instruction's bytes as
`!byte $xx, $yy, $zz`, followed by a trailing comment holding the decoded
mnemonic and operand exactly as the table above would have rendered them, e.g.:

`        !byte $8b, $0f                  ; ane #$0f  [not expressible in ACME !cpu 6510]`

Emitting every byte is what keeps the following instruction at the correct
address, and putting the mnemonic in the comment means a human loses nothing.
**The round-trip therefore has zero exclusions and is byte-exact by
construction** — that is D-09's whole purpose, and it is what criterion 4's
"enumerated and asserted rather than skipped" is satisfied by.

**Truncated instructions** (`notes` contains `"truncated"`): emit the bytes that
exist as `!byte ...` with the comment
`; truncated -- partial instruction at the end of the requested range`. Never
render a mnemonic for a truncated instruction: the operand is unknown.

**D-10 — notes as trailing comments.** Every note on an instruction renders as
part of the line's trailing `;` comment, in the decoder's note order. Fixed text:
  - `nmos-page-wrap` → `NMOS page-wrap: the high byte is fetched from $xx00, not the next page`
  - `truncated` → `truncated -- partial instruction at the end of the requested range`
  - `acme-unassemblable` → `not expressible in ACME !cpu 6510`
  - `illegal-opcode` → `illegal opcode`
A line with several notes joins them with ` | ` inside one `;` comment. Comments
cannot affect the round-trip, which is exactly why one mechanism carries
criterion 3's page-wrap warning, criterion 3's truncation report and D-09's
substitution explanation.

Also emit the instruction's own address and raw bytes as a leading comment column
if it does not interfere with assembly — **optional**; if you do, it must be
inside a `;` comment so ACME ignores it. Prefer readability that costs nothing.

Header comment — `stock-schema-check.ts` density. State by name: WHY THIS FILE
EXISTS (04-06 feeds its output to a real ACME; 04-05 returns it as `listing`);
the `+2` assumption and that 04-06 is its proof; and WHAT NOT TO DO —
  - never import `stock-*.ts`/`vice*.ts` (in particular never `stock-address.ts`);
  - never emit a mnemonic for an opcode whose `acmeExpressible` is false (that is
    the exclusion-list approach D-09 rejected, and it ships output that provably
    does not reassemble);
  - never substitute a symbol into an immediate operand;
  - never emit a substituted symbol without also emitting its definition.
