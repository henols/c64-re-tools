<objective>
Make a known-data range actually exclude bytes from discovery. The annotation store's
existing 12-member data-type vocabulary is the source, `-B` and `-l` files this project
writes are the route, and dxa's own listing is where the exclusion is observed.

Purpose: dxa's errors run the dangerous way — data called code — and graphics regions are
the largest single source of them. An emitter that produces a syntactically valid `-B` file
which dxa ignores would look exactly like a working one, so the acceptance evidence has to
come from dxa's classification, not from the emitter's output.

Output: `dxa-blocks.ts`, `dxa-blocks.test.ts`, the `datablocksPath`/`labelsPath` wiring in
`dxa-run.ts`, and the live exclusion case in `dxa-live.test.ts`.
</objective>

## Planner decisions recorded here

**A-11 — the exercise uses a hand-supplied known-data range, not automatic VIC derivation**
(resolves RESEARCH Open Question 2). `AUTO-06`'s VIC-pointer-derived graphics ranges are
Phase 37's requirement, and `DXA-03`'s own text asks only that the `-B`/`-l` route be
exercised on a real image — not that the ranges come from automatic derivation. So this
plan supplies the range explicitly, from store rows an operator annotated, and Phase 37's
`AUTO-07` reuses THIS emitter rather than building a second one. State that reuse
expectation in the module's header so the next phase finds it. Reversibility: **reversible**.

**A-12 — which of the 12 `DATA_TYPES` members select a row.** The emitter selects rows whose
`dataType` is any member EXCEPT `"code"` and `"undefined"` — those are, respectively, bytes
the store says are program and bytes the store says it does not know. The remaining ten
(`byte`, `word`, `address`, `petscii`, `screencode`, `lo_hi_address`, `hi_lo_address`,
`lo_hi_word`, `hi_lo_word`, `external_file`) are all bytes the store already knows are data.
This selection must be derived from the frozen array rather than hand-listed, so a
thirteenth member added by a later phase is a compile-time or test-time event rather than a
silent omission. Reversibility: **reversible**.

**A-13 — the plain range form only, no `!` or `?` prefix.** `dxa.1` documents three `-b`
forms: `xxxx-yyyy` (a data block), `!xxxx-yyyy` (additionally, no vectors point here) and
`?xxxx-yyyy` (additionally, wholly unused). The two stronger forms are assertions the store
does not make and this project cannot derive from a `dataType` alone — and the man page
itself warns that `?` can cause code to be listed as data. Emit the plain form. Reversal
condition: a later phase with a derived no-vectors-point-here fact may widen the emitter,
and would do so by adding a field to the row selection rather than by guessing from the
type. Reversibility: **reversible**.
