## Planner decisions recorded here (no CONTEXT.md exists for this phase)

Six design questions were genuinely open — three of them `35-RESEARCH.md`'s own Open
Questions. Each is decided here so the executor implements a decision rather than
re-opening one.

**A-01 — the tool id is `dxa.disassemble`, and the vendored binary is found at a fixed
computed path, not an environment variable** (resolves RESEARCH Open Question 1).
`buildHostToolArgv()`'s branch resolves the binary as `vendor/dxa/dxa` relative to
`import.meta.url`, exactly as `ghidra-project.mts` is reached from `host-tool.mts`'s own
directory. Reasoning: `ACME_BIN` and `GHIDRA_HOME` exist because those tools are declared
HOST PREREQUISITES that a user installs anywhere; dxa is vendored AND built by this
project, so an override would only ever select a binary this project did not build and did
not pin — which is precisely what `DXA-01` forbids ("never one assumed present on
`$PATH`"). The branch refuses by name when the computed path does not exist, naming
`build.bash` as the remedy. Reversibility: **reversible** — adding an override later is one
line and no data migration.

**A-02 — `imageKind` is a typed argument and `-g 0000` is derived from it** (resolves
RESEARCH Open Question 3). Reasoning: MEASURED this session on the real vendored binary —
`dxa … -a dump tracer.prg` with no `-g` correctly reads `01 08` as the load address and
emits `* = $0801`, while `-g 0000` on a flat 64K capture is mandatory or dxa re-bases to
`* = $372f` and discards ~50K. Leaving that to caller convention is a silent, catastrophic
re-basing bug one call site away. Making it a typed field means the wrong value is a typed
mistake at the call site rather than an absent flag nobody notices. Reversibility:
**reversible**.

**A-03 — the seam captures dxa's stdout and writes it to a listing file, then digests the
file.** dxa has NO output-file option: READ-IN-SOURCE `vendor/dxa/main.c`'s `getopt`
switch has no `-o`-to-file case and `vendor/dxa/dump.c` emits every listing line with
`fprintf(stdout, …)`. Returning stdout in the response body (the `oracle.run` shape) is
structurally wrong here: MEASURED this session, a full 64K flat image yields a
**699,116-byte, 21,848-line** listing, and `oracle.run`'s stdout cap is 64 KiB — the
listing would be silently truncated and `dxa-listing.ts`'s byte-total refusal would then
fire on a truncation the seam caused. So the branch keeps the `acme.build`/`ghidra.analyze`
file-digest envelope: stdout is written to `<outDir>/<imageStem>.dxa-dump.lst` and that
path is the single `outputs[]` entry. Reversibility: **reversible**.

**A-04 — the parser's window contract, and what the refusal is.** `parseDumpListing(text,
{ origin, imageSize })` classifies over the half-open window `[origin, origin + imageSize)`.
The ONE refusal predicate is `covered.size !== imageSize`, where `covered` is the set of
DISTINCT in-window addresses. This is a deliberate correction to the Phase 23 evidence
script, which compared a running EMISSION count against the image size — a predicate that
cannot represent an overlapping decode at all and that, MEASURED this session, refuses a
perfectly good full-64K listing. Emitted addresses outside the window are never added to
any set; each such line is recorded in a reported `outOfWindow[]` and is never silently
dropped. MEASURED reason this is not hypothetical: running the pinned dxa over a 65,536-byte
flat image this session produced a final listing line whose hex column carries THREE bytes
at `$ffff` while its directive emits ONE — dxa's dump column wraps and re-prints the image's
first two bytes at the top-of-memory boundary — which over-counts by exactly 2 and makes the
Phase 23 predicate throw `accounted byte total 65538 does not equal expected image size
65536`. That transcript is this phase's real, unplanned, non-hand-planted refusal, and plan
35-05 records it as `DXA-02`'s criterion-2 evidence. Reversibility: **reversible**.

**A-05 — `HOST_TOOL_TIMEOUT_MS["dxa.disassemble"]` is `DEFAULT_HOST_TOOL_TIMEOUT_MS`
(20_000 ms) and the CLIENT table gains no entry.** Justified from a measurement rather than
a round guess: MEASURED this session, the pinned dxa disassembles a full 65,536-byte image
in **21 ms** wall-clock — a 950× headroom against the default ceiling. Leaving the client
table untouched keeps the cross-seam ordering test satisfied by construction, because
`DEFAULT_HOST_TOOL_REQUEST_TIMEOUT_MS` (30_000) already exceeds 20_000. Reversibility:
**reversible**.

**A-06 — the vendored C source is NOT added to `package.json`'s `files[]`, and neither are
the `dxa-*` modules, in this phase.** `check-npm-packages.mjs`'s four leak checks
(`node_modules/`, `*.test.*`, `fixtures/`, `test-corpus.mjs`) do not see `vendor/`, so this
is a decision no gate makes for us either way — which is why it is stated here rather than
discovered later. Reasoning: at this milestone dxa is a maintainer-side discovery engine
with no consumer-facing entry point (no MCP tool, no `anno` CLI verb, no skill route), and
shipping a module whose native dependency is deliberately not shipped would publish a broken
promise. Reversal condition: the phase that registers a consumer-facing entry point for the
code/data map decides `files[]` for the whole family — the `dxa-*` modules and the vendored
tree together — in that same commit. Reversibility: **reversible**.

The deterministic `assumption-delta` detector fired at plan time: `{ "detected": true,
signals: [{ kind: "pluralization", term: "also" }] }`. The matched snippet ("It **also** has
no machine-readable output") is incidental prose, but re-reading the phase scope confirms a
real pluralization sitting underneath it, so the checkpoint is answered rather than

**The noun that pluralized: `image`.** Until this phase every image this project handed to
an analysis tool was of one kind. This phase introduces a second: a `.prg` carrying a real
two-byte load address that dxa should honour, and a flat 64K capture whose first two bytes
are the processor-port values `$2f $37` and which dxa would otherwise read as a load address
and re-base to `* = $372f`, discarding roughly 50K.

**Decision: `promote`.** `imageKind` becomes an explicit typed field on `dxa.disassemble`
(`"prg" | "flat64k"`), and the `-g 0000` flag is DERIVED from it. The alternative —
add-alongside, leaving `-g` as an optional flag a caller sets by convention — is what makes
the flat-64K case silently wrong at exactly one forgotten call site, with no error and a
plausible-looking listing. Promoting the distinction to the identity of the request means a
wrong value is a typed mistake at the call site rather than an absent flag nobody notices.
The same field is what `dxa-run.ts` uses to compute the parser's window (`parsePrg()`'s
origin and `fileSize - 2` for a `.prg`; origin `0` and the file's own size for a flat
capture), so one decision serves both the argv and the window.

**Companion invariant test (accepted, in plan 35-01 task 2):** `dxa-seam.test.ts` asserts
both directions — `flat64k` emits `-g` immediately followed by `0000`, and `prg` emits no
`-g` at all — so a future phase that reintroduces the singular assumption by defaulting the
flag goes red immediately rather than silently.
</assumption_delta_decision>
