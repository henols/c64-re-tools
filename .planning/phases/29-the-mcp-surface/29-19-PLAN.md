documented command cannot see the exact shape it was built for.**

`scripts/lib/anno-cli-invocations.mjs:216-251` checks two things and says so in
its own doc comment: flag **membership** and positional **extension**. It never
checks whether a REQUIRED flag is **present**. The verifier planted
`anno coverage game.prg` — the required `--store` omitted — at
`routine-queue-walker/SKILL.md:241`, ran the gate, and got
`check-skill-cli-invocations: OK -- 10 documented anno CLI invocation(s) …`,
**exit 0**, for a command that exits 1 at runtime.

**Why this belongs to gap 1 rather than to the warning pile.** The previous
verification round found two documented commands that did not run. This gate is
what round 1 built so that class could never ship again — `29-16-PLAN.md`'s own
words: *"a name-only floor cannot see a dead command"*. It is the same failure
mode as the seam that shipped CR-02/CR-03: **a guard proven thoroughly on the
wrong axis.** A gate that is blind to the shape it exists to catch is worse than
no gate, because it is a written warrant for the next maintainer not to check.

**Fix the cause, not the symptom.** The cause is not "one missing `if`". It is
that the gate's declaration tables live where its own committed test cannot read
them, so the test proves a **fixture copy** while CI runs the **shipped copy**.
`anno-cli-invocations.test.ts:51` already declares its own private
`POSITIONAL_KINDS`. Adding `REQUIRED_FLAGS` to
`scripts/check-skill-cli-invocations.mjs` and a second private copy to the test
would reproduce that same asymmetry one table deeper.

Purpose: `REPOINT-01`/`REPOINT-02` are recorded ⚠️ PARTIAL, and this is one of the
four `missing` items under them. Output: a gate that reports an omitted required
flag by name, with a committed control and a live plant observed biting.

<table_location_decision>
**Decision: the two declaration tables move into
`scripts/lib/anno-cli-invocations.mjs` and are exported from there.**

The verifier's instruction is *"declare each verb's REQUIRED flags **beside**
`POSITIONAL_KINDS`"*. That is honoured — the two tables stay adjacent; what
changes is which file they are adjacent **in**.

**Why the lib and not the gate script.** `scripts/check-skill-cli-invocations.mjs`
runs the gate at module top level, so nothing can import it without running it —
which is precisely why the committed test declares a private `POSITIONAL_KINDS`
copy today. The lib is already the import-safe, side-effect-free home that
**both** the gate and the test import. Moving the tables there makes the committed
test assert against the table CI actually uses. One definition, two callers — the
shape `scripts/lib/anno-cli-verbs.mjs` already uses in this repository.

**The lib's stated purity is not violated.** Its header says the tables are
"passed IN rather than imported here, so this module stays a pure predicate with
no first-party TypeScript import and no filesystem access". Declaring frozen
**data** constants adds neither a TypeScript import nor filesystem access;
`checkInvocation()` keeps taking both tables as parameters, so the predicate stays
pure and the planted controls can still pass deliberately-wrong tables. Update
that header sentence to say what is true afterwards — leaving it as-is would
breach the live 29-14 prohibition inside the plan that discharges it.

**There is no stop rule, and the reason is recorded here so that nobody
restores one.** An earlier draft of this decision carried a fallback: *if the
test cannot import the lib without pulling in filesystem work, leave both tables
in `check-skill-cli-invocations.mjs` and assert the test's copies equal the
gate's instead.* That branch is **dead by construction** — its precondition is
already false and cannot be made true by anything this plan does. Measured on
2026-08-30, three independent ways:

- `src/mcp/vice/anno-cli-invocations.test.ts:24-28` **already imports**
  `parseDocumentedInvocations`, `checkInvocation` and `ANNO_INVOCATION_FLOOR`
  from `scripts/lib/anno-cli-invocations.mjs`, at module top level.
- `node --test src/mcp/vice/anno-cli-invocations.test.ts` exits **0** with 16
  passing on the tree as it stands, so that import demonstrably works today.
- The lib contains no `node:fs`, no `readFileSync` and no `node:child_process`
  reference at all — its own header at `:42` says nothing there `import()`s or
  `require()`s anything — and importing it in isolation resolves to exactly three
  exports with no side effect. Adding two frozen **data** literals introduces
  neither an import nor filesystem work, so the move cannot make the precondition
  true either.

A dead branch is not free: it strands every acceptance criterion that has to be
written around it. Criterion 3's *"the local declaration is gone"* clause is only
satisfiable on the branch that actually runs, so a guarded-but-unreachable
fallback leaves behind a criterion a correct execution cannot pass — the same
stale-guard shape this round exists to close, and worse than having no fallback
at all. Deleted rather than scoped.

**Every acceptance criterion in task 1 therefore applies unconditionally.** The
tables move into the lib, `checkInvocation()` gains its fourth parameter, and
`scripts/lib/anno-cli-invocations.d.mts` declares that parameter **and** both
tables. If execution finds the import failing after the move — contradicting the
measurement above — that is new information: **stop and report it**, do not
invent a fallback.

**Reversibility:** `reversible`. Two frozen object literals moving between two
files in the same package, with no data migration and no published API — a plain
revert restores the previous shape.
</table_location_decision>
