- **D-14** (locked, user decision, 2026-08-29): the kept-verb set is
  `render-memmap` and `coverage`. `gen-enums`, `export-lbl` and `import-lbl` follow
  the export route into Phase 30 with the ACME oracle — the same reasoning D-02
  already applied to `export-asm`. `coverage` stays because the census re-point was
  already in scope.
- **The consequence D-14 requires this plan to carry:** `R2000-14` / `R2000-15`'s
  ✓ Validated symbol round trip has **no route for the duration of Phase 30**. That
  is a *temporary loss of a validated capability*, and it is recorded here, in the
  commit that withdraws it, in `PROJECT.md`'s shipped-capability list — which is
  where a reader checks whether a capability works.
- **Discretion 4, adopted as research measured it, with its one flagged assumption
  established rather than carried.** The census re-point is a four-function adapter
  in the CLI, not a change to the coverage module: that module declares its input
  shapes and its own header states it never calls a tool, so only the *caller*
  changes. Three of the four shape mappings were verified by research; the fourth —
  the block-type vocabulary — was flagged **unverified (A3)**, and Task 1
  establishes it before the re-point depends on it.
- **Research's C-3 arithmetic is not re-litigated here.** The module floor is plan
  29-05's subject; this plan owns only the CLI **verb** floor, which is a different
  guard over a different subject.
- **Stated constraint: this plan WRITES the removal gate that plan 29-08 READS, in
  the same wave, with no dependency edge between them.** Recorded here as a decision
  rather than left as an accident, matching the shape 29-05 used for its own
  same-wave floor coupling. The coupling is deliberate: 29-08 only invokes the gate
  as a verification and never edits it, while this plan discharges the two CLI
  entries; declaring the edge would cascade the wave numbers of everything
  downstream for no ordering benefit. **The obligation this puts on this plan:**
  leave the gate green at every commit — never mid-edit — because 29-08 may invoke
  it at any point in this wave, and a transiently red gate would surface there as a
  failure attributed to the wrong plan. Record in the summary whether 29-08 ran
  before or after this plan's gate commit, if that is observable.
- **The re-citation target is constrained by 29-05's reachability rule.** Task 2's
  fallback — lowering an entry's count and re-citing it to 29-10 — is legal only
  because 29-10 carries **both** `scripts/check-no-regenerator2000.mjs` **and**
  `anno-cli.ts` / `anno-cli.test.ts` in its own `files_modified`. That was added to
  29-10 for exactly this reason. Do not re-cite either entry to any other plan
  without checking the same two conditions: an entry citing a plan that cannot edit
  the file it names can never be discharged, and survives to the phase close as an
  orphan that makes 29-11's emptiness assertion unreachable.
