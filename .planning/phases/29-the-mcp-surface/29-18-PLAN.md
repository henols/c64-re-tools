**The tracer for gap-closure round 2.** Make the drift gate stop contradicting its
own artifact, by removing machine identity from the bytes it compares — and prove
it end to end, at two roots, through the shipped CLI, before any prose expands
around it.

`render-memmap --check` reports `drifted` for a byte-identical store, sidecar and
rendered file whenever the checkout sits at a different absolute path, **while
printing the same `render_digest` in both runs**. The verifier reproduced it from
scratch: digest `0bc87b17…` in both trees, verdict `{"status":"drifted","line":3}`.

**The cause, stated so the fix lands on it rather than beside it.**
`anno-memmap-render.ts:462-463` push `storePath` and `provenancePath` into the
banner **verbatim** — and by the time they arrive they are realpaths, because
`cmdRenderMemmap()` puts both through `storePathWithinWorkspace()`.
`checkRenderedMemoryMap()` at `:601-603` compares the rendered file **byte for
byte**. `computeRenderDigest()` deliberately covers the store rows, the sidecar
bytes and `RENDERER_VERSION` and **not** the paths. So the digest and the verdict
disagree *by construction*: the digest says the content is identical and the
verdict says the file drifted, and both are correct about the different things
they measure.

**Attribution, stated precisely because the record must not blame the wrong
round.** The `store:` half **predates** plan 29-14 — at `e776be7^`
`cmdRenderMemmap()` already passed a realpath and the banner already pushed it
verbatim. Plan 29-14 correctly confined `--provenance` (a necessary fix, CR-03)
and thereby extended the same machine-dependence to the `sidecar:` line. This is
a Phase-29 defect present since 29-12 built the verb, **widened** by the gap
round, not invented by it.

**Why this is blocking rather than cosmetic.** This repo runs GSD with worktree
isolation ON, so a differing checkout path is the **normal** case, not an edge.
The memory map is meant to be a committed artifact. And
`anno-memmap-render.test.ts:378` **asserts** the absolute `provenancePath` into
the banner (`:439` asserts the markdown includes it) — the suite pins the defect,
which is exactly how it shipped green.

Purpose: `REPOINT-01` and `REPOINT-02` are recorded ⚠️ PARTIAL on this one verb.
This plan closes the half that needs code; plan 29-20 closes the prose half, and
depends on this plan because the corrected prose describes the corrected code.
Output: a path-independent banner, a seam that gives "workspace-relative spelling"
one definition, a cross-root regression test that could not exist before, and a
suite that no longer pins the defect.

<renderer_version_decision>
**`RENDERER_VERSION` is NOT bumped from `"3"`, and this is a decision rather than
an omission.** Read the constant's own doc comment (`anno-memmap-render.ts`
around `:270-290`) before disagreeing: version 2 was an **output-shape** change
(`escapeMarkdownCell()`), version 3 an **input** change (the digest canonicalises
this store's own row types). Its stated job is that "two incompatible renderings"
must not "compare as ordinary drift".

Three reasons not to bump:

1. This change alters **no row's content and no digest input** — the digest
   hashes store rows, sidecar bytes and the version constant, and none of the
   three moves.
2. A bump would change `render_digest` in **every** previously rendered file,
   burying a one-line banner correction inside a digest change. The banner lines
   drifting **once, visibly, as a banner diff** is the more legible signal and is
   exactly what a drift gate is for.
3. `anno-memmap-render.test.ts:183-190` asserts `RENDERER_VERSION === "3"` under a
   test **named for the store re-point rationale**, and `:328` asserts the source
   still carries the `"2" -> "3"` paragraph. Bumping would require rewriting a
   test whose name encodes a different decision's reason — churn bought with a
   falsified test name.

**The consequence is HANDED TO A USER, not left inherited (W4).** Not bumping
means a memory map rendered **before 2026-08-30** reports `drifted` on its first
`--check` after this change, once, because the banner's `store:` and `sidecar:`
lines moved from absolute to workspace-relative spellings. In **this** repository
that regresses nothing — measured 2026-08-30, `git ls-files` shows no committed
rendered `memory-map.md`, only the template — but a **consuming** project that
already rendered one will see it. **Plan 29-20 task 2 writes that sentence into
both copy-forward texts, in both skill trees**, with its one-step remedy: re-run
the generator and commit the new banner. This plan does not write it, because it
does not own those files; recording the handoff here is what stops it being lost
between the two.

**Reversibility:** `reversible` — bumping later is a one-character edit plus the
two test updates. If a future change alters a digest input, bump then.
</renderer_version_decision>
