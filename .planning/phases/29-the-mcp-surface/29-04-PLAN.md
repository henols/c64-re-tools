<objective>
Build `STORE-06`: cross-references and search over the typed decode, derived on
every query from the surviving `disasm-*` decoders and never cached — plus the
address-details composition the surface reads them through.

Purpose: this is the one Phase-29 requirement with no Phase-28 substrate. Neither
derived cross-references nor search exists anywhere in the store; `listXrefs()`
covers only the non-derivable rows, by `putXref`'s own explicit contract. Splitting
the derivation into its own module is not cosmetic — it puts the never-cache rule
in a file whose whole subject is derivation.
Output: `anno-derive.ts`, `anno-details.ts` and the never-cached control.
</objective>

## Decisions and readings adopted by this plan

- **D-07** (locked): the read verbs take a required image-path argument per call.
  The store's DDL holds **no** program image, so every derived answer is computed
  from bytes the caller names, resolved under the workspace root.
- **Pitfall 7 / the three independent statements of the never-cache rule:**
  `putXref`'s own doc block (*"a cached derivation would be a SECOND ON-DISK TRUTH
  that can disagree with the range table it came from"*), `XrefRow`'s type doc
  (*"Only NON-DERIVABLE references live here"*), and `COV-01`'s derived-from-bytes
  census. Three sources forbid it independently; this module is where that is
  enforced.
- **Pitfall 5, adopted:** the family is **not** chunked — `buildViceTool(def, run)`
  calls `run` directly and never reaches `wrapPossiblyChunked()`. The measured
  client ceiling is 40-60 KB. The two mitigations are the existing conventions: a
  byte cap on region reads, and `max_results` required with no default and the
  count returned so truncation is detectable.
