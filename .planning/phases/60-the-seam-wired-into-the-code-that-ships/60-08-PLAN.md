<assumption_delta_decision>
- **Noun now primary:** *the authoritative source of a declared tool id's location.* Not "the
  candidate list" and not "the fallback chain" — the single source that, once it speaks, answers
  for that id.
- **Decision: `promote`.** Grounded in the two calls the code actually makes, which ask different
  questions with the same helper: inside the environment layer, `resolveOnPath(envValue, env)`
  walks `$PATH` for *the developer's own literal value*; in Layer 3, `resolveOnPath(id, env)`
  walks it for *the declared id*. The first is the environment variable still speaking — it
  resolves what the developer wrote. The second is a different question entirely, asked on behalf
  of a name the developer never typed. Treating the second as a *fallback candidate standing
  alongside* a value that was named and missed is precisely what produces the substitution
  hazard, and it is the reading plan 60-01 introduced. Promoting the environment variable to
  authoritative — once set non-empty for an id, it is terminal for that id, and the declared-id
  probe is demoted to "the mechanism used when nothing named the tool" — is what the slash-free
  half already implements, and this plan extends it to the only remaining shape.
- **Accepted debt:** none is incurred by `promote` itself. The one behaviour it removes is the
  silent substitution, which no declared truth asks for. A developer whose absolute `VICE_BIN` is
  stale now gets a named refusal instead of a different binary starting — strictly more
  information, at the cost that a setup that was accidentally working via `$PATH` while pointing
  a variable at a dead path now stops working loudly. That is the intended outcome, not debt.
- **The generalized invariant, proposed and taken:** task 2 adds a test encoding the promotion
  itself rather than one input shape — *for every declared id carrying an `envVar`, a non-empty
  value that resolves through neither environment step never yields a path from a different
  mechanism*. It goes red the instant a future phase reintroduces a per-shape carve-out, which is
  exactly how this residual survived plan 60-06.
</assumption_delta_decision>
