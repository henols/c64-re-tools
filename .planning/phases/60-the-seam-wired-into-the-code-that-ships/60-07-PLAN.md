## Planner decisions recorded for this gap-closure pass

- **PD-17: `WR-01` is fixed in this pass.** It is a message-composition change inside one
  function and its two call sites, it follows a precedent the same file already sets three
  functions away, and leaving it would mean this phase knowingly ships a refusal that names the
  wrong remedy category. The precedent is `buildHostToolArgv()`'s ACME branch: a seam `refusal`
  is quoted verbatim with no remedy appended, because the declaration's remedy is prose for
  "the tool is missing" and not for "your file entry is wrong"; a null path with no refusal is
  the not-found case and carries the remedy. The two `c1541`/`petcat` sites adopt exactly that
  shape.
- **PD-18: `WR-02` is DEFERRED, with the rationale recorded here and in the module.** The
  roadmap's own cross-cutting constraint for this phase states it in as many words:
  "`findSiblingBinary()`'s per-process memoisation keeps its current semantics: widening what it
  can resolve must not change when it caches." Removing or narrowing the memo now would violate
  a constraint the phase was planned and verified against, to fix an inconsistency that is real
  but harms nobody at runtime — the only observable effect is that an edited `tools.json` needs
  a process restart to take effect for two of the eight tools. The trigger to revisit it is
  already named in `60-01-PLAN.md`'s own assumption-delta note: when the sibling mechanism moves
  inside the seam, the memo moves with it or dies with it, and that is the right moment to
  reconcile it with the seam's no-memo rationale. Recorded as a carried-forward concern, not as
  closed.
- **PD-19: `IN-01` is already closed by plan 60-06 and is not re-opened here.** The hardcoded
  `"x64sc"` display name in `backend-detect.mts` stops being hardcoded the moment the configured
  name is taken from the seam's `envCandidate`. No separate work item; recorded so a reader of
  the review's third finding is not left looking for it.

## Why this plan lists three requirement ids

`LOC-03` is listed because task 2 is its measurement clause — the same clause plan 60-05 served,
re-served because plan 60-06 changed the contract being measured.

`LOC-04` and `DECL-03` are listed because `PD-17` genuinely changes behaviour they own. `LOC-04`'s
verified truth in `60-04-PLAN.md` says both refusal messages keep their shape — the tool id, the
statement of absence, the `tried` list — and now also carry the declaration's remedy. After this
plan that is still true for the not-found case and deliberately no longer true for the
malformed-file case, which instead carries the seam's own reason and no remedy. `DECL-03` is
listed for the same reason from the other side: this plan changes which text a refusal site
emits, and `DECL-03` is the requirement that owns where refusal text comes from. Both are listed
so the change is visible to a verifier rather than arriving as a surprise under an unrelated id.
