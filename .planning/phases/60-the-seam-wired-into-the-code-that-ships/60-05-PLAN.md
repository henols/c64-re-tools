## Planner decisions recorded for this phase

There is no Phase 60 CONTEXT.md. The decisions below are the planner's, recorded visibly.

- **PD-10: `acme-gate.ts` is the one declared exception in the closed consumer set, for the
  ACME binary variable alone.** That module is TEST-ONLY — its own header says so, says it
  must never be imported by a production module, and says the variable may never be renamed
  because CI binds the exact name and a rename converts CI's hard failure into a silent skip.
  It is nevertheless a plain `.ts` file directly under `src/mcp/vice`, so the
  `hostpath-consumers.test.ts` module walk sees it. Naming it in the expected set, with the
  reason, is honest; excluding it by widening the walk's filters would hide a real reader.
- **PD-11: the expected set for the other three names is EMPTY, and for the ACME binary name
  it is exactly one entry.** The seam itself does not appear in any of the four lists,
  because it reads the variable through a computed lookup on the declaration's `envVar`
  field rather than by literal name — which is the strongest possible statement of the
  criterion: after this phase no module in the tree names a tool-location environment
  variable in shipped resolution code at all.
- **PD-12: the baseline for the unchanged-behaviour claim is the tree at commit
  `884e68c8`,** the last commit touching `src/mcp/vice/` before this phase began. Later
  planning commits touch only `.planning/`, so that tree is exactly the pre-rewiring source.
