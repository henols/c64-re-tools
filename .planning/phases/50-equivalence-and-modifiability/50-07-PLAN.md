<objective>
State the CI boundary rather than blurring it, and make a stale transcript a
failure rather than a quiet pass.

A GitHub runner has no emulator. It can run the whole store, export, assemble,
gate and byte-diff segment on the ACME the workflow already installs. It cannot
run anything that needs a running C64. ROADMAP criterion 5 requires that
division be stated, not implied, and that the emulator-dependent half be covered
by a freshness check so a stale transcript is caught instead of read as a pass.

This plan writes that check, writes the boundary document, and observes a broken
step actually reddening the command CI runs.

Purpose: ROADMAP criterion 5, and requirement EQUIV-04.

Output: a freshness test file, a boundary document, and a recorded observation
of a deliberately broken step going red.
</objective>

  <action>
Create `src/mcp/vice/phase50-transcript-freshness.test.ts`. Place it in
`src/mcp/vice/` so CI's existing Test step picks it up, matching every other
test file's location in this codebase. Do not place it under `docs/`.

Give the file a header stating why it exists. An emulator-dependent transcript
cannot be re-derived on a GitHub runner. The only thing checkable there is
whether the transcript still describes the fixture committed today. A transcript
whose fixture has since changed is stale. A stale transcript read as a current
pass is worse than no transcript.

Discover the transcripts by globbing `docs/phase50-*.md` rather than by naming
them individually, so a transcript added later is covered without a code change.
Refuse with a named failure when the glob matches nothing, so the test cannot
pass vacuously on a tree where the transcripts were deleted.

Direction 1, freshness. For each transcript, parse its frontmatter `subjects:`
block. For each subject, recompute the named `.prg` file's sha256 with
`createHash("sha256")`. Compare it against the recorded value. On a mismatch,
fail with a message naming the transcript path, the subject name, the recorded
digest and the current digest. Name the remedy too, which is to re-run the live
session and commit a fresh transcript.

Direction 2, orphans. For each subject named in a transcript, fail when the
named `.prg` does not exist on disk. Report it as an orphaned transcript
reference, naming the transcript and the missing path.

Direction 3, the green-only refusal. Take each transcript that carries a section
whose heading begins with `## Green`. Fail when the same file carries no section
whose heading begins with `## Red`. Name the transcript. State that a green
result without a paired red control is refused as evidence. This is ROADMAP
criterion 2 made checkable. It is the reason this file is worth more than a hash
comparison alone.

Add no emulator call, no process launch and no network access. The whole file is
file reads and hashing, so it runs unchanged on a runner with no C64.

Do not add this file to `MANUAL_ONLY_TESTS`. It must run under both
`npm run test:automated` and CI's wider `npm test` glob.
  </action>
