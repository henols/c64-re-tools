**The pre-registration manifest**, `exported-edit.manifest.json`, committed in the
fixture directory. It is the acceptance contract and it is written BEFORE the
assembler is ever run against the edited tree. Give it three parts.

Part one, provenance: the store document path
(`hazard-subject.annostore.json`), the image path (`hazard-subject.prg`), and a
one-line statement that the tree this manifest edits is produced by
`exportAsmTree()` and by nothing else.

Part two, `source_edits`: an ordered array. Each entry names the target `file`
(here, the scope file the alignment routine lands in -- resolve its real name
from the export's own `files` list rather than assuming it), an exact `find`
array of source lines, an exact `replace` array of source lines, and a `why`
string that cites the hazard-report finding the change is anchored to by anchor
address, hazard class and mechanism. The `why` field is not decoration: ROADMAP
criterion 4 requires each change be cross-referenced to a named finding or a
moved range, and this field is where that cross-reference lives in
machine-readable form.

There are exactly two behaviour changes and both land in the alignment routine's
own scope file:

- **Removed, anchored to `$088B`, `page-alignment`,
  `sprite-pointer-names-aligned-base`.** Remove all four sprite-construction
  stores the routine performs -- the sprite-0 pointer write at `$07F8`, the
  sprite enable at `$D015`, and the two position writes at `$D000` and `$D001`
  -- together with the immediate loads that feed them. Leave the three
  constructions above them untouched: the bank select at `$DD00`, the
  character-set selector at `$D018` (whose own `page-alignment` finding at
  `$0881` must survive this edit), and the screen-control write at `$D011`.
  Leave the screen write at `$0400` and the routine's `rts` untouched.
- **Added, anchored to `$0825`, `self-modifying-code`,
  `store-target-in-instruction-opcode-byte`.** Add one `jsr hazard_smc2_entry`
  inside the region the removal frees. `hazard_smc2_entry` is the second,
  deliberately-undetected self-modifying construction the committed subject
  already carries and never calls; this addition makes it run for the first
  time. Use the symbol, never a raw address -- `symbols.a` already defines it and
  `BUILD-03` requires every `JSR` go through a symbol.

The replacement must preserve the block's total length exactly, so pad the
remainder of the freed region with `nop`. This is not cosmetic: the exporter
writes an origin-drift assertion at the start of each block and an end-drift
assertion at its end, and a length change makes the assembler refuse. Preserving
length also leaves every later address and every symbol value unchanged, which
is what lets the committed store keep describing the image.

Part three, `expected_byte_changes`: an array of `{ address, from, to }` rows
covering every byte the two source edits change, with `from` read out of the
committed image and `to` derived from the replacement source. Every value here
is derivable before the assembler runs -- that is the whole point. This is a
BYTE-level pre-registration only. Do NOT pre-register a runtime effect here: what
the two changes do in a running emulator is Task 3's measurement, not this file's
claim.

**The driver**, `make-exported-edit.mjs`, committed beside the other two
generators in the fixture directory. Model it on `make-rebuild.mjs` step for
step and reuse its `blocksInTreeSourceOrder()` helper on the same stated terms
(the helper is duplicated in this codebase deliberately, and `make-rebuild.mjs`'s
doc comment says why). The driver must contain no process-launch call of its own:
the only assembler that runs on its behalf is the one `acme-verify.ts` starts,
and `acme-verify.test.ts` pins that that module still holds exactly one such
launch. Sequence:

1. Import the committed store document into a fresh throwaway store through
   `importStoreDocument()`.
2. Export the tree twice into two separate throwaway directories -- one to edit,
   one left pristine as the comparison baseline.
3. For each manifest `source_edits` entry, assert the target is a member of the
   export's own `files` list, then apply the edit by exact unique match. Refuse
   by name and write nothing on a missing or ambiguous match.
4. Assert every file in the edited tree other than the declared targets is
   byte-identical to its counterpart in the pristine tree. This is the guard that
   makes "nothing but the declared edit changed" a measurement.
5. Build the expected bytes by applying `expected_byte_changes` to the pristine
   export's own `expectedBytes`, refusing when any row's `from` does not match
   the byte actually there.
6. Call `verifyAcmeAssemblesTree()` once with the edited tree, the patched
   expected bytes, and `blocksInTreeSourceOrder()`'s segment order. Exit non-zero
   on anything other than a successful outcome, printing the reason and the
   diagnostics.
7. Derive the two-byte little-endian load address from the export's own lowest
   block start, cross-check it against the assembler's own per-segment result
   lines, and refuse rather than guess on disagreement -- the same rule
   `make-rebuild.mjs` states.
8. Write `hazard-subject-exported-edit.prg` into the fixture directory, and write
   a machine-readable record to the phase evidence directory carrying the store
   digest, the tree file list, the applied edits, the pre-registered byte rows,
   the assembler's verdict block (outcome, exit status, per-segment result lines,
   aggregate lines, diagnostics and byte diff), the derived load address and its
   derivation, and the produced file's size and digest. Record byte-identity
   against `hazard-subject-modified.prg` as a measured extra if it happens, and
   state in the same record that it is not the acceptance criterion. Do not aim
   for it: the hand-written subject placed its added call at a different offset,
   so the two images are not expected to match and matching is not a goal.
