<objective>
Make a disassembly read `lda #D011_YSCROLL3_ROW25_SCREENON_TEXT` instead of `lda #$1b`, from a
table generated out of `memmap.json` rather than hand-written.

**The mechanism is not what the requirement's wording assumes — read this before starting.**
`EnumDefinition.variants` is a flat `BTreeMap<u16, String>`, a value→name map; there is no bit-OR
composition anywhere in 0.9.20. An enum binds to an **instruction address** via
`r2000_apply_enum_usage`, and that address is the one holding the immediate operand — the `lda`,
not the `sta` (measured directly, and `handler.rs:1236-1264`). Applying an enum emits its
**entire** variant list into the exported header, and an unmatched value falls back to bare
`#$1b` while still emitting the dead definitions. That is why D-20 generates one variant per value
the program actually writes, and why the 256-values-per-register and single-bit-mask options were
both rejected as measured-worse.

**Criterion 3's acceptance surface is the ACME export, not the live query view.** Measured
discrepancy: `--export_asm` renders `EnumName_VARIANT` (underscore) exactly as the criterion
quotes it, while `r2000_search_disassembly` renders the same reference as `EnumName.VARIANT`
(dot) — different code paths (`disassembler/formatter_acme.rs:367-369` vs `state/search.rs`). A
test asserting on the live view's operand text would fail even when the generated source is
correct. Version-scope this finding (RESEARCH.md Assumption A2): re-verify against
`--export_asm` at execution time rather than trusting it as permanent.

**Decision this plan owns (`<decisions_you_own>` #7 — the curated table's on-disk shape and its
generator).** Shape: `r2000-regbits-gen.ts` (generator, carrying the override table as a typed
const with a per-entry WHY comment) → `r2000-regbits.json` (committed, banner-marked generated
artifact) → `r2000-regbits.test.ts` (drift guard: re-run in memory, compare). Reasons: a generator
in TypeScript can carry the reasoning next to each override, which a JSON overrides file cannot;
`resources-sync.test.ts` is this repo's established shape for a generated-but-committed artifact
with a CI drift guard (ENGINEERING_RULES.md §11); and a committed JSON keeps the runtime path off
the skills tree, which CI never tests.

**Decision this plan owns (`<decisions_you_own>` #2, the verb): enum generation is a CLI verb
(`vice-mcp r2000 gen-enums`), not an 18th MCP tool.** Reason: it is a whole-project mutation plus a
save plus a coverage report — the same shape as `bootstrap`, which is already a CLI verb — and a
CLI run leaves the coverage numbers in a visible transcript. The individual enum tools stay on the
MCP surface (D-18) for in-session single-value naming; bulk generation is the CLI's job.

Purpose: criterion 3 is the phase's most distinctive deliverable — neither project can produce it
alone.

Output: the generator, the committed table, the enum generator with its coverage report, the
`gen-enums` verb, and an acceptance test that reads the ACME export.
</objective>

Create `r2000-enum-gen.ts`.

**`variantNameFor(register: number, value: number): string`** — decode `value` against the
register's fields from `r2000-regbits.json`, in bit order, emitting one token per field:
a `numeric` field emits `NAME` + the decoded number (e.g. `YSCROLL3`), a `flag`/`enum` field emits
its token for the decoded value. Join with `_`. The measured target must hold exactly:
`variantNameFor(0xd011, 0x1b) === "YSCROLL3_ROW25_SCREENON_TEXT"`, so that with enum name `D011`
the ACME reference is `D011_YSCROLL3_ROW25_SCREENON_TEXT`. Decide and document how a field whose
decoded value has no token is handled — it must be a refusal or an explicit numeric fallback, never
a dropped token that makes two different values produce the same name.

**Sanitization (T-11-ENUM-NAME, the highest-value threat in the phase).** Export
`assertLegalAcmeIdentifier(id: string, what: string): void` and call it on the enum name AND every
variant name immediately before any `r2000_create_project_enum` call. Rule: matches
`^[A-Za-z_][A-Za-z0-9_]*$`, length-bounded (name a constant), and not an ACME reserved word or
pseudo-op (list the ones that matter and cite where you checked). r2000 validates the enum name
only (`validate_new_enum_name`) and performs ZERO validation on variant names — they flow straight
into `format!("{}_{}", enum_name, variant)` at export time, so an illegal identifier reaches
generated assembly and only fails at assembly time, far from its cause. Refuse before the call.

**`generateEnums({ projectPath, maxResults })`** — the pass:
1. `r2000_search_disassembly` with `query: "^lda #"`, `use_regex: true`,
   `search_instructions: true`, `search_labels: false`, `search_comments: false`, and an EXPLICIT
   `max_results` (default a named constant, 10000 — the child defaults to 50, `handler.rs:1074-1077`,
   which would silently truncate a full-program pass).
2. `r2000_search_disassembly` for stores to registers the curated table knows, built as a hex
   alternation from `r2000-regbits.json`'s own keys — the register list is derived from the table,
   never a second hardcoded list.
3. Pair adjacent only (D-23): index pass-1 by address, and for each store at address S look for an
   immediate load at S-2 (`lda #imm` is always 2 bytes in immediate mode, so the following store
   begins at ldaAddr+2 regardless of the store's own addressing mode). No dataflow. A miss costs
   nothing; a wrong binding renders a confident semantic name over an unrelated value, which is
   worse than none.
4. Group by register, one variant per DISTINCT value observed (D-20). Create/replace the enum via
   `r2000_create_project_enum` (or `r2000_update_project_enum` when it already exists — decide the
   precedence and document it), then `r2000_apply_enum_usage` at each **`lda` address** (not the
   store address), then `r2000_save_project` through the curated runner's verified-save route.
5. Return and log a coverage report (D-23, no silent caps): total register stores seen, stores
   paired, stores unpaired, and per pass whether the returned count equalled the requested
   `max_results` (a possible-truncation signal). If either search returns exactly `max_results`
   rows, the report must say so in words, not leave it to be inferred.

Header carries: WHY (criterion 3, and that neither project can do it alone); the ONE authoritative

unsanitized identifier, never write a machine-global enum via `save_global_enum()`'s config dir
