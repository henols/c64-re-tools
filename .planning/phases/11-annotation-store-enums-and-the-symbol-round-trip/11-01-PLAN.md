Fix the two Phase 10 review findings that this phase's foundations rest on, and land the one
seam every later plan's live tests will import.

**WR-02 is a prerequisite, not cleanup.** D-16 makes `r2000-launch.ts` the only sanctioned
regenerator2000 spawn path, and plan 11-04 adds three more argv builders to it. Those builders
are protected by the D-07 `--vice` deny-by-construction guard whose test can currently be

guard until it is proven able to fail.

`lda #$1b / sta $d011` rendering semantically runs regenerator2000's `--verify`/`--export_asm`
and reads the verdict through `r2000-verify.ts`'s `acmeVerdict()`. That function currently
returns `ok: true` for a transcript containing both a passing and a failing ACME line, which is
exactly the "misleading success" this module was written to refuse.

test is not evidence (ENGINEERING_RULES.md §6).

Output: a non-vacuous D-07 guard, a unanimity-checking ACME verdict parser, and
`r2000-test-gate.ts` — the single availability-gate module plans 11-04..11-07 import instead of

Rewrite `stripCommentLines()` so a block comment closes on the first `*/` **anywhere in the
remaining text of the line**, not only as a line-ending suffix, and so the text after the last
`*/` on that line continues to be scanned as code. Concretely: while `inBlock`, search the line
for `*/`; if found, clear `inBlock` and re-process the remainder of the line after that `*/`
through the same line logic (so a `// …` tail on that remainder is still stripped and real code
on it is still pushed to `out`); if not found, drop the line as before. Apply the same remainder
handling to a line that both opens and closes a block comment.

Then make the guard non-vacuous **permanently**, not by a manual one-off run:

1. Extract the three guard predicates currently inlined in the assertions into named local
   helpers in this file — one per property: (a) no `filter(` call appears over
   `FORBIDDEN_R2000_FLAGS`/the deny list, (b) no rest parameter (`...`-prefixed parameter) appears
   in any exported builder signature, (c) no options field whose name suggests argv
   pass-through (`extraArgs`, `args`, `argv`, `passthrough`, `flags`, `rest`) appears. Each
   predicate takes the stripped source text and returns a boolean or a list of offending lines.
   There must be exactly ONE definition of each predicate in the file — the real-source tests
   and the planted-violation test below both call it.
2. Add a test named so it contains the literal words `planted violation` that builds the
   reviewer's exact synthetic source in-memory: a multi-line block comment whose closing line
   is of the shape `*/ export function buildEvilArgs(...extra: string[]): string[] { return extra; }`
   (i.e. real code trailing a legitimate `*/`), and asserts that after `stripCommentLines()`
   (a) the text `buildEvilArgs` and `...extra` are still present in the stripped output, and
   (b) predicates (b) and (c) both REPORT the violation. This is the committed proof the guard
   can fail.
3. Add a unit test for `stripCommentLines()` itself covering: a `*/ code();` closing line
   (code survives), a single-line `/* … */ code();` (code survives), a `//` line (dropped), and
   a genuinely unterminated `/*` block (everything after is dropped, and the test says so — this
   remains correct behaviour for a malformed file).

Do not weaken any existing assertion to accommodate the new stripper. If the fixed stripper
surfaces a real violation in `r2000-launch.ts`, that is a finding, not a test to relax
(ENGINEERING_RULES.md §5) — report it in the SUMMARY.
