<objective>
Demonstrate criterion 4 on a real program against a real emulator, as one loop.

**The phrase to design against is "one closed loop, not two independent one-way dumps."** A
passing `--export_lbl` step plus a passing `--import_lbl` step does not satisfy the criterion. The
transcript must show, in order, that a name which was **not in the store** was discovered against
the running machine and then ended up in the store — and that the address the outbound name
resolved to was resolved by the emulator, not asserted by us.

**Live-testing facts that must be honoured** (each has an incident behind it):
- Genuine unpatched stock `x64sc` is at `/usr/bin/x64sc`; the custom fork shadows it on `PATH`, so
  reach it by absolute path.
- **`-default` must precede `-binarymonitor`** or the monitor never binds.
- Stock's binary monitor services **exactly one client**. A second connection sits unserviced with
  no reply and no EOF, indistinguishable from a wedge. Do not open a second connection to
  diagnose a slow one.
- **One MCP connection per flow.** Phase 9 found `vice_memory_write` and `vice_snapshot_save` on
  separate connections producing a snapshot missing the written bytes. Do not split a
  write-then-read sequence across connections.
- If the emulator stops responding, use `vice-wedge-triage`'s decision procedure rather than
  recycling on instinct, and record what happened — a voided run recorded is worth more than a
  clean-looking run that was silently retried.

**D-31's real-program half, with a stated fallback rule.** The automated fixture test (plan 11-08)
guards the mechanism; this artifact is the claim about a real program. Resolve the subject in this
order and record which applied: (1) a real release resolved through
`.claude/skills/c64-ram-capture/scripts/releases.mjs` / `test-corpus.mjs` if this host has a
consuming project registered; (2) otherwise plan 11-07's committed `recon-subject.prg`, which is a
genuine assembled 6510 program that runs on a real emulator. If (2) applies, state the evidence
ceiling explicitly (ENGINEERING_RULES.md §8): the loop is proven end to end against a real
emulator, but not against a commercial release's size, packing or self-modification — and say what
would raise the ceiling.

Purpose: `DERIV-04` shipped a symbol consumer with no producer. This is the artifact that shows the
producer exists and the loop closes.

Output: one ordered walkthrough transcript, the two label files it produced, and this phase's
BACK-02 gate result.
</objective>
