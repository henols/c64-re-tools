<objective>
Turn two standing disciplines into checked properties: the assembler is launched from a known,
frozen set of places, and a pass-or-fail is derived from produced bytes in one place only.

Purpose: both disciplines are real and both are currently unenforced in the one direction that
matters here. The existing spawn-site guard scans for the emulator binary over the published
module set, which excludes the assembler oracle entirely; the skills spawn guard scans only the
skills tree. Neither would notice a new raw assembler launch, or a second byte-comparison
verdict, placed in a new file under the server tree — which is exactly where this phase adds
files. A gate whose own spawn and comparison seams are protected only by review is a gate that
degrades silently.
Output: one guard test holding two frozen, reasoned, both-directions set equalities, plus the
single-call-site and single-verdict-body assertions on the oracle.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the frozen declared sets → the assertion that protects them | The sets are editable source; the protection is that editing one is a visible diff with a reason column, not that it is impossible. |
| module source text → the scan's verdict about it | A scan that cannot see a launch form reports a clean tree it never examined. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-49-19 | Repudiation (false assurance) | the scan's coverage | high | mitigate | A scan that silently matches nothing passes exactly like a clean tree. Mitigated by asserting a lower bound on the module count, by the two synthetic sources proving the scan both fires and declines, and by the reverse direction of each set equality, which fails when a declared member stops being found. |
