<objective>
The tracer: one committed store, one real multi-file reassembly, one byte-diff, one gate
verdict — the whole phase architecture walked end to end once, before any control, any
relocation or any acknowledgement is built on top of it.

Purpose: every layer this phase touches is proved wired together while the plan still has its
best context. The one thing the existing byte-diff oracle cannot do today is assemble a tree —
it writes a single source file and never sets the child's working directory, so the bare
filename source directives the exporter emits by design cannot resolve. That is the only gap,
and closing it additively is what makes everything downstream a pure consumer.
Output: a tree-aware entry point on the existing oracle, the gate module with its rule table
and its required inputs, and a green end-to-end run against the committed purpose-built subject.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied tree directory and root file name → the assembler child's working directory and argv | A path the module did not derive becomes the directory a child process runs in. |
| the assembler's produced bytes → the gate's verdict | The consequential boundary: what a reader will act on. |
| the frozen rule document → the rule table in code | A rule implemented differently from the one committed makes the pre-commitment cosmetic. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-49-04 | Tampering | the assembler child launch | high | mitigate | A command assembled as a shell string, or a binary path interpolated into one, would let a crafted tree directory name reach a shell. Mitigated by reusing the existing argv-array launch unchanged — the extraction moves the call, it does not rewrite it — and by a verify command asserting exactly one child-launch call site remains in the oracle and zero exist in the gate module. |
| T-49-05 | Repudiation (false assurance) | the byte-diff verdict | high | mitigate | A verdict derived from the exit status, a summary line or a stale output file is the recorded false pass this module exists to refuse. Mitigated by the shared verdict body being the only place an outcome is produced, by the absent-before-spawn conjunct travelling with it into the tree path, by the output file living in a directory created for that call alone, and by the empty-expected-buffer refusal closing the two-empty-buffers-compare-equal hole. |
| T-49-06 | Spoofing | the gate's rule table versus the committed rule document | high | mitigate | A rule table that quietly differs from the frozen document turns a derived verdict back into a judged one. Mitigated by the rule ids being recorded in the verdict, by each rule carrying the criterion it enforces beside it, and by the verdict-producing plan reading the rule id back out of the verdict and checking it against the document. |
| T-49-07 | Information Disclosure | caller-supplied paths reaching the filesystem | low | accept | The tree directory and image path are supplied by in-repository test code and by the exporter's own result, never by an external caller; the module opens nothing outside the directories it is handed, and confinement of those paths is already owned by the exporter's callers. Accepted at the configured assurance level for a development-time gate with no network surface and no external input. |
| T-49-SC | Tampering | npm / pip / cargo installs | high | accept | No package-manager install task exists in this plan. The one external tool involved is the assembler, which this project detects and never installs, reached through the existing availability gate. |
