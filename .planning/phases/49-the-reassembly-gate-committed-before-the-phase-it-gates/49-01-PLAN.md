<objective>
Freeze the gate's vocabulary and its decision rules in git, in a commit that contains no
measurement — the whole point of the phase, done first, so every later plan measures against
rules it cannot edit.

Purpose: a rule written after the measurement makes every future gate advisory. This project
has done this correctly four times (the dual-channel coexistence gate is the nearest and its
git history was read directly this session: the rule pair landed in one commit and the first
measurement in a later, separate one). The recovery cost of getting it wrong here is recorded
and high — a gate later found to be exit-status-derived freezes every consumer and forces
every prior "passing" rebuild back through the corrected gate.
Output: `evidence/SCHEMA.md` and `evidence/DECISION-RULE.md`, committed together, alone.
</objective>

## Phase-wide decisions (bind every plan in this phase)

**D49-A — The gate's real assembler run extends the existing byte-diff oracle; it does not
route the verdict's spawn through the host-tool build op.** The host-tool op's argv carries
`-v1` and its response envelope is digest-only (`path`, `sha256`, `byteLength`), while the
oracle's unanimity rule reads the per-segment lines only `-v2` emits. Routing the gate through
the host-tool op would starve that rule of its input while still appearing to work — which is
precisely the exit-status-derived failure mode whose recovery cost is recorded as high. The
standing ban is on minting a NEW raw assembler spawn site, not on using the existing correct
one; the oracle already owns a legitimate argv-array spawn and is test-only and unpublished.

**D49-B — The tree-aware entry point is ADDITIVE.** A sibling exported function beside the
existing single-source one, funnelling into one shared private verdict body so the five ordered
verdict rules exist exactly once. The existing signature is not changed and no existing caller
is touched.

**D49-C — Relocation happens at the store-document + image layer, never as a text splice of
generated assembly.** A movement that edits emitted source would stop exercising the real
export path, which is the thing under test. The transform shifts a chosen symbol's address,
its owning range and its scope, copies the block's bytes to the new address in a rebuilt image,
and patches the FIXTURE-DECLARED absolute reference sites that point at the moved symbol. The
reference sites are a declared input of the relocation subject, not something the transform
derives — deriving them would re-implement the exporter's own symbolisation inside the check
meant to test it.

**D49-D — Hazard acknowledgement is keyed on the `(hazardClass, anchorAddress, mechanism)`
triple.** The finding type carries no identity field; an anchor address alone is insufficient
because one address can carry findings under two mechanisms. Keying on the triple makes the
findings array's ordering irrelevant by construction, which matters because no ordering
contract for that array is documented anywhere.

**D49-E — The gate is test-only and stays unpublished.** No new entry in the server package's
published file list, no MCP verb, no CLI verb. It is a development and CI gate, exactly as the
existing assembler oracle is.

**D49-F — No source file this phase adds or edits under the server tree may carry this
project's planning bookkeeping.** Those files ship, or are one published-file-list edit away
from shipping, and a consumer has no planning tree to resolve a citation against. State the
reason a reader can act on instead.

<assumption_delta_decision>
The deterministic detector fired on this phase's roadmap section with two signals: the word
"second" in *"rather than minting a second one. A test refuses a second independent verify
path"*, and the word "optionally" in *"movement is exercised on every run, not optionally"*.

**Noun examined:** the byte-diff verdict — the thing that says whether an exported tree really
rebuilt. Before this phase it had exactly one producer, the single-source assembler oracle.

**Decision: `no-change`.** Both signals point the OPPOSITE way from the transition the
checkpoint exists to catch. The phase does not introduce a second verdict producer that would
make the existing one one-of-many; it forbids one by name and adds a structural guard that
fails when a second appears. And the second signal is a required-becoming-optional cue firing
on text that makes an operation MANDATORY rather than optional — movement moves from
"something a gate could exercise" to a required input field with no path around it.

**Rationale:** the correct move when a generalisation occurs is to promote the general
representation and demote the specific one. No generalisation occurs here. The tree-aware entry
point is a second ENTRY POINT into one unchanged verdict body, not a second verdict — which is
exactly why D49-B requires the extraction into one shared private body rather than a parallel
implementation.

**What would later force a re-examination:** a second assembler, a second output format whose
byte-diff needs different rules, or a consumer that needs a verdict without an assembler run.
Any of those would make the outcome token set itself the thing that has to generalise, and that
is a decision to take deliberately rather than to discover.

**Companion invariant test, accepted:** the frozen-set guard in plan 49-06 is the test this
checkpoint would otherwise suggest. It goes red the moment a future phase reintroduces a second
byte-comparison verdict path, so the regression cannot land silently.
</assumption_delta_decision>
