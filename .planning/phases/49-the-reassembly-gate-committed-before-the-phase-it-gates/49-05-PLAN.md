<objective>
Close the last way a gate can go quietly green: make a non-clean hazard report either block the
gate outright or pass only with an explicit, recorded, per-finding acknowledgement that a
reader can see in the verdict.

Purpose: the hazard report reports and acts on nothing, which means the decision about what to
do with a finding lands here. A blanket acknowledgement, a count, or a class-wide waiver would
hand that decision back to the tool and hide it from the reader. Keying each acknowledgement to
one finding by class, anchor address and mechanism is also what makes the findings array's
ordering — which nothing documents as stable — irrelevant by construction rather than a defect
waiting for a re-export to expose.
Output: the acknowledgement matcher, the disposition rule, the deterministic rendering the
verdict artifact reads, and an exhaustive check that no non-clean report can reach green.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the acknowledgement set → the gate's hazard disposition | A human decision crosses into a machine verdict here; a weak matching rule lets one decision cover findings nobody looked at. |
| the hazard report → this module | The report is another module's output and is consumed read-only; anything this module changed about it would be invisible to the report's own tests. |
