<objective>
Commit the first text-channel fixture batch — the raw bytes the next phase's
parsers will be built against — captured from **both** binaries on this host with
the same five-key provenance discipline the binary-monitor fixtures already carry,
plus the sibling loader that refuses an incomplete sidecar and the single automated
test that proves the refusal.

Purpose: criterion 5 states its own mechanism — "the loader refusing a sidecar that
is missing a key is what makes this checkable rather than claimed". Two-binary
provenance is captured here, once, so the next phase inherits it instead of
re-running a live capture; and a command a binary was built without yields a
committed refusal, because the cheapest moment in the project to capture a real
unsupported response is while the channel is already open.

Output: a capture script and its evidence file under the phase evidence directory;
a fixture tree, a sibling loader and one new test under the shipped package.

**Serialization note:** this plan runs in its own wave because the capture spawns
emulators and every probe refuses to start when another one is alive — a real
constraint from `D-16`, not a file conflict.

**Scope boundary:** this plan writes a fixture *loader*, which is test support. It
writes no parser, no text-monitor client module, and no serialization authority.
The next phase owns all three.

Task 2 carry `39-CONTEXT.md`'s own ratings forward rather than re-deriving them. No
`checkpoint:decision` precedes them because the owner already chose each of those

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the probe process → a directly spawned emulator (D-12) | The capture reaches both emulators by `execve` rather than through the broker, so none of the broker's guards apply: no single-client enforcement, no port allocation, no crash supervision, no pre-kill incident capture |
| a committed fixture's sidecar → every later claim about what the fixture proves | A sidecar is the only statement of where a payload came from; a wrong one is indistinguishable from a right one at read time |
| a committed payload → the next phase's parser specification | These bytes become the specification the parsers are built and tested against, so an edited payload silently redefines the format |
| an untrusted sidecar file → the loader | A sidecar is JSON read from disk and parsed; a malformed or non-object one must fail as a fixture problem rather than escaping as a raw parse error |
