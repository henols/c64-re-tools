<objective>
Take **one** gate input end to end, on the thinnest complete path through every
layer this phase will use, before the other six are attempted: spawn genuine stock
`x64sc` with both monitor channels bound, drive the binary half through the shipped
wire encoders and the text half through a crude throwaway client, measure
`IDLE_COEXIST`, write its value at column 0 of its own evidence file, and
transcribe that value mechanically into the verdict document's frontmatter.

Purpose: `IDLE_COEXIST` is the natural first slice on the merits, not merely by
convenience. `D-09` makes it the **sole** `no-go` trigger, and `39-CONTEXT.md`
records it as both the cheapest experiment and a precondition for the other four —
so if this slice returns `corrupts` or `not-taken`, the verdict is already
determined and the four expansion plans behind it are known-moot before they are
dispatched. It is also where three of the phase's four load-bearing research
assumptions get settled: nothing in this repository has ever opened a socket to the
text-monitor port, so the exact connect banner, the exact prompt bytes and the
port's bind-time budget are all unmeasured until this task runs.

Output: the shared probe harness, the throwaway text client, the idle-coexistence
probe, its evidence file with one gate input and four recorded facts, and the
seeded verdict document.

**Ordering:** this is the first *measuring* plan and it comes after `39-01`, which
is the pre-commitment. The rules land in `39-01`'s commit and this slice's
measurement in a later one — git order is the proof and it is not inverted to
satisfy a tracer-first shape.

**Reversibility note:** the `one-way` ratings on this plan's tasks carry
`39-CONTEXT.md`'s own ratings forward rather than re-deriving them. No
`checkpoint:decision` precedes them because the owner already chose each of those
doors at `/gsd-discuss-phase` — re-asking a decision already recorded produces
checkpoint fatigue, not a gate. The phase's one genuinely unasked door, the rule
text and its ordering, is gated at `39-01` Task 1.
</objective>

Build the thinnest complete path and take one real measurement on it. Three
scripts and one evidence file, all under the phase evidence directory.

**`probe-harness.mjs` — the one place this phase's probes do host things.** Every
later probe imports it rather than re-deriving any of it. Carry the project's
structured header: why the file exists, what it is the ONE place for, and what not
to do — with the "what not to do" naming the specific incidents, not generalities:
never add a passthrough argv parameter (an externally-derived string reaching
`execve`), never run without the refusal check (Phase 33's own postmortem records a
plan that ran a probe as a habit, orphaned five emulators, and had to void sixteen
subsequent runs whose numbers then moved), never single-shot connect after spawn on
either port, and never resolve the emulator by bare name.

Export these:

  - `VICE_STOCK` and `VICE_FORK` as the two resolved absolute paths — the genuine
    unpatched stock 3.9 build and the fork 3.10 build. The absolute path is
    load-bearing: the fork shadows stock on bare `PATH`.
  - `viceKind(path)` deriving the literal token `stock` or `fork` **from the
    resolved path itself**, never from an environment variable. The existing binary
    fixture tree records a real incident where an operator-supplied kind token
    mislabelled the fork as stock for over two months; deriving it removes the
    class.
  - `viceVersion(path)` running the binary's own version flag and returning the
    reported version string, for the `VICE_VERSION_OBSERVED:` line.
  - `systemdBrokerState()` and `aliveX64sc()` reading the broker unit's active
    state and any live emulator PIDs.
  - `preflight()` which logs both observations and **throws** — not warns — when
    the broker is anything but inactive or when any other emulator process is
    alive, with a message naming the observed value and stating that the
    measurement was not taken. Support a `--preflight` entry point on this module
    so the refusal path is runnable on its own.
  - `allocPorts()` returning two distinct, free, probe-chosen localhost ports (bind
    a throwaway listener on port 0 twice, read the assigned ports, close). The probe
    owns both port numbers, which is precisely why no broker plumbing is needed.
  - `buildProbeArgs({ binaryPort, textPort, headless })` reproducing the shipped
    stock-branch argv order exactly: the reset-to-defaults flag first, optionally
    the console flag, the drive-type pair, then the **imported** frozen
    determinism-flag array, then the binary-monitor flag and its loopback address
    pair, then the text-monitor flag and its loopback address pair last. Import the
    determinism array from the shipped launcher module; do not retype any flag
    spelling or seed value from it. Both addresses bind `127.0.0.1` only — never a
    wider bind, which the shipped launcher itself warns about because both monitors
    are unauthenticated.
    In the same function's comment, record the ordering distinction as a fact and
    an assumption respectively: the reset-to-defaults flag preceding the
    binary-monitor flag is MEASURED on this host and documented in the project
    constraints; the same discipline for the text-monitor flag is **assumed, not
    measured**, because nothing has ever dialed that port. Do not state the second
    as fact.
  - `spawnVice(binPath, args)` plus a `CHILDREN` set and `reapAll()` registered on
    process exit and on the interrupt and terminate signals, so no orphan emulator
    survives to answer a later run.
  - `connectWithRetry(client, port, { budgetMs })` retrying a refused connection
    inside a budget, used for **both** ports independently — the text port has no
    measured bind-time budget on file, so it is retried rather than assumed to
    match the binary port's. Return the elapsed milliseconds so the caller can
    record the observed budget.
  - `pingReady(client)`, `armNonStoppingExec(client, { address })` arming an exec
    checkpoint with stop-on-hit **off**, and `checkpointHitCount(client, cpId)`
    reading that checkpoint's own hit count. Build every command body with the
    shipped encoders and send it with the shipped monitor client; encode nothing on
    the wire in this file.
  - `testAutomatedBaseline()` running the gated automated suite from
    `src/mcp/vice` and returning the observed totals and failing file names, for
    the `TEST_AUTOMATED_BASELINE:` and `TEST_AUTOMATED_BASELINE_FILES:` lines. It
    reports what it observed; it never asserts a count.
  - `PROBE_DIR` pointing at the phase cache directory under the user's home cache,
    never inside the checkout and never under the system temporary directory, which
    is a RAM filesystem on this host.
  - `log()` and `sleep()`.

**`textmon-probe-client.mjs` — the throwaway text client.** Same structured
header, with its "what not to do" stating in full: this client is deliberately
crude; it does not solve framing that survives the prompt arriving split across TCP
segments and does not distinguish a prompt-shaped substring inside command output
from a real terminator; solving that properly is a later phase's owned scope and
building it here would be that phase's code under another name; and nothing in this
file is promoted into any module under `src/`.

Export `PROMPT_RE` (a prompt matcher anchored at the end of the accumulated
buffer), `connectTextMonitor(port)`, `awaitBanner(sock, { timeoutMs })` which
returns the raw bytes received before the first prompt without sending anything,
`sendAndAwaitPrompt(sock, command, { timeoutMs })` returning the full accumulated
raw response, and `closeTextMonitor(sock)`. Buffer as `Buffer` and expose the raw
bytes as well as a decoded string, so the banner can be recorded byte-exactly
rather than through a lossy decode.

**Capture before trusting.** The first thing the probe does after connecting to the
text port is call `awaitBanner()` and write the raw bytes it received into the
evidence file, in hex and as text, **before** any command is sent. Only then check
whether `PROMPT_RE` matches those bytes. If it does not, correct `PROMPT_RE`
against the observed bytes in this same task and record both the original matcher
and the corrected one in the evidence file — the matcher shape is an unverified
research assumption, and this run is the first observation of the real bytes in the
project's history. Record `TEXT_PROMPT_LITERAL_CONFIRMED:` accordingly.

**`idle-coexist-probe.mjs` — the measurement.** Same structured header, naming what
it measures and the derivation it implements. Sequence:

  1. `preflight()`, then log the broker state and emulator-liveness observations.
  2. Allocate two ports, build argv, spawn the stock baseline binary by absolute
     path, record `VICE_BINARY:` and `VICE_VERSION_OBSERVED:`.
  3. Connect the binary channel with retry; ping until ready. Record the binary
     port's observed time-to-bind.
  4. **Control leg, no text client connected.** Read the KERNAL ROM window
     `$E000`-`$E0FF` three times with a non-halting memory read (side effects off,
     main memory space) and keep the three payloads. Assert the three agree with
     each other; if they do not, the control itself is void — record the void with
     its reason and stop rather than proceeding to compare against a moving
     reference.
  5. Connect the text channel with retry; record its observed time-to-bind as
     `TEXT_BIND_BUDGET_MS_MAX:` and whether the text port needed more budget than
     the binary port. Capture and record the banner as described above. Send
     nothing further on the text channel for the remainder of this leg.
  6. **Is the machine still running with a silent text client attached?** Arm a
     non-stopping exec checkpoint at the IRQ frame anchor `$EA31`, read its hit
     count, wait one second, read it again. Record
     `IDLE_TEXT_CLIENT_HALTS: yes` when it did not advance and `no` when it did.
     This is a recorded fact, not a gate input, and it does not feed the
     `IDLE_COEXIST` decision — but a `clean` read on a machine that a silent text
     client has silently halted is a materially different world from a `clean` read
     on a running one, and the verdict document needs to be able to say which.
  7. **Measured leg, text client connected and silent.** Repeat the three
     `$E000`-`$E0FF` reads. Compare each byte-for-byte against the control
     payloads. Read the binary client's own desync-byte and duplicate-reply
     counters before and after, and count any unsolicited frame that arrived at the
     broadcast request id during the window.
  8. Derive `IDLE_COEXIST` strictly by `SCHEMA.md`'s rule — `clean`, `corrupts` or
     `not-taken` — and take `not-taken` only for the two causes the schema names
     (the text port never accepted a connection, or the binary channel could not be
     established), with the reason named in the transcript. A timeout or an
     unexpected payload is not a reason to record `not-taken`; those are `corrupts`.
  9. Record `REMOTEMONITOR_FLAG_ORDER:`. Use `default-first-assumed` when the run
     succeeded with the assumed order and no alternative was tried. If the text
     port failed to bind, try once more with the text-monitor flag pair moved ahead
     of the binary-monitor pair, record which order bound, and set the value to the
     measured member accordingly — that turns assumption A1 into a fact rather than
     leaving it to poison every other experiment.
 10. `reapAll()`, then append every outcome and fact line to the evidence file.
