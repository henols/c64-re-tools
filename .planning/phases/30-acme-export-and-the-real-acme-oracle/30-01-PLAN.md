**D30-01 — The verify module is TEST-ONLY (USER-D-02, locked).** It mirrors `acme-gate.ts`:
it stands and is exercised on every suite run, is **never** added to `package.json`'s
`files[]`, and is therefore invisible to both `spawn-seam.test.ts`'s scan set and
`check-npm-packages.mjs`'s closure walk. This is what lets it `import { ACME_BIN }` from
`acme-gate.ts` instead of carrying a second copy of the env-var name
(RESEARCH.md Pitfall 6). **The exporter DOES ship.** Reversibility: `costly` — shipping the
verify module later would force it to resolve `ACME_BIN` itself, which `acme-gate.ts:44-51`
forbids by name.

**D30-02 — `export-asm` is a CLI verb only, not an MCP tool** (RESEARCH.md Open Question 2).
The withdrawal notices in both skill trees name the CLI verb and never a tool; adding a tool
would move `check-skill-tool-coverage.mjs`'s floor and grow the curated surface for a route
that writes a file. Reversibility: `reversible` — adding a tool later is purely additive and
inherits MCP-02's construction-level satisfaction (`vice-proxy.ts:3388-3390`).

**D30-03 — Assumption A4's reading, adopted explicitly.** The **byte-diff is the verdict**.
ACME's own result lines are `-v2`'s per-segment `Segment size is N (0xN) bytes (0xA - 0xB
exclusive).` lines on **stdout**; the `Saving …` line is the untrusted aggregate — the
structural twin of the aggregate that lied in the carried false-pass trap. Unanimity means:
every parsed per-segment line must correspond to a block the exporter emitted, with matching
start and exclusive end, and the **first** mismatch drives the verdict. "Refuse to guess when
more than one authoritative line is present" is implemented as: if ACME emits more than one
`Saving …` aggregate line, the outcome is `failed` with a reason naming the disagreement —
never a pick between them.

**D30-04 — The diff subject.** ONE whole-source ACME invocation per verification, `-f plain`,
diffed against an `expectedBytes` buffer the **exporter** builds from the **image** bytes over
its covered ranges with `$00` in the gaps between blocks. This is exactly ACME's `-f plain`
gap zero-fill behaviour (RESEARCH.md Pitfall 7, measured), so padding is never a false
disagreement, and a wrong byte inside a covered range still fails. `expectedBytes` is derived
from the image, never from the exported text — that is what keeps this a round trip rather
than a self-check. **Stated limit, to be written into the module header:** bytes at addresses
no range covers are not checked, because the export makes no claim about them.
Reversibility: `reversible`.

**D30-05 — D-11 is inherited unchanged.** The exporter substitutes store labels through
`renderLine()`'s existing `symbolFor` hook, so symbols still never reach an immediate or
zeropage-family operand. **Every** store label is nevertheless emitted as a header symbol
definition, in a block before the first `* =` (RESEARCH.md Pitfall 4's mitigation), with the
width rule that is correct for both worlds: an address below `$0100` is written with **two**
hex digits, `$0100` and above with **four** (RESEARCH.md Pitfall 5, measured — the
definition's hex-digit count decides the operand width). Reversibility: `reversible`.

**D30-06 — `expectedSegments` is REQUIRED, not optional.** An earlier draft made it optional and
skipped the unanimity rule when it was omitted, recording the skip in `reason`. That is refused: every
consumer in this phase branches on `outcome`, and a caller could therefore obtain `ok` from a verdict
that never ran one of criterion 1's five rules. Recording a shortfall in a string while the field a
human reads says `ok` is *structurally the same failure* as trusting the aggregate line — a pass that
quietly covers less than it appears to, which is the exact defect this module exists to refuse. Making
the option required moves the property from *recorded* to *impossible*: the compiler rejects a call
site that omits it. Every call site in plans 30-01, 30-03 and 30-04 already passes `result.blocks`, so
this costs nothing. Reversibility: `reversible` — widening a required option to optional later is
additive, though it would reopen exactly this hole.

**Reversibility summary: no decision in this phase is rated `one-way`, so no
`checkpoint:decision` task is inserted.** `costly` items (D30-01, and `exportAsm()`'s public
signature, which plans 30-04 and 30-05 bind to) are flagged rather than gated.
</design_decisions>

`verifyAcmeAssembles()` behaviour, in this order:

1. `mkdtempSync(join(tmpdir(), "acme-verify-"))`; everything below runs inside a `try` whose
   `finally` calls `rmSync(dir, { recursive: true, force: true })` — the failure path included,
   because this host's `/tmp` is RAM-backed.
2. Write `source` to `<dir>/export.a`. Compute `outPath = join(dir, "export.bin")` and assert it
   is absent (`existsSync(outPath) === false`) **before** the spawn; record that fact.
3. `spawnSync(options.acmeBin ?? ACME_BIN, [...ACME_VERIFY_ARGV_FLAGS-with-format-substituted, "-o", outPath, srcPath], { encoding: "utf8", timeout: 30_000 })`.
   `ACME_BIN` is **imported** from `./acme-gate.ts`, never re-derived from the environment here.
4. If `r.error !== undefined || r.status === null` → `outcome: "skipped"`, `byteDiff: null`,
   `reason` naming the spawn error code and the binary that was attempted. This branch is
   reached before any exit-status arithmetic exists.
5. Parse stdout into `acmeResultLines` (lines matching the per-segment shape
   `Segment size is <n> (0x<n>) bytes (0x<a> - 0x<b> exclusive).`, capturing `<a>` and `<b>` as
   hex) and `aggregateLines` (lines matching the `Saving …` shape). Parse stderr into
   `diagnostics` using the MSVC shape; classify each as Error / Warning / Serious error from the
   captured severity group. **Warnings never fail.**
6. If any diagnostic is Error or Serious error → `outcome: "failed"`, `reason` quoting the first
   such diagnostic verbatim.
7. If `aggregateLines.length > 1` → `outcome: "failed"`, `reason` naming the disagreement and
   stating that the module refuses to guess between competing authoritative lines (D30-03).
8. Compare `expectedSegments` against `acmeResultLines`' parsed extents — **unconditionally**,
   because the option is required and there is no omitted case: the counts must match and each pair
   must agree on start and exclusive end. The **first** mismatch drives the verdict →
   `outcome: "failed"` with a reason naming the index and both extents.
9. If `existsSync(outPath) === false` → `outcome: "failed"`, `reason` stating that ACME produced
   no output file and that a pre-existing file is the reason this module assembles into a fresh
   directory every time.
10. Read `outPath`, build `byteDiff` with `Buffer.compare` for equality and a byte-wise scan for
    `firstDifferingOffset`. `equal === true` **and** the file was absent before the spawn ⇒
    `outcome: "ok"`; otherwise `"failed"` with a reason naming the offset and both lengths.

`exitStatus` is assigned once, from `r.status`, and is read by nothing in this function.
There is no substring-containment call against `options.source` anywhere in the module.

**Reason precedence is the rule order above, and is stated in the function's JSDoc** so a caller
knows which refusal wins: a source whose own `!error` fires reports the ACME diagnostic (rule 6),
not the absent output file (rule 9), because ACME's own words about why it stopped are more use to
a human than the downstream consequence. Every one of these paths sets `outcome: "failed"` and
leaves `byteDiff` `null` — nothing was read, so nothing can be reported as compared.
