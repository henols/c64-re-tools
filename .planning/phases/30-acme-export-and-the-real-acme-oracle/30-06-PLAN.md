**Why this plan is tagged `requirements: [EXPORT-01]` when it ships no exporter code.** It
discharges EXPORT-01's *last* clause — *"a skipped assembler is not a pass"* — on the only surface a
human actually reads. Six shipped files across two skill trees currently state that
`anno export-asm` is **withdrawn and returns in Phase 30**; the moment plan 30-05 lands the verb,
every one of those sentences is false, and a shipped file that misstates whether a verification
route exists is the documentation form of the exact defect EXPORT-01 exists against. The same clause
is why this plan's own prohibitions forbid the skill text from implying the export self-verifies at
runtime: USER-D-02 keeps the ACME oracle test-only, so the CLI verb writes source and assembles
nothing, and prose suggesting otherwise would present an assembler that never ran as a pass.

**The structural obligation this plan also serves is `REPOINT-02`'s — the gitignored-yet-shipped
`installer/skills/` twin tree — and it is deliberately NOT listed in `requirements`.** `REPOINT-02`
maps to **Phase 29** in `REQUIREMENTS.md`'s traceability table and is already `Complete`; listing it
here would give one requirement two owning phases and claim credit for closing something already
closed. It is honoured here as a standing constraint (see `must_haves`), not as a requirement this
plan discharges. Phase 30's requirement line remains `EXPORT-01, EXPORT-02, EXPORT-03`.

**USER-D-01 is the cause and it has two halves.** `anno export-asm` landed, so six shipped files
across two trees that call it *withdrawn, returning in Phase 30* are now wrong in one direction.
`gen-enums`, `export-lbl` and `import-lbl` did **not** land, so every statement that they return
in Phase 30 is wrong in the other — and no Phase 30 requirement or success criterion ever covered
them.

**Checked, and the answer changes the plan:** neither existing guard would catch this.
`comment-phase-pointers.test.ts` scans shipped `.ts`/`.mts` **comments** for seven assignment
shapes and reads no markdown; `docs-dangling-refs.test.ts`'s FLOW-02 is deliberately scoped to
shipped **string and template literals** only. A stale "returns in Phase 30" in a `SKILL.md` is
invisible to both. So this plan does the repair by hand **and** adds the guard that would have
caught it, tied to the parsed verb set rather than to a list.

Output: both skill trees, the shipped module headers, the guard scripts and the project record,
all saying what is true — plus a new drift guard that fails when they stop.
