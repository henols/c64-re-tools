<objective>
Prove the language does what it exists for: all 105 opcode bytes stock Ghidra omits decode
under the new language, the six electrically unstable and page-crossing-dependent ones read as
**declared unknowns** rather than plausible p-code, the 15 bytes the stock 65C02 language also
claims keep **its** meanings, and the same assertion is observed **FAILING** under
`6502:LE:16:default`.

Purpose: that failing observation is the second half of criterion 1, and it is what
distinguishes the phase delivering from the phase reporting delivery. `OPC-01` and `OPC-02` are
the same work seen from two sides — the eight constructors that failed to compile sit at
exactly the unstable and page-crossing instructions.

Output: the opcode sweep and its three assertions in `ghidra-opcode-live.test.ts`, plus one
evidence file carrying the per-byte decode table under both languages and the 65C02 reading.
</objective>

<decisions>

**D-36-15 — The 105-byte set is derived from the extension source, never typed out.** The
sweep's expected set is computed at test time from the committed
`6502_undocumented.sinc`'s own single-byte opcode constraints, de-duplicated and lowercased,
and its cardinality asserted to be exactly 105. MEASURED at plan time: that derivation over
the committed source yields exactly 105 distinct bytes. A hand-typed list would drift from the
source silently and would make the assertion a statement about the list rather than about the
language.

**D-36-16 — The 65C02 overlap is 15 bytes and is asserted, not assumed.** MEASURED at plan
time by the same derivation over `65c02.slaspec`'s own single-byte constraints: all 15 of them
are inside the 105-byte set — `$1a`, `$34`, `$3a`, `$3c`, `$5a`, `$64`, `$74`, `$7a`, `$7c`,
`$80`, `$89`, `$9c`, `$9e`, `$da`, `$fa`. Two of those, `$9c` and `$9e`, are in the
eight-constructor compile-failure set, so the overlap and the fix touch the same bytes. This is
the concrete answer to `OPC-01`'s adjacency question — what happens where two languages'
claims exactly touch — and `OPC-02`'s non-collision check is meaningful precisely because that
set is non-empty.

**D-36-17 — The synthetic sweep is generated in-test, not committed.** One byte of the 105 set
per fixed-size slot at a known address, so the address of each byte is computable and each
decode verdict is attributable to one byte. Generated into the temporary workspace root each
case builds, never committed: a generated layout is cheaper to keep correct than a blob, and
the generator IS the documentation of the layout. Record the layout rule in
`fixtures/ghidra/README.md` so the evidence is readable without re-running the generator.

</decisions>
