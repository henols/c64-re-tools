<objective>
Run the language against **real cracked code** and record the before/after difference, then
take the acceptance run: structural facts no listing-level query can produce, exported through
the decompiler layer, with typed cross-references, per-function accounting, denominator-free
dispatch reporting, and the `DataTypeManager` control observed returning essentially nothing on
the **same image**.

Purpose: this is the phase's fifth criterion and the last of its major ones. `OPC-03` exists
because crack and packer code is exactly where the 105-byte gap bites, and a synthetic sweep
structurally cannot satisfy it. The control exists because writing the export against the
listing's data types is the single most expensive mistake available in this design, and its
symptom is an empty result rather than an error.

Output: the corpus before/after artifact, the acceptance-run artifact, and the phase's
consolidated findings document.
</objective>

<decisions>

**D-36-18 — The corpus exercise runs on the extracted program from the release image, on the
`.prg` route.** MEASURED at plan time: the release image exists on this host, is gitignored and
is never committed; no flat-64K capture of any corpus release exists on this tree. The prior
milestone's own live corpus case established the route — read the image's directory, take its
first entry, extract that entry's program bytes — and this plan reuses it rather than inventing
a second extraction path. Recorded as a decision because it narrows `OPC-03` to the `.prg`
route, and that narrowing is stated rather than absorbed.

**D-36-19 — The acceptance run and its control are the SAME image, one script argument apart.**
Not two images, not two scripts. `GHID-04` requires the control on the same image as the
acceptance run, and plan 36-03 made that structural by putting both modes in one script behind
a mode argument. This plan runs them back to back on the same extracted program and records
both count sets side by side.

**D-36-20 — The corpus cases carry a second, narrower opt-in.** `VICE_LIVE_GHIDRA_CORPUS` in
addition to the file-level `VICE_LIVE_GHIDRA`, mirroring the prior milestone's own corpus-case
gating. The image is gitignored, so a machine without it must skip with a reason naming the
expected path rather than fail.

</decisions>
