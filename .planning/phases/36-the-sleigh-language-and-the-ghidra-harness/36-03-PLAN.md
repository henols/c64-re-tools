`GhidraStructExport.java`, named for their function, never their originating phase

acceptance run. One script with an explicit mode argument makes "same image" structural: the
same `.java` file, the same import, the same analysis state, one flag apart. A second script
would make the sameness a matter of the caller remembering, which is the shape of failure the
control exists to catch.

**D-36-10 — The `bank` fixture is committed as source AND assembled output.** Precedent in
this tree: `src/mcp/vice/fixtures/dxa/` commits both `fixture.a` and `fixture.prg`. The
source is copied from the committed `.planning/notes/dxa-ghidra-pivot-evidence/bank.a`, which
is the fixture the volatile-carve hazard was originally demonstrated on. Committing the
assembled `.prg` too means the live suites do not need ACME on the machine that runs them.
The flat-64K variant is NOT committed: it is generated in-test from the same body, because a
65,536-byte blob in git buys nothing a five-line generator does not.

**Script arguments.** `getScriptArgs()[0]` is the output path, required, throwing a named refusal when absent or empty. `getScriptArgs()[1]`, when present, is an expected classification line count used as an OVERRIDE for the internal assertion — it exists so `GHID-01`'s gate 1 can plant a deliberately wrong expectation and observe the throw. `getScriptArgs()[2]`, when present, selects the export mode: the `DecompInterface` route by default, or the `DataTypeManager` control route when explicitly named. Name both modes as constants and print which one ran.

**Fix the classification expectation (`GHID-01`).** Compute the expected count from `mem.getBlocks()` inside the script — the sum of the block sizes over the program's own memory blocks — print both the computed expectation and the observed count on their own labelled lines, and assert equality internally. When `getScriptArgs()[1]` is present, assert against THAT value instead and say on its own line that an override was used, so a planted wrong expectation is visible in the log rather than mistaken for the real thing. No fixed number, and no image size, appears in this assertion. Throw loudly on a mismatch: a short classification file looks exactly like a complete one, and every count computed over it is wrong.

**The `DecompInterface` walk (`GHID-04`).** Open a `DecompInterface` on the current program and walk every function from the function manager in ascending entry-point order. Per function, decompile with a timeout named by a constant whose value is stated in a comment, and increment exactly one of three counters: decompiled when the result completed, timedOut when `isTimedOut()` reports true, and neither-nor recorded as its own explicitly-labelled category so it cannot be silently absorbed. Increment attempted unconditionally. After the loop, emit an accounting section carrying attempted, decompiled, timedOut and the neither-nor count, and assert internally that attempted equals decompiled plus timedOut plus the neither-nor count; throw loudly on a mismatch. Assert the timedOut count is at or below a named ceiling constant and throw naming both numbers when it is not. When attempted is zero, emit an explicit labelled zero-function line — an empty section is indistinguishable from a complete one, which is the whole failure shape this accounting exists to catch.

**The five structural facts (`GHID-04`).** From each completed decompilation's printed C text and its high function, emit a structural-facts section carrying, each on its own labelled line with the function and address it was found at: an array bound; the split-pointer idiom, detected either by scanning the printed C text for the `CONCAT11` call form or by walking the high function's p-code for an operation whose opcode equals `PcodeOp.PIECE`; a record stride; a resolved computed jump; and a self-modifying write target. Where a kind is not found, emit an explicit labelled not-found line for it rather than omitting the line — an omitted line reads as a fact that was never looked for.

**Unresolved dispatch, with NO denominator (`GHID-04` NARROWED).** Emit a count and then one line per site. Emit no ratio, no percentage and no total-sites figure. Naming a denominator this milestone cannot source is exactly the defect the unreproducible published headline was; state that in a comment so a later editor does not helpfully add one.

**Typed cross-references (`GHID-05`).** Keep the ancestor's uncapped reference loop and its `Reference.getReferenceType()` printing unchanged, and keep the written-count line. Add no numeric bound to the loop. State in a comment that the access kinds the annotation join consumes must all survive, and that nothing filters by kind.

**The `DataTypeManager` control mode (`GHID-04`, `D-36-09`).** In the control mode, do not touch `DecompInterface` at all: query the composites and the defined data through `DataTypeManager` and emit the same section headers with whatever that route yields plus an explicit count line per section.
