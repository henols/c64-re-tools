<decisions>

**D-36-11 — Two live suites, not one, registered in a single commit.** `36-VALIDATION.md`
anticipated one new live suite. Two are landed instead: `ghidra-live.test.ts` for the harness
half (`GHID-01`..`GHID-05`) and `ghidra-opcode-live.test.ts` for the language half
(`OPC-01`..`OPC-04`). Reason: with one file, every remaining plan in the phase would contend
on it and the whole phase would serialise, even though the volatile-carve work and the opcode
work are otherwise disjoint. Two files cost one extra `MANUAL_ONLY_TESTS` entry, and both
entries plus the enumerating assertion land in THIS commit so the next wave's two plans touch
neither `test-gate.mjs` nor each other.

**D-36-12 — Every live run uses a temporary directory as its workspace root, and tears it
down.** `resolveGhidraProject()` computes the run directory under the workspace root it is
given. Passing this repository's own `src/mcp/vice` would leave untracked run directories
there, because the existing `tools/ghidra-runs/` ignore entry is anchored at the repository
root. So each live case creates a temporary root, copies the committed fixtures and the
committed `.java` scripts into it, passes that root, and removes it in a `finally`. This
host's temporary filesystem is RAM-backed with ageing disabled, so an untorn-down tree is
leaked memory rather than leaked disk. Plan 36-01 also added a defensive ignore entry, which
is a second line of defence and not a licence to skip the teardown.

</decisions>
