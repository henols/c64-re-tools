<decisions>

**D-36-01 — Who installs the SLEIGH extension into the host's Ghidra tree** (resolves
`36-RESEARCH.md` Open Question 1). A **dedicated host-tool-seam op**,
`ghidra.installExtension`, materialises the extension and compiles its `.sla`. The
`ghidra.analyze` op then performs a **checked, non-materialising preflight** (landed by
plan 36-02) that refuses **by name** when the requested language id is not declared by an
installed `.ldefs` whose `slafile` exists on disk. Three parts, each load-bearing:
(a) the host-tool seam is this project's only sanctioned out-call route for a runtime
path; (b) a preflight that silently **re-materialised** the extension on every invocation
would mask exactly the failure criterion 1 exists to catch, so it must *check and refuse*,
never *fix*; (c) the refuse-by-name idiom is already proven in `host-tool.mts` — it refuses
by name today when `GHIDRA_HOME` is unset or `support/analyzeHeadless` is absent at the
resolved path, and `findAcmeLib()`/`findDxaBinary()` are the same probe-then-refuse shape.

**D-36-02 — The three stock files are copied at install time, never committed.** The
extension's `.slaspec` needs `6502.slaspec`, and its `.ldefs` names `6502.pspec` and
`6502.cspec`. `36-RESEARCH.md` proposed copying those into the vendored tree. They are
**not** copied into this repository: `ghidra.installExtension` and the compile gate each
copy them from `$GHIDRA_HOME/Ghidra/Processors/6502/data/languages/` into the tree they
build in. Rationale: those are files of the declared host prerequisite, and committing
them would silently pin a Ghidra version inside this repo — the same objection the ROADMAP
already recorded against committing the `.sla`. MEASURED this session at plan time: stock
`6502.slaspec` (8059 bytes) contains **no `@include` of its own**, so one copied file plus
the two spec files is the whole dependency set; a scratch tree of exactly those three
copies plus a one-line `.slaspec` reading `@include "6502.slaspec"` compiles under
`support/sleigh` to exit 0 and a 5094-byte `.sla`.

**D-36-03 — Ordering, and why `OPC-01`'s "earliest task" and the seam-first finding do not
conflict.** `OPC-01` requires the `sleigh` compile gate to be the earliest task in the
phase; `36-RESEARCH.md` finds the seam-argv extension is necessarily the first engineering
task because `buildAnalyzeHeadlessArgv()` has no `-processor` support at all. Both hold,
because the compile gate is a **hermetic test that invokes `support/sleigh` directly** and
needs no seam change whatsoever — exactly as `dxa-build-gate.test.ts` invokes
`vendor/dxa/build.bash` directly. The distinction an executor must not blur: a **test** may
invoke a host binary directly (dxa's precedent; this repository is host-developed with no
devcontainer); the **runtime** path must go through the host-tool seam. The compile gate is
therefore the first layer of Task 1's tracer, and the `.ldefs` id lands in the same commit
as the `-processor` change, as `OPC-04` requires.

**D-36-04 — The promoted Java scripts are named for their function, never their phase.**
`VolatileCarve.java` and `GhidraStructExport.java` (landed by plan 36-03). Reason recorded
here so the naming is a decision rather than a habit: `docs-dangling-refs.test.ts`'s
FLOW-02 state machine scans **shipped** TypeScript string literals for phase numbers, and
the ROADMAP already flags the rename-on-promotion as a guard this phase breaks. Naming them
right from the start is strictly cheaper than a rename later. Never put a phase number in a
shipped string.

**D-36-05 — The run log reaches the container side as a digested output file, not a stdout
field.** MEASURED this session at plan time against real Ghidra 12.1.3: `analyzeHeadless`
writes its log lines — including `INFO  Using Language/Compiler: 6502:LE:16:default:default
(ProgramLoader)` — to **stdout**; stderr carried only a three-line JDK version banner
(53 stdout lines vs 3 stderr lines). READ-IN-SOURCE: `HostToolClientResult` carries
`exitStatus`, `results[]` and `stderrTail` and **no stdout field at all**, so the run log is
structurally unreachable from the container side today. `runHostTool()`'s ghidra branch
therefore writes the child's stdout followed by its stderr to `outputs[0]` — the run-log
slot — before the digest loop, mirroring the existing `dxa.disassemble` stdout-to-file
branch. Both streams are written because the criterion depends on not losing a line.

</decisions>

**The genuine delta, and the decision.** Two nouns lose their monopoly in this phase.

1. **The Ghidra language.** `OPC-04`'s own text records that *every existing artifact in
   this repo names the stock language* — the language is currently **implicit**, and
   `36-RESEARCH.md` MEASURED that `buildAnalyzeHeadlessArgv()` emits no `-processor`
   argument at all. Primary noun: **the language id of a Ghidra run**.
   **Decision: `promote`.** `processor` becomes a **required, non-defaulted** field of every
   `ghidra.analyze` request. Rationale: adding a new language *alongside* a still-implicit
   default is precisely how criterion 1's silent failure happens — a failed `sleigh` leaves
   the stock `.sla` in place and an unchecked run goes green on a language that decodes none
   of the 105 bytes. A required field makes "no Ghidra run reaches `analyzeHeadless` without
   an explicitly named language id" true by construction rather than by discipline.

2. **The import route.** `.prg` and flat-64K are now **two** routes whose behaviour MEASURED
   diverges: the `MemoryConflictException` path is route-dependent, and a pre-script correct
   on one is wrong on the other. Primary noun: **the import route of a Ghidra run**.
   **Decision: `promote`.** `importRoute: "prg" | "flat64k"` becomes a required enum field
   (landed by plan 36-02), mirroring `dxa.disassemble`'s own `imageKind` two-member enum in
   the same module — not an inferred property of the image, and not a free-form
   `loader`/`loaderBaseAddr` string pair. This also closes the argv-injection surface the
   free-string form would have opened.

**Suggested invariant test (offered, not required):** an assertion that no accepted
`ghidra.analyze` request shape omits `processor`, driven over the allowlist tables rather
than over a hand-typed list — it goes red the instant a future phase reintroduces an
implicit default. Task 1's acceptance criteria include the refusal half of this.
