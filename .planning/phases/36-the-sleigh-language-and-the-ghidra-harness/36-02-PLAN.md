<decisions>

**D-36-06 — Named typed fields, never a free-form script-argument array.** `36-RESEARCH.md`
proposed `preScriptArgs?: string[]` / `postScriptArgs?: string[]`. This plan does NOT add
either. Reason: an arbitrary string array cannot be classified as path-bearing or not, so it
defeats both `HOST_TOOL_PATH_ARG_KEYS`'s purpose and `host-tool.test.ts`'s both-directions
census — a caller could pass a path that never reaches `resolveWorkspacePath()`, which is
exactly the threat pattern `36-RESEARCH.md` § Security Domain names. Instead the three
argument values the two scripts actually take become three named, individually-typed fields:
`entrypointsPath` (path-bearing, `-preScript` argument 0), `exportPath` (path-bearing,
`-postScript` argument 0) and `expectedClassificationLines` (a non-negative integer,
`-postScript` argument 1). This mirrors how `dxa.disassemble` landed five named path keys
plus one enum rather than a flag array.

**D-36-07 — `-loader BinaryLoader` is a fixed literal and the base address derives from the
route.** `importRoute: "prg" | "flat64k"` is required, mirroring `dxa.disassemble`'s own
`imageKind` two-member enum in the same module. `loaderBaseAddr` stays available as an
optional anchored-hex field because a `.prg`'s load address is a property of the image, not
of the route; on the `flat64k` route the base is the route's own and a differing value is
refused rather than honoured. `loader` is not a wire field at all. This removes two
free-string argv tokens the research's shape would have introduced.

</decisions>
