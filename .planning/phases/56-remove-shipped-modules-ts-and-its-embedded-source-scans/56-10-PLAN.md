<cut_rule>
## What qualifies for removal in the test file

IN SCOPE: a case whose SUBJECT is the source TEXT of a module, by any route.
NOT IN SCOPE: a case that reads a non-source artifact.

- **D-01.** Whole-case removal is the default.
- **D-02.** A case is exempt only when removal of every source-text assertion still leaves at
  least one assertion that exercises production behaviour.
- **D-03.** An exempt case is stripped in place, byte-for-byte, and renamed to what it now proves.
- **Helper rule.** A module-scope helper goes with its cases only when every caller is itself
  being removed. grep the whole file for other callers first.
- **D-17.** Compare SETS, never counts. Never pin a case count in an assertion.

## What qualifies for repair in a production module

- **D-11.** Repair ONLY the five named modules. The set is bounded by name so it stays checkable.
- The edit shape is: find the clause of the form naming a test file as asserting or allowing a
  fact, remove ONLY that clause, and remove any dangling connective that exists only to attach
  it. Leave every surrounding sentence byte-identical. The constraint is the reason the comment
  exists. The removed clause was only a pointer to enforcement.
- **D-10 (prohibition).** Write NO new prose. Do not compose a replacement justification. Do not
  add a note. Do not add a weaker assertion. The repair is removal and trimming only.
- **D-12.** A stale enforcement claim outside the five named modules may survive. That is
  accepted. Do not widen the sweep.
- **D-13.** Two test files name the doomed module in a comment with no import, and six planning
  maps cite the doomed scanners. All are left stale ON PURPOSE. Do not touch them.
</cut_rule>
