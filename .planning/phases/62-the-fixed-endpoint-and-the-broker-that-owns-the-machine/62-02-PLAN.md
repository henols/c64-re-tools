<objective>
Give the broker a home of its own, one level up from every project, and stop the
codebase teaching a bind rule the owner has reversed.

Purpose: a machine-level broker that writes into whichever project happened to start
it is not a machine-level broker. BROKER-06 is what makes "one broker serves every
project" honest rather than nominal, and it has to exist before Phase 64 stages files
or Phase 63 holds sessions. The prose rewrite rides along because a reader who
faithfully preserves the old header implements the reversed decision.

Output: a new host-bound module owning the machine-level root and every directory
derived from it, its committed compiled copy, and three client-side comment sites
rewritten to state the new rule.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker process → user's home directory | The broker creates and writes directories under a machine-level root outside every project checkout |
| environment → path resolution | An operator-supplied root override becomes a filesystem path the broker creates directories under |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-62-07 | Tampering | `broker-home.mts` path resolution | medium | mitigate | Every resolver returns an absolute, resolved path; a relative override is absolutized before use, so a resolved path can never depend on the broker's current working directory |
| T-62-08 | Information Disclosure | broker-owned state leaking into a project tree | medium | mitigate | The two-project isolation test asserts no resolved path is inside either of two distinct project roots, which is the direct check that broker state cannot land where an unrelated project's `git status` or `git clean` reaches it |
| T-62-09 | Denial of Service | concurrent subdirectory creation | low | mitigate | `ensureBrokerDir` is a recursive, already-exists-tolerant make rather than a check-then-create pair, so two brokers racing on the same path both succeed |
| T-62-10 | Repudiation | stale in-code guidance teaching the reversed rule | medium | mitigate | Task 2's negative and positive greps together make the rewrite structural: the old sentence cannot survive and deletion alone cannot satisfy the gate |
| T-62-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package of any kind; RESEARCH.md records the legitimacy audit as not applicable. Nothing to verify, so no legitimacy checkpoint is required |

**Canon referral (not minted here):** path traversal on an operator-supplied root
override is canon — covered by `/gsd-secure-phase` and ordinary lint rules; a bespoke
prohibition is not minted for it. The override is supplied by the machine's own
operator, not by a remote caller, so it is not a trust-boundary crossing in this
project's threat model.
</threat_model>
