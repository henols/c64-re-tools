<objective>
Narrow what the broker listens on to loopback plus the bridge gateways it actually
finds, and make every way that can go wrong loud rather than silent.

Purpose: the per-boot credential is dropped for the new dial model, so the bind set
IS the access-control mechanism now, not a convenience. A plan that narrows the bind
incompletely is a security regression, not a cosmetic one. This is also where the
control plane stops being a single-address listener, which every later phase's
multi-client story depends on.

Output: an interface enumerator with the owner's name allowlist, a multi-address
listener that shares exactly one pending-acquire queue, a port-conflict refusal
extended to the per-address case, and the two existing assertions D-12 names updated
rather than left red.
</objective>

Export `BRIDGE_INTERFACE_ALLOWLIST` from `src/mcp/vice/broker-control.mts` as a frozen

address, which on untrusted wifi is close to the wildcard bind the settled decision

Export `enumerateBindHosts(opts)` taking a destructured options object with an
optional `networkInterfaces` override defaulting to the platform's own interface
listing (the project's injection convention — the suite has no mocking library, so
an injectable seam is the only testable shape). It returns an ordered array of host
strings.

Identify loopback by the record's own INTERNAL flag, never by the interface name:
the loopback interface is named differently on macOS and BSD, and the flag is the
portable signal. Identify a bridge candidate by matching the interface NAME against
the allowlist among interfaces whose internal flag is false. Filter both to IPv4
address records only — an allowlisted interface commonly carries a link-local IPv6
record as well, and binding that address serves no routing purpose here while
complicating the empty-set logic for no benefit. Return loopback first, then the
bridge addresses in the platform's own enumeration order, and de-duplicate.

Never hardcode a gateway address. A custom container network has its own gateway, so
a fixed literal is wrong by construction; the whole point of D-09 is that the set
comes from the live interface list.

Export `startControlListenerOnHosts(hosts, opts)` alongside the existing
`startControlListener`, which stays exactly as it is so nothing currently calling it
changes. The new function resolves the port once, allocates exactly ONE
pending-acquire queue, then calls the existing `bindControlListener()` and
`attachControlProtocol()` pair once per host, passing that SAME queue every time. Do
NOT implement this by calling `startControlListener()` in a loop: that function
allocates its own queue per call, so N calls would silently fork acquire fairness
into per-listener silos and a request queued via one bound address would never drain
when a slot freed on another. Return the per-host bind results together with the one
shared queue.

Let a per-host bind failure surface to the caller rather than swallowing it: the new
function resolves with both the successfully bound listeners and the per-host
failures, and it is the startup path in Task 2 — not this function — that decides
which failures are fatal. Never leave a partially-bound set with no record of what
failed.

Rewrite the module header (lines 16-20 region) so it no longer prescribes the old
bind rule. State the settled v2.0.0 rule instead: loopback plus the bridge gateway
addresses enumerated once at startup from an interface-name allowlist, never the
wildcard address, never a hardcoded gateway. State that the credential the header
currently describes is dropped for the new handshake model and that the bind
narrowing IS the access-control mechanism now, so a reader cannot conclude the
narrowing is cosmetic. Keep the wire-format and port sentences intact.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local network → broker control plane | The set of addresses the listener binds is the entire network-level access control for the control plane now that the per-boot credential is dropped for the new dial model |
| operator environment → bind decision | An explicitly-set control-host variable directly determines what the broker listens on |
| container → host bridge gateway | A containerized client reaches the broker across a bridge gateway address the broker enumerated at startup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-62-11 | Information Disclosure | `vice-broker.mts` startup bind | high | mitigate | The wildcard default is removed from both the control-plane and broker startup paths, and both removals are asserted by a fixed-string gate against the source and its compiled copy; the bound set is loopback plus name-allowlisted bridge interfaces only |
| T-62-12 | Elevation of Privilege | `enumerateBindHosts` allowlist | high | mitigate | Matching is on interface NAME against four explicit patterns among non-internal interfaces, filtered to IPv4; the machine's own wireless and wired local-network interfaces do not match, so a laptop on untrusted wifi never exposes the control plane there |
| T-62-13 | Spoofing | operator-supplied control host | medium | mitigate | An explicit wildcard value is refused by name before any bind, naming the variable and the observed value, rather than being silently narrowed or silently honoured |
| T-62-14 | Denial of Service | per-address bind failure | medium | mitigate | Only a totally empty bound set is fatal; a single bridge address failing is logged and the broker continues on the reduced set, so one misconfigured bridge cannot take the whole machine's broker down |
| T-62-15 | Tampering | trust boundary drifting after startup | low | accept | D-10 accepts that a bridge appearing or changing after startup is not tracked; the remedy is a broker restart, documented rather than coded. Accepted because the immutable set is what makes the bound set trivially auditable, which is the property the posture now rests on |
| T-62-16 | Repudiation | unknown bound set at runtime | medium | mitigate | The full bound set is printed on standard error at startup as one labelled line, so what is listening is auditable without reading the discovery record |
| T-62-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package of any kind; RESEARCH.md records the legitimacy audit as not applicable. Nothing to verify, so no legitimacy checkpoint is required |
</threat_model>
