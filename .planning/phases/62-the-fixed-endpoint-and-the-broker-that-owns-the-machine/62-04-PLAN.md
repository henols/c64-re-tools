<objective>
Give the user one command to start the broker with, make that command refuse a
below-floor interpreter before it can fail confusingly, and let the broker it starts
own its state at machine level instead of inside whichever project happened to launch
it.

Purpose: the refusal written in plan 62-01 quotes a start command; this is where that
command becomes real. It has to be a fixed string with no path in it, because under
this milestone a containerized client has no bind mount and cannot compute a host
path at all — which is also why the per-project deployment model that used to supply
such a path is obsolete.

Output: a new hand-authored plain-JavaScript entry point that is the package's single
binary target, the broker subcommand behind it, the broker's state resolved from the
machine-level root when nothing names a project, and the two-project integration case
that proves one broker serves both.
</objective>
