Extend `scripts/audit-gate.mjs` with a `--hook` mode. Do not create a wrapper
script: D-12-01 requires exactly one file, and a wrapper is a second file that
can drift. Hook mode calls the same `checkAuditGate()` / `docsGuardFiles()` /
`runGuardsLive()` / `isGatedStatus()` functions check mode uses.

Extend the header comment with a `HOOK MODE:` paragraph stating the exit-code
contract and the fail-closed scoping decision recorded below.

Bounded stdin read (threat T-12-01, hook DoS). Set `process.stdin.setEncoding("utf8")`,
accumulate on `data`, act on `end`. Install a 5000 ms `setTimeout` guard and a
10 MiB byte cap. On timeout or overflow, do not hang: evaluate whatever bytes
arrived for scope (below); if the partial payload is in scope, exit 2 naming the
truncated read as the reason; if not, exit 0. If zero bytes arrived, exit 0 —
scope is unknowable and blocking every tool call in the session is the DoS this
mitigation exists to prevent.

Payload parsing. `JSON.parse` inside try/catch. Never `eval`, `import()`,
`require()` or shell-execute any part of the payload (ASVS V5, threat T-12-03).
Read `tool_name` and `tool_input`.

Scope determination — this is the fail-open/fail-closed boundary, and it is the
open question CONTEXT.md left to the planner. **Decision: fail-closed, narrowly
scoped.** Rationale to record in the header comment and in the phase SUMMARY:
D-12-14 forbids a hatch, and an unhandled internal error inside the gated write
class is indistinguishable from one; but a bug in this script must not be able
to brick every unrelated `Write`/`Edit`/`Bash` call in a session, so the
absolute behaviour applies only once the call is known to be in scope.
Concretely:
  - Out of scope -> `process.exit(0)` immediately, before any `spawnSync`. A call
    is out of scope when `tool_name` is not one of `Write`, `Edit`, `MultiEdit`,
    `NotebookEdit`, `Bash`, or when no `*MILESTONE-AUDIT*` token appears in the
    relevant target.
  - In scope -> every subsequent failure path (unknown payload shape, guard
    spawn failure, unreadable `.planning/`, guard-glob floor violation) exits 2
    with a reason naming the internal failure. Never exit 0 on an error once in
    scope.

Target extraction, field-name-agnostic (Route C — this is what makes RESEARCH
assumption A1 non-load-bearing). Add `extractHookTarget(toolName, toolInput)`
returning `{ pathish, written, shapeKnown }`:
  - `pathish` collects candidate path strings from `file_path`, `path`,
    `notebook_path`, and — for `Bash` — the `command` string.
  - `written` collects candidate written text from a prioritised list of known
    keys: `content`, `file_text`, `new_string`, `new_str`, every
    `edits[].new_string` / `edits[].new_text`, and `command`. Deliberately
    EXCLUDE `old_string` / `old_str` / `old_text`: an Edit that downgrades an
    existing `status: passed` to `status: gaps_found` carries the gated string in
    its *old* side, and blocking that would violate D-12-13's rule that honest
    bad news is never obstructed.
  - If none of those keys is present but `tool_input` is a non-empty object and
    the tool is in the matcher set, set `shapeKnown = false` and fall back to
    `JSON.stringify(tool_input)` as the `written` text, with the same
    `old_*`-key stripping applied first. A `shapeKnown: false` refusal must say
    so in its reason, so a future Claude Code payload rename shows up as a loud
    refusal rather than a silent no-op.

Gated-status detection in the written text. Reuse `isGatedStatus()` semantics
via a helper `writtenDeclaresGatedStatus(text)` that finds any line matching
`/^\s*status:\s*['"]?(passed|tech_debt)['"]?\s*$/im` after stripping `\r`. Allow
leading whitespace here (unlike `frontmatterStatus()`), because a heredoc body
inside a shell command is not column-anchored. `gaps_found` and every other
value are not matched — D-12-13.

Bash-specific targeting (D-12-04). For `tool_name === "Bash"`, require BOTH:
  - a write-indicator immediately preceding a milestone-audit filename token,
    matched by a regex of the shape "redirect-or-writer followed by optional
    whitespace and quotes followed by a path token containing
    `MILESTONE-AUDIT` and ending `.md`", where the redirect-or-writer alternation
    covers `>`, `>>`, `tee` (with optional `-a`), `sed -i` (with optional suffix),
    `perl -i`, and `dd of=`; and
  - `writtenDeclaresGatedStatus(command)` true.
Requiring adjacency is what keeps `grep 'status: passed' <audit> > /tmp/out`
from false-blocking: the redirect target there is `/tmp/out`, not the audit.
Add a comment recording the accepted limitation (threat T-12-02): a base64 or
`python -c` payload that assembles the text at runtime evades this scan by
design; Layer 1 re-reads the actual committed file content and is the unevadable
enforcement point. Do not attempt to parse shell syntax generally.

Write/Edit targeting. In scope when any `pathish` entry's basename contains
`MILESTONE-AUDIT` and ends `.md`, and `writtenDeclaresGatedStatus(written)` is
true.

Verdict. Once in scope, run the guards live via the same `docsGuardFiles()` /
`runGuardsLive()` path check mode uses, rooted at the repo containing the
script (or `--root` if also supplied, so the hook is testable against a
synthetic tree without an env hatch — D-12-14). If no guard is red, exit 0. If
any guard is red, write the full D-12-15 refusal to **stderr** and
`process.exit(2)`.

Output contract (Pitfall 2). Use `exit 2` plus stderr as the sole blocking
mechanism. Do NOT print a `hookSpecificOutput.permissionDecision` JSON blob
alongside it — on current Claude Code, JSON is only honoured on exit 0, and the
combined form is unreliable (upstream `anthropics/claude-code#43407`). Add an
inline comment naming that issue so a future maintainer does not "improve" this
by adding the JSON back.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code runtime → `audit-gate.mjs --hook` stdin | Untrusted-shaped JSON of arbitrary size arrives on every matched tool call; parsed defensively, never executed |
| hook payload text → gated-status scan | Markdown and shell-command strings are matched by regex only; never evaluated, never used to build the guard file list |
| in-scope error paths → session availability | A hook that hangs or crashes stalls every matched tool call in the session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Denial of Service | `--hook` stdin read | mitigate | 5000 ms `setTimeout` guard and a 10 MiB byte cap on the stdin accumulator (same shape as `gsd-prompt-guard.js:36`); `JSON.parse` in try/catch; out-of-scope calls `exit(0)` before any `spawnSync`, so the ~215 ms guard run is only paid on a milestone-audit write.
