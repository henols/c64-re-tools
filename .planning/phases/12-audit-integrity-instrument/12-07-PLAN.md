<hazards>
**Do not plan around the human.** The one thing this plan exists to obtain is an
observation only a human in a hook-loaded session can make. There is no automation
route to it. In particular:

- **No nested headless session.** `claude -p` / `claude --print` from inside this
  executor stalls in this project (a recorded, repeated failure mode), and a
  nested session's hook dispatch says nothing about this session's. This is
  written into `must_haves.prohibitions` because it is the single most likely way
  this plan fails.
- **No direct-subprocess substitute.** `printf '...' | node scripts/audit-gate.mjs --hook`
  is already in `12-GATE-PROOF.md` and is explicitly not what is being asked for.
- **The executor stops at Task 2.** Prepare the commands, prepare the artifact
  skeletons, then stop. Do not attempt the live writes yourself: your own tool
  calls go through the same hook, so a refusal you observe from inside this
  executor is a legitimate observation *if and only if* the hook was loaded for
  this session — which you cannot establish, and which the human's restart is
  precisely what establishes. Report what you see, do not conclude from it.

**The live test creates a real scratch milestone-audit file.** The final step
(after the revert, the same Write succeeds) leaves
`.planning/v9.9.9-MILESTONE-AUDIT.md` on disk declaring `status: passed`. It must
be deleted in Task 3. Left behind, it becomes a permanent member of
`milestoneAuditFiles()`'s discovery set and every future `node scripts/audit-gate.mjs`
run reports one extra gated audit.

**Editing these artifacts:** use the Write and Edit tools. Never `sed -i`, never a
heredoc. Both artifacts contain milestone-audit tokens and gated-status text, so a
Bash command that manipulates them in place is exactly the shape the hook now
detects.
</hazards>
