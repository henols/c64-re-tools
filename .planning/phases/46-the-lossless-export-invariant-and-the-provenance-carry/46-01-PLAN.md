four design forks the researcher surfaced. **These are assumptions, not measurements. Do
not restate any of them as a MEASURED fact anywhere in the code or the SUMMARY.**

- **A1 — provenance annotation is OPT-IN, via an optional `ledgerPath` on
  `ExportAsmOptions`.** Mandatory would break the ~40 existing `exportAsm()` call sites in
  the 2708-line test file just to keep compiling, contradicting the ROADMAP's own "extends
  the shipped `anno-export-asm.ts` against existing fixtures". Criterion 4's "ledger
  absent" state is only reachable and testable if invoking ledger-mode is itself an
  explicit caller action. So "declines by name" means: **the option was supplied and the
  ledger is missing or malformed → refuse by name with the remedy.** A no-ledger export
  does not refuse.
- **A2 — the reader PARSES the persisted `recovery/PROVENANCE.md`; it does NOT recompute
  via `diffRanges()`.** BUILD-05 criterion 4's own wording is "read from the existing
  ledger, never re-derived". Recomputing would force the exporter to import a
  registry-resolution path (`dataRoot()`) it has no other reason to know about, and would
  make "ledger absent" ambiguous between three different missing things.
- **A3 — criterion 3's `HIGH` / `UNKNOWN` / `CRACKER-PATCH` list conflates two separate
  ledger fields.** MEASURED against `diff-images.mjs:702-709`: `HIGH` is a **Confidence**
  value; `UNKNOWN` and `CRACKER-PATCH` are **Verdict** values. Resolution: **carry BOTH
  fields into the emitted comment**, a strict superset of either reading. Recorded so a
  later reader sees the drafting ambiguity was resolved knowingly rather than missed.
- **A4 — the exclusion SETTER is an `anno_*` MCP tool pair (plan 46-04); the export itself
  stays CLI-only.** `.planning/research/ARCHITECTURE.md` Answer 6 recommends the
  paired-verb shape; Answer 1's CLI-only reasoning applies to the export's output tree,
  not to a bounded setter.
