<objective>
Ship D-13's launch half: the broker launches stock `x64sc` with `-remotemonitor`
on a second, broker-allocated port alongside `-binarymonitor`, and the instance
record carries that port so Phase 7 can discover it.

Purpose: there is no binary-monitor command for disk detach. The text monitor's
`detach` exists and `-remotemonitor` coexists with `-binarymonitor`, so
DIRECT-06's detach half moves to Phase 7 (D-13) — but the *launch flag* must land
now, because adding it later would require relaunching a live instance, which
destroys all emulation state. Phase 3 builds no text client and dials nothing on
the second port.

Output: `InstanceRecord.remoteMonitorPort`, an `exclude` option on
`nextFreePort()`, the extended stock argv, the wiring at the two real broker call
sites, the rebuilt `resources/*.mjs` artifacts, and tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker daemon (host) → emulator process argv | the bind address of two unauthenticated monitor sockets is decided here |
| network → the second (`-remotemonitor`) port | a socket nothing in Phase 3 dials, accepting arbitrary text monitor commands |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-07 | Elevation of Privilege / Tampering | the `-remotemonitor` socket's bind address | mitigate | The text monitor binds the SAME resolved host as the binary monitor, defaulting to `127.0.0.1`; widening past loopback emits exactly one stderr note per process naming the resolved address and stating that the text monitor accepts arbitrary monitor commands. No new env var, no separate default |
| T-3-07b | Elevation of Privilege | uncoordinated second client on the text-monitor socket | accept | Phase 3 dials nothing on this port, so there is no ownership conflict to guard yet. Recorded explicitly in `broker-state.mts`'s new field banner so Phase 7's security review does not assume `monitor_claim`/`monitor_release` already covers it |
| T-3-08 | Denial of Service | second-port allocation exhausting the port band | mitigate | The second port comes from the existing bounded `nextFreePort` scan and is `blockPort`ed rather than re-offered; an allocation failure degrades to launching **without** `-remotemonitor` instead of failing the acquire, so a port nothing uses cannot make the backend unavailable |
| T-3-06 | Tampering (unrequested state change) | the launch path | accept | This plan changes only argv and record fields; it starts, stops and resumes nothing, so D-05's no-unrequested-resume policy is untouched. The broker's synchronous `inFlight` guard is asserted unchanged |
</threat_model>
