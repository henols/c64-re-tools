  <action>
    Preconditions, checked first and aborting on failure: the working tree is
    clean (`git status --porcelain` empty), `git fetch origin` succeeds, and HEAD
    still matches the sha 03-17 recorded (if it moved, re-run 03-17's task 1
    rather than pushing an unvalidated tree).

    Then, per the authorised route ONLY:

    - `defer`: perform no remote action. Record the deferral and stop. The gap
      stays open by explicit developer choice, and the SUMMARY must say so.
    - `pr-branch`: create a branch from the current HEAD named
      `ci/phase-03-validation` (append `-2` etc. if taken), `git push -u origin`
      it, then `gh pr create --base main --title "CI: validate phases 01-03"` with
      a body stating this PR exists to run CI against the milestone tree and
      naming the phases it covers. Do not merge it.
    - `push-main-skip-release`: verify the head commit's SUBJECT contains
      `[skip release]`; if it does not, create an empty commit
      (`git commit --allow-empty`) whose subject carries the marker, then
      `git push origin main`. Never amend an existing commit to add the marker.
    - `push-main-release`: `git push origin main` with no marker. Before pushing,
      restate in the run log that this publishes both npm packages.

    Then watch the run to a conclusion: `gh run list --limit 5` to find it,
    `gh run watch <id>` (or poll `gh run view <id> --json status,conclusion`)
    bounded to ~20 minutes. Record the run URL, the sha, per-job conclusions, and
    — for main pushes — whether `release-on-merge` ran and what it published.

    On failure: capture the failing step and `gh run view <id> --log-failed`
    (last 50 lines). Do NOT push fixes, re-run, or adjust the workflow from this
    plan. Report it; a fix is a separate gap-closure plan.
