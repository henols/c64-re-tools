<objective>
Close the Phase 3 UAT **blocker**: `vice_registers_set` refuses every register on
every real VICE build.

`stock-registers.ts:260-268` compares the catalog's `size` field against the byte
counts `1` and `2`, but that field is copied verbatim (line 110-111) from
`REGISTERS_AVAILABLE`'s wire size byte, which VICE reports in **bits** — live
evidence from genuine stock VICE 3.9 (03-UAT.md test 5): `PC size16`, `A size8`,
`LIN size16`. Every real register therefore falls through to the "unexpected
declared size" refusal, so the tool is unreachable end-to-end. The existing unit
tests missed it because `REGISTER_FIXTURE` (stock-registers.test.ts:34-41) stubs
`size` as 1/2 — encoding the code's wrong assumption rather than the wire's truth.

Root cause is already diagnosed and verified. Do NOT re-diagnose; implement.

The fix makes the unit explicit in the type (`size` -> `sizeBits`) rather than
converting bits to bytes at the boundary, so a future reader cannot repeat the
same misreading, and derives the maximum from the width itself instead of a
two-branch magic-number ladder.

Purpose: DIRECT-02 is currently a false green — the phase claims register writes
work on stock and they do not.
Output: a working `vice_registers_set`, a wire-shaped regression fixture, and a
manifest that no longer calls a bit count a "byte size".
</objective>
