Behaviour, exactly:
- The module holds ONE module-level `WeakMap<ViceMonitorClient, RunStateTracker>`.
  `attachRunStateTracker()` is **idempotent**: if the client already has a tracker
  in the WeakMap it returns the existing one and registers NO second listener.
  This closes RESEARCH.md Pitfall 4 (double registration) structurally rather than
  by call-site discipline.
- Initial value is `"unknown"` (D-07). Do not initialise from anything else — in
  particular do not assume `"stopped"` after a handshake, and do not attach inside
  `stockConnect()`, because the handshake's own `PING`+`EXIT` pair would then be
  projected as the *user's* run state. The attach call site is plan 03-12's
  business; this module only provides the function.
- The single `client.on("event", ...)` listener updates state as: `"stopped"` on
  `item.type === "stopped"`, `"stopped"` on `item.type === "jam"`, `"running"` on
  `item.type === "resumed"`. Every other event type (`"checkpoint_info"`,
  `"registers"`, the `unknown` fallback shape) leaves the state untouched.
- The listener is the SOLE writer. There is no setter, no `set()` on
  `RunStateTracker`, and no exported mutator — D-06's "projection, never derived
  from the commands sent".
- The listener performs no I/O and never calls `client.send()` (the standing
  "never send from inside the event handler" rule).
- `runStateFor(client)` returns `"unknown"` when no tracker is attached — the
  honest answer, never a throw, since a handler must be able to answer even on a
  client nothing attached to.
- `resetRunStateTrackersForTest()` replaces the module-level WeakMap with a fresh
  one, matching `clearHeldStockSession()`'s role in `stock-dispatch.test.ts`'s
  `beforeEach()` convention.

`parseAddress` accepted forms, exactly:
- a JS `number` that is an integer in `0..0xffff`
- `"$1000"` / `"$1f"` — leading `$`, hex digits, case-insensitive
- `"0x1000"` / `"0X1000"` — hex
- `"4096"` — **decimal** (a bare numeric string with no prefix is decimal here;
  this is the MCP argument surface, not VICE's condition lexer, where bare
  literals are hex — do not conflate the two, and say so in the doc comment)
- surrounding whitespace is trimmed

Refusals (throw `StockAddressError` with a message naming the offending value and
the accepted forms):
- out of `0..0xffff`, including negatives and non-integers
- an empty string, `"$"`, `"0x"`, `"$$1000"`, `"0xzz"` and any other malformed
  numeric form
- a value that is neither a number nor a string
- **a symbolic name** (matches `/^[A-Za-z_][A-Za-z0-9_.]*$/` and is not a valid
  numeric form) when no resolver is installed: the message must state that no
  symbol table is loaded and that a numeric or `$hex` address is required — it
  must NOT read as a parse/syntax error (D-04's explicit requirement). When a
  resolver IS installed and returns `undefined`, refuse naming the symbol as
  unknown.

`parseByteCount` accepts the same numeric forms, defaults `max` to `0xffff`, and
refuses `0`, negatives, non-integers and values above `max`, so the `size`-style
range check is not re-derived per family either.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent/LLM → stock handler arguments | untrusted `address`/`size` values cross here and become wire bytes |
| container MCP server → binary-monitor socket | an encoded body reaches an unauthenticated monitor with full memory read/write |
| emulator → agent-facing error text | a wire error code becomes prose an agent will act on |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Information Disclosure / Tampering | `parseAddress()` / `parseByteCount()` in `stock-address.ts` | mitigate | Range-check every address to `0..0xffff` and every count to `1..0xffff` before any value can reach an encoder, so an out-of-range or NaN value can never be written into a `u16LE` field and silently wrap to a different address |
| T-3-06 | Tampering (unrequested state change) | `stock-runstate.ts`, `stock-handler.ts` | mitigate | Neither seam calls `client.send()` at all (grep-gated to 0 occurrences in `stock-runstate.ts`), so no shared seam can issue an `EXIT` the agent did not request (D-05); the projection is read-only and its sole writer is the event listener |
| T-3-04 | Denial of Service (misdiagnosis) | `convertWireError()` | mitigate | Wire error codes get distinct, specific text and the words `wedge`/`hung`/`unresponsive` never appear, so a legitimate `ObjectMissing` or `CmdFailure` cannot misdirect `vice-wedge-triage` into treating a working emulator as wedged |
| T-3-02 | Tampering (session integrity) | `runStateFor()` default | accept | An unattached client answers `"unknown"` rather than throwing; `"unknown"` is the state D-07 already gates the execution tools on, so the fail-open direction here is the conservative one |
</threat_model>
