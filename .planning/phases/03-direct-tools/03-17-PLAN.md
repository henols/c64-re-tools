<objective>
Close the Phase 3 UAT gap "CI validates the tree before a phase is verified".

Local `main` is **214 commits ahead of origin/main**; the last CI run was
2026-08-11 (68b0a79), predating all Phase 01/02/03 work. Every green-CI signal
available describes a tree that no longer exists.

This gap is a process gap, not a code defect, and a plan can only do two honest
things about it: (1) reproduce CI locally so the outcome is known rather than
hoped for, and (2) obtain explicit authorisation before touching the remote.

**Why authorisation is mandatory and cannot be auto-advanced.** `ci.yml`'s
`release-on-merge` job runs on every push to `main`, bumps the patch version off
what is published on npm, and publishes **both** `@henols/vice-mcp` and
`@henols/c64-re-tools` to the public registry via OIDC — unless the head commit's
SUBJECT line contains `[skip release]`. Pushing 214 commits to `main` is
therefore a release event affecting downstream consumers, not merely a CI
trigger. A `pull_request` against `main`, by contrast, runs only the `build` job:
no release, no publish, no tag.

Purpose: Phase 3 cannot be marked verified on CI evidence that predates the
milestone.
Output: a CI-equivalence result table and an authorised route. Plan 03-18
executes it.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repo -> origin (GitHub) | pushing crosses from private state into a trigger for automated jobs with write and OIDC permissions |
| CI -> public npm registry | `release-on-merge` holds `id-token: write` and publishes to consumers with no further human gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-17-01 | Elevation of Privilege | `release-on-merge` auto-publish on push to main | mitigate | Blocking decision checkpoint states the consequence explicitly before any remote action; the recommended route (`pr-branch`) cannot reach the release job at all |
| T-03-17-02 | Tampering | publishing an unfinished milestone to consumers | mitigate | The `push-main-release` option names the 3-of-8-phases state in its cons so the choice is informed; the default recommendation avoids it |
| T-03-17-03 | Information Disclosure | pushing local-only artifacts or secrets | mitigate | Task 1 ends with a `git status --porcelain` check; `dist/` is confirmed gitignored; nothing is added to the index by this plan |
| T-03-17-04 | Repudiation | trusting stale CI as evidence | mitigate | The ahead/behind count and HEAD sha are recorded in the SUMMARY, so any future claim of CI coverage names the exact commit it applies to |
| T-03-17-SC | Tampering | package installs | accept | `npm ci` installs from the committed `package-lock.json` only; no new dependency is added and no version is changed by this plan |
</threat_model>
