<objective>
Advertise the stock surface: write all 24 new `tools-manifest.stock.json` entries
(plus an `outputSchema` for the existing `vice_ping` entry), then close D-02's
contract with a harness that invokes every handler against a stubbed session and
validates its actual answer against its own declared `outputSchema`.

Purpose: D-02 makes `outputSchema` the *enforced* contract rather than a prose
divergence list, and this is where the enforcement lands. `outputSchema` has zero
precedent anywhere in this repo — `grep -c outputSchema tools-manifest.json` returns
0 — so the shape is designed here from the checker's supported subset.

`vice-proxy.ts` needs **no change**: it reads the manifest and serves whatever
`tools` array it finds, so `outputSchema` passes through as inert extra JSON that a
client which does not understand it simply ignores. Confirm that by reading, do not
assume it.

Output: a 25-entry stock manifest and the conformance harness. This plan is the last
wave because both files are shared with plan 03-12.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| manifest → agent's model of the backend | `tools/list` is what an agent believes the stock backend can do and what shape its answers take |
| `inputSchema` → handler arguments | the declared schema is the first thing that constrains what an LLM sends |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-09 | Spoofing (capability misrepresentation) | `outputSchema` on every entry | mitigate | Every entry declares its answer shape and a test dispatches the real handler and validates the real answer against that declaration, so an entry cannot advertise a shape the handler does not produce.
