<objective>
Ship the memory half of Family A on the stock backend: `vice_memory_read`,
`vice_memory_write` and `vice_memory_banks`, as `StockSessionHandler`-shaped
exports in a new `stock-memory.ts`.

Purpose: this is the first half of phase success criterion 1 — reads must be
side-effect-free by default and must not force a pause/resume round trip. On stock
there is no round trip at all: the command halts the machine (D-05) and the answer
reports `runState`.

Output: `stock-memory.ts` and `stock-memory.test.ts`. This plan registers nothing
in the dispatch table and writes no manifest entry — plan 03-12 and 03-13 own
those files, so this plan can run in parallel with the other family plans.
</objective>

`export const handleMemoryRead: StockSessionHandler`:
- Arguments: `address` (required, through `parseAddress`), `size` (required,
  through `parseByteCount({ max: 0xffff })`), `bank` (optional string name),
  `encoding` (optional, `"hex" | "array"`, **default `"hex"`** — the divergence
  recorded in the parity doc), and the stock-only optional
  `sideEffects` (boolean, **default `false`**) permitted by D-03.
- Compute `end = start + size - 1` and refuse with an explanatory message when
  `end > 0xffff`, naming both the start and the size — never truncate silently.
- Resolve `bank` through `bankCatalogFor(session)` (Task 2). An unknown bank name
  refuses, listing the names the catalog actually returned. Omitted `bank` sends
  bank id `0x0000`.
- Memspace is fixed to `0x00` (main) in Phase 3; drive memspace is Phase 6's
  GAIN-03. Say that in a comment rather than adding an unused argument.
- Send `CommandType.MemoryGet` with `memGetBody({ sidefx: sideEffects, start, end, memspace: 0x00, bank })`.
  Wrap the `send()` in `try/catch` and return `convertWireError("vice_memory_read", err)`.
- Refuse a response whose `type` is not `"memory_get"` with text naming the
  observed type (the `stockConnect()` discipline).
- Refuse when the returned `bytes.length !== size`, naming both numbers — a short
  read is a wrong answer, not a partial success.
- Answer through `stockAnswer(session.client, { ... })` with:
  `address` (the resolved numeric start), `size`, `encoding`, `sideEffects`,
  `bank` (the resolved id, plus the name when one was given), `memspace: "main"`,
  and either `hex` (one compact lowercase hex string, no separators) when
  `encoding === "hex"` or `bytes` (an array of numbers) when
  `encoding === "array"`. Exactly one of `hex`/`bytes` is present.

`export const handleMemoryWrite: StockSessionHandler`:
- Arguments: `address` (required, `parseAddress`), `data` (required, an array of
  integers `0..0xff`; refuse a non-array, an empty array, a non-integer element or
  an out-of-range element, naming the offending index), `bank` (optional, same
  resolution as read).
- Compute `end = start + data.length - 1`, refuse when `end > 0xffff`.
- Send `CommandType.MemorySet` with
  `memSetBody({ start, end, memspace: 0x00, bank, data: Buffer.from(data) })`.
  `memSetBody` forces `sidefx` to 0; a write is not a read and takes no
  `sideEffects` argument.
- Same wire-error and unexpected-type handling.
- Answer through `stockAnswer()` with `address`, `bytesWritten` (`data.length`),
  `bank`, `memspace: "main"`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent/LLM → `address`/`size`/`data`/`bank` arguments | untrusted values become a memory range the emulator will read or overwrite |
| container MCP server → binary-monitor socket | `MEM_SET` grants arbitrary write access to the emulated machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Tampering / Information Disclosure | `handleMemoryRead`'s `sidefx` byte | mitigate | `sideEffects` is a stock-only optional argument defaulting to `false`, so `memGetBody`'s byte 0 is `0x00` unless the caller explicitly opts in. Asserted at the byte for a read of `$D019`, the register whose side-effecting read acknowledges the IRQ and silently alters the debugged program's behaviour |
| T-3-01b | Tampering | address/size range arithmetic | mitigate | `parseAddress`/`parseByteCount` bound both arguments, and `end = start + size - 1` is refused when it exceeds `0xffff` naming both inputs — so a range cannot silently wrap into a different region, and a short read is refused rather than reported as a partial success |
| T-3-01c | Tampering | `handleMemoryWrite`'s `data` array | mitigate | Every element is checked to be an integer in `0..0xff` with the offending index named; a non-array, empty array or over-long array is refused before any body is built |
| T-3-06 | Tampering (unrequested state change) | this module | mitigate | Grep-gated to zero `CommandType.Exit` references: a read leaves the machine halted and reports `runState: "stopped"` rather than resuming it (D-05) |
| T-3-05 | Information Disclosure | this module | accept | No path arguments and no filesystem access — `hostpath.ts` is not a consumer here (D-17's declared table does not list any memory tool) |
</threat_model>
