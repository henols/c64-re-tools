Add a new section to `stock-protocol.ts`, opened with the banner comment

    // ---------------------------------------------------------------------------
    // Request-body encoders (Phase 3)
    // ---------------------------------------------------------------------------

placed after `encodeRequestHeader()` and before the response-parser section, with
a block comment stating that these are the ONLY functions in the tree that turn
tool arguments into wire body bytes, that five of them are ported from
`probe-binmon.mjs`'s already-tested builders, and that a caller must never
hand-assemble a body Buffer.

Every encoder takes a single plain options object (never positional args, except
`cpNumBody` which takes one number) and returns a `Buffer`. Add these exports:

1. `memspaceByte(memspace?: number): number` — the shared validator. Accepts
   `undefined` (→ `0x00`, main) and `0x00`-`0x04`. Refuses anything else by
   throwing a `StockProtocolError`-family error whose message states that the
   wire memspace byte is `0x00` = main and `0x01`-`0x04` = units 8-11 and that
   `0x08` (VICE's internal enum value) is rejected by the monitor. Every encoder
   below that takes a memspace routes through this function.
2. `memspaceBody({ memspace }): Buffer` — the one-byte body shared by
   `REGISTERS_GET` (0x31) and `REGISTERS_AVAILABLE` (0x83).
3. `memGetBody({ sidefx = false, start, end, memspace, bank = 0x0000 }): Buffer`
   — **always exactly 8 bytes**: `sidefx(1) start(u16LE) end(u16LE) memspace(1)
   bank(u16LE)`. `sidefx` is a boolean in the TS signature and defaults to
   `false`, encoded as byte `0x00` — DIRECT-01's side-effect-free-by-default. The
   JSDoc must state why the body is always 8 bytes (stock VICE's handler
   dereferences the body before its length check). Range-check `start`, `end`,
   `bank` to `0..0xffff` and require `end >= start`.
4. `memSetBody({ start, end, memspace, bank = 0x0000, data }): Buffer` — the same
   8-byte header with `sidefx` forced to `0x00`, then `data` copied at offset 8.
   Refuse when `data.length !== end - start + 1`, naming both numbers.
5. `cpNumBody(checkpointNum: number): Buffer` — 4 bytes, `u32LE`. Shared by
   `CHECKPOINT_GET` (0x11) and `CHECKPOINT_DELETE` (0x13). Range-check to
   `0..0xffffffff`.
6. `checkpointSetBody({ start, end, stop = true, enabled = true, operation, temporary = false, memspace }): Buffer`
   — 8 bytes, or 9 when `memspace` is supplied:
   `start(u16LE) end(u16LE) stop(1) enabled(1) operation(1) temporary(1) [memspace(1)]`.
   `operation` is the op bitmask: load `0x01`, store `0x02`, exec `0x04`. Export
   the three values as `export const CheckpointOperation = { Load: 0x01, Store: 0x02, Exec: 0x04 } as const;`
   so no family module hardcodes them. Refuse `operation === 0` (a checkpoint
   that watches nothing) naming the three flags.
7. `checkpointToggleBody({ checkpointNum, enabled }): Buffer` — 5 bytes,
   `checkpointNum(u32LE) enabled(1)`.
8. `conditionSetBody({ checkpointNum, expression }): Buffer` —
   `checkpointNum(u32LE) exprLen(1) expr(ASCII, NOT NUL-terminated)`. Port
   `probe-binmon.mjs`'s >255-byte guard verbatim, throwing BEFORE encoding, and
   keep that file's own comment framing it as the ASVS V5 control (a silently
   truncated frame desyncs the stream). Also refuse an empty expression and any
   non-ASCII byte in the expression, naming the offending character index — the
   condition lexer is ASCII-only and a multi-byte UTF-8 character would produce a
   byte length that disagrees with the character count the caller reasoned about.
   The JSDoc must state that this function is the ONLY place condition text
   becomes wire bytes and that its input must always come from
   `stock-condition.ts`'s emitter, never from a raw caller string.
9. `registersSetBody({ memspace, items }): Buffer` where
   `items: Array<{ id: number; value: number; size?: number }>` —
   `memspace(1) count(u16LE)` then per item `itemSize(1) regId(1) value(u16LE)`
   with `itemSize = 3` (the byte count following the itemSize byte itself),
   matching the `offset += itemSize + 1` stride the `RegisterInfo` parser reads.
   Refuse an empty `items` array, an `id` outside `0..0xff`, and a `value`
   outside `0..0xffff`. The JSDoc must point at the parser case this inverts, by
   line reference, so the two stay in sync.

Add the encoder-shape test cases to `stock-protocol.test.ts`, in that file's
existing golden-table style. For each encoder assert the exact `body.length` and
then hand-decode each field at its literal offset (`body[0]`,
`body.readUInt16LE(1)`, …) rather than re-calling the encoder — an assertion that
re-derives the offsets from the implementation proves nothing. Required cases:
`memGetBody({ start: 0xd019, end: 0xd019 })` has length 8 and `body[0] === 0x00`;
the same call with `sidefx: true` has `body[0] === 0x01`; `memspaceByte(0x08)`
throws with a message containing `0x08`; `memSetBody` with mismatched data length
throws; `checkpointSetBody` with and without `memspace` produce lengths 8 and 9
with `body[8] === memspace`; `conditionSetBody` with a 256-byte expression throws
and with `"(RL == $64) && (CY == $14)"` produces `body[4] === 25` followed by
those exact ASCII bytes; `registersSetBody` with two items produces length
`3 + 2 * 4` with `body[2] === 3` and `body[6] === 3`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent/LLM → encoder arguments | untrusted addresses, byte counts, expressions, filenames and text lengths become wire bytes here |
| container MCP server → binary-monitor socket | a malformed length field desynchronises a stream shared with the event demux |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-01 | Tampering / Information Disclosure | `memGetBody()` `sidefx` byte | mitigate | `sidefx` defaults to `false` → byte `0x00`, asserted by a test that encodes a read of `$D019` and checks byte 0 is 0, so a default read cannot acknowledge the IRQ |
| T-3-02 | Tampering (session integrity) | `conditionSetBody()` | mitigate | Refuses an empty or non-ASCII expression and throws before encoding when the expression exceeds 255 bytes, so a truncated `exprLen` can never ship a condition different from the one the emitter produced |
| T-3-04 | Denial of Service | every variable-length encoder (`conditionSetBody`, `keyboardFeedBody`, `autostartBody`, `dumpBody`, `undumpBody`) | mitigate | Every `u8` length field is range-checked before encoding; a length/payload disagreement would desync the framing the request-id demux depends on and present as a wedged emulator |
| T-3-05 | Tampering | `autostartBody`/`dumpBody`/`undumpBody` filename bytes | transfer | These encoders reject non-ASCII and over-long filenames but do NOT decide whether a path is inside the workspace — that control is `hostpath.ts` plus the D-17 declared table, owned by plan 03-10 |
| T-3-06 | Tampering (unrequested state change) | this whole plan | accept | No encoder is written for `EXIT` (0xaa), and this plan adds no code that calls `send()`, so nothing here can resume a machine the agent did not ask to resume (D-05) |
</threat_model>
