<objective>
Wire everything the six family plans built into the one dispatch seam: the
`withStockSession()` adapter, the `runState` tracker attach points, all 25
`STOCK_DISPATCH_TABLE` entries, and the reworked manifest contract test plus the
hand-rolled `outputSchema` checker D-02 needs.

Planner decision recorded here (CONTEXT.md's open item 5, manifest-entry ownership):
the family plans deliberately own **no** manifest or dispatch entries. This plan owns
every `STOCK_DISPATCH_TABLE` entry and plan 03-13 owns every
`tools-manifest.stock.json` entry. Reason: those two files are the only files all six
families would otherwise write to, and separating them is what lets the six family
plans run genuinely in parallel in wave 2 with zero `files_modified` overlap. The
cost — one broad integration surface — is paid in two focused plans instead of six
conflicting writers.

Purpose: this is where D-09's "one table, one dispatch site, no fall-through" and
D-06's "`runState` on every answer" become structurally true rather than
per-handler discipline.

Output: an extended `stock-dispatch.ts`, the new `stock-schema-check.ts`, and a
reworked `stock-dispatch.test.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code (stdio) → `dispatchStock()` | an arbitrary tool name and argument object arrive here from outside |
| dispatch table → family handlers | the point where a tool call becomes an emulator command |
| manifest → advertised surface | what an agent believes the stock backend can do |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-06 | Tampering (unrequested state change) | `attachRunStateTracker()` placement | mitigate | Attached at exactly the two fresh-client branches and never in the session-reuse branch, and idempotent besides — so the D-11 rate limiter's side-effecting listener cannot fire more than once per real event and auto-disable a checkpoint the agent never armed twice (RESEARCH.md Pitfall 4). Asserted by a listener-count test across a reuse call |
| T-3-04 | Denial of Service (never-throw boundary) | `withStockSession()` | mitigate | The delegated handler call is wrapped so anything a family handler lets escape becomes a `convertWireError()` refusal. `vice-proxy.ts`'s stdio server is never restarted by Claude Code for the rest of the session, so a single escaped exception would end the session's tool surface |
| T-3-09 | Tampering (surface regression) | the dispatch table and manifest contract | mitigate | Bidirectional table/manifest agreement means a handler with no advertised tool and a tool with no handler both fail CI; the twelve trimmed tool names are each asserted absent with their decision id in the message; `STOCK_ONLY_TOOLS` is an explicit named list so loosening the fork-compatibility rule requires a deliberate edit |
| T-3-09b | Spoofing (capability misrepresentation) | `outputSchema` enforcement | mitigate | Every stock entry must declare an `outputSchema` with a required `runState` enum, so a tool cannot advertise an answer shape that omits the halt-state field an agent needs to know whether the machine is running (D-06) |
| T-3-05 | Information Disclosure | `dispatchStock()`'s miss branch | mitigate | A miss refuses **without reading `deps`**, asserted by passing a deps object whose `ensureLease` throws — so an unknown tool name never causes a broker lease to be requested or a socket to be opened |
</threat_model>
