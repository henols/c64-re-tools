fallbacks are `LIN`/`CYC` plus a non-stopping frame-count checkpoint or wall-clock.

**`CON-no-monotonic-cycle-register`.** Its closing sentence, "`REGISTERS_GET` (`0x31`) therefore
cannot serve as a stopwatch", is error (c) verbatim. Replace it. The heading claim survives — there
genuinely is no monotonic cycle register — but `LIN` and `CYC` are in `mon_reg_list_6510`
(`mon_register6502.c:57`) and `REGISTERS_GET` does return them. State that absolute cycles can be
reconstructed as `frames * 19656 (PAL) + delta(LIN * 63 + CYC)` with a frame count from a
non-stopping exec checkpoint's `hit_count`, and carry the cost warning that every hit of a
non-stopping checkpoint fires a synchronous `CHECKPOINT_INFO` from inside the CPU loop. Add a
cross-reference that Phase 7 chooses between this route and the CPU-history route with measured
cost; do not pre-decide it here.

**`CON-no-pause-now-opcode`.** Its constraint text is error (b) verbatim and the constraint NAME
itself asserts the retracted fact. Retire it: rename the block to something that states the
corrected model (for example a name built around "any inbound byte halts"), and rewrite the
constraint to say that `monitor_check_binary()` calls `monitor_startup_trap()` on any inbound byte
(`monitor_binary.c:281`), invoked every vsync from `monitor_vsync_hook` (`monitor.c:395`), so a
bare `PING` (0x81) halts the machine within roughly one frame and emits `STOPPED` (0x62) with no
temporary checkpoint required; `EXIT` (0xaa) resumes; and a timeout here means no vsync is
running, which is a wedge-triage signal. If any other block or the file header references
`CON-no-pause-now-opcode` by name, update that reference in the same edit — a dangling constraint
ID is a defect.

**`CON-async-event-demux`.** It lists three event types. Correct to five: `STOPPED` (0x62, 2-byte
PC body), `RESUMED` (0x63, 2-byte PC body), `JAM` (0x61, **zero-length body** —
`monitor_binary.c:384-394` computes the PC then passes `length = 0`), `CHECKPOINT_INFO` (0x11, on
every checkpoint hit) and `REGISTER_INFO` (0x31, on every monitor open). State that the last two
share a response type with a legitimate command reply, so the demultiplexer must key on request-id
and must never resolve a pending request with an event. This block is what Phase 2's PROTO-03 and
PROTO-04 derive from; it must not undercount.

**File header (lines 5-7).** It currently says items tagged PROVISIONAL await the empirical probe
