<objective>
Sweep the server entry point and the advertised tool manifest — about 141
citations across two files — to zero.

Purpose: the manifest is the highest-value rewrite in the phase and the most
delicate. Its descriptions are not comments; they are advertised to the client at
tool-listing time and read by a model deciding which tool to call and what it
does. A citation there is an instruction the reader cannot follow. Several of
those descriptions currently anchor a real behavioural warning — that a call
halts the machine, that a non-stopping checkpoint is a trace hazard, that a
default differs from what a reader might assume — to an internal reference.
Replacing the reference with the rule makes the tool surface strictly better.

Output: two files at zero, two ratchet entries deleted.

Counts are sizing context measured before planning; the ledger is the authority.

Locked decisions implemented by this plan:

- D-06: sweep plans partition by module family, not by file and not by citation category.
- D-07: recovery is tiered by identifier class, so lookup effort is spent where the ambiguity actually is.
- D-08: where nothing recovers a reason, the comment is rewritten to a weaker but true statement and the site is named in the plan's summary, never deleted.

Those identifiers belong to this planning document. No replacement string this
plan writes into product source may contain one.
</objective>
