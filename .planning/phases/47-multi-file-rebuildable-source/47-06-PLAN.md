<objective>
Make a split hi/lo address table relocatable the way the store's four split layouts exist to
make it: each entry's two halves generated from one symbol, so the table moves with the code
it points at instead of freezing it.

Purpose: the ROADMAP's own Notes for this phase state it directly — "Split hi/lo address
tables must generate paired names and move together; the store's four split-layout types exist
for this and per-byte symbolisation is the defect to avoid." Today `emitDataLines()` sends all
four split layouts down the raw byte fallback, so a `lo_hi_address` table is emitted as
literal octets and every target it names is frozen. That is precisely the failure BUILD-03
exists to prevent, arriving through the data path instead of the instruction path.
Output: paired-symbol emission for the two ADDRESS split layouts, the same refusal rule the
instruction path already uses, and the move-together property asserted rather than assumed.
</objective>

## What this plan does NOT do, and where that is decided

The ROADMAP note's last sentence assigns one thing to a later phase, and this plan honours that
split rather than quietly absorbing or quietly dropping it: **"The control that moves one half
without the other belongs to Phase 49's gate."** So this plan makes the paired emission real
and asserts that the halves cannot be separated by the exporter; the adversarial control that
deliberately moves one half and proves the gate catches it is Phase 49's, by that note's own
words. Nothing here weakens it — a later gate needs the paired emission to exist first.

## Measured ACME facts this plan is built on

Run live 2026-09-12 against `/home/henrik/.local/bin/acme` (0.97 "Zem"), in a scratch
directory, with the same flag set `acme.build` uses:

```
routine_a  rts          ; $0801
routine_b  rts          ; $0802
tbl_lo     !byte <routine_a, <routine_b
tbl_hi     !byte >routine_a, >routine_b
```
assembled at exit 0 with no warning and produced `60 60 01 02 08 08` — the low halves `01 02`
and the high halves `08 08`, byte-identical to what the raw octets would have been, with both
halves of each entry derived from one symbol. The report listing shows the two lines at `$0803`
and `$0805`. The block-end bracket assertion over the whole range held.

The store's own byte-order semantics, quoted from `anno-types.ts`'s `DATA_TYPES` comment: the
bytes `10 34 00 ff 08 12 c0 cf` resolve as `$0810 $1234 $c000 $cfff` under `lo_hi_address` —
first half low bytes, second half high bytes — and as `$1008 $3412 $00c0 $ffcf` under
`hi_lo_address`. The same comment states that the address forms produce cross-references and
the word forms do not.
