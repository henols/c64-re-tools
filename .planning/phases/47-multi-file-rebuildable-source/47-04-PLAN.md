## The dispatch-table fixture question, answered plainly

The ROADMAP's own Notes name `fixtures/dxa/tracer.prg` as this phase's dispatch-table subject.
Both the researcher and the pattern mapper independently read the committed bytes and reached
the same finding, which is recorded here rather than silently followed or silently corrected:
**`tracer.prg` is a 23-byte fixture carrying `LDA #$00` / `STA $D020` / `RTS` and no jump
table, no indirect `JMP`, and no dispatch mechanism of any kind.** A verify command asserting
it has a dispatch table would be checking a fact about the wrong file.

**Decision:** the cross-file reference cases in this plan use synthetic bodies built through
`buildStore()` — the idiom every other exporter test in this file already uses — rather than
`tracer.prg`. Criterion 3's requirement is that a reference across the file split still
resolves, and a plain cross-scope `jsr`/`jmp` is that requirement exactly; a dispatch table
adds a second mechanism without adding a second question. The indirect-vector case in Task 1
covers the dispatch idiom's own shape (`jmp ($xxxx)` with its vector inside an emitted block)
without needing a fixture that carries one.

`fixtures/export-asm/smc.prg` IS used where a committed fixture is the right subject — it
carries a real in-tree `jmp $0801` and a real mid-instruction label — and it must keep passing
unchanged under the new symbol rule.
