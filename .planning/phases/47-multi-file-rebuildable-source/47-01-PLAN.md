<objective>
Make an annotation store become a TREE of ACME files that a real assembler reassembles —
the thinnest complete path, wired end to end and proven by bytes — and fix the one piece of
infrastructure that path cannot exist without.

Purpose: Phase 47's whole goal turns on two facts that are today untested because they are
today unreachable. `anno-export-asm.ts` has never emitted a `!source` line, and
`host-tool.mts`'s `acme.build` spawn has never set a working directory. Measured live this
session against the installed ACME 0.97: a bare `!source "symbols.a"` resolves against the
PROCESS's working directory and nothing else, so the moment the exporter emits one, an
export assembled from anywhere but its own directory fails with `Cannot open input file`.
This plan wires the slice that makes both real at once, so an architectural dead end shows
up after one commit rather than after four.
Output: a `cwd`-aware `acme.build` spawn, an `exportAsmTree()` that writes a real tree, and
one end-to-end byte-diff through `runHostTool()` plus the negative control that proves the
`cwd` is carrying weight.
</objective>

## Planner decisions recorded for this phase

These bind every plan in Phase 47. They are decisions, not preferences, and a plan that
contradicts one has failed the phase.

**D47-A — The tree is the primary output shape; a single file is a degenerate one-scope
tree.** This is the `promote` answer to the assumption-delta checkpoint (see
`<assumption_delta_decision>` below). `exportAsm()` keeps returning one string, because it
is the proven EMITTER and every byte-correctness guarantee in this repository is anchored
to it — but it is demoted to the engine. `exportAsmTree()` is what a caller reaches for,
and the CLI's `--out` becomes a directory in plan 47-05.

**D47-B — The tree's file set, and the order `root.a` sources it.** Names are DERIVED from
integers this project controls, never from store free text:

| File | When | Contents |
|---|---|---|
| `root.a` | always | one banner comment, `!cpu 6510`, then the `!source` lines in the order below |
| `symbols.a` | always | one banner comment, then `ExportAsmResult.headerLines` verbatim |
| `scope_XXXX.a` | one per scope that contains at least one block | one banner comment, then each contained block's `lines` |
| `unscoped.a` | only when at least one block lies inside no scope | one banner comment, then those blocks' `lines` |
| `data_XXXX.bin` | one per `external_file` range (plan 47-03) | that range's raw bytes |

`XXXX` is the start address in four lowercase hex digits with no `$`. The `!source` order
is `symbols.a` FIRST, then each scope file ascending by scope start, then `unscoped.a` last.
Symbols first is not cosmetic: measured live this session, a zero-page symbol defined AFTER
its first use widens `a5 90` to `ad 90 00`, ACME still exits 0, and only the block-end
bracket assertion catches it.

**D47-C — A range that crosses a scope boundary is REFUSED by name** (research Open
Question 1). `anno_range` has no foreign key to `anno_scope`, so a range can straddle a
boundary. Splitting one block across two files would break the single-block `!if * != ...`
bracketing invariant that every byte guarantee in this file rests on, and guessing which
file it belongs in is the "tool decides" shape this project's governing constraint forbids.
Refuse, naming both extents. Owned by plan 47-02.

**D47-D — A block inside no scope goes to `unscoped.a`** (research assumption A2). Not a
refusal: `listScopes()` is read by nothing today, so every existing store has zero scopes,
and refusing would make the tree export unreachable for all of them. Losslessness is the
governing constraint — the block is emitted somewhere, never nowhere.

**D47-E — No `!zone` is emitted, anywhere** (research Pattern 2). `anno_label.name` is
`unique` in the schema and `assertLegalAcmeIdentifier()` accepts only
`^[A-Za-z_][A-Za-z0-9_]*$`, so every emitted name is already a plain global ACME symbol and
cross-file references resolve in ACME's default flat namespace. Measured live: a forward
`jmp` from one sourced file to a label in a later one assembles at exit 0 with the correct
target. The load-bearing invariant is the store's name uniqueness, so plan 47-04 asserts it
directly rather than leaving a "by construction" claim unguarded.

**D47-F — BUILD-03's symbol rule is scoped to IN-TREE targets.** A branch, `JSR`, `JMP` or
data reference whose target address falls inside an emitted block MUST resolve to a symbol,
or the export refuses by name. A reference to an address outside every emitted block —
`$d020`, `$ffd2`, a KERNAL entry — renders as a hex literal and is NOT a refusal: those
addresses are fixed hardware and cannot move, which is the entire thing "so code can move"
is about. This boundary is recorded here as an explicit decision rather than left implicit,
and plan 47-04 asserts BOTH directions so the boundary cannot quietly drift either way.

<assumption_delta_decision>
**Signal.** The deterministic detector fired `pluralization` on this phase's scope. Both
literal matches are weak — "fallback" matched ACME's three-byte absolute encoding and
"second" matched prose that FORBIDS a second export route — but there is a real
singular-to-plural transition the detector's vocabulary did not name: **the exporter's
primary output noun moves from one file to a tree of files.** Research left it open
(Open Question 2: does `--out FILE` become `--out DIR`, or does a new flag appear beside it).

**The noun that is now primary:** the exported **tree** — a directory of ACME source and
data files that assemble together — not the single `.a` file.

**Decision: `promote`.** The tree becomes the primary output shape at every layer, and the
single file is demoted to a detail of one variant:

- `exportAsm()` keeps its single-string return, because it is the proven EMITTER and every
  byte guarantee in this repository is anchored to it. It becomes the engine, not the
  product.
- `exportAsmTree()` is what a caller reaches for, and what the CLI calls.
- `anno export-asm --out` names a DIRECTORY (plan 47-05). A store with zero scopes does not
  get a different code path — it gets a degenerate tree (`root.a`, `symbols.a`,
  `unscoped.a`) that assembles identically.

**Rationale for promote over add-alongside.** `add-alongside` — keeping `--out FILE` and
minting `--out-dir DIR` — would leave two export shapes to keep in sync forever, and the two
would diverge the moment `external_file` lands: a single-file export cannot carry a
`!binary` sibling, so the single-file shape would become the one that silently cannot
express part of the store's vocabulary. A shape that cannot represent a supported store
state is exactly the "stored but never confirmable" contradiction the checkpoint warns about.

**Accepted cost, stated rather than discovered later.** `anno export-asm --out FILE` is
published (`@henols/vice-mcp`) and documented in a shipped skill, so this is a breaking
change to a published surface. That is why plan 47-05 carries the phase's one
`checkpoint:decision` and is `autonomous: false`: the human confirms the door before the
agent walks through it.

**Companion invariant test (accepted, in plan 47-02):** every emitted block round-trips
through the tree — every block's line group appears exactly once across the tree's files,
and the tree carries no content line `exportAsm()` did not produce. That assertion goes red
the instant a future phase reintroduces a second, singular emission path.
</assumption_delta_decision>
