<objective>
Carry the text channel over the same relay the binary channel now uses, and preserve
the one place the two channels are deliberately not symmetric.

Purpose: the phase goal says every `vice_*` tool reaches the emulator over a relayed
connection. The text tools are half that surface, and they dial a second, separate
emulator port today. Leaving them on a direct dial would leave the milestone's core
hypothesis half-proven and would leave one code path still needing a network route to
the emulator itself.

Output: a socket-injection entry point on `TextMonitorClient`, a rewired
`textConnect()`, a channel-aware emulator dial on the broker side, and a text-specific
relay test file.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-63-01 | Elevation of Privilege | the attach arm, text channel | high | mitigate | The text attach is gated by the same per-claim handle Plan 63-01 introduced, minted by the text channel's own claim; the handles are per channel, so a binary-channel handle cannot attach the text channel. |
