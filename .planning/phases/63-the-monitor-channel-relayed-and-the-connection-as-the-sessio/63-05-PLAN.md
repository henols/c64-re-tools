<objective>
Let a user look at a broker serving several unrelated projects and say "that one is
mine", and confirm that a stateless call is genuinely stateless.

Purpose: one machine-wide broker makes a stuck emulator ambiguous in a way a
per-project broker never was. SESS-06 closes that. SESS-01 is the other half of the
same picture: the two call shapes have to be distinguishable in the broker's own state,
not merely in intent, or "the connection is the session" is a claim nobody can check.

Output: a client-resolved session label declared at acquire time, recorded on the grant
and surfaced in status beside the grant id and the in-flight operation; the invariant
test that keeps the label from becoming a credential; and a behavioural proof that a
stateless call leaves the broker's state exactly as it found it.
</objective>

## Plan-level decision (RESEARCH Open Question 2, decided here)

- **The session label is client-resolved, declared once at acquire time, and optional in the
  protocol but always present in practice.** Its value is the agent-session environment
  variable when that is set, and otherwise the current working directory's base name joined to
  the process id. Rationale: the environment variable is the only existing precedent in this
  tree for "which agent session is this", and the fallback is universally available and still
  distinguishes two processes in the same repository. It is declared at **acquire**, not at
  attach, because a grant can exist before any monitor channel is claimed and a user needs to
  identify a session that is holding an instance without having attached to it yet. It is
  optional on the wire so a bare test client or a future non-agent caller is not refused for
  having no label; an absent label is reported as absent, never fabricated.

## Flagged assumptions (unresolved edge-probe rows, surfaced rather than dropped)

The deterministic edge probe classified two of its eight rows as `unclassified`. Per the
fallback protocol they stay `unresolved` and are surfaced here as explicit assumptions rather
than auto-resolved or silently dropped:

- **SESS-01, unclassified.** The probe could not derive an edge category for "a skill script's
  call is a stateless one-shot that binds no emulator and holds no lease". The assumption this
  plan proceeds on: SESS-01 is a **confirmation** requirement, not a build requirement — the
  stateless shape already ships for the host-tool family, and what is missing is a check that
  the broker's own state is provably unchanged across such a call. Task 3 supplies that check.
  If a reviewer reads SESS-01 as also requiring a NEW stateless path for some `vice_*` tool,
  that is a different requirement and is not in this plan.
- **SESS-06, unclassified.** The probe could not derive an edge category for "a user can tell
  which live session is their own". The assumption this plan proceeds on: identification is
  satisfied by the status projection naming the label, the grant id and the in-flight
  operation; it does not extend to a new diagnostic tool, a new CLI subcommand or a change to
  any `vice_*` tool's output. If a reviewer reads SESS-06 as requiring a user-facing surface
  beyond broker status, that is a different requirement and is not in this plan.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client acquire request -> broker grant state | a caller-supplied display string becomes broker-held state and is served back to every status reader |
| broker status reply -> any caller holding the per-boot token | one project's reader sees entries belonging to unrelated projects |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-63-03 | Information Disclosure | the status reply's new identity fields | medium | mitigate | The label is a short, client-chosen string capped at 64 characters with control characters and line terminators stripped; nothing is derived from it server-side and no filesystem path, username, hostname or home directory is added to the reply. The client-side default is the working directory's base name only, never its full path. |
| T-63-17 | Spoofing | the session label | high | mitigate | The label is never accepted as a target selector by any op. The invariant test in Task 2 sends every target-naming op a label in place of a target id and requires the shared authorisation denial, and asserts its covered op set against the request-kind union so a future op cannot slip past it. |
| T-63-18 | Tampering | the declared label | medium | mitigate | Sanitised through the same exported function the operation name uses before any state or rendered record sees it, so a hostile value cannot inject line structure into status output, a log line or an incident record. |
| T-63-19 | Elevation of Privilege | the stateless call path | high | mitigate | The stateless callback is declared separately from every lease callback and is never composed from one, so the branch has no reachability into lease state. Task 3 proves the property by observation: broker state is deeply equal before and after, and no lease callback fires. |
| T-63-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no package; nothing is added to the runtime or dev dependency sets, so the package-legitimacy gate has no subject. |
