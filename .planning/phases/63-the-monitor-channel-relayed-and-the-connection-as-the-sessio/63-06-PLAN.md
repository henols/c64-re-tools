<objective>
Prove against a real emulator what a stub cannot prove: that the relay is byte
transparent for the frames that actually matter, and record the convergence census this
phase leaves behind.

Purpose: every other assertion in this phase runs against a synthetic pair, which
reproduces TCP semantics exactly and reproduces the binary monitor's semantics not at
all. A register read, a memory write, a checkpoint hit and a machine jam are the four
shapes whose real wire bytes exercise the parser's demux, its unsolicited-event routing
and its zero-length-body handling. Only a genuine stock build produces them.

Output: an opt-in, default-skipped live test in this project's existing live-test family,
its manual-only registration, and a measured convergence census in the plan summary.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a live emulator process -> the developer's own machine | the live run spawns a real emulator and a real broker on the host that runs the suite |
| the opt-in variable -> a spawned binary path | a path supplied by the environment becomes the binary the run executes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-63-20 | Denial of Service | a leaked emulator or broker process | medium | mitigate | The run tears down in a finally block: the grant is released, the control session closed and the broker stopped, so no process outlives the test. The human-check step confirms it explicitly, because a leaked emulator on this host holds a machine-wide control port and a monitor slot other work needs. |
| T-63-21 | Tampering | the binary the opt-in variable names | medium | mitigate | The binary is never installed, downloaded or resolved from the search path by the test: the variable must name an absolute path, the guard refuses by name when that path is not on disk, and the project's standing rule is to detect and refuse rather than install. The spawn itself happens only through the broker's own single spawn site, in argv-array form. |
| T-63-22 | Repudiation | a live case that fails | medium | mitigate | A failure against the real build is recorded as a finding with the observed bytes and routed to gap handling; relaxing the assertion to make it pass is named here as the wrong move so a later reader can see it was considered and refused. |
| T-63-SC | Tampering | npm/pip/cargo installs | high | mitigate | This plan installs no package; nothing is added to the runtime or dev dependency sets, so the package-legitimacy gate has no subject. The emulator is a pre-existing host tool the project only detects. |
</threat_model>
