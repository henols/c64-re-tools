<objective>
Pay the one unpaid cost of the fork backend: exercise its own `-mcpserver` HTTP
transport against a real fork binary, and commit that exercise as a repeatable,
default-skipped test.

Purpose: ROADMAP Phase 14 criterion 3 requires the decision to be reflected in
the code's actual state, *checked live*. Research Q3 established that no test in
this repository has ever driven the fork's HTTP endpoint — `broker-e2e.test.ts`
deliberately stubs the binary to `/bin/sleep`, Phase 8's human walkthrough was
stock-only, and even Phase 13's live captures spoke `-binarymonitor` to the fork
*binary* rather than the fork's own endpoint. This plan is unconditional on the
FORK-01 branch: the fork transport still ships at the end of this phase on every
branch, so it must be exercised on every branch. Doing it here also produces the
last honest evidence of the transport's behaviour before any future deletion.
Output: `fork-live.test.ts`, its registration in the single manual-only registry,
and `14-CRITERION3-EVIDENCE.md`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test process → spawned emulator's HTTP `/mcp` endpoint | The fork's `-mcpserver` endpoint is unauthenticated full machine control; whatever can reach it can do anything to the emulated machine and, through file tools, to paths the emulator can see |
| host PATH → binary identity | `/usr/local/bin/x64sc` (fork, 3.10) shadows `/usr/bin/x64sc` (genuine stock, 3.9); a bare name silently selects the wrong one |
| live run → committed evidence | The evidence document is read later as ground truth; a mislabelled capture propagates a false fact |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-09 | Information Disclosure | The spawned emulator's `-mcpserverhost` bind address | high | mitigate | The argv is fixed to the loopback literal and test 1 asserts the spawned argv's bind address, so a widened bind fails the suite instead of shipping quietly |
| T-14-10 | Spoofing | Binary selection | medium | mitigate | Absolute paths only, in the test default, the env var's skip message, and both `--help` probes; the evidence document names both binaries and their versions side by side |
| T-14-11 | Denial of Service | Leaked emulator child process and scratch directory | medium | mitigate | Acquire nothing outside the `before`/`after` pair; teardown runs even when a test throws; an acceptance criterion checks no `x64sc` with the server flag survives the run |
| T-14-12 | Tampering | Evidence integrity | high | mitigate | The test must not be tuned to make the run pass — an acceptance criterion requires a clean diff against the Task 1 commit unless a recorded finding explains it; a failed hard-loss call is recorded as a finding, never worked around |
| T-14-13 | Elevation of Privilege | `-mcpservertoken` | low | accept | The flag is deliberately not passed: it makes the server *require* a bearer token the client cannot supply. Loopback binding, not a token, is the control here, matching the posture already documented for the stock binary monitor |
| T-14-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no packages; the package-legitimacy gate does not fire |
</threat_model>
