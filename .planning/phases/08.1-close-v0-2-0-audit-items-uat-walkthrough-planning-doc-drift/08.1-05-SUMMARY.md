- Read `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md` and the 2026-08-19 milestone audit
  in one pass and produced `08.1-CONSISTENCY-READ.md`: a 27-data-row reconciliation

  frontmatter from disk-ground-truth on write (`buildStateFrontmatter`, independent
  of `phase.complete` and of ROADMAP.md's table format), and this plan's own
  `08.1-05-SUMMARY.md` landing on disk was enough to flip Phase 8.1 to "complete" by
  that measure. Corrected the body line to 89% to match, and synced ROADMAP.md's
  Phase 8.1 row/checkbox to `5/5 Complete` via `roadmap.update-plan-progress`, so all
  three documents landed in agreement rather than STATE.md running ahead of
  ROADMAP.md.
- Replaced `08.1-d-checklist.sh`'s D-5 bare `] 78%` literal sub-check with a
  self-consistency invariant (body Progress % must equal frontmatter `percent`) —
  the literal could not tell a wrong drift from a correct advance, which is precisely
  what happened. The new check is durable against any future `state.*` or
  `phase.complete` call, whatever the correct percent turns out to be.

**1. [Rule 1 - Bug] STATE.md's own initial RESIDUAL-1 fix (78%) went stale mid-execution and was corrected to 89%**

  `state.record-metric` call (needed simply to record this plan's duration).

  as a side effect of that call, because *every* `state.*` SDK command resyncs
  frontmatter from disk (`buildStateFrontmatter`, triggered by
  `readModifyWriteStateMd` on every write) — not only `phase.complete`, as the
  first pass of tracing had concluded. This left the just-fixed body Progress line
  (78%) disagreeing with the now-correctly-advanced frontmatter (89%) — the exact
  class of defect this plan exists to catch, self-inflicted mid-run.
- **Fix:** Updated the body Progress line to 89% (the new, correct, disk-ground-truth
  value), synced ROADMAP.md's Phase 8.1 row/checkbox to match via
  `roadmap.update-plan-progress`, and replaced the D-5 checklist's bare-literal
  sub-check with a self-consistency invariant so this class of "correct advance,
  wrongly read as drift" cannot recur.
- **Files modified:** `.planning/STATE.md`, `.planning/ROADMAP.md`,
  `08.1-d-checklist.sh`.
- **Verification:** `bash 08.1-d-checklist.sh` — all 7 PASS, exit 0. Body Progress
  (89) and frontmatter `percent` (89) confirmed equal by direct grep.
- **Committed in:** `74a109c`.

**2. [Rule 1/3 - Blocking issue / bug] Skipped the standard `state.update-progress` closing call**

  plan's own remaining closing steps.

  `gsd-sdk query state.update-progress`, which recomputes STATE.md's body Progress

- **Fix:** Did not invoke `state.update-progress` as part of this plan's closing
  steps. `state.record-metric`, `state.add-decision`, `state.record-session`,
  `roadmap.update-plan-progress` and `requirements.mark-complete` are still used
  normally — only the one harmful sub-step is skipped.
- **Files modified:** none beyond the fixes already committed.
- **Verification:** `grep -c '100%' .planning/STATE.md` returns 0.
- **Committed in:** `d4d0907`/`74a109c` (procedural omission, no separate commit
  needed for the absence of a call).
