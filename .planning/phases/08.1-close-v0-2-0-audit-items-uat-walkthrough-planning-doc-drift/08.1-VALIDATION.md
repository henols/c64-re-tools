# Phase 8.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `08.1-RESEARCH.md` § Validation Architecture.

**This phase is documentation- and evidence-heavy, not code-heavy.** Most tasks have no
conventional automated test — the "test" is a grep/diff assertion against a document's own
text. That is deliberate, not a gap: see `08.1-RESEARCH.md` § Don't Hand-Roll. No permanent
test infrastructure is added.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Node's built-in test runner (`node --test`) — unchanged, no new framework |
| **Config file** | none — `.claude/mcp/vice/package.json:58` (`"test": "node --test '*.test.*'"`) |
| **Quick run command** | per-task `grep`/`diff` assertion for the D-item being fixed (see Per-Task Verification Map) |
| **Full suite command** | `cd .claude/mcp/vice && node test-gate.mjs` — must stay green; this phase should touch no `.ts`/`.mts` file |
| **Repo-root guardrails** | `node scripts/check-skill-tool-coverage.mjs`, `node scripts/check-npm-packages.mjs`, `node scripts/check-skill-fork-honesty.mjs` |
| **Estimated runtime** | quick: <1s per grep · full gate: as per existing `test-gate.mjs` |

---

## Sampling Rate

- **After every task commit (D-1..D-7):** re-run that item's grep assertion, and confirm no
  other D-item assertion regressed (D-6's wording fix can break D-6's own arithmetic — see
  `08.1-RESEARCH.md` Pitfall 2).
- **After every plan wave:** run the full seven-item D-checklist once; run
  `cd .claude/mcp/vice && node test-gate.mjs` only if any `.ts`/`.mts`/`.mjs` file was touched.
- **Before `/gsd-verify-work`:** all seven D-item assertions clean, `08-VALIDATION.md`
  confirmed already-compliant, and `08-HUMAN-UAT.md` Test 1 shows a non-`pending` result.
- **Max feedback latency:** ~1 second for the doc-drift loop.
