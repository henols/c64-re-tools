<objective>
Close **WR-07** (07-VERIFICATION.md gap 3): make the advertised stock tool contract match what the
stock handlers actually answer.

`tools` in `vice-proxy.ts` is a name-keyed record. The manifest loop fills it (line 3179-3182), and
then lines 3191-3192 **overwrite** two entries unconditionally:
`tools[RECYCLE_TOOL.name] = ...` and `tools[DIAGNOSE_TOOL.name] = ...`. `tools/list` is served from
that object, so on the stock backend an agent reads `DIAGNOSE_TOOL`'s fork description — which says
the verdicts are *"restarted, checkpoint_trap, wedged, stale_read_path, or live"*. That advertises a
verdict stock cannot produce (`stale_read_path`, deliberately absent per locked decision **D-03**)
and omits one it can (`monitor_held_elsewhere`). The carefully corrected stock manifest entries added
in 07-09 never reach an agent, and `vice-wedge-triage/SKILL.md` explicitly tells that agent to *"read
the tool's own schema for the exact contract on whichever backend is active"* — so the skill's own
instruction currently leads to the wrong contract.

This plan also lands the `outputSchema` deltas that plans **07-14** and **07-15** deliberately did not
make: their new answer fields (`machineHalted`, `raceResolved`, `machinePausedSource`, and the rest)
must be declared, and `reached` must leave `required` so 07-14's honest "I could not determine it"
shape is legal.

Purpose: the schema an agent reads on stock is the contract the stock code honours.
Output: one pure, tested selector; a backend-aware registration; a manifest that matches the handlers.
</objective>
