  <action>
Add `ParsedCpuHistoryResponse` to the exported interfaces and to the `ParsedResponse`
union, with `type: "cpu_history"`, a `count: number` field, and an `entries` array whose
elements carry at minimum `cycle: bigint` (the monotonic absolute clock) plus
`opcode: number`, `instructionLength: number`, `p1: number`, `p2: number`.

Add `case ResponseType.CpuHistoryGet:` to `parseResponse()`'s switch. Body layout,
confirmed against `monitor_binary.c:1563-1617`: `count` is a uint32LE at offset 0, then
per entry, in order — `item_size` (1 byte), a register block of `item_size` bytes,
`cycle` (uint64LE), `instruction_length` (1), `opcode` (1), `p1` (1), `p2` (1), and one
trailing placeholder byte (five bytes total after the cycle field).

Skip the register block deliberately and say why in a code comment: VICE hard-fills
`LIN`/`CYC` inside CPU-history entries with the sentinel `0xffff`
(`monitor_binary.c:1585-1590`), so those per-entry raster positions carry no real value
and this phase never interprets them. Read `cycle` with `readBigUInt64LE` — a uint64
clock does not fit a JS number safely, and the stopwatch's whole value is exactness, so
do not narrow it to `Number` here.

Call `need()` before every offset read: once for the 4-byte count, once per entry for
the `item_size` byte, and once per entry for `item_size + 8 + 5` bytes before touching
the register block through the placeholder. An entry whose declared `item_size` runs the
cursor past the body end is a `StockFramingError` through `need()`, never a truncated
silent success and never a `RangeError`.

Add tests in `stock-protocol.test.ts`: (a) a single-entry synthetic body decoding to the
exact `cycle` bigint, opcode and operand bytes; (b) a two-entry body where the **first**
entry is the newest, asserting `entries[0]` is the one Route A will read; (c) a
truncated body (count says 1, body ends inside the cycle field) rejecting with
`StockFramingError`; (d) a body whose `item_size` is `0xff` with only a few bytes
following, also rejecting with `StockFramingError`.
  </action>
