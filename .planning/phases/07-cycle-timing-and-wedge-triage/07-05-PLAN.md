<objective>
Build `vice_cycles_stopwatch` for the stock backend, where no monotonic cycle register
exists on the wire and the fork's in-process `mon_stopwatch_get_elapsed()` has no
equivalent. Two routes, chosen from the capability Phase 2 already resolved at connect
time: **Route A** (VICE >= 3.10) reads `CPUHISTORY_GET`'s newest entry's monotonic
uint64 cycle field and is exact for any bracket length; **Route B** (below 3.10)
reconstructs a frame position from `LIN`/`CYC` and is exact only within one frame,
refusing explicitly when a frame boundary is proven crossed.

rather than returning zero". This plan also produces the shared
`readCycleBaseline()`/`resolveVideoStandard()` helpers that `stock-diagnose.ts`'s
liveness bracket consumes in plan 07-06.

Create `.claude/mcp/vice/stock-timing.ts`.

**`VIDEO_STANDARDS`** — an exported record keyed by `MachineVideoStandard`'s own
integer resource values (which are 1-based, not 0-based, per `machine.h:57-60`):
`1` = PAL, 63 cycles/line, 312 lines; `2` = NTSC, 65 cycles/line, 263 lines;
`3` = NTSC-old, 64 cycles/line, 262 lines; `4` = PAL-N, 65 cycles/line, 312 lines. Each
entry carries `cyclesPerLine`, `screenLines` and `name`. Cite `c64/c64.h:36-58` and
`machine.h:57-60` in a comment. All four are included — the surface is one table row
each, and silently mis-measuring an NTSC-old instance is a wrong answer, not a missing
feature.

**`resolveVideoStandard(session)`** — sends `CommandType.ResourceGet` with
`resourceGetBody({ name: "MachineVideoStandard" })`, expects the integer variant, and
maps the value through `VIDEO_STANDARDS`. Cache the resolved standard per
`session.targetId` in a module-level Map, matching `bankCatalogFor()`'s
cache-per-session shape; the write side of this resource power-cycles the machine
(CLAUDE.md), so any change to it necessarily produces a fresh session and a stale cache
entry cannot outlive the session that read it — record that reasoning in the comment.
On a wire failure, or a value not in the table, fall back to PAL (`1`, the resource's
own documented default, `c64-resources.c:438`) and return the result with
`assumed: true` plus the reason, so every caller can report the assumption rather than
present it as an observation. Never throw from this helper.

**`positionWithinFrame(lin, cyc, cyclesPerLine)`** — returns `lin * cyclesPerLine + cyc`.
Pure, exported, and tested against all four standards.

**`readCycleBaseline(session)`** — the shared primitive `stock-diagnose.ts` also uses.
Returns a discriminated record:
- When `session.capabilities.cpuHistory === "available"`: sends
  `CommandType.CpuHistoryGet` with a 5-byte body (`memspace` `0x00` at byte 0, count as
  uint32LE at offset 1) with a count of `clampCpuHistoryCount(1)` — **never 0**, which
  real VICE rejects with `InvalidParameter` (this is the defect plan 07-01 fixed) — and
  returns `{ route: "cpu_history", cycle: <bigint from entries[0].cycle> }`. The newest
  entry is first.
- Otherwise: sends `CommandType.RegistersGet` with `memspaceBody({ memspace: 0x00 })`,
  resolves names through `registerCatalogFor(session)`, and returns
  `{ route: "frame_position", lin, cyc, pc, standard, position }`. When the build
  enumerates no `LIN` or no `CYC` register, return
  `{ route: "unavailable", reason: <naming which register the build does not expose> }`
  — never a substituted zero.

Also read and return `PC` on both routes (Route A issues one extra `REGISTERS_GET`, or
reads it from the same registers reply on Route B) — `stock-diagnose.ts`'s liveness
comparison needs PC alongside the cycle evidence, and having one primitive produce both
keeps the bracket at exactly two halting reads.

Export `resetTimingStateForTest()` clearing the video-standard cache and (task 2's)
baseline store, following `resetBankCatalogsForTest()`/`resetCheckpointStateForTest()`.

  <action>
Add `handleCyclesStopwatch: StockSessionHandler` to `stock-timing.ts`.

`action` is required and must be one of `reset`, `read`, `reset_and_read`; anything else
is refused naming the three valid values. Any unexpected argument key is refused by
name, matching `handleRegistersGet`'s existing discipline.

Baselines live in a module-level `Map` keyed by `session.targetId`, cleared by
`resetTimingStateForTest()`. A baseline is whatever `readCycleBaseline()` returned.

**`reset`** — capture a fresh baseline, store it, answer with
`{ requested: "cycles_stopwatch", action: "reset", route, measurable: false, reason:
"a baseline was recorded; call read to measure elapsed cycles" }`.

**`read` / `reset_and_read`** — capture a current sample. Then:
- *No stored baseline*: `measurable: false` with a reason naming that no `reset`
  happened on this instance. Emit **no** `cycles` key at all.
- *Route mismatch* (baseline taken on one route, sample on another — possible only
  across a reconnect that changed capabilities): `measurable: false` naming the
  mismatch. No `cycles` key.
- *Route A, delta >= 0*: `measurable: true`, `cycles` as a `Number` of the bigint delta,
  plus `cyclesExact` as the bigint's decimal string (the exact value survives even where
  the `Number` would round), `route: "cpu_history"`, `exactness: "exact"`.
- *Route A, delta < 0*: the monotonic clock went backwards — the machine restarted or
  history was cleared. `measurable: false`, reason naming it. No `cycles` key.
- *Route B, `positionAfter >= positionBefore`*: `measurable: true`, `cycles` as the
  position delta, `route: "frame_position"`, `exactness:
  "within-one-frame-unverified"`, plus a `caveat` string stating in words that `LIN`/`CYC`
  cannot distinguish "0 frames elapsed" from "exactly N whole frames elapsed", so this
  figure is trustworthy only for a bracket known to be bounded well under one frame, and
  `standard` naming the video standard used (with `standardAssumed` when
  `resolveVideoStandard` fell back).
- *Route B, `positionAfter < positionBefore`*: **proven** wraparound. `measurable:
  false`, reason stating that at least one frame boundary was crossed and the elapsed
  count cannot be reconstructed from `LIN`/`CYC` alone on a VICE below 3.10, naming
  `CPUHISTORY_GET` (VICE >= 3.10) as the route that can. Emit **no** `cycles` key, and
  do **not** guess a `+ k * cyclesPerFrame` correction for an unknown `k`.
- *Route `"unavailable"`*: `measurable: false` with the helper's own reason.

`reset_and_read` stores the new sample as the next baseline on every path, including the
unmeasurable ones — the caller asked for an atomic read-and-reset and a failed
measurement must not silently leave a stale baseline behind.

Every answer goes through `stockAnswer(session.client, payload)` so the `runState` stamp
is present by construction; never build a bare `{content, isError:false}` literal. Write
a header comment on the handler stating the rule in one line: **an unmeasurable bracket
emits no `cycles` key at all — `0` is a wrong answer, not a null answer.**
  </action>
