<objective>
Close **Gap 1's blast radius** (07-VERIFICATION.md gap 1, finding **CR-01**): make a
CPUHISTORY_GET *decode* failure incapable of failing the whole stock connect handshake.

Today `probeCpuHistory()` (`.claude/mcp/vice/stock-connect.ts:117`) classifies only
`StockProtocolError`. Against a genuine VICE >= 3.10 build the monitor answers with a real,
well-formed CPUHISTORY_GET frame that this tree's parser cannot decode, so a `StockFramingError`
is rethrown at the end of the `catch`, propagates through `resolveCapabilities()` (`:144`, no
try/catch at its `probeCpuHistory()` call site) and out of `stockConnect()` step 5, which treats
it as fatal. Live-reproduced twice independently (07-REVIEW.md CR-01 and 07-VERIFICATION.md's own
probe against `/usr/local/bin/x64sc`):
`StockFramingError | response type 0x86 body is 52 byte(s), needs at least 65`.

Because `ensureStockSession()` is the seam every stock tool goes through, this single line makes
**every** stock tool unreachable on VICE >= 3.10 — which is why this plan carries all four
`TIME-*` requirements even though it only touches capability resolution.

This plan is the cheapest unblock and is deliberately independent of plan 07-12's parser
re-derivation: after this plan, a wrong layout degrades Route A to "absent" instead of killing the
backend. 07-12 then makes the layout right. Neither plan depends on the other.

Purpose: restore reachability of the stock backend on the VICE version this milestone targets.
Output: a guarded capability probe, a guarded capability resolver, and regression tests for both.
</objective>

Two changes in `.claude/mcp/vice/stock-connect.ts`.

**(a) `probeCpuHistory()` (currently at line 117).** Extend the existing `catch` so a decode
failure becomes a capability answer instead of a rethrow. Keep the three existing
`StockProtocolError` mappings exactly as they are (`ErrorCode.InvalidType` -> `"absent"`,
`ErrorCode.CmdFailure` -> `"not_compiled_in"`, `ErrorCode.InvalidParameter` -> `"absent"`) — 07-01
established them and they are not being revisited. Add, after the `StockProtocolError` block and
before the final `throw err`:
  - `err instanceof StockFramingError` -> return `"absent"`.
  - `err instanceof StockDesyncError` -> return `"absent"`.
  - `err instanceof StockResponseMismatchError` -> return `"absent"`.
These three all mean "the monitor answered with a frame, so the opcode exists, but this client
could not read the answer" — Route A is unusable on this build, which is exactly what `"absent"`
already means to every consumer (`resolveCapabilities()`'s own cache comment documents `"absent"`
and `"not_compiled_in"` as both meaning "never attempt CPUHISTORY_GET again").
Import `StockFramingError`, `StockDesyncError` and `StockResponseMismatchError` from
`./stock-protocol.ts` — the existing import at line 33 currently pulls only `ViceMonitorClient`,
`CommandType`, `ErrorCode`, `StockProtocolError`.
Do **not** widen the catch to `catch (err) { return "absent"; }`. `StockConnectionClosedError`,
`StockRequestTimeoutError` and `MachineRestartedError` must still propagate — a dead socket is not
a capability answer, and `stockConnect()`'s own retry/restart posture depends on seeing them.
Rewrite the function's doc comment so it states the new rule in the same voice as the rest of the
file: a *decode* failure never fails the handshake; a *transport* failure still does. Name CR-01
and the live-reproduced message
`response type 0x86 body is 52 byte(s), needs at least 65` in the comment, and point at
`.planning/phases/07-cycle-timing-and-wedge-triage/07-VERIFICATION.md` gap 1 as the record.

**(b) `resolveCapabilities()` (currently at line 144).** The `await probeCpuHistory(client)` call
site has no guard. Wrap it so that any error class this function is not prepared to interpret
cannot reach `stockConnect()`'s fatal `catch`: on `StockConnectionClosedError`,
`StockRequestTimeoutError` or `MachineRestartedError`, rethrow (those are real transport/instance
conditions the handshake must fail on). On anything else, write one line to `console.error`
naming the error and the resolved fallback, and return `{ cpuHistory: "absent" }` **without**
writing a capability cache record — a capability answer nobody could establish must not be
persisted for the next connect via `writeCap`. Keep the existing cache-hit short-circuit and the
existing `writeCap` call for the normal path untouched.

| capability cache file (`.vice-supervisor/`) -> `resolveCapabilities()` | A persisted capability value changes route selection on every later connect |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-11-01 | Denial of Service | `probeCpuHistory()` / `resolveCapabilities()` | mitigate | A malformed or undecodable 0x86 frame currently denies service to the ENTIRE stock backend. Task 1 converts it to a capability downgrade, so a single bad frame can no longer take down every tool. |
| T-07-11-02 | Tampering | capability cache record | mitigate | Task 1(b) refuses to `writeCap` a capability value derived from an uninterpreted error, so a transient wire fault cannot pin a wrong route selection for all future connects. |
| T-07-11-03 | Information Disclosure | `console.error` fallback line in `resolveCapabilities()` | accept | Logs the error message and the fallback capability only; no memory contents, no host paths, no credentials (the binary monitor has none). |
| T-07-11-04 | Spoofing | broadening the catch to `catch { return "absent" }` | mitigate | Explicitly forbidden in Task 1: a closed socket or timed-out request must not be able to masquerade as a legitimate capability answer, because that would hand back a session whose emulator is unreachable. |
