<objective>
Implement D-01: `vice_recycle` on the stock backend. The research found a third
skill-called tool broken on stock for the same root cause as the other two —
`gatherWedgeEvidence()` calls `rewriteArguments()`/`call()` and is fork-only — while the
destructive action itself (`controlSession.recycle(grantId)`) is a broker control-plane
RPC that is already transport-independent.

Without this, the new stock `vice_diagnose` correctly reports `wedged` and then the
skill's own documented recovery step fails on the same backend. This plan builds the
stock-native evidence gatherer, reusing the liveness bracket and checkpoint-trap
algorithm plan 07-06 already produced, and preserves the fork's load-bearing ordering:
**the record is written BEFORE the request**, so capturing is structurally impossible to
skip rather than a discipline to remember.

Purpose: keeps ROADMAP success criterion 4 honest — the wedge-triage skill's flow works
end to end on stock, not just its opening move.
Output: `stock-recycle.ts` and its unit tests. No screenshot (`SHOT-*` was cut).
Registration is plan 07-09's job.
</objective>

Add `handleRecycleStock: StockSessionHandler` to `stock-recycle.ts`.

**Reason gate, first, before anything else.** A missing, non-string or whitespace-only
`reason` returns an error result naming the requirement and stating that **no record and
no request were written**. Use the same substance as the fork's message so the two
backends refuse identically. Nothing has been gathered and nothing has been sent at this

**Lease.** Re-consult `deps.ensureLease()` to obtain the `HeldLease`; the destructive
RPC needs `lease.brokerControl` and `lease.targetId`, which the session object alone
does not carry (`session.brokerControl` is the narrowed claim/release interface). A
non-ok lease outcome returns its message verbatim, having written nothing.

**Evidence, then record, then RPC — in that order and no other.**
1. `const evidence = await gatherStockWedgeEvidence(session, deps)` — cannot throw,
   cannot stall past its per-step deadlines.
2. `const recordPath = writeIncidentRecord({ at, port: lease.port, epoch_before, reason,
   session_id, evidence })`, where `epoch_before` is read from `lease.epochFile` (absent
   or unreadable records `null`, never a fabricated number) and `session_id` comes from
   `CLAUDE_CODE_SESSION_ID` or `null`.
3. `const recycled = await lease.brokerControl.recycle(lease.targetId)`.
There must be no argument, branch or environment read between steps 2 and 3 that can
reach step 3 with step 2 skipped. Put the fork's own ordering sentence in the comment.

**Outcomes.** On each non-ok `kind`, call `finaliseIncidentRecord(recordPath, { outcome
})` with a distinct outcome and return an error result naming the record path and the
honest state of the instance (unknown, neither confirmed killed nor confirmed alive) —
mirroring the fork's per-kind wording without inventing a fourth kind. On success,
finalise with the success outcome and return `stockAnswer(...)` — but read the run state
before the teardown below, since `stockAnswer` stamps it from the client.

**Teardown after a confirmed recycle.** Call `stockDisconnect(session)` so the socket
and the broker-side monitor claim are released **together** (CR-05's discipline: a
leaked client keeps occupying stock VICE's single client slot, and the next connect then

`clearHeldStockSession()`; the held session's now-disconnected client makes the next
`ensureStockSession()` reconnect, and the epoch has moved, so `stockReconnect()` raises
the correct `MachineRestartedError` through the existing converter. Explain that chain in
a comment so a later reader does not "fix" it by adding the forbidden import.

The handler never throws: any unexpected error becomes a well-formed `isError: true`
result that names whether a record was written and whether the request was sent.
