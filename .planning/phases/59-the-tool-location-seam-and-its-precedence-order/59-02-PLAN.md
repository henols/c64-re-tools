<objective>
Finish the declaration, and teach the seam the three things a record can say about itself: which
environment variable names it, whether the file may name it at all, and whether the thing being
named is a file or a directory.

Seven records gain a `location` block and a `kind`. Two of those eight — the vendored disassembler
and the Node interpreter — say `fileOverridable: false` and carry the sentence a refusal will
quote, and the seam stops resolving them entirely rather than inventing a route the exclusions
exist to close.

Purpose: make the declaration the only place that knows how a tool is located, so the refusals in
plan 59-03 quote a declared sentence instead of authoring a second one.
Output: seven completed records, a `kind`-aware and exclusion-aware `resolveTool()`, and the
regenerated compiled artifact.
</objective>

  <action>
Teach `resolveTool()` to read the record rather than to know the tools.

For each queried id, load its record from the declaration and branch on three declared facts and
nothing hardcoded in this module. First, `location.fileOverridable`: when it is `false`, return
immediately with `path: null`, `layer: null`, `mechanism: null`, `tried: []` and `refusal` set to a
sentence that names the tool id and quotes the record's own `reason` field (D-16). No layer is
walked — not the environment, not the file, not `$PATH` — because the exclusion is about the tool
having exactly one legitimate location, and a `$PATH` match for the vendored disassembler is
precisely the substitution `LOC-05` refuses. Second, `location.envVar`: when the key is absent, the
environment layer is skipped entirely and `tried` gains no environment candidate; when present, its
value names the variable read from the injected environment (D-06). Third, `kind`.

Make the existence test `kind`-aware. An `executable`-kind candidate must be a statable file. A
`directory`-kind candidate must be a statable directory that contains its declared `marker`; test it

## Trust Boundaries

| Boundary | Description |

| committed declaration → the seam | Every branch `resolveTool()` takes is decided by a field in `prerequisites.json`. A wrong value there is a wrong behaviour here, with nothing in between to catch it. |

## Flagged Planner Assumptions

- **The node `reason` sentence's pronoun substitution.** `.planning/REQUIREMENTS.md`'s Out of Scope
  row reads "reads **it** before any working Node exists". Quoted on its own inside a refusal the
  pronoun has no antecedent, so this plan records the sentence with the variable named. That is a
  judgement about Phase 58 D-09's "usable verbatim inside a refusal sentence" constraint, not a
  transcription — if the intent was strict transcription, the sentence in the declaration is one word
  different from its source and plan 59-05's placement document is where that gets re-argued.
- **`location` carries no provenance field.** D-05 locks the block's shape to three keys, so the two
  `reason` sentences are the only prose in this document without a `provenance`/`source` label, in a
  file whose entire point is labelled provenance. Honouring the locked shape was preferred over
  inventing a fourth key that three consumers would then have to walk. Recorded rather than resolved.
