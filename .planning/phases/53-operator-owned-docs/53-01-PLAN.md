    For each site, replace the pointer with the reason it stood for. A rewrite must have all
    three properties:

    (a) It states WHAT was empirically established and AGAINST WHAT. For this file that is
    almost always one of two grounds, and the file's surrounding text usually already tells
    you which: the byte layout was read out of the emulator's own request decoder in its
    source, or it was confirmed by sending the frame to a genuine unpatched emulator and
    matching the reply. Where a site carries a `[VERIFIED probe-binmon.mjs:NNN-NNN]` marker
    alongside the citation, that marker names a real sibling file in this same package and
    STAYS — criterion 4 targets evidence-document paths, not every citation. Only the
    evidence-document pointer is removed.

    (b) It names ZERO paths in place of the one removed. Not a relocated path, not a planning
    tree path, not a rewritten pointer of any kind. Repointing is what roadmap criterion 4
    calls "the same defect one hop along" and it fails the criterion as hard as leaving the
    original (locked decision L4). If you find yourself wanting to write where the fact was
    recorded, write the fact instead.

    (c) It is LONGER than what it replaced. The bracketed markers being removed are terse;
    the reasoning that replaces them is not. A site that shrinks has deleted information
    rather than relocating it, and roadmap criterion 5 fails a diff whose net effect is
    deleting explanatory comments (locked decision L5).

    Do not touch the WHY header block at the top of the file beyond the one citation inside
    it, do not reflow unrelated comment lines, and do not change a single expression,
    numeric literal, exported name or type. Every edit in this task is inside a comment.
