<objective>
Resolve `capability-registry.ts` by decision, and retire the generated support table that depended on it and on the deleted fork manifest.

**Decision 1, recorded with its basis: delete `capability-registry.ts` (456 lines), with its data migrated rather than its file repurposed.** `capabilityRefusalMessage()` renders, for every category, some variant of *"Use the other backend instead (Set VICE_BACKEND=…)"* — a sentence that becomes **actively false** once there is nothing to switch to. A tool name absent from `tools-manifest.stock.json` should fall through to the plain unknown-tool message, which is now the true answer: the tool does not exist anywhere. Of the 31 entries, 17 are `descoped` fork tools that simply cease to exist, 8 are `stock-only-gain` entries whose "gain over the other backend" framing is vacuous with one backend, and 6 are the `hardware` entries whose technical text is the one thing worth keeping — and plan 52-01 already migrated it verbatim into `docs/stock-hard-losses.md`. **The named alternative — repurpose the file in place as a static accepted-limitations registry with no `activeBackend` parameter — was considered and rejected**: its `providedBy`/`activeBackend` axis IS the per-backend delta, so a one-value version is a data structure with one column, and its content would then exist twice (in the registry and in the doc) with no mechanism keeping them agreed.

**Decision 2, recorded with its basis: retire the tool-support table.** `scripts/generate-tool-support-table.mjs` derives a per-tool two-backend support table from both manifests plus `CAPABILITY_REGISTRY`; `src/mcp/vice/tool-support-table.test.mjs` (393 lines) is its byte-identity drift guard. With one manifest and no registry the table has no second column and the guard has no subject. The alternative — regenerate a single-backend tool list — was considered and rejected: with one backend, "the full per-tool answer" is `tools-manifest.stock.json` itself, and a generated Markdown mirror of a JSON file is a second, staleable copy of facts the manifest already holds. README's `docs/tool-support.md` pointer is repointed at `docs/stock-hard-losses.md` by plan 52-09.

Purpose: land criteria 5 and 6's remaining half, and close the `check-npm-packages.mjs` assertions plan 52-05 knowingly left red.
Output: no registry, no generated support table, a green package check.
</objective>
