<objective>
Capture the three VERIF-02 cases a real emulator can actually generate and commit
them with provenance, so the protocol client's tests assert against real wire
bytes rather than the planner's model of them.

Purpose: D-19 is locked — record everything a real emulator will produce, and
synthesize only the impossible cases. `DISPLAY_GET`'s ~157 KB frame, an event
interleaved between a request and its reply, and `CHECKPOINT_LIST`'s N+1 frames
on one request id are all ordinary things a healthy build emits; a hand-built
approximation of them would only ever test the planner's reading of the spec.
Output: three `.bin` fixtures plus provenance sidecars, a filled README table,
and a test asserting each parses as a well-formed frame sequence.

This plan cannot run inside the planning container: no VICE binary and no
display are present (RESEARCH.md § Environment Availability, confirmed via
`command -v x64sc`). It runs against the dual-build host Phase 1 already used.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| emulator → capture writer → repository | Bytes from a live emulator become permanent, committed test inputs |
| committed fixture → protocol parser | A hand-edited fixture silently redefines what "correct" means for every test that reads it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Tampering | `fixtures/binmon/*.bin` | mitigate | Every `.bin` carries a sidecar with `capturedFrom`/`viceVersion`/`capturedAt`/`command`; the README states hand-editing is forbidden and names the regeneration command; `binmon-fixtures.test.ts` asserts structural well-formedness so an edited fixture fails rather than quietly redefining the contract |
| T-02-10 | Repudiation | synthesized-fallback path | mitigate | A fallback fixture must be labelled `synthesized-fallback` in both its sidecar and the README row, plus a todo — a downgrade of D-19 is never allowed to look like a real capture |
| T-02-08 | Denial of Service | live capture session | mitigate | The `MAX_CAPTURE_FRAMES` cap and `finally`-block checkpoint deletion from plan 02-01 are exercised here for the first time against a real build; the checkpoint explicitly verifies no armed checkpoint survived |
| T-02-03 | Elevation of Privilege | `--help` invocation during evidence gathering | mitigate | The invocation is run by hand against a known local binary path with output captured to a file; no path is interpolated into a shell command by code, and plan 02-07's implementation uses `spawnSync` with an argv array and `shell: false` |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan |
</threat_model>
