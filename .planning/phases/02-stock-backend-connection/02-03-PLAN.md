<objective>
Teach the broker to launch a stock `x64sc` with binary-monitor flags, and retire
the argv-substring heuristic that currently decides which host processes the
startup reap is allowed to kill.

Purpose: BROK-01 is the launch half of the backend switch. BROK-03 is the promise
that adding a second launch shape does not cost the broker any guarantee it
already makes — and the orphan reap is one of those guarantees, currently
implemented as a plain substring match over any host process's full argv gated
only by "some integer ≥ basePort appears somewhere" (folded todo
`2026-08-12-broker-orphan-reap-substring-identity-match.md`, shipped code, runs
on every broker start). Phase 2 adds a second launch shape to that band, which
is exactly when a heuristic like that starts picking wrong targets.
Output: a `backend`-parameterised `buildViceArgs()`, a reap driven by the
broker's own on-disk allocation record, and rebuilt `resources/*.mjs`.
</objective>

<decisions_implemented>
- **D-12** — stock launches with the binary monitor only: `-binarymonitor` plus
  `-binarymonitoraddress` on the broker-allocated port. No `-remotemonitor`, no
  `-warp`.
- **D-14** — ports are allocated, never contested. An occupied port is skipped and
  a free one used; the broker never probes, judges, or kills whatever sits there.
- **D-15** — ownership is the broker's own allocation record, not argv archaeology.
- **D-04** — one broker only ever launches one kind of binary, so nothing
  downstream needs to tell two launch shapes apart at runtime.

**Planner decision (binmon bind address):** the stock binmon address defaults to
`127.0.0.1`, read from `VICE_BROKER_BINMON_HOST` when set. This is deliberately
narrower than the fork path's `0.0.0.0` default. VICE's binary monitor is
unauthenticated by design and grants full read/write over the emulated machine
plus process control, so a loopback-only default is the correct posture for the
common host-native install; a container-hosted MCP server widens it explicitly
via the env var, and the widening emits a one-time stderr note. The fork path's
existing `0.0.0.0` default is untouched (BACK-02).

**Planner decision (who reads `VICE_BACKEND` in this plan):** `broker-launch.mts`
gains exactly one exported reader, `backendFromEnv()`, and its doc comment states
that plan 02-07 replaces it with `backend-detect.mts`'s cached verdict and that no
second reader may be added in the meantime. The phase is not complete while
`backendFromEnv()` still exists; D-01's detection is planned in 02-07.
</decisions_implemented>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker → host process table | The reap chooses which host processes to SIGTERM/SIGKILL |
| broker → spawned `x64sc` argv | A configured binary path and port are assembled into a process launch |
| network → binmon listener | The launched binary monitor accepts unauthenticated connections granting full memory read/write and process control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Denial of Service | `reapOrphanedInstances()` | mitigate | Kill targets come only from the broker's own per-instance `epoch.json` (`pid` + `vice_bin`), passed to `verifiedKill`'s existing identity check; the argv substring match and the `>= basePort` numeric-token scan are deleted, so an unrelated host process can no longer be selected (D-15) |
| T-02-05 | Information Disclosure / Elevation | stock `-binarymonitoraddress` bind | mitigate | Default bind is `127.0.0.1`; widening requires an explicit `VICE_BROKER_BINMON_HOST` and emits a one-time stderr note naming what the exposure grants. Broader network exposure of the emulator control plane remains the already-accepted, already-deferred QUAL-03 posture |
| T-02-03 | Tampering | launch argv construction | mitigate | `buildViceArgs()` returns an argv array consumed by the existing `spawn` path — no shell, no string interpolation of the binary path into a command line; port is coerced through `String(port)` from a broker-allocated integer, never from request input |
| T-02-12 | Tampering | `VICE_ARGS` full override | accept | An operator who sets `VICE_ARGS` fully controls the launch argv by design (it exists so tests can launch `/bin/sleep`); this is pre-existing, requires local env control, and is not widened here |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan |
</threat_model>
