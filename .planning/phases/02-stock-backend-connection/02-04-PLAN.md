**Planner decision (desync recovery shape):** on an STX mismatch the parser advances
exactly one byte, increments a desync counter, and keeps scanning within the same
call — it does not bail out to wait for more bytes, and it never returns without
having advanced past the bad byte. An implausible declared body length is treated as
the same class of event: skip one byte from the STX position and count it, exactly
as `probe-binmon.mjs`'s `_onData()` already does in this repo.
</decisions_implemented>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| binmon TCP socket → parser | An attacker-controlled or corrupted uint32 length field is read before any allocation decision |
| committed fixture file → parser | Fixture bytes are parsed with the same code path as live wire bytes |
| parser → MCP process | An unhandled exception inside a socket `'data'` listener reaches the never-throw boundary and can kill a stdio server Claude Code will not restart for the session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Denial of Service | `parseBuffer()` declared body length | mitigate | `MAX_BODY_LEN` (4 MiB) checked before any body slice or allocation; an over-cap length is treated as desync (skip one byte, count) rather than honoured — the vendored client has no cap at all |
| T-02-13 | Denial of Service | `#buffer` accumulation | mitigate | Accumulated unparsed bytes above `MAX_BODY_LEN` reset the buffer and emit `StockDesyncError`; the vendor's unbounded `Buffer.concat` growth path is not carried over |
| T-02-14 | Denial of Service | throw inside the socket `'data'` listener | mitigate | Parser never throws on malformed input (defect a and b fixes); the `'data'` handler additionally wraps the parse so a genuinely unexpected throw drops the buffer and emits rather than reaching `uncaughtException` and killing the stdio server |
| T-02-15 | Spoofing | api_version byte at header offset 1 | mitigate | The byte is read and asserted equal to `0x02`; a mismatch raises a typed `StockFramingError` naming the observed value instead of being silently skipped as the vendor does |
| T-02-06 | Tampering | committed fixtures as parser input | mitigate | Fixtures carry provenance sidecars (plan 02-02) and are structurally asserted before any client consumes them |
| T-02-07 | Tampering | vendored third-party source | mitigate | Source is a reviewed hand-port from a named repo/version/license with the three known defects fixed, not an `npm install`; the vendor's own dependency chain (`zod` via `contracts.ts`/`errors.ts`) is deliberately not pulled in, asserted by a grep gate |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan. `zod` is explicitly refused (D-16); `package.json`'s `dependencies` block must be unchanged |
</threat_model>
