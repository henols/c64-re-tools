<objective>
Build the one connect handshake for the stock path: claim the monitor socket,
dial it, prove the protocol version, read the build's identity, settle its
version-gated capabilities once, and detect when the machine underneath has been
replaced.

Purpose: BACK-04 says capabilities are determined at connect rather than at first
use. PROTO-06's second half — "this is a new machine, re-handshake" — is a
question the socket layer cannot answer, because a socket close only ever means
"this socket died". PROTO-08's client-observable half lives here too: the claim
happens before the dial, so an ownership conflict arrives as a named refusal on a
working control socket instead of as a `connect()` that never returns.
Output: `stock-connect.ts` and its tests.
</objective>

<decisions_implemented>
- **D-11** — PROTO-06 rides the socket lifecycle; a broker relaunch on the same
  lease is a new machine with fresh state, so the client invalidates its
  connect-time record and re-handshakes. `MachineRestartedError` already models
  this on the fork path: reuse the type, do not invent a second one.
- **D-10** — version-gated capabilities fold into the same cached probe record,
  determined once per binary, not per connect. Phase 1 proved the signal is clean:
  `CPUHISTORY_GET` returns `0x83` (opcode absent) on stock 3.9 and `OK` on the 3.10
  fork; `0x8f` is the distinct not-compiled-in case.
- **D-13** — the ownership refusal is broker-side and arrives before any second
  `connect()`.
- **D-16** — the `api_version === 2` assertion is part of the handshake.
</decisions_implemented>

    Implement `stockConnect({ host, port, targetId, brokerControl, deps })` in this
    order, and document the ordering as load-bearing:

    1. `claimMonitor({ targetId })`. A `monitor_owned` outcome rejects immediately
       with `MonitorOwnershipError` — no socket is opened. A `timeout` outcome
       rejects distinctly, because "the broker did not answer" is not "someone else
       owns it".
    2. Open a `ViceMonitorClient` against `host:port`.
    3. Assert the protocol version. The api_version byte is read off every frame by
       `stock-protocol.ts`'s parser; the handshake sends one `PING` (`0x81`) and
       treats a non-`0x02` api_version as a fatal, typed framing failure — disconnect
       and reject rather than proceeding against an unknown wire contract.
    4. Send `VICE_INFO` (`0x85`) and read the version quad.
    5. Gate capabilities. Call `readCapabilityRecord(binPath)`; if it exists and its

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| broker control plane → connect decision | The claim outcome decides whether a socket granting full memory read/write is opened at all |
| binmon socket → handshake | Version and capability answers are taken from the emulator's own replies |
| `.vice-supervisor/backend.json` → capability gate | A cached capability record decides whether a version-gated opcode is attempted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | connect without a claim | mitigate | The claim is the first step and a refusal returns before any socket is opened; a grep gate asserts the claim call precedes the dial in source order, and a test asserts no TCP connection is attempted on refusal |
| T-02-15 | Spoofing | wrong api_version accepted | mitigate | A non-`0x02` api_version is fatal: disconnect and reject with a typed framing failure naming the observed value, rather than proceeding against an unknown wire contract |
| T-02-02 | Tampering | stale or poisoned capability record | mitigate | The record is only trusted when its stored `versionQuad` matches the quad read live from `VICE_INFO` in this handshake; a restart re-validates it, so a replaced binary cannot inherit the previous build's answers |
| T-02-17 | Denial of Service | claim leaked by a failed handshake | mitigate | Every failure path calls `releaseMonitor()` before propagating; a grep gate requires at least two release call sites (success and failure) |
| T-02-28 | Denial of Service | `CPUHISTORY_GET` count wrap | mitigate | Count is clamped client-side to 65535 — the opcode reads it as uint32 but stores it in a `uint16_t`, so a larger value wraps to a small one and silently returns the wrong slice |
| T-02-18 | Repudiation | restart reported as timeout, or conflict as wedge | mitigate | Three distinct error classes with an `instanceof` test pinning their separation, and a doc comment stating what each means; the ownership message is grep-gated against wedge language |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan |
</threat_model>
