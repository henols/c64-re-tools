<objective>
Close the stock path: a dispatch table that answers by name or refuses by name,
`vice_ping` reporting which backend and which VICE version is connected, and the
three `vice-proxy.ts` seams that make the backend switch real without changing
anything the fork path does.

Purpose: D-09 requires no fall-through from the stock path to `forwardToVice()`.
D-05 puts BACK-03's answer on the tool an agent already calls first. D-01/BACK-01
require one config value to switch backends with no code edit. And D-13 requires
that the handler which finally reaches `stockConnect()` does so with a lease from
the fork path's own acquisition — this is the plan where an unleased dial would
first become possible, so this is where it is proven impossible.
Output: the second half of `stock-dispatch.ts` and three functional edits to
`vice-proxy.ts`.
</objective>

<decisions_implemented>
- **D-09** — the change is which entries the manifest carries per backend, plus a
  stock dispatch path with **no fall-through** to the fork's HTTP forward, and no
  second dispatch site in `vice-proxy.ts`.
- **D-05** — BACK-03 surfaces as fields on the existing `vice_ping`: backend, VICE
  version, resolved binary path. No new tool.
- **D-01/BACK-01** — one config value switches backends; the resolved value is read
  through `backend-detect.mts`'s single seam, once, at module scope.
- **D-13** — the stock handler reaches `stockConnect()` only through plan 02-09's
  `ensureStockSession()`, fed by `ensureBrokerLease()` itself, so the broker's
  monitor claim always precedes the binmon dial.

**Planner decision (testability of `vice-proxy.ts`):** `vice-proxy.test.ts` is one
of the three files excluded from the automated gate, so any logic added inside
`vice-proxy.ts` would be effectively untested. Therefore the manifest selection,
the dispatch choice, and the lease-to-session logic are exported functions in
`stock-dispatch.ts`, unit-tested there; `vice-proxy.ts`'s own diff is reduced to
calling them and to widening one existing return type.

**Planner decision (three edits, not two):** an earlier draft of this plan set
capped `vice-proxy.ts` at two functional edits. That count omitted the lease
wiring entirely, which left the stock `vice_ping` handler with no way to learn a
host and port and no way to claim the monitor before dialling — the automated gate
would still have been green, because the handler's tests stubbed the handshake
away. Three is the floor, not a relaxation of discipline: there is still exactly
one dispatch site, exactly one manifest site, and exactly one acquisition
function, each grep-gated as a single occurrence below. `02-PATTERNS.md` §
"`stock-dispatch.ts`'s consumer edits to `vice-proxy.ts`" carries the same
corrected count and describes edit 3.

**Planner decision (test stubbing boundary):** tests in this plan stub only
`StockDispatchDeps.connect`/`reconnect` — the socket-touching half. They never stub
`ensureStockSession` and never stub `ensureLease` away to a no-op, because the
wiring between them is exactly what a stubbed handshake hid last time.
</decisions_implemented>
