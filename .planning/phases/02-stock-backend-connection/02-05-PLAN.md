<objective>
Make exclusive monitor-client ownership a broker-enforced fact, so a second
client is refused before it can dial — the one state stock VICE cannot report
and no client-side heuristic can diagnose.

Purpose: stock VICE's binary monitor services exactly one client. A second
`connect()` sits unserviced in the backlog with no reply and no EOF, which is
byte-for-byte indistinguishable from a wedged emulator. PROTO-08 and BROK-02 are
two halves of one mechanism and land together here. The existing `GrantRecord`
does not already solve this: it answers "which container-side process may use
this instance's lifecycle", not "has the raw binmon socket been dialled" — and
the acquire happens strictly before the dial, so the two events are not the same
event.
Output: an additive ownership record on `InstanceRecord`, two new control-plane
ops, a typed conflict outcome on the container side, and rebuilt
`resources/*.mjs`.
</objective>

<decisions_implemented>
- **D-13** — exclusivity is enforced broker-side; the lease is the owner. The
  broker's instance record carries "this instance has a monitor client"; a
  conflicting request is refused with an ownership conflict naming the holder.
  Nothing ever reaches a second `connect()`. No client-side timeout heuristic —
  that would be a guess on exactly the signal that has no distinguishing shape.
- **D-15** — ownership is the broker's own record, read from its own bookkeeping.

**Planner decision (RESEARCH.md Open Question 1 — how the client tells the broker
the socket is open):** a genuinely new control-plane op, and it is a *claim before
dialling*, not a report after connecting. Two ops join
`ControlRequestKind`'s existing five-message vocabulary: `monitor_claim` and
`monitor_release`. Rationale: reporting after the fact cannot satisfy PROTO-08,
because by then the second `connect()` has already been attempted and is already
sitting in the backlog with no reply — the exact undiagnosable state the
requirement exists to prevent. Claiming first means the refusal is a JSON response
on a socket that already works, and the second client never dials at all. Folding
the flag into `acquire` was rejected for the reason RESEARCH.md gives: the acquire
happens before the client has dialled the binmon port, so the two events are not
simultaneous.
</decisions_implemented>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| container-side client → broker control plane | A TCP control session that can claim exclusive control of an emulator instance |
| broker control plane → instance ownership record | The record that decides who may open a socket granting full memory read/write over the emulated machine |
| any local process → binmon TCP port | VICE's binary monitor is unauthenticated; the broker's ownership record governs this codebase's own clients, not arbitrary local processes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | `monitor_release` from a non-holder | mitigate | The release handler compares the requesting grant id against `monitorClient.grantId` and refuses a non-holder, so one client cannot steal another's ownership by releasing it; the same comparison makes a repeat claim from the holder idempotent rather than a conflict |
| T-02-16 | Elevation of Privilege | unauthenticated control op | mitigate | Both new ops run the same constant-time `newControlToken()` check every existing op runs, before any state read or write — the token gate is not re-derived locally |
| T-02-17 | Denial of Service | stale ownership lock after a client crash | mitigate | `monitorClient` is cleared on release, on recycle, and on the instance's process exit in `broker-launch.mts`'s supervision path — a dead client cannot hold an instance forever |
| T-02-18 | Repudiation | ownership conflict misreported as a wedge | mitigate | The refusal payload names the holding grant id and claim timestamp; grep gates assert the conflict text never uses wedge/hung/unresponsive language, so `vice-wedge-triage` is not misdirected |
| T-02-19 | Denial of Service | an out-of-band local process dialling the binmon port | accept | VICE's binary monitor has no authentication and this cannot be prevented at the wire level. Scope of BROK-02/PROTO-08 is this codebase's own clients never racing each other; broader network exposure of the emulator control plane is the already-deferred QUAL-03 posture (RESEARCH.md § Security Domain, ASVS V4 marginal) |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan |
</threat_model>
