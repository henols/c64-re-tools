**A. Add `parseRootArg()` to `scripts/lib/audit-root.mjs`.**

Signature: `parseRootArg(argv, { script, booleanFlags = [] })`. `argv` is
`process.argv.slice(2)`. `script` is the invoking script's own base name, used only in
error messages so a refusal names its source — this repository's guards are invoked as
their own file names (D-12-11) and their errors must read the same way. `booleanFlags`
is a caller-supplied list of value-less flags the script also accepts; the only current
member across all six consumers is `--json`, on `scripts/check-guard-fates.mjs`.

Returns `{ root, flags }` — `root` is the raw string value or `undefined` when the flag
was absent; `flags` is an object with one `true` entry per declared boolean flag that
appeared.

It throws an `Error` — never returns a partial result, never warns and continues — for
each of these, and each message begins with the literal `BAD ARGUMENTS --` so a caller
can tell an argv rejection from `resolveContainedRoot()`'s containment refusal by its
message rather than by its exit status. Keeping both at exit 1, distinguished by the
message, is the existing convention stated verbatim in four of the consuming scripts'
preambles ("exit with the SAME code, so they are separated by their message"); do not
mint a new exit code for this.

  1. Any token that is not `--root`, not a declared boolean flag, and not the value
     immediately following `--root`. Message quotes the token and prints the accepted
     usage line for `script`.
  2. `--root=<value>` in any form. Message quotes the whole token, states that the
     space-separated spelling is the only accepted one, and shows the corrected
     invocation. Do NOT quietly accept the equals form: the verifier's finding is that
     an operator typo currently reaches a filesystem write, and a parser that guesses
     is what produced that.
  3. `--root` as the final token, or followed by a token beginning with `--`. Message
     says the flag requires a directory.
  4. `--root` followed by an empty string. Message says an empty value is not a
     directory and is specifically not a request for the default root — the silent
     fallback is the defect.
  5. `--root` appearing more than once. Message names both values and states that a
     repeated flag is rejected rather than resolved by position, so no invocation's
     meaning depends on which copy the parser happened to keep.

Give it a docblock in the file's established voice: WHY it lives here rather than in six
consumers (`IN-06` — the same reader was copy-pasted verbatim into six files and the
same defect shipped six times), and WHAT NOT TO DO (do not add a permissive mode; do not
return `undefined` on a parse error; do not resolve the value here — resolution is
`resolveContainedRoot()`'s job and the two stay separate so a containment refusal and an
argument rejection never blur).
