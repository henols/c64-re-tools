<objective>
GAP CLOSURE, round 3 — **TRACER.** Gap 2: the restore machinery is disarmable, and this is a
REGRESSION introduced by round 2's own remedy.

**The defect, in one paragraph.** `scripts/audit-mutation-harness.mjs` guards its restore-all
function with a module-level boolean that is set on the first call and never reset. Plan 32-19
EXPORTED the plant and restore-all functions so an in-process driver could reach the harness's
real registered handler — the right call, and it landed a two-round behaviour-unverified truth.
But the two together mean any consumer that completes one restore cycle **permanently disarms**
the `exit`, `SIGINT`, `SIGTERM` and `uncaughtException` handlers for the rest of the process.
The round-3 verifier reproduced it against a scratch root with its own driver: plant → restore →
plant again → SIGINT gave `EXIT=130`, `pendingRestoreCount()` = 1, and the second plant still on
disk. That is exactly the half of plan 32-19's must-have 1 that reads *restores every captured
original byte-for-byte*.

**Scope, stated so this plan does not over-claim.** The shipped CLI path is **provably safe**
and the verifier proved it twice: `main()` calls the per-row revert inside the row loop (which
deletes from the captured-originals map without touching the latch) and the restore-all function
exactly once in the `finally` after that loop, so the latch is never set while a plant is on
disk; the verifier's own 61-row `--all` sweep ended `tree: restored byte-identical to the
baseline`. The one in-process consumer that exists plants once per child process and is
unaffected — which is precisely why its 5/5 green does not catch this.

**The remedy is proven by the code itself, not proposed from expectation.** The restore-all
function ends by clearing the captured-originals map, so a second call iterates an empty map and
writes nothing even with no latch present. The latch is therefore redundant for the property it
was added for and harmful for the property it breaks, and the committed `WR-03` sentinel test
stays green by construction rather than by adjustment.

**Why this is the tracer.** It is the smaller, fully-proven defect, self-contained and
independently verifiable end to end — instrument, fixture-driver layer, test layer, and a real
runnable end-to-end check (`node --test src/mcp/vice/audit-harness-restore.test.ts`). Plan 32-21
expands from this green base with gap 1's arithmetic and the whole-set `--all` re-run.

**Why the bite proof is not optional.** Round 1 and round 2 each closed their gaps AND left a
regression in this same file. `WR-36` records that three of this instrument's behaviours ship
with no standing guard at all. So this plan captures the new case RED against a deliberately
re-introduced latch before it captures it green.

Two cheap hardenings land here because they are in files this plan is already editing, and they
are taken rather than deferred: **`WR-29`** (the porcelain attribution excludes `src/`, which is
where a mis-contained plant lands) and **`WR-28`** (the plant-observation loop reads only its own
deadline, never the child's exit state). Everything else the verifier dispositioned is deferred
by name in plan 32-21's Task 3 rather than silently dropped.

Implements **D-04** (the harness is a committed, re-runnable instrument whose reverting cleanly
is load-bearing), **D-08** (only text that misdescribes live behaviour is corrected; dated
records stay byte-identical), **D-13** (broker state is an asserted, recorded precondition of
every recorded figure), **D-15** (the evidence artifact carries raw commands, raw output, broker
state and the commit measured), **D-16** (no new CI step and nothing added to either
`package.json` `scripts` block) and **D-17** (the harness stays a phase instrument; this plan
adds a restore-machinery contract test, not a harness CI job).

Purpose: verifier truth 16 stops reading FAILED, and the ledger records the arc of the defect
instead of quietly closing the entry that was about it.

Output: a latch-free restore path; one new in-process driver; the discriminating case for both
signals; two hardenings in the same test file; an evidence file carrying the bite proof; and one
atomic ledger commit.
