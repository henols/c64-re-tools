<objective>
GAP CLOSURE, round 2. **Gap 2, second half — `scripts/audit-mutation-harness.mjs`, the sole
producer of this phase's entire observed-red evidence, and the one script the shared parser
was modelled on but never reached.**

**What the verifier measured.** The harness's reader does reject an unrecognised token — that
is why round 1 cited it as the model — but it takes `argv[i + 1]` with no missing-value check.
So a valueless `--root` yields `root === undefined`, which `resolveContainedRoot()` maps to
the repository root with no message at all, and the run proceeds to load the REAL registry
while the operator believes they pointed it at a synthetic tree. Reproduced live:

    node scripts/audit-mutation-harness.mjs --row src/does/not/exist.ts --root
    -> row selection: "src/does/not/exist.ts" matched 0 registry row(s)   [exit 1]

Reaching row selection means the real `guard-fates.json` had already been read. Nothing in the
output mentions `--root`; the control run without the flag prints the identical message, and
`--root /tmp` prints a refusal, so the space form works and the defect is exactly the
valueless path. The same reader also swallows a following flag as a value: `--root --row
<path>` consumes `--row` as the root and then rejects the path. `--rows` and `--out` carry
the identical hole.

**Why this one matters more than the other seven.** With a real row name and `--all`, that
same invocation plants mutations in the real working tree, rewrites the real registry and the
real evidence file. This is the ONE instrument in the phase that both MUTATES the tree and
WRITES the record. The committed evidence is not corrupted — measured, `--root` appears in
`guard.argv` in 0 of 61 rows and all 35 plants are worktree plants — but it is sound because
nobody exercised the defective path, not because that path is safe. That is `CR-05`, and it
is why the verifier calls the reliance coincidental rather than laundering it.

**Why the parser has to grow first.** `--row`, `--rows` and `--out` are value-taking flags
`parseRootArg()` does not know about. `gaps[0].missing[0]` gives two acceptable shapes and
this plan takes the first: extend the parser with a declared `valueFlags` list, supplied in
code and never from argv, applying the same three rules to each. The alternative — restating
the three rules per flag inside the harness — would recreate `IN-06` on a smaller scale, in
the file the seam was extracted from, which is the exact irony this gap already contains once.

**And the citation that made the gap invisible.** `scripts/lib/audit-root.mjs:119-122` records
the harness's reader as the model that was reused everywhere. It was not reused in the file it
was taken from, and that file still carries half the defect it was cited as immune to. Round 1
therefore shipped, in the seam's own documentation, a claim that would have led a reader
checking the seam's provenance straight past the remaining hole.

Implements **D-04** (a committed, re-runnable harness produces the evidence — an instrument
that can be silently pointed at the wrong tree cannot keep that promise), **D-06** (`--root`
is the testability seam and there is no other hatch), **D-07** (`--root` work carries an
ordering boundary), **D-15** (the evidence artifact carries raw commands, raw output, broker
state and the commit measured) and **D-17** (the harness stays a phase instrument, not a CI
job — nothing here adds a CI surface).

Purpose: the precondition the whole of `CUT-04`'s evidence rests on stops being a habit and
becomes a property of the code.

Output: a parser that knows about value-taking flags; a harness on the seam with its selector
rule intact; a corrected citation; and an evidence file carrying every malformed form for all
four flags, before and after.
