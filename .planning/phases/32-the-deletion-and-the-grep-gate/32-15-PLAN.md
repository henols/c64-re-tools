<objective>
GAP CLOSURE, round 2. **Gap 4 (`CR-06`) — the instrument that refuses honest evidence and
cannot finish a sweep.** This is the TRACER for the round: the thinnest path that touches
every layer this round will modify — descriptor, plant, guard run, observed red, registry
write-back, evidence file — proven end to end on one row and then on the whole set, before
any other plan expands out from it.

**What the verifier measured.** `scripts/audit-mutation-harness.mjs:219` computes the
post-condition count as the number of occurrences of the recorded replacement string in the
WHOLE mutated file, and throws unless it is exactly 1. Row
`scripts/lib/skill-honesty-checks.mjs` has an honest descriptor — its `find` occurs exactly
once, the mutation is unambiguous — but the un-negated form of its `replace` already occurs
once elsewhere in the same file, so the count comes out 2 and the plant throws. Reproduced
by the verifier at HEAD in one command, tree clean before and after.

Two consequences, both inside `CUT-04`'s own subject matter. That row is planted row 23 of
35, and the throw is caught by the try/catch in `main()`, which restores and exits 1 — so a
sweep aborts, later rows go unmeasured, and the registry write-back is never reached. And
the failure message tells the operator to change the descriptor rather than the check: an
instrument that instructs a reader to edit the evidence is worse than one that is merely
wrong.

**What this plan measured that the verifier did not, and why it changes the shape of the
fix.** The post-condition is the SECOND blocker of an `--all` sweep, not the first.
`selectRows()` returns all 61 rows for `--all`, and `measureRow()` calls `runGuard()`
unconditionally — but only the 35 `re-pointed` rows carry `guard` and `plant` descriptors.
The 19 `kept-unchanged` and 7 `deleted` rows carry neither, by design: `D-05` says the
verdict decides what evidence a row owes, and those verdicts owe a removal trigger, not an
observed red. So the sweep throws at registry index 22, `scripts/lib/skill-descriptions.mjs`,
BEFORE it reaches index 23. Measured by one command during planning, with
`git status --porcelain` byte-identical before and after:

    node scripts/audit-mutation-harness.mjs --rows scripts/lib/skill-descriptions.mjs
    -> audit-mutation-harness: FAIL -- row scripts/lib/skill-descriptions.mjs: no `guard` descriptor.

Fixing only the arithmetic would therefore leave `gaps[2].missing[2]` — "run `--all` once to
prove the whole-set sweep completes" — unachievable, and an executor would discover that
halfway through. Both blockers are the same gap and both are fixed here.

Implements **D-04** (a committed, re-runnable harness produces the evidence — re-runnability
is the property `CR-06` broke), **D-05** (the verdict decides what evidence the row owes —
the rule the skip branch encodes), **D-08** (nothing historical is rewritten), **D-13** (the
broker's state is an asserted, recorded precondition of every recorded figure), **D-15** (the
evidence artifact carries raw commands, raw output, broker state and the commit measured) and
**D-17** (the harness is a phase instrument, not a CI job — so nothing here adds a CI
surface).

Purpose: `CUT-04`'s promise to a later reader is that the recorded evidence can be
re-measured by the committed instrument. At HEAD it cannot — not one row, and not the set.

Output: a harness whose post-condition is arithmetically correct and whose sweep completes;
one row re-measured; one whole-set sweep captured; and an evidence file recording both.
</objective>
