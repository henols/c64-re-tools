<objective>
Close G-64-4: a cold session's first `vice_*` call fails because the broker answers the
relay `attach` as soon as it has STARTED its one dial to the emulator, not when that dial
has connected. Real x64sc binds its monitor port 55-142ms after spawn; the client's attach
and first PING land 17-31ms after spawn; the dial gets ECONNREFUSED, the relay dies under
the PING, and the tool answers "stock handshake failed ... 1 request(s) abandoned".

The fix goes at the splice/attach seam, because every affected path already passes through
it — the cold acquire's first attach, the first attach after a recycle respawn, and the text
channel, whose port binds 1-2ms after the binary one. The broker dials the emulator first,
retries ECONNREFUSED at a short interval up to a bounded deadline, and only then
acknowledges and splices. An acquire-side readiness wait was considered and rejected: it
would cover only the cold arm, it sits beside the `inFlight` guard, and it would need a
reservation step to keep the 500ms promotion pass from handing the record to a concurrent
acquire.

This is the same fault class as G-64-3 (plan 64-13) — a broker acknowledgement sent when
its own side is done, not when the far side is ready — but on a different seam with no
shared code, so it is a separate plan. The two plans share files (`vice-broker.mts`,
`broker-endpoint.ts`, `stock-handler.ts` and the compiled `resources/vice-broker.mjs`), so
they run in sequence, this one first because it blocks every cold session.

Purpose: a Claude session's very first vice tool call works, which the Core Value's "keep
working when the emulator misbehaves" requires on the happy path.

Output: the gated attach seam; regression tests whose emulator stand-in binds late; a client
attach wait longer than the broker's deadline; truthful handshake-failure text.
</objective>
