<objective>
Remove the client-side empty-token parameters from the relay and transfer dial paths,
now that plan 64-08 made the broker authenticate `attach` and `transfer` by handle
alone — the second half of G-64-1 route (b), which the orchestrator's direction names
explicitly.

Purpose: the production code has sent `token: ""` on every relay and transfer line
since Phase 63 because the parameter existed and nothing ever filled it. Leaving the
parameter in place leaves a documented slot that invites the next reader to "fix" the
empty value by threading the per-boot token through — exactly route (a), which owner
decision 5 rules out. Deleting the slot makes that mistake unwritable.

Output: two dial option types and three dependency types with no credential field,
request lines whose key sets are pinned by wire-level tests, and every client comment
that described a token-authenticated relay or transfer rewritten.
</objective>
