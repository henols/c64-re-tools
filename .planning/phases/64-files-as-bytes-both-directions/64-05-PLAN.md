<objective>
Close the second half of `XFER-07`: a sweep that removes what a crashed broker left
behind. Fold in the `resolves_phase: 64` todo D-08 accepts as real work — the
per-launch emulator config scratch directories move under the machine-level broker
root and are reaped there, with the live-pid guard D-08 makes mandatory.

Purpose: this is the phase where the broker first grows a cleanup discipline at all,
and two independent sweepers in one process is exactly the duplication this
codebase's one-module-per-seam rule exists to prevent. The decisive caveat is that
the two kinds have opposite lifetime rules, so they share a sweeper and a root but
never a rule.

Named cost, accepted at the point of decision: on this host `/tmp` is a tmpfs whose
aging is disabled, so moving these directories off it stops the RAM leak — 4,779
directories measured after seven days of uptime — but lands them on real disk, where
they survive reboot. The sweep becomes load-bearing rather than a nicety.

Output: the relocated scratch directory with its header comment rewritten, two
live-pid-aware reap passes in `broker-kill.mts`, and both wired into the broker's
existing unconditional startup reap.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk pid record → reap decision | A record a previous broker wrote, read by a new one, deciding whether to delete a directory |
| staging root enumeration → recursive delete | A directory listing driving an unconditional recursive removal |
