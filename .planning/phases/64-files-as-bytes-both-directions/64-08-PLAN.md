<objective>
Close G-64-1's PRIMARY root cause by making the broker authenticate relay `attach` and
file `transfer` connections by their broker-minted handle alone, ahead of the per-boot
token gate — route (b), chosen by the orchestrator and binding on this plan — and prove
it with the regression test that did not exist: the REAL `vice-proxy.ts` over stdio,
against a REAL control listener, reaching the relay attach and returning a result that
the test actually reads.

Purpose: since Phase 63 every `vice_*` tool opens its relay (and, since Phase 64, its
transfer) connection with an empty token, because no production code supplies one, and
`broker-control.mts` checks the token before it dispatches `attach`/`transfer`. The
owner decision (REQUIREMENTS.md decision 5, echoed in ROADMAP.md: "There is no token and
no credential of any kind") forbids fixing that by threading the token through. The
handles are already unguessable, broker-minted, and only ever handed out over the
still-token-gated control session, so they can carry the authority on their own.

Output: two dispatch arms moved ahead of the gate with every handle check intact, one
default-port resolver shared by every fixed-endpoint dial (closing the latent
"relay always dials 19510" note the diagnosis recorded), end-to-end regression tests
through the real proxy on the binary channel, the text channel and both transfer
directions, and the T-63-01 reversal on record as Phase 64 evidence.
</objective>
