<objective>
Migrate the snapshot pair — `vice_snapshot_save` and `vice_snapshot_load` — off the
shared-filesystem path and onto the transfer protocol.

Purpose: CONTEXT.md's specifics note picks this pair to go first because a `.vsf`
is binary and definitely not valid UTF-8, which makes it the natural `XFER-05`
byte-for-byte fixture, and because the two tools prove each other — save downloads
what load uploads. That mutual proof is what makes a byte-corruption bug fail loudly
here rather than quietly in a later tool.

Output: both handlers reading and writing bytes over the socket, their results
carrying the opaque handle instead of a broker-side path (D-15), and a round-trip
test over disjoint client and broker roots.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tool argument → snapshot name | An agent-supplied `name` used to build a filename under the client's own snapshots directory |
| broker staging reply → binmon request body | A broker-chosen filename the client relays into a DUMP or UNDUMP body without opening it |
| downloaded bytes → client filesystem | Untrusted bytes written under the client's own tool-written root |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-64-18 | Tampering / Elevation of Privilege | `handleSnapshotSave` / `handleSnapshotLoad` — a `name` treated as a path fragment | high | mitigate | The existing 1-to-64 alphanumeric-underscore-hyphen allow-list stands unchanged (D-13); it refuses rather than sanitising, and it runs before any path is built. |
| T-64-19 | Information Disclosure | A tool result leaking a broker-side path to the agent | medium | mitigate | D-15 replaces `sentPath` with the opaque handle; a test enumerates every key of the result object and asserts no value contains the staged path or staging directory. |
| T-64-20 | Tampering | A download interrupted mid-payload leaving a partial `.vsf` at its final name that a later load then consumes | high | mitigate | The atomic publish lives in the transfer layer (plan 64-01): temp write, rename only after digest and length verify, temp removed on every failure path.
