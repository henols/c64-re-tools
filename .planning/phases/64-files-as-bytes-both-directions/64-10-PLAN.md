<objective>
Close G-64-1's SECONDARY root cause: the broker and the client resolve broker.json in
different directories on the documented start route. With no `--repo-root` the broker
writes `~/.c64-re-tools/supervisor/broker.json` (broker-home.mts, BROKER-06), while the
client reads `<project>/.c64-re-tools/supervisor/broker.json` (repo-root.ts) and never
consults broker-home.mts. Only vice-launcher.sh's `--repo-root` pin made the two agree,
and that pin puts broker state inside one project's tree — the thing BROKER-06 forbids.

Decision taken here (the orchestrator asked for it): the `--repo-root` pin stops moving
the state directory, and the client imports broker-home.mts's resolver. Both sides then
compute the state directory through one function, so every start route resolves the
same file. The remaining container-side gap — a devcontainer cannot see the host's
home — has no translation fix (the path is outside the bind mount) and is permanently
removed by Phase 66's deletion of broker.json (RM-02); it is recorded, with its
interim remedy, rather than papered over.

Output: one resolver shared by broker and client, route-agreement tests that start a
real broker per documented route under a scratch HOME, a hermetic proxy test harness,
a tarball that ships what its entry points import, and the decision record.
</objective>
