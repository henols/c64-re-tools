# Phase 64: Files as Bytes, Both Directions Verification Report

**Phase Goal:** The four file-carrying tools work with no shared filesystem
between client and broker at all. Bytes cross the socket; the client writes
only under its own `.c64-re-tools/`; the broker chooses and owns every path
on its own side; neither ever names a path the other must be able to open.

**Verified:** 2026-09-24
**Status:** human_needed
**Re-verification:** Yes — round 4, after gap-closure plan 64-16 (G-64-6,
CR-01 from the round-three review).

## What changed since the previous verification round

The previous round (round 3, 2026-09-24T13:15:00Z) scored 7/8 truths verified
and left one gap open: **G-64-6** (CR-01 in the round-three `64-REVIEW.md`,
truth #5) — `vice-broker.mts`'s `run()` called `sweepOrphanedStaging()`
unconditionally, before the control-port singleton bind was even attempted,
with no liveness check of any kind. A second broker started while a live
broker held the control port could delete every staging session directory
the live broker's own sessions owned — including a disk image attached to
unit 8 or a file mid-transfer — before ever learning, via `EADDRINUSE`, that
it had lost the race.

Plan **64-16** closed this. Route (a) was chosen: the staging sweep now runs
exactly once, only in the process that has won the control-port bind, and
only before that process publishes its control token. Three new
spawned-real-broker tests prove it through the real, compiled `run()` path
(not a direct call of `sweepOrphanedStaging()`), and a mutation check proves
the guarding test is not vacuous. `broker-kill.mts`'s contract text was
corrected to state the new precondition rather than the old, now-false
unconditional-residue claim.

This verifier independently re-confirmed the closure against source and
against re-run tests (see the `re_verification.gaps_closed` entry above and
"Observable Truths" below) — not from `64-16-SUMMARY.md`'s own claims. This
round's own code review (`64-REVIEW.md`, reviewing all six 64-16-changed
files at full-file depth) found **zero critical findings**: one Warning
(a retained comment inaccurately claims a structural test covers
`reapOrphanedConfigScratch()`'s placement, which this verifier independently
confirmed is true — no such test exists) and one Info (no fast structural
regression guard exists yet for the new sweep-placement invariant, only the
three slower spawned-process tests). Neither is a defect in the fix itself,
and neither blocks this phase's own success criteria.

**This closes the phase's last outstanding code gap.** All 8 observable
truths (mapping to ROADMAP Success Criteria 1–5 and requirements
XFER-01..08) are now VERIFIED. However, this verification's status is
