<objective>
The executor's own allowlist catches up with the endpoint route, now that no caller sends the
removed keys (plans 65-05, 65-06 and 65-07 removed the last senders). Per D-08, `outDir` leaves
HOST_TOOL_ARG_KEYS and HOST_TOOL_PATH_ARG_KEYS on every tool, with a named refusal. Per D-06,
`sourceDir` leaves ghidra.installExtension, and the broker installs from its own vendored tree.

**A constraint outside the offered options, recorded in writing.** D-06's premise is that "the
broker ships from the same @henols/vice-mcp package". `vendor/ghidra-ext` is tracked but is not
in package.json's files[], so an npm-installed broker (the universal start command) has no tree
to install from. This plan adds it to files[] so that D-06 holds on that route too. The unbuilt
checkout and the plugin route already carry it.

Purpose: the two removed keys are refused everywhere by name, and the extension install needs no
upload.
Output: an allowlist with no outDir and no sourceDir, a vendored-tree locator, and moved census
tests.
</objective>
