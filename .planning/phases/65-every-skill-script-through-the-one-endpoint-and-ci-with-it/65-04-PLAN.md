<objective>
SEAM-02's second criterion, made true for the four host-tool skill scripts (D-14): the file they
resolve on ladder rung 3 must execute from a real `node_modules` tree. Node refuses to type-strip
any `.ts` under `node_modules`, and no flag lifts that (RESEARCH Critical Finding 1, reproduced on
Node v24.20.0). So the client closure the skill scripts reach is compiled into `resources/`, and
the CLI entry the skill scripts spawn is the compiled `resources/host-tool-endpoint.mjs`.

The ladder itself is untouched (SEAM-02). Only the FILE NAME a skill script passes to
`resolveMcpModule()` changes, and that change lands in plans 65-05 and 65-06. The invocation shape
stays a subprocess, `process.execPath <resolved> run --tool --args --repo-root` (Claude's
Discretion, decided: `import()` would hit the same restriction, so the shape is not the fix).

**Constraints outside the offered options, recorded in writing:**
- **A compiled mirror of broker-endpoint is not a second copy.** The orchestrator flagged the
  risk (a compiled broker-endpoint must not become a hand-written copy, SEAM-01). The mirror is
  GENERATED by build.ts from the one `broker-endpoint.mts` source, banner-marked, and
  drift-tested by resources-sync.test.ts, the existing precedent (`transfer-hash.mts`).
- **Two files are renamed.** `broker-endpoint.ts` becomes `broker-endpoint.mts` and `version.ts`
  becomes `version.mts`, because CLAUDE.md's convention is that `.mts` marks what build.ts
  compiles, and the build emits `.mjs` only. `rewriteRelativeImportExtensions` (measured working
  in TypeScript 7.0.2) lets one source import `./x.mts` in source mode and emit `./x.mjs`
  compiled, so every module in the closure runs from source AND from resources/.
- **The compiled client must find its package.json one directory up.** broker-endpoint's
  CLIENT_VERSION resolves `package.json` beside the module. From `resources/` that file does not
  exist, the version would degrade to the dev placeholder, and a published client would refuse
  every published broker as a major-version mismatch. version.mts gains an ordered candidate
  list (beside, then one up), which is the same two candidates broker-control.mts's own
  resolveBrokerVersion() already reads.
- **D-07 wants every result root to go through toolsDir(); the compiled CLI cannot.**
  repo-root.ts imports install-resources.ts and hostpath.ts, which cannot be compiled. The CLI
  therefore joins the `.c64-re-tools` literal onto its `--repo-root` argument by the documented
  convention the five host-bound files already follow. repo-root.ts's census comment gains the
  file in the same commit. The same-package route keeps calling toolsDir() (plan 65-07).
- **The execution test cannot run npm.** CLAUDE.md forbids calling a package manager from code,
  and that binds a test too. The fixture is built by copying the package's own `files[]` set and
  a version-stamped package.json into `<tmp>/proj/node_modules/@henols/vice-mcp/`. The property
  Node's restriction binds is the literal `node_modules` path segment, and the copy has it.
  Phase 64's route-agreement check missed the restriction because its directory had another name.
- **The test's negative control is the D-14 route itself.** `vice-cli.mjs anno` run from the
  fixture fails with the type-stripping refusal. When the follow-up todo fixes that route, this
  control flips, and the test says so in a comment.

Purpose: an npm-installed skill script reaches a module that actually runs.
Output: the compiled client closure, the CLI entry, the execution test, and the follow-up todo.
