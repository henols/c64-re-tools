<objective>
Expand the tracer to every host tool: every input kind crosses as bytes (D-03), acme.build carries
its trees (D-04) through a walk that skips dot entries and refuses escaping symlinks (D-05), the
one 16 MiB constant caps every file and every request's upload aggregate (D-11), only declared
results come back and the scratch goes with the request (D-09), and no broker path reaches the
client (D-10). All of it still rides `runHostToolOverEndpoint()`; no caller switches yet.

**Constraints outside the offered options, recorded in writing:**
- **D-03 lists `exportPath` as an input to upload. It is an output.** host-tool.mts's ghidra
  branch appends the resolved exportPath to `outputs[]`, and Ghidra's post-script writes it. The
  endpoint route therefore sends exportPath as a bare output NAME. The broker validates it as one
  safe segment (refuse, never sanitise), places it at `<scratch>/out/<name>`, and returns it as a
  declared result that lands under the client's `runs/ghidra/`, exactly as D-07/D-09 say for
  every result.
- **D-03 lists `scriptPath` as a single-file input. It is a directory.** ghidra-project.mts passes
  it as `-scriptPath <dir>`. The endpoint route uploads it as a tree under D-04/D-05's walk rules,
  like an acme `-I` tree.
- **Ghidra's project cannot move into the scratch.** The scratch sits under brokerStagingDir(),
  whose absolute path carries a dot-prefixed segment, and Ghidra's ProjectLocator refuses one.
  The project therefore stays under the broker's own `--repo-root`, reached through the existing
  alias, until Phase 67 (RM-06) relocates it. `HostToolDeps.projectRoot` carries that root, and
  the same root keeps feeding the tool-location seam's `tools.json` layer, exactly as today.
- **A tree can exceed the broker's line cap before it exceeds the byte cap.** broker-control.mts
  destroys a connection whose line reaches MAX_LINE_BYTES (65536). The client refuses by name
  before dialling when its stage line would not fit. A relation test keeps the mirrored budget at
  or under the broker's cap.

Purpose: the endpoint route carries every tool's real inputs and outputs, so the callers can move.
Output: complete input binding, tree upload, both-end caps, declared-results-only, path-free
replies, and their tests.
</objective>
