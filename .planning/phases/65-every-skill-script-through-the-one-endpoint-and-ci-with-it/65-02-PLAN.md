<objective>
Anno leaves the MCP surface. The 25 `anno_*` tools stop appearing in `tools/list` (D-13), anno
runs as a stateless, client-local CLI (D-12), and every skill moves off the tools onto that CLI in
the same change, naming only invocation forms that run today (D-14).

**A constraint none of the offered options contained, recorded here in writing.** D-12 and D-13
assume the anno CLI can already answer the 25 verbs. It cannot: `anno-cli.ts` dispatches exactly
six verbs (render-memmap, coverage, export-asm, evid-disagreements, decomp-completeness,
hazard-report), and none of the 25 store-writing or store-reading tools has a CLI route. Two of
the 25 names even collide with CLI verb names (hazard-report, evid-disagreements). This plan
therefore adds ONE generic verb, `call`, that takes an `anno_*` name and one JSON argument object
and hands both to the existing `runAnnoTool()`. The name set and the argument shapes stay exactly
the MCP tools' own, so a skill's argument documentation stays valid and no verb is implemented
twice.

**A second recorded constraint.** D-13 relies on "the existing structural guard that catches a
skill claiming a tool the server does not advertise". That guard,
`scripts/check-skill-tool-coverage.mjs`, was deleted in commit `e4759250`
(`ci(260914-poo): drop the four text-scanning skill checkers ...`). 260914-poo D-1 bans a test
that asserts on document text, so this plan does not rebuild it. The proof becomes a measured
census in phase evidence, the same measure-don't-assert shape 64 D-18 chose.

**A third recorded constraint.** `src/skills/vice-wedge-triage/SKILL.md` line 185 names "the
`anno_*` tool surface". The main working tree carries uncommitted owner edits to that file that
are not this phase's work, so this plan does not edit it: merging a branch that touches it would
collide with those edits. The census records the line as a known residual, to fix once the owner
commits.

No REQUIREMENTS id owns this work (CONTEXT: folded todo). The frontmatter names SEAM-01 because
the plan schema needs a non-empty list and this plan changes the MCP server's advertised surface,
which SEAM-01's census covers. D-12 and D-13's own criteria verify it.

Purpose: the MCP surface keeps only tools that are the server's; annotation keeps working with no
emulator.
Output: the `anno call` verb, an MCP surface with no anno tools, migrated skills, corrected
living docs, the census, and the closed todo.
</objective>
