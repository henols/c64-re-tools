<objective>
The tracer: a host tool runs through the one endpoint with no shared filesystem, one file in and
one result back. A new client function, `runHostToolOverEndpoint()`, uploads the source over
Phase 64's transfer, asks the broker to run `acme.build` against its own per-request scratch copy,
downloads the declared result, and writes it under the caller's own `<toolsRoot>/builds/`.

The legacy routes stay live and untouched in this plan: `runHostToolFromContainer()`, its
isInsideContainer() branch, `hostToolOverHostRoute()` and the token-gated `host_tool` op all keep
working exactly as today, so the suite stays green. Later plans move the callers.

Decisions implemented here: D-03 (inputs cross as bytes, the request names the minted handle),
D-07 (results land under the client's own per-kind directory, first live producer of the XFER-03
validator), D-09 (the request's scratch is deleted when the request ends), D-10 (host-tool.mts's
byte-payload prohibition amended in this change, because this change is the one that makes its
second clause untrue), D-11 (the one TRANSFER_MAX_BYTES constant governs each file). The D-01
harness is created here in its minimal form, because the tracer's own verify needs a real broker.

Discretion items decided here, in writing:
- **Wire vocabulary (RESEARCH Pitfall 3, Assumption A3).** Two NEW literals, `host_tool_stage` and
  `host_tool_run`, answered ahead of the token gate. The legacy `host_tool` arm is not touched.
  No field-discriminator on the old literal.
- **Where the handle is minted (Critical Finding 2, Assumption A2).** `stage_file` stays
  session-scoped. A new session-free mint, `host_tool_stage`, runs on the SAME host-tool
  connection as `host_tool_run`. The byte-moving `transfer` op is reused unchanged.
- **Staging lifetime.** Per request: the request key is bound to the host-tool connection, and
  that connection's close is the end of the request (the same connection-is-the-session shape
  SESS-01..03 use). The scratch sits under `brokerStagingDir()`, so 64 D-07's startup sweep
  already covers it.
- **Kind directories.** A frozen per-tool table in host-tool-endpoint.mts: `acme.build` →
  `builds`, `dxa.disassemble` → `dxa`, every `c1541.*` → `c1541`, `petcat.decode` → `petcat`,
  `ghidra.analyze` → `runs/ghidra`. A same-name result from a later request replaces the earlier
  one through an atomic temp-then-rename, exactly as a rebuild replaced the file beside its source
  before D-07.

Purpose: prove the architecture end to end on one path before any caller moves.
Output: the endpoint host-tool route, a minimal broker harness, and one real end-to-end test.
</objective>

## Constraints recorded in writing

- **Critical Finding 2 (RESEARCH).** `stage_file` cannot serve a stateless call: it is gated on
  `ownsTarget(targetId)` and a skill call holds no target. This plan adds a session-free mint on
  the host-tool connection instead and reuses `transfer` unchanged.
- **Where the cap is enforced.** broker-control.mts is loaded unbuilt by its own tests, so it
  cannot value-import `transfer-hash.mjs`. The per-file cap check therefore lives in
  broker-transfer.mts (`stageHostToolRequest()`), and broker-control.mts narrows shape only.
- **The validator moves.** `validateContainedDestination()` moves from transfer-paths.ts to
  transfer-client.mts, because plan 65-04 compiles the client closure and transfer-paths.ts
  imports repo-root.ts, which cannot be compiled. transfer-paths.ts re-exports it, so every
  existing importer is unchanged.
