<objective>
Make criterion 4 mechanical: **derived, never hand-written** (**D-D**).

Verified this session against the shipped manifests and `vice-proxy.ts`: 62 fork tools / 38 stock
tools; after removing the four `DENY_LIST` names that actually appear in a manifest (`DENY_LIST` has
five entries, but `vice_disk_list` is in neither manifest) that is 58 real fork tools and 38 stock,
and adding the **three** proxy-local synthetic tools to both sides gives **34 genuinely shared, 24
fork-only, 2 genuine stock-only, 3 synthetic-on-both** -- a **63-row** union, of which 37 rows are
available on both. Those numbers are reproducible from the two JSON files plus one source file at any
time, which is exactly why the table must be computed rather than typed.

The count is 63 because the derivation carries **zero hand-curated exclusions**, and that -- not the
number -- is the invariant. The row count follows from the derivation; it does not constrain it.
`vice_result_continue` is the case that proves the point: the proxy advertises it on both backends
and it is present in *neither* manifest, so the only way it could be absent from a "full tool
inventory" (DIST-01's words) is a human deciding it was uninteresting. That decision is exactly the
hand-derivation that criterion 4 forbids, so it gets a row like every other advertised tool.

For the same reason the literal `63` is a **tripwire, never the proof**. Task 2 asserts the emitted
row count equals the size of a union it computes independently from the same three inputs; that
equality is what proves the table is complete. The literal only tells a future maintainer that the
inventory changed. Adding or removing a tool is therefore *expected* to require updating the literal
here and in Task 1's verify, and that is intentional -- a stale literal must fail loudly rather than
be quietly absorbed.

The generated document is this repository's **first** generated markdown file, so its drift guard is
what makes **D-D** real rather than aspirational: `resources-sync.test.ts` already proves the
generate-into-scratch-then-byte-diff mechanism on compiled `resources/*.mjs`, and the same shape
applied to one markdown file gives criterion 4 a CI guarantee instead of a code-review convention.

Purpose: the support table cannot rot.
Output: a generator, its committed artifact, and the drift guard that keeps them in agreement.
</objective>

Derivation, in this order:
1. Parse both manifests; build `forkNames` and `stockNames`.
2. Remove every `DENY_LIST` name from both sets. Those are host meta-tools, not capabilities, and
   already carry a different refusal shape.
3. Add the proxy-local synthetic names to **both** sets, **discovered mechanically** from
   `vice-proxy.ts` rather than hardcoded. A hand-typed include- or exclude-list here is the exact
   drift hazard **D-D** exists to prevent. Discovery is a **two-hop resolution**, because the
   registration lines assign through a property access, not a string literal -- a regex over the
   assignment target alone yields the bare identifier (`RECYCLE_TOOL`), not the tool name
   (`vice_recycle`):
   a. Match the registration sites to capture *identifiers*: the shape is `tools[IDENT.name] = ...`,
      so a pattern like `tools\[(\w+)\.name\]\s*=` captures `RESULT_CONTINUE_TOOL`,
      `RECYCLE_TOOL`, `DIAGNOSE_TOOL`.
   b. Resolve each captured identifier to its literal name by locating its declaration -- the shape
      is `const IDENT: ToolDefinition = { name: "..." }` -- and extracting that `name:` string
      literal.
   c. Skip the manifest loop's own `tools[def.name] = ...` site: `def` is a loop variable with no
      `ToolDefinition` declaration, so it is not a synthetic tool.
   If any captured identifier cannot be resolved to a literal name, **throw a named error that names
   the unresolved identifier, and exit non-zero**. Never skip it. A silently dropped identifier is
   the same incompleteness failure as a hand-curated exclusion, and unlike a hand-curated exclusion
   it leaves no trace in the source to notice.

   Against the current `vice-proxy.ts` this yields exactly `{vice_result_continue, vice_recycle,
   vice_diagnose}` -- all three go into both sets. Why it matters factually (research Pitfall 2):
   `vice_diagnose` and `vice_recycle` are advertised on both backends yet appear only in
   `tools-manifest.stock.json`, so a naive set-difference reports them as stock-only, which is a
   factual error. `vice_result_continue` is likewise proxy-local on both and appears in *neither*
   manifest, so a naive derivation omits it from the table entirely -- the worse failure, because
   nothing in the output hints that a row is missing.
4. Rows are the sorted union. Columns: Tool, Fork, Stock, Note. Use one consistent marker pair for
   the availability columns and state the legend once above the table.
5. Note content: empty for a row available on both. For a divergent row, take `reason` from the
   registry entry and prefix it with a short category label -- one label for hardware-unrecoverable,
   a visibly different one for descoped/not-implemented, a third for stock-only. Research Pitfall 3:
   these must be distinguishable, because a reader who cannot tell "will never work" from "nobody
   built it yet" cannot tell which one to file an issue about. Append `alternative` when the entry
   has one. If a divergent row has no registry entry, **throw** with a message naming the tool and
   instructing the caller to add a `capability-registry.ts` entry; a silent blank note is how this
   table would rot.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `tools-manifest*.json` on disk -> the generator | The manifests are inputs; a malformed or substituted manifest changes what the published table claims |
| `vice-proxy.ts` source text -> the generator's synthetic-name discovery | The generator regex-reads a source file to learn which tools are proxy-local on both backends |
| the committed `docs/tool-support.md` -> a human reader deciding which backend to install | A wrong row sends a user to a backend that cannot do the thing -- the exact failure this phase exists to prevent |
