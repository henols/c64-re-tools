<decisions>

**D-37-14 — The mutation is a textual replacement in a scratch copy, dynamically imported.**
This is the pattern `anno-regbits.test.ts:71-115` already established in this tree: mirror
the repository shape to the depth the module's own path constants need, copy the source in,
apply a named textual replacement, import with a cache-busting query, and assert on the
mutated module's answer. It is chosen over the alternative — a production toggle or an
injected strategy the test flips — because a production seam for the mutation would mean the
wrong behaviour is reachable in shipped code. `sleigh-compile-gate.test.ts:310-360` is the
worked example for the assertion half: assert the specific named failure signal, never
merely a non-zero or a differing result.

**D-37-15 — Each control is its own task and its own transcript.** Three tasks, three
evidence files, one shared test file. The shared file is a convenience for the executor; the
three tasks and three transcripts are the requirement. `.planning/research/PITFALLS.md`
§ *Pitfall 23* names the batching temptation explicitly and this phase carries the milestone's
largest single concentration of these rows, so the separation is structural rather than
stylistic.

**D-37-16 — The scratch tree lives under the system temporary directory, never in the
repository.** This host's `/tmp` is a RAM-backed filesystem whose ageing is disabled, so every
scratch root is torn down in a `finally`. Writing scratch files into the repository tree has
already produced an intermittent multi-failure run in this suite; do not do it.

</decisions>
