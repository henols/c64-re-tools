<decisions>

**D-37-17 — The in-image control asserts BOTH the wrong label and the spy call.** The
requirement's wording is a control-flow claim: an in-image address is "never looked up". A
result-only assertion cannot distinguish a guard that skips the lookup from a filter that
discards its result, and the filter version is a real implementation somebody would write. So
the control asserts two things under the mutation — that the address now receives a specific
machine-feature label, AND that the injected selection spy recorded a call for it. Plan
37-03's injected-selection seam exists for exactly this.

**D-37-18 — The mutation for this control is a DELETION, not a replacement.** Plan 37-03
landed the guard as a single early-return block precisely so this control could remove it with
one textual deletion. Hold the guard's exact committed text as a constant, assert it is still
present in the committed source, and delete it from the scratch copy. A control implemented
by rewriting the guard into something subtly different would be observing a different defect
from the one the requirement names.

**D-37-19 — The provenance control mutates the MAP, not the module.** The question it answers
is "can this token tell one map version from another", so the thing that must change is the
map bytes. The pattern is `anno-regbits.test.ts`'s existing drift control verbatim: mirror
the repository shape three levels deep, copy the map in, append one byte to the COPY, copy
the digest-computing module in beside it at the mirrored depth so its own relative path
constant resolves against the mutated copy, dynamically import, and compare digests. The
committed map is never written.

**D-37-20 — This plan uses a test file of its own, not plan 37-04's.** Plans 37-04 and 37-05
run in the same wave and must not share a file. The scratch-tree helper is duplicated rather
than extracted into a shared module: a shared helper would create a file both plans modify,
which is exactly the same-wave conflict the separation exists to avoid. Note the duplication
in the file header so a later reader sees it as deliberate.

</decisions>
