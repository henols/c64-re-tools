**D-37-01 — Two new `ANNO_TOOL_DEFINITIONS` entries, no new tool family, and no new CLI
verb.** The importer is `anno_import_ghidra_export`; the join is `anno_join_memmap`. Both
are added to the SAME `ANNO_TOOL_DEFINITIONS` array at `anno-tools.ts:438`, registered
through the SAME `for (const annoDef of ANNO_TOOL_DEFINITIONS)` loop at
`vice-proxy.ts:3388-3390`. Reason, MEASURED: `stock-dispatch.test.ts:1507-1510`'s
`BACKEND_SEAM_BYPASS_KEYS` is exactly `["RESULT_CONTINUE_TOOL.name", "annoDef.name"]` under
an order-sensitive `deepEqual`, and its own comment reads *"A THIRD entry collides here
rather than being absorbed into a superset."* Array length does not create a registration
key; a second loop would. **No `anno-cli.ts` verb is added either**, because
`anno-verb-coverage.test.ts:53`'s hand-maintained `REAL_VERBS` is exactly
`["coverage", "export-asm", "render-memmap"]` and moves in lockstep with
`ANNO_CLI_VERB_FLOOR` — raising both is a separate, deliberate event this phase has no
reason to trigger. `AUTO-01`'s "one command" is satisfied by one tool call.

**D-37-02 — The reserved `bank` column stays NULL. This phase does not write it, and the
premise that it would is FALSE.** The planning brief carried an assumption that Phase 37
would be the first phase to populate `anno_xref`/`anno_range`'s reserved `bank` column.
Two committed facts refute it, both read at plan time:
(a) `.planning/REQUIREMENTS.md` § *Out of Scope* records **"Bank-qualified addressing as a
modelled store feature"** as excluded, with the reason *"`STORE-05` reserves the field;
nothing interprets it"*; and
(b) `anno-store.test.ts` already asserts, over four rows in the four tables that carry the
column, *"every row this store writes today has bank null"*, and asserts structurally over
`codeOnly()`-stripped source that there is **no branch, no comparison, no arithmetic on a
bank value** in `anno-store.ts`. Writing a non-null bank would redden a committed guard.
**Decision:** bank state is an INPUT to selection inside `anno-join.ts` (plan 37-06), never
a stored column value. Where the resolved bank state must be recorded, it is recorded in the
annotation's own provenance text in an **axis-qualified** form — `cpu01=$34`, naming which
banking axis produced it — so that a later phase adding the `$DD00` axis is an additive
change to a text field and not a migration over every row this phase writes. `putXref()`'s
hard-coded `null` fourth bound parameter is left exactly as it is.

**D-37-03 — `memmapSha256` provenance rides in the comment text, not in a new column.**
`anno-regbits-gen.ts:377` already exports `memmapSha256()`, computing the sha256 of
`src/skills/c64-memory-mapping/memmap.json` from a `HERE`-relative path
(`anno-regbits-gen.ts:62`). `memmap-lookup.ts` re-implements that path constant and digest
locally rather than importing the generator — the generator's own header declares itself
"the sole read of c64-memory-mapping's own memmap.json ... for this purpose", and
`module-classification.ts:490` records its consumer set; widening either is a separate
decision this plan does not make. `AUTO-08`'s provenance is a trailing token appended to
every derived comment's text (plan 37-03 lands the token; this plan lands the digest
function). `MAX_COMMENT_BYTES` is 4096, so a 64-hex digest per comment is affordable.

**D-37-04 — The transfer file is never a committed fixture.** `IMP-02` deletes it. Every
test that imports one writes it into an `mkdtempSync(tmpdir())` scratch directory from a
string constant held in the test file, and tears the scratch root down in a `finally`. A
committed fixture would be deleted by the first passing run. This host's `/tmp` is a
RAM-backed filesystem whose ageing is disabled, so an untorn-down scratch tree is leaked
memory. Do not write scratch files into the repository tree — an intermittent multi-failure
run in this suite has already been traced to a repo-tree scratch race.

**D-37-05 — Unrecognised `Reference.getReferenceType()` values are dropped and COUNTED,
never refused** (resolves `37-RESEARCH.md` Open Question 2). `## REFERENCES` is uncapped and
emits every Ghidra `RefType`/`FlowType`, including `UNCONDITIONAL_JUMP`,
`CONDITIONAL_JUMP`, `UNCONDITIONAL_CALL`, `COMPUTED_CALL` and `DATA`. The store's
`XREF_ACCESS_KINDS` is the frozen four `READ`/`WRITE`/`READ_WRITE`/`COMPUTED_JUMP`
(`anno-types.ts:313`). Only `COMPUTED_CALL` and `COMPUTED_JUMP` map onto `COMPUTED_JUMP`;
`READ`, `WRITE` and `READ_WRITE` map onto themselves; every other token is dropped and
reported in a `kindsSeenNotImported` map keyed by the token, with its count. A real corpus
binary carries ordinary jump and call references constantly, and refusing on them would make
the importer unusable — but silently discarding them without a count would hide a mapping
regression. The mapping table is a frozen constant in `anno-import.ts`, not a regex.

**1. `src/mcp/vice/memmap-lookup.ts` — the map loader, its digest, and narrowest-range selection.**

Give it the same module-header posture `dxa-blocks.ts` carries: it never names the persistence dependency, never opens the store, and never imports the host-path module. Export:

`MEMMAP_PATH` — a `HERE`-relative constant resolving to `src/skills/c64-memory-mapping/memmap.json`, using the same five-hop `join(HERE, "..", "..", "..", "src", "skills", "c64-memory-mapping", "memmap.json")` formula `anno-regbits-gen.ts:62` uses. Copy the formula; do not import the generator (D-37-03).

`MemmapEntry` — `{ start: number; end: number; label: string; section: string; desc: string; src: string; sym?: string }`. MEASURED at plan time: 959 entries, `start`/`end` are INCLUSIVE integers with no length field, and `sym` is present on 219 of them.

`loadMemmap(): readonly MemmapEntry[]` — reads and parses the file once, caches the parsed array in a module-level variable exactly as `anno-enum-gen.ts`'s `loadRegBits()` does, and returns it. Refuse by name if the top-level shape is not `{sources, entries}` or if `entries` is empty.

`memmapDigest(): string` — the sha256 hex digest of the file's raw bytes, computed with `createHash("sha256").update(readFileSync(MEMMAP_PATH)).digest("hex")`. MEASURED at plan time: this currently equals the same value `anno-regbits.json`'s committed banner carries; assert that relation in the test rather than pinning the literal digest, because the map is a living file.

`selectMemmapEntry(address: number, entries?: readonly MemmapEntry[]): MemmapSelection | undefined` — this task lands the NARROWEST-CONTAINING-RANGE rule only. Collect every entry whose inclusive `[start, end]` contains `address`; if none, return `undefined`; otherwise return the one with the smallest `end - start`.
