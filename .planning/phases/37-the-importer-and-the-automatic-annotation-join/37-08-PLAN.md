<objective>
Feed the derived graphics ranges back to both consumers, and prove the containment works by
showing the labels a graphics region mints when decoded as code are present BEFORE the
feedback and absent AFTER it.

Purpose: this is the containment for the pipeline's most dangerous failure, and the
requirement is explicit that it is exercised rather than merely built. Graphics bytes decoded
as instructions mint labels indistinguishable in form from genuine ones; a phantom routine
inside a character set is promoted to a function, yields phantom cross-references, feeds the
join, and emerges as a confident wrong comment the next pass treats as established. The
disassembler half of the feedback is already fully built and needs exercising, not
rebuilding. The analyser half has no existing mechanism at all.

Output: a new pre-script that marks a range as data before analysis, its wire field and the
threading for it, a graphics-bearing fixture, the join's write-back and feedback wiring, and
one evidence file carrying both the before and the after label sets.
</objective>

<decisions>

**D-37-31 — The label-name examples in the ROADMAP are NOT to be asserted.** The roadmap cites
three specific phantom label names as examples of what a character set decoded as code mints.
MEASURED by the researcher: a search for those exact tokens across every committed phase-36
evidence file and summary returned **zero matches**. They may be from an earlier exploration
under different settings. `37-RESEARCH.md` Open Question 4 leaves this unresolved and
recommends capturing the actual names from a real run first. **Therefore: Task 2 captures the
minted-label set from a real run and commits it as measured output; Task 3 asserts the
before-set is non-empty and the after-set is empty. No task asserts any specific label name
taken from a planning document.** If the captured names happen to match the cited ones, say so
in the transcript as a confirmation; if they do not, say that, because a later reader
comparing the two documents needs the discrepancy explained rather than discovered.

**D-37-32 — The disassembler half is exercised, not rebuilt.** MEASURED: the data-block and
label emitters already exist, already sort, already refuse overlaps, already omit the file
entirely for zero rows, and the disassembler run module already accepts a known-data-rows
field that is mutually exclusive with caller-supplied paths and calls both emitters itself.
This plan supplies the ROWS. It writes no second emitter and adds no wire field on that side.
`37-RESEARCH.md` § *Don't Hand-Roll* names a second writer as the thing not to build.

**D-37-33 — The analyser half is a new pre-script plus one new path-bearing wire field.** No
existing wire field marks a range as data before analysis; the analyser tool's existing fields
cover script wiring and entry-point seeding only. The new script follows the existing
volatile-carve script's plumbing shape — read a file of addresses supplied through a
path-bearing field, act per entry — but its semantics are the opposite: it marks DATA, where
that script marks code. The pattern map records this directly as having no true analog, so it
is planned as greenfield within the additive-pre-script pattern, not as porting an existing
capability.

**D-37-34 — The host-bound modules change, so the build artifacts change in the same commit.**
The host tool module and the analyser project module are both host-bound and compiled into
committed build artifacts; a drift guard fails continuous integration when the committed
artifacts do not match. Both regenerated artifacts land in the same commit as their sources.
This is the single most common way a plan touching these files goes red after everything else
passes.

**D-37-35 — The live before-and-after run is manual-only; its hermetic counterpart is
mandatory.** The automated gate skips manual-only files entirely, so a requirement routed
there alone ships with no gate at all. The live run lands as cases in the existing
manual-only analyser test file behind its established opt-in. The hermetic counterpart is a
committed capture of both label sets plus automated cases asserting the before-set is
non-empty, the after-set is empty, and the range-membership classification is correct at both
boundaries. Both halves, or the requirement is not covered.

</decisions>

`encoding` and `ordering` — three as plain `must_haves.truths` strings and one as a
`verification: backstop` marker. The backstop entry is the `adjacency` edge at its hardest
reading: whether a label minted at the exact first or exact last byte of a derived range is
classified as inside it. A verifier that cannot confirm it with explicit evidence must abstain
to `human_needed`, never pass silently.

The `encoding` edge is authored as the byte-versus-character comparison rule, and it is not
boilerplate here: a range boundary compared as a character index rather than a byte index
would misclassify membership, and a label name compared case-insensitively would merge two
distinct minted names into one and make an after-set look empty when it is not.

The phase-wide 25-authored-plus-2-flagged accounting is in plan 37-01's
`<flagged_assumptions>` table.
