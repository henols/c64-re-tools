<objective>
Run the one genuinely unexercised safety-critical probe this milestone has left: arm a
non-stopping checkpoint on a hot address on a real stock instance, drive sustained hit
pressure past the auto-disable threshold, and record whether the deferred auto-disable
actually fires without stalling the emulator or deadlocking the client.

Purpose: this closes two carried items with one experiment. `03-HUMAN-UAT.md` scenario 3
asks whether the D-11 rate-limit auto-disable fires at around 20 hits per second instead of
stalling the emulator thread. The remaining A4 item of
`2026-08-14-probe-phase3-assumed-wire-details.md` asks whether the deferral through
`setImmediate()` is race-free under a real synchronous `CHECKPOINT_INFO` flood from inside
VICE's CPU loop. Those are the same question about the same code, and Phase 13 deliberately
excluded A4 (D-13-05) precisely because arming that checkpoint risks stalling the emulator —
which is what makes the probe worth doing rather than a formality. No probe run by any prior
phase has armed a checkpoint of any kind.

The design deliberately starts gentle: the KERNAL IRQ handler on a booted machine already
fires at roughly 50-60 Hz, comfortably past the 20-per-second limit, with no fixture and no
million-hits-per-second cliff. Escalate to a tight loop only if the gentle tier does not
reproduce, and only under the wedge-triage discipline.

Output: one opt-in probe file, one evidence document, scenario 3 recorded, and the probe-debt
todo closed.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client event listener ↔ emulator CPU loop | The hit frame is emitted synchronously over the blocking socket from inside the CPU loop, before the stop flag is consulted — so client-side work in that path can stall emulation |
| one binary-monitor socket ↔ one client | Stock VICE's monitor services exactly one client; a second connect is unserviced with no reply and no EOF |
| local auto-disable state map ↔ the checkpoint's real wire-side enabled flag | The report can say disabled while the wire says enabled; that divergence is the race under test |
| recorded UAT verdict → the milestone record | A pass recorded without execution becomes the evidence a future close relies on |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-05 | Denial of service | arming a non-stopping checkpoint on a hot address stalls the emulator thread from inside a synchronous socket write | high | mitigate | Start at the roughly 50-60 Hz KERNAL IRQ tier rather than a tight loop; every wait bounded with an explicit deadline; the wedge-triage recovery route written down before any escalation; a stall recorded as a genuine failure rather than retried |
| T-15-26 | Denial of service | a second monitor client against the instance under test | high | mitigate | One granted instance per case and the harness's single-session discipline; an unanswered connect is treated as the documented single-client condition, never diagnosed as a wedge |
| T-15-33 | Spoofing | the auto-disable report claiming a disable that never reached the wire | high | mitigate | The probe reads the checkpoint's enabled flag back from the emulator, so a local-only disable is detected rather than trusted |
| T-15-27 | Repudiation | a UAT verdict recorded without execution, or softened to pass | high | mitigate | Every verdict quotes raw observations; the negative branch is specified in advance with its own todo and promotion path so there is no incentive to reach for a pass |
| T-15-28 | Denial of service | orphaned emulator or broker processes on the host | medium | mitigate | Harness teardown plus explicit process and scratch-directory checks as acceptance criteria, with output recorded |
| T-15-SC | Tampering | npm/pip/cargo installs | — | accept | Not applicable — this plan installs no packages and adds no dependency |
