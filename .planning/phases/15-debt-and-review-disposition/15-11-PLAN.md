manifest todo on its real (inverted) ground, and settle the CI test-command divergence from

Purpose: three carried items, each of which looks like one thing and is actually another.

The `vice_disk_attach` item looks like a documentation nicety and is a caller-facing
correctness gap: a recon session calling it to inspect a disk without disturbing machine state
gets the machine reset and a program loaded anyway, per Phase 13's A5 probe. The cheap,
in-scope half is correcting both places that advertise the false promise; the expensive half
is deciding whether the tool should exist in its current form, which is a product decision
this phase's own scope fence excludes.

**deliberately deleted** by D-16 as a documented single exception to BACK-02, because nothing
in the repo called it. `fork-manifest-surface.test.ts`'s header says so and warns that a
regeneration against a server still advertising it would silently re-add it — which is exactly
what the todo recommends doing. So the correct disposition is `wont-fix` plus a fix to the
*reporting* that produced the false finding, not a regeneration.

The CI item looks like a config tidy-up and has release consequences: every merge to the
default branch auto-publishes a patch version unless the commit subject opts out, so a hanging
or silently-narrowed CI gate ships. It is decidable today — `gh` is available and recent runs
are readable.

Output: two corrected records, one promoted product question, one inverted disposition with a
reporting fix, and one CI decision backed by a run id.
</objective>
