<objective>
Relocate the MCP server package from the auto-discovery path to `src/mcp/vice/` and sweep
every functional consumer, with the repository-root depth constraint resolved by verified
assertion rather than by hope.

Purpose: this is the expansion of plan 16-01's tracer onto the large half of the payload —
roughly 180 files, ~70 shipped modules, their colocated tests, committed generated launcher
artifacts, and about thirty consumers across manifests, CI, packaging scripts, corpus checks
and the module's own test suite. The tracer already proved every layer of the relocation
machinery on six directories; this plan drives the same path through the tree that actually
carries the risk.

Two facts settled at plan time, by direct measurement, that change what this plan has to do:

**The published tarball does not change.** `npm pack --dry-run --json` in the module
directory lists 73 entries and every path is package-relative (`README.md`,
`backend-detect.mts`, …). `bin` and `main` are relative to the package's own manifest. So
relocating the directory changes the published `@henols/vice-mcp` tarball not at all, and
nobody pinning `@henols/vice-mcp/vice-proxy.ts` breaks. **Decision D-16-04: no compatibility
shim, no major version bump** — the release semantics the pending todo's Solution step 7 asks
about are "ordinary release", and the only manifest field that changes is the repository
subdirectory metadata. This is asserted, not assumed: the post-move path list must equal the
pre-move list plan 16-01 recorded.

**The depth constraint is satisfiable without touching the hop count.** `src`/`mcp`/`vice` is
the same three segments as the old location, so `repoRoot()`'s three-level last resort stays
correct, and `vice-launcher.sh`'s four-level `resources`-named branch stays correct too. What
does need work is the *record*: `repo-root.test.ts` carries a standing warning against
"moving into a `src/` subdirectory", written about adding a fourth level inside the flat
module directory. Left as-is, that comment reads as forbidding the move that just happened.
Task 2 resolves the tension in the file itself.

**Reversibility:** `costly`, same rating and rationale as plan 16-01 — mechanically a `git mv`
back plus the same sweep, with published tarballs unaffected, but the plugin zip layout and
the marketplace path contract churn once per direction. Not `one-way`, so no decision
checkpoint.

Output: `src/mcp/vice/`, every functional consumer repointed, the depth record corrected, the
tarball parity proven, and the full glob green.
</objective>
