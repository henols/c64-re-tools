<objective>
Take the phase's single documentation sweep: repoint every path reference in the
repository-root documents and the documentation directory to the relocated payload, refresh
the skills table, and re-verify the architectural line-number citations against the final
source — after every source-editing plan in this phase has landed, so the sweep happens once.

Purpose: the ROADMAP's stated reason for sequencing this whole phase after Phases 12-15 is
that "CLAUDE.md's line-number citations drift with every phase", so doing the relocation once
after all disposition work has settled "sweeps the path and line-reference citations a single
time instead of re-sweeping them per phase". This plan is the discharge of that rationale. It
is deliberately the last plan of the phase in wave order: plans 16-04, 16-06 and 16-07 all
add or edit source, and any of them could move a cited line.

Two things make this more than a find-and-replace.

First, the documentation directory mixes design prose with dated evidence. In a roadmap or
parity document, a path is a pointer and updating it is correct. In a probe-findings or
probe-evidence document, everything except the path pointer is a measurement someone took on
a specific date against a specific binary, and Phase 09's records in particular are covered
by a standing evidence-immutability decision. The sweep must change pointers and nothing else.

Second, the line-number citations are checked mechanically. The committed line-reference guard
extracts every bare-filename line citation from the derived-tool bullet and asserts each one
lands on either the cited call or a function declaration, with its own planted-violation
check to prove it is not vacuous. So the acceptance criterion here is a green guard, not a
careful read — and if the four numbers measured at plan time (call sites at 1525 and 3046,
enclosing functions at 1501 and 2981) still hold, the honest action is to confirm and leave
them, recording that they were checked.

**Reversibility:** `reversible`. Documentation content; every edit is a text change with no
behavioural coupling except the citations, which are guarded in both directions.

Output: root and documentation-directory path references current, the skills table pointing
at real files, and the architectural citations verified green.
</objective>
