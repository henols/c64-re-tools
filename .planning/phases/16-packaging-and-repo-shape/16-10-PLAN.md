<objective>
Revert the CRITICAL regression this phase shipped, and the three more sites of the same
class — then guard the class so the next blanket sweep cannot repeat it.

Plan 16-04's `.claude/skills` → `src/skills` sweep rewrote four literals that name where a
skill lives **once installed into somebody else's project**, not where it lives in this
repository. Three of them are written into files a consumer keeps: the generated
`recovery/PROVENANCE.md` ledger (`renderLedger`, three places), the generated
`recovery/LOADING.md` record (`renderLoading`), and the assembly scaffold `acme.mjs new`
writes into a user's own source file (`template.a`'s `; Build:` line). The fourth is the
generic "copy these into any project" advice in `acme-build/SKILL.md`, which now
recommends this repository's internal layout — a layout this repo's own README states
Claude Code does not auto-discover.

Plan 16-01 had explicitly named the first two as deliberately preserved and added a
comment at the generation site saying so. The sweep rewrote the comment's own example too,
so both halves of "the consumer's installed location, not this repository's source-tree
location" now name the same string. That self-contradiction in place is the tell, and it
survived because the plan's verification was a substring grep satisfied identically by
both path forms.

Purpose: a user or agent following the embedded instruction in their own generated ledger
runs a command against a file that is not there. Reverting the literals closes today's
break; the assertions are what stop the class, and every one of them must require the
consumer form to be present AND the source-tree form to be absent — never a substring both
satisfy.

Output: four corrected sites, a repaired guarding comment, two behavioural guards on the
real generator functions, one generated-scaffold assertion, and one registry guard covering
the whole class.
