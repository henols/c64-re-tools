(`kind: pluralization`, term `also`, from the ROADMAP planning note about wave order).

what this gap is: **the leak assertion set became plural** (one package checked, then a
second package added with fewer checks), and **CI's test-suite invocation became plural**
(one suite, then two more added and never wired).

- **Primary noun:** *the packed tarball* — a package-agnostic subject that every packed
  package is measured against, not "the vice-mcp tarball plus some installer extras".
- **Decision: `promote`.** The leak assertions (no `node_modules/`, no test files, no
  `fixtures/`, no test-only helper) move into one shared assertion invoked from inside
  `packFiles()`, so every packed package is checked by construction. Package-specific
  requirements (vice-mcp's bin entry, closure walk, `scripts/`/`VERSION` absence;
  the installer's bin entry and six-`SKILL.md` count) stay as per-package additions —
  demoted to details of one variant, not the general rule.
- **Companion invariant (accepted, Task 1):** `check-npm-packages.mjs` asserts the set of
  packed package names is exactly the two it expects, so a third package cannot be added
  without a deliberate decision — the generalized intent goes red the instant someone
  reintroduces the singular assumption.
- The same promote applies to CI in Task 3: instead of naming three suites, the guard
  derives the set of directories holding committed test files and requires each to be
  covered by a `build`-job step.
</assumption_delta_decision>
