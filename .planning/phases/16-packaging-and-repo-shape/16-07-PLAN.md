<objective>
Build the orphaned-planning-reference gate PKG-03 asks for, fix every site it finds, and
demonstrate that it bites — as a one-time recorded plant-and-revert and as a permanent
committed fixture.

Purpose: PKG-03 inherits QUAL-02, deferred at v0.2.0 scoping. The promoted todo names two
comment sites. The census taken at plan time found **fifteen**, across nine shipped modules,
and the extra thirteen are the same defect class: a comment handing pending work to a phase
that has since closed without delivering it, or to a phase that was cut outright. Fixing only
the two named sites would leave a guard that goes green over thirteen live violations — which
is the precise failure this milestone has already been burned by once, when a document guard
reported green while blind to 31 findings.

Two design choices, both grounded in measurement rather than preference.

**A new comment-scoped guard, not a widening of the existing literal-scoped one.** The
existing guard deliberately scans string and template literals and never comments, and its
own header records why: a comment legitimately quotes old wording in a what-not-to-do note, so
a comment-scanning version of *that* guard would fail on the commit that fixes the violation
it exists to prevent. Measured here: 123 comment lines across the 58 shipped modules name a
phase, and the overwhelming majority are accurate historical narration that must stay legal.
So the new guard detects the *assignment shape*, not the mention.

**Two complementary checks, one of them derived from the roadmap.** Check one is the
assignment-shape family — measured at plan time to flag exactly 7 lines with zero false
positives, after one pattern needed a past-tense exclusion to stop flagging narration. Check
two is simpler and sharper: any comment naming a phase the roadmap records as cut. A reference
to a cut phase is orphaned by definition, the cut set comes from the roadmap's own progress
table rather than a hand-typed list, and it accounts for the other 9 sites.

Every fix has a destination that already exists. Both tools whose comments point at a closed
or cut phase already carry dated cut records in the parity document, and the tool whose
comment says its timing route is merely pending is already covered by its own module's
permanent-exclusion header. So this plan invents no scope decision — it repoints at records
that were already made, which is exactly what the promoted todo asks for.

**Flagged assumption, carried deliberately.** One edge probe for this requirement resolved
`unclassified`, so its category is undetermined and no acceptance criterion here derives from
it. It is recorded as unresolved rather than closed by guesswork; a verifier encountering it
should treat it as an open question about this requirement's edge surface, not as a covered
case.

**Reversibility:** `reversible`. A new test, a new fixture, and comment rewordings; reverting
restores the prior comments exactly and deletes two files. No behaviour changes.

Output: a green comment-scoped guard, fifteen fixed sites, a committed fixture, and a recorded
plant-and-revert demonstration.
</objective>
