<objective>
Answer criterion 3(3) (`R2000-16`(3)): does `--export_lbl` emit a format
`DERIV-04`'s symbol store — `vice_symbols_load` — consumes **as-is**?

Purpose: Phase 11's criterion 4 closes the symbol round trip in both directions.
`DERIV-04` shipped a consumer with no producer; `--export_lbl` is the candidate producer, and
whether it needs a conversion step is what this criterion settles.

**Rule 4 is the trap, and it is the reason this plan has three tasks instead of one.**
`export_vice_labels` filters to `LabelKind::User` only, and auto-analysis produces a
different label kind. An auto-analysed-only project therefore exports a **syntactically
valid, zero-line file** that passes a naive regex check and proves nothing. So this plan
seeds at least one real user label first — and if it cannot, it records
"empty because no user label was set" as a **distinct finding**, never as criterion 3(3)
passing.

The ROADMAP's own wording is also binding: an **unmodified** exported file must be handed to
`vice_symbols_load` and "either consumed as-is or not". A static grammar match alone is a
weaker claim than the criterion asks for, so both are done: the static comparison settles the
grammar, and the live call settles the consumption.

Output: `evidence/criterion3-export-lbl.txt` with `LABEL_SEED_ROUTE:`, `EXPORT_LBL_LINES:`,
`GRAMMAR_MATCH:`, `SYMBOLS_LOAD:` and a single `EXPORT_LBL:` outcome line; plus the
byte-for-byte exported file and the two throwaway harnesses.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| exported `.lbl` file → `vice_symbols_load` | A file written by a third-party binary crosses into this project's own parser, which enforces three documented resource ceilings |
| harness argv → MCP stdio `tools/call` | Tool names and JSON arguments cross from the shell into the real dispatch path |
| broker → live emulator | The broker owns the binary-monitor socket; nothing else may open it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-05-A | Denial of Service | A second binary-monitor client (`--vice` on regenerator2000, or any hand-rolled monitor connection) | mitigate | regenerator2000 is invoked only `--headless` with `--import_lbl`/`--export_lbl`, and once optionally under the pty with `--mcp-server`. `--vice` is in no argv. All emulator access goes through `vice-proxy.ts` and the broker, which owns the socket. Stock VICE's monitor serves exactly one client and a second `connect()` is indistinguishable from a wedge |
| T-09-05-B | Denial of Service | Resource exhaustion via a large or pathological label file | mitigate | `stock-symbols.ts` already enforces 2 MiB / 50 000 lines / 20 000 symbols and refuses with both the observed value and the limit. The plan requires a refusal on a ceiling to be recorded as a *different* finding from a format refusal, so the control is exercised rather than bypassed |
