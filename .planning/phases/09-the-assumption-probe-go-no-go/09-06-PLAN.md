<objective>
Answer criterion 3(4) (`R2000-16`(4)): does a `.vsf` written by `vice_snapshot_save` load into
regenerator2000 **carrying the expected machine type and start address**?

Purpose: this is what the ROADMAP's standing constraint "prefer `.vsf` over `.raw` for
anything leaving the emulator" rests on. `.bin`/`.raw` loads at origin `$0000` with no
`--origin` flag to override it, so if the `.vsf` route does not carry machine type and start
address, the emulator-to-static-analysis bridge loses its origin information and the
`c64-ram-capture` bridge Phase 10 assumes does not exist as assumed.

**Evidence Integrity Rule 6 is the whole shape of this plan: the snapshot must be
interrogated, not merely loaded.** "It did not crash" is not the criterion. The evidence must
show the machine type and start address regenerator2000 **actually derived**, compared against
what the snapshot **actually carried**. That means recording both sides independently and then
comparing them — three tasks, not one.

Output: `evidence/criterion4-vsf-load.txt` with `SNAPSHOT_FILE:`, `SNAPSHOT_CARRIED:`,
`R2000_DERIVED:` and a single `VSF_LOAD:` outcome line, plus the export that reveals the
derived origin.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live emulator → snapshot file | Emulator state crosses to disk via the emulator's own DUMP path, driven through the broker |
| snapshot file → regenerator2000 | A binary file is parsed by third-party code; the parser was reverse-engineered upstream against a real capture |
| loopback network → regenerator2000's MCP server | Unauthenticated JSON-RPC on hardcoded `127.0.0.1:3000` while the bootstrap runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-06-A | Denial of Service | A second binary-monitor client — `--vice` on regenerator2000, or any direct monitor connection to work around a wedge | mitigate | regenerator2000 receives only `--mcp-server <snapshot>` and `--headless --export_asm`. All emulator access is through `vice-proxy.ts` and the broker, which owns the socket. The plan explicitly forbids taking the socket to work around a wedge and requires `vice-wedge-triage`'s decision order instead. The closing check greps the transcript for `--vice` |
| T-09-06-B | Information Disclosure | Unauthenticated MCP HTTP server on `127.0.0.1:3000` during the bootstrap | mitigate | Loopback-only via the upstream default with no bind override; the port is confirmed free before launch, held only for the bootstrap, and teardown is proven with `ss -ltn` and `pgrep` |
| T-09-06-C | Tampering | Third-party parsing of a binary snapshot | accept | This is the criterion. The snapshot is produced locally by this project's own tooling from a throwaway emulator session containing only a probe fixture; no sensitive state is in it |
| T-09-06-D | Information Disclosure | Committing a multi-megabyte snapshot of machine memory into the repository | mitigate | Snapshots above a megabyte are not committed; the transcript records path, size and sha256 instead, and says so explicitly |
| T-09-06-E | Tampering | Shell-string interpolation of snapshot paths | mitigate | ASVS V5: harness calls are argv-driven and every spawn uses an argv array; no path is interpolated into a shell command string |
| T-09-06-F | Repudiation | Recording `pass` for a load that was never interrogated | mitigate | The `## COMPARISON` block and the explicit prohibition on "it did not crash" make `pass` structurally unavailable without per-field matches (Evidence Integrity Rule 6) |
| T-09-06-G | Denial of Service | Resource contention with plan 09-05 in the same wave | mitigate | The live-resource protocol: check, bounded 10-minute wait, then a recorded `could-not-run`. Never kill another plan's process |
