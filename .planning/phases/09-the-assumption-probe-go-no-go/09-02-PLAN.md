<objective>
Answer the second half of criterion 1: the **container-side Rust toolchain build time and
image-size cost, measured rather than estimated** (`R2000-16`(5)).

Purpose: Phase 10's `R2000-03` has to state the toolchain cost plainly in the install
documentation. "About a gigabyte" written from intuition is not a measurement, and the
single number people reach for is the wrong one.

`09-RESEARCH.md` Pitfall 4 is binding here: **two numbers are asked for and they are
genuinely different.** A single-stage `FROM rust:… ; cargo install` image carries
`rustc`, `cargo` and `~/.cargo/registry` in the final layer set forever. A multi-stage
build discards the builder and `COPY --from=` only the compiled binary into a slim
runtime. Reporting one number that conflates them answers the wrong question.

This plan is wave 2, not wave 1, for one reason: the Dockerfiles run
`cargo install regenerator2000`, which is the same third-party build-script execution
plan 09-01 Task 2 gates behind a blocking human authorization. Sandboxed in a throwaway
container is safer, but it is not a different decision, so it waits for the same approval.

Output: `evidence/Dockerfile.single`, `evidence/Dockerfile.multi`,
`evidence/criterion1-container-toolchain-cost.txt`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| crates.io → throwaway container | Third-party Rust source is compiled and its build scripts executed inside the image build, not on the host |
| Docker registry → this host | Base images (`rust:*`, `node:*`) cross here |
| container → host | Nothing crosses back: no bind mount, no published port, no host network |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02-SC | Tampering | `cargo install regenerator2000` inside `docker build` | mitigate | Inherits plan 09-01 Task 2's blocking human authorization (this plan is wave 2 specifically so it cannot precede it). Executed inside a throwaway image with no bind mounts, no `--network host`, no published ports; both images are deleted and the builder cache pruned in Task 2 |
| T-09-02-A | Tampering | Base image provenance | mitigate | Only official Docker Hub library images (`rust`, `node`) are used, and each tag's resolvability is recorded via `docker manifest inspect` before use. No third-party or unofficial base image |
| T-09-02-B | Information Disclosure | Docker build context leaking repository contents into an image layer | mitigate | The build context is `evidence/` only, not the repo root, and neither Dockerfile has a `COPY .` of the context. Nothing from the checkout enters either image |
| T-09-02-C | Denial of Service | An unbounded `docker build` consuming the host | mitigate | 45-minute per-variant give-up with at most one retry, `--no-cache` builds explicitly cleaned up, `docker builder prune -f` after measurement |
| T-09-02-D | Denial of Service | `--vice` passed to regenerator2000 | mitigate | The only invocation of the binary in this plan is `--version` inside a container that has no VICE and no network path to one. `--vice` appears in no argv and in neither Dockerfile |
</threat_model>
