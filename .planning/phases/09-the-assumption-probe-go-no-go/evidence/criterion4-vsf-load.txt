## ACCEPTED LIMIT

The ROADMAP's standing "prefer `.vsf` over `.raw` for anything leaving the
emulator" constraint is **well-supported for RAM content and for the
entry-point/start-address field**, both genuinely carried and verified here
against a real stock-VICE-produced snapshot. It is **not well-supported for
machine-type auto-detection**: `file_io.rs`'s `suggested_system` match on
`vsf_data.machine_name` only recognises the four literal strings
`"C64"`/`"C128"`/`"VIC20"`/`"PET"`/`"PLUS4"`, while real VICE machine
variants write model-specific names (`"C64SC"` confirmed here; other VICE
machine models are very likely to write their own non-matching variants by
the same pattern, though this plan did not produce or check one). Any Phase
10/11 pipeline that bootstraps a project from a stock-VICE `.vsf` and needs
the correct system set must **not** trust regenerator2000's auto-detected
system for that purpose -- it happened to be right here only because C64 is
also the tool's own baseline default, which will not generalise to other
machine types. The system should be verified or explicitly set (e.g. via a
direct `.regen2000proj` settings edit, the same technique plan 09-04 already
used for `use_illegal_opcodes`) rather than trusted from auto-detection.
