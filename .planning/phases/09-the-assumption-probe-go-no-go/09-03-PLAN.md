<objective>
**This plan is the gate within the gate.** Answer criterion 2 (`R2000-16`(1)) by running
it: does `--mcp-server <raw binary>` survive a pty with no real TTY, is an MCP client
served or refused in that state, and can the project-file bootstrap be completed **with no
human**?

Purpose: this decides whether Phase 10's `R2000-09` delivers an automated bootstrap or a
documented manual step — and, in its sharper failure mode, whether the milestone's thesis
survives at all. ROADMAP criterion 2 orders it first among the five for exactly this reason.

**The load-bearing correction to the grounding notes, and it changes what this plan tests.**
`r2000_save_project` **cannot create the first `.regen2000proj`.** Its handler refuses with
`-32603 No active project path` unless `app_state.project_path` is already `Some`, and the
only code path that sets it for a freshly-loaded raw binary is the TUI's own **Save-As
dialog** (`Alt+S` → filename prompt → Enter). So the question is not "does raw mode survive
a non-TTY" alone — it is **"can this project drive a TUI menu action through a pty with no
human"**, which needs keystroke injection after the child has started. A bare
`script -qec '…'` one-shot cannot do that, by construction.

Two sequential sub-checks, and the distinction between them is the whole verdict:
- **2a — pty tolerance.** Raw mode is entered, the input thread starts, the TUI draws, and
  the process stays alive. **2a failing is what threatens `reconsider`.**
- **2b — keystroke-driven bootstrap.** `Alt+S` → filename → `Enter` produces a
  `.regen2000proj` that a later `--headless` invocation loads. **2a passing with 2b failing
  is what indicates `degrade`.**

Output: `evidence/criterion2-pty-transcript.txt` with explicit `PTY_TOLERANCE:` and
`BOOTSTRAP_AUTOMATABLE:` outcome lines, the three captured pane snapshots,
`evidence/mcp-harness.mjs`, and (only if the tmux route was unavailable)
`evidence/pty-driver.py`.
</objective>
