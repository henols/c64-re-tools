# Quick Task 260914-9n4: Gate the dxa-dependent tests on the vendored binary Summary

## Accomplishments

- Exported `findDxaBinary()` from `host-tool.mts`, regenerated the committed `resources/host-tool.mjs` artifact, and created `dxa-gate.ts` (modelled on `acme-gate.ts`) as the ONE test-availability gate for the vendored dxa binary — `DXA_AVAILABLE`, `dxaSkipReasonFor()`, `assertDxaRequired()`/`assertDxaRequiredIfEnvSet()` — plus its own two-direction gate test `dxa-gate.test.ts` (7 cases, 0 skips).
- Restructured `dxa-seam.test.ts` so all five cases needing a resolvable dxa (four `buildHostToolArgv()` argv-shape cases plus the success-response-shape case) share one `withPlantedDxa()` wrapper, making the file's own "never requires the real vendored binary" header claim true for the first time.
- Restructured `dxa-build-gate.test.ts`'s two cached-tarball cases to synthesise their own tarball from the same scratch-tree copy each case already makes (`synthesizeCachedTarball()`), deleting the `$HOME/.cache` dependency and the `REAL_CACHED_TARBALL`-absent throw guards, and running both against a stub `curl` on PATH that must never be reached (asserted absent from output).

- Measured both directions on real runs: binary present keeps the protected baselines green with an unchanged skip count; binary absent (with `$HOME` emptied) produces zero failures and exactly one new named skip; `VICE_REQUIRE_DXA=1` with the binary absent hard-fails with the gate's own wording, isolated from unrelated noise.
- Restored the vendored binary after every absent-direction measurement and verified sha256/size/executable-bit/banner each time.

## Decisions Made

- **dxa-gate.ts reaches `findDxaBinary()` through the COMPILED `resources/host-tool.mjs` artifact, not the unbuilt `.mts` source.** Measured directly: importing `./host-tool.mts` from a plain `.ts` module throws `ERR_MODULE_NOT_FOUND` for `ghidra-project.mjs`, because `host-tool.mts` value-imports two sibling `.mjs` specifiers that resolve only inside `resources/`. This is still the ONE probe — `resources/host-tool.mjs` is `build.ts`'s committed, drift-checked compilation of the exact same `findDxaBinary()` declaration — but the plan's own measurement 7 ("host-tool.mts has no top-level side effects... costs nothing at load") did not anticipate this resolvability constraint. Dynamic `await import(new URL(...))` with a cast, mirroring the existing test-file idiom, is the fix; `dxa-gate.ts` does not call `build()` itself, relying on the already-committed, drift-checked artifact instead (avoiding a redundant `tsc` invocation per importer).
- **Six of seven kept CI coverage by restructuring, not gating.** Per the plan's own skip-cost accounting, gating all seven would have been the easy but wrong path; the four argv cases, the success-response-shape case, and the two build-gate cases were all measured to work hermetically once given their own fixture, so they were restructured instead.
- **The seventh case's skip is a genuinely unavoidable cross-file race, not a shortcut.** `host-tool.test.ts` and `dxa-seam.test.ts` both import the same compiled artifact and resolve `findDxaBinary()`'s fixed candidate list through the identical planted path; a second plant/remove pair in `host-tool.test.ts` would race `dxa-seam.test.ts`'s own cleanup across parallel `node --test` processes. This was the design already specified by the plan and is preserved as designed.
