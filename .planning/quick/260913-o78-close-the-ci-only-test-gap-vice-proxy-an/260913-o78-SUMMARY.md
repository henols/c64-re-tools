## Accomplishments

- `writeProbeAnsweringStub()` now resolves its listen port from the real stock argv (`-binarymonitoraddress ip4://<host>:<port>`), located by flag name, never by a positional scan for the first `ip4://` string — the same branch can also emit a second `ip4://` URL for `-remotemonitoraddress`, which a positional scan would have bound instead.
- The stub answers a real binary-monitor PING (0x81) with a correctly framed reply (STX, api version, zero body length, response type, error code, echoed request id) derived directly from `broker-launch.mts`'s own `BINMON_*` constants and `defaultBinmonProbe()`'s frame walker, and silently ignores any other command (the probe's own follow-up EXIT) without replying or closing, so a later grant-time re-probe still finds it listening.
- Any unresolvable argv (missing flag, flag as last element, unparseable or out-of-range port) now makes the stub exit non-zero with stderr naming the flag it looked for and the argv it received, instead of computing `Number(undefined)` → `NaN` and binding a random OS-assigned port — the exact silent failure mode that made a correct product path look like a broker regression.
- That refusal is proven, not merely written: a new planted-violation test spawns the stub directly with a deliberately port-free argv and asserts a non-zero exit whose stderr names `-binarymonitoraddress`.
- Corrected `writeProbeAnsweringStub()`'s header comment, which was false in four places after the fork-to-stock backend collapse: it named the dead `-mcpserverport` flag twice, described a retired loopback-HTTP/JSON substring contract, and claimed "the two tests below" when only one real caller remains (the warm-floor test that made "two" true was removed earlier). The still-true paragraphs (`.cjs` rationale, mode-0755/`verifiedKill()` identity rationale, rebind-after-kill note, "NOT a rule violation" paragraph, and the VICE_ARGS coupling) were kept and repointed at the current flag name.
- Surveyed the four other `MANUAL_ONLY_TESTS` files that mention the retired fork flag (`stock-live.test.ts`, `stock-live-triage.test.ts`, `stock-live-broker-monitor.test.ts`, `stock-broker-live.test.ts`): all six mentions are descriptive prose inside PATH-shadowing refusal messages warning that a fork build on `$PATH` would be picked up instead of stock. None parse the flag; none carry the dead-flag assumption this task fixes. Left untouched, as scoped.
