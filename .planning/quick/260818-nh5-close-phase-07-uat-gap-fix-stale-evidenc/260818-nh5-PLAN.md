<decision_record>
## D-01 (RESOLVED HERE, do not re-open): `jamObserved` STAYS on the restarted branch

The UAT's `missing:` item 2 asked whether `jamObserved` is inert noise on the restarted
path and should be excluded at `stock-diagnose.ts:770` for that branch. **It is not inert.
Keep it. Relax the test instead.** Evidence from the source, which the executor must NOT
re-derive:

1. **There are two restarted call sites, and the field is live on one of them.**
   - `stock-diagnose.ts:891-897` — `diagnoseVerdictResult(null, "restarted", ...)` on a
     thrown `MachineRestartedError` during acquisition. `session === null`, so
     `jamObserved` is the constant `false`. Inert here.
   - `stock-diagnose.ts:911-917` — the step-2 epoch comparison,
     `diagnoseVerdictResult(session, "restarted", ...)` with a **non-null** session. Here
     `jamObservedFor(session.client)` (`stock-runstate.ts:138`) reads the still-held
     client's real tracker, and `jamObserved` is documented and tested as **latching**
     (`stock-runstate.test.ts:70,81` — "a jam is a latching fact about the instance, not a
     transient state"). A JAM that arrived before the epoch bump is exactly the causal fact
     a restarted answer should carry: a JAM'd instance is a plausible reason the supervisor
     respawned it. **Not inert.**
2. **The live test itself cannot predict which of the two branches it takes** — its own
   step-5 comment calls the choice "a race this test does not need to resolve ... both
   outcomes are the SAME correct answer". A branch-specific evidence shape would make that
   race observable in the payload, which is precisely what the test was written to avoid.
3. **Excluding it re-introduces the defect WR-03/WR-04 removed.** The comment at
   `stock-diagnose.ts:754-759` is explicit: derived in ONE place, "stamped into EVERY
   verdict's evidence -- not added per-call-site ... Always present (never omitted when
   false), so an absent field can never be read as 'no jam'." A per-verdict exclusion makes
   absence ambiguous again.

Therefore: `stock-diagnose.ts` is **NOT MODIFIED by this plan**. Task 1 relaxes the
assertion; Task 2 makes the shape auditable from the automated gate.
</decision_record>
