- **WR-01 / T-11-PATH-ESCAPE closed:** `resolveStorePath()`'s ENOENT fallback no longer trusts the literal (unresolved) candidate path. ## Decisions Made

- Label-name policy is **REJECT**, never sanitize or quote — matches this codebase's existing T-11-ENUM-NAME/T-11-REGBITS-PROSE precedent (a malformed name is a bug to surface, never silently rewritten, so the store's printed name can never diverge from what actually gets exported into ACME source).
- The identifier policy was **moved** into a brand-new, import-nothing module (`r2000-acme-ident.ts`) rather than importing it from `r2000-enum-gen.ts`, because `r2000-enum-gen.ts` statically imports `runR2000Tool` FROM `r2000-tools.ts` — importing the policy the other way would form a module cycle. `r2000-enum-gen.ts` re-exports both names so its own tests and consumers needed zero changes to their import path.
- Markdown-cell escaping (WR-04) is a **separate control** from the identifier policy, by design: comment `evidence` legitimately contains `|` and embedded newlines (`r2000_set_comment`'s own schema documents multi-line support), so the render leg escapes rather than rejects — refusing here would refuse valid data, not an attack.
- The dangling-symlink guard inside `resolveStorePath()`'s new ancestor-walk was added even though neither RED test in the plan's own `<behavior>` block strictly required it (both RED cases already resolve via a live, non-dangling symlink target) — it closes a related bypass shape (a symlink whose OWN target does not yet exist) named explicitly in the plan's `<action>` instructions, so it was implemented as part of the same fix rather than deferred.
