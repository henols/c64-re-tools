# Quick 260821-jd8 — Close WR-08: flag-shaped and missing option values

## Why

`10-REVIEW.md`'s **WR-08** is the single open item in Phase 10's retroactive security
audit (`10-SECURITY.md`: 24/25 threats closed, verdict `OPEN_THREATS`). It is the only
thing standing between milestone v0.3.0 and a clean close.

It was never promoted into any plan's `<threat_model>` block — it fell between the two
Phase 10 fix batches (CR-01/CR-02/WR-01 at close-out; WR-02..WR-07 by plans 11-01/11-02)
and was named in neither. That is itself an instance of AUDIT-01's defect, caught by the
disposition ledger Phase 11.1 built.

**Reproduced live on the current tree** (security audit, 2026-08-21):

```
$ node vice-proxy.ts r2000 bootstrap game.prg --out --entry FOO
# parseArgs() -> { out: "--entry", entry: undefined }
# writeFileSync then creates a file literally named "--entry"
```

`checkAcceptedOptions()` (added by plan 11.1-06 for IN-06) does **not** catch this:
`--entry` is a legitimately-accepted flag for `bootstrap`, so the option-name check
passes. Nothing validates that the token *following* `--out` is not itself a flag.

**Severity: Low-Medium, and bounded.** A dash-prefixed filename is a real shell-glob
hazard for whatever later consumes the output directory, but this is **not reachable
through any MCP tool** — `r2000-cli.ts` is dispatched at `vice-proxy.ts:271`
(`argv[2] === "r2000"`) before any JSON-RPC object exists, and the untrusted-input byte
parsers are imported only by `r2000-cli.ts` and a test-only gate, never by
`r2000-tools.ts`/`r2000-mcp-client.ts`. It requires a human already at a local shell.

## The fix is a pattern already in this file

`parseExportLblArgs()` (`r2000-cli.ts:684-698`) and `parseGenEnumsArgs()` already do
exactly the right thing:

```ts
if (a === "--out") {
  const value = rest[i + 1];
  if (value === undefined || value.startsWith("--")) {
    outMissingValue = true;
  } else {
    out = value;
    i++;
  }
}
```

`parseArgs()` (`:201-214`) instead does `entry = rest[++i]`, unconditionally. Bring it to
the same posture. Do **not** invent a third convention — reuse the existing one so there
is one shape for this in the file.
