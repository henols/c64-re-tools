<objective>
Close Phase 4 code-review finding **WR-01**: `decode()` in
`.claude/mcp/vice/disasm-decoder.ts` accepts a `startAddress` above `0xffff`
and silently wraps it via `(startAddress + offset) & 0xffff`, returning a
plausible-looking disassembly at the wrong address. Apply the review's
option (a): a dedicated `isValidStartAddress()` guard that additionally
requires `value <= 0xffff`, used for `startAddress` **only**, returning `[]`
(never throwing) when violated. Add the missing test case, document the bound
in the module header, and record resolution status for all four Phase 4
findings in `04-REVIEW.md`.

Purpose: consistency with `stock-address.ts`'s `parseAddress()`
(`inAddressRange()` already enforces `0..0xffff` strictly) and with this
module's own stated ethic — "never fabricate", "a wrong length here silently
desynchronises everything downstream". Refusing beats silently wrapping.

Output: a two-line guard, one test, a header note, and a resolution block on
the review report.

## Honest scope note — this is hardening, not a bug fix for a reachable defect

Record this, because it changes the finding's severity and a future reader will
otherwise re-derive it from scratch:

WR-01's stated motivation was that two future consumers import
`disasm-decoder.ts` **directly**, bypassing `parseAddress()` — Phase 5's
backtrace (`DERIV-02`) and Phase 6's CPU-history decode (`GAIN-01`).
**Both were cut from v0.2.0 scope on 2026-08-17** (`.planning/ROADMAP.md`:
Phase 6 removed wholesale; `DERIV-02` listed under "Cut from scope" —
"No skill calls `vice_backtrace`"). Every remaining reachable caller reaches
`decode()` through `stock-disassemble.ts`, which parses its address with
`parseAddress()` and therefore cannot produce an out-of-range value.

So WR-01 is now **defense-in-depth on a currently unreachable path**, not a
live gap. It is still worth fixing — it is two lines, and the module's own
philosophy favours refusal over silent wrapping — but do not describe it as a
bug fix in commit messages or in the review update.
</objective>
