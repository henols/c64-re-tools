## Category Decision

Use the existing **`Dependency`** category. Rationale, so it is not re-litigated:

- `Dependency` is already the category this list uses for statements about **external
  prerequisites and how you obtain them** — the existing `CPUHISTORY_GET` bullet is a
  version floor on an external emulator build that ends by telling the reader which
  builds are acceptable. Provisioning policy for external tools is the same subject.
- `Safety` in this list means something narrower and already-established: an action that
  destroys live emulation state one call deep (the power-cycle resources bullet). Filing a
  provisioning rule there would dilute a category that currently has exactly one, very
  specific, runtime-hazard meaning.
- Do **not** invent a new category (e.g. `Provisioning`). The list has eight categories in
  use and the format context is explicit that an existing one should be picked.

## Canonical Bullet Text

Write this as **ONE unwrapped line** (every bullet in both lists is a single long line;
`docs-linerefs.test.ts` documents that hard-wrapping a constraint bullet is what breaks
its line-scoped predicate). Append it directly after the `- **Testing**: ...` bullet,
which is the last bullet of the list and is byte-identical in both files
(`CLAUDE.md:48`, `.planning/PROJECT.md:513`).

> - **Dependency**: External tools are **never auto-installed** — the user installs them and the project only *detects* what is already present (owner's standing constraint, stated 2026-09-08, not up for re-litigation). The permitted pattern, stated positively, is **detect, then refuse by name with the remedy in the message**: `x64sc` is probed by `probeBackend()` / `resolvedBackend()` in `backend-detect.mts` while `README.md` carries the per-distro `apt` / `brew` / `pacman` line for the *user* to run; `c1541` and `petcat` are resolved by `findSiblingBinary()` in `host-tool.mts` as siblings of the already-resolved `x64sc`, memoised per process, with a `$PATH` fallback that logs a warning naming the shadowing hazard; ACME is probed on `$PATH` plus four documented prefixes (`src/skills/acme-build/SKILL.md`); Ghidra is declared by version only, non-vendored, at a user-chosen path (search for `analyzeHeadless`, never guess a prefix); and dxa ships as committed source under `src/mcp/vice/vendor/dxa/`, where `findDxaBinary()` in `host-tool.mts` makes `dxa.disassemble` refuse **by name** with `bash vendor/dxa/build.bash build` as the remedy rather than building it — the `curl` inside `build.bash` is user-invoked only and exists to verify the committed tree against the pinned `src/mcp/vice/vendor/dxa/dxa-0.1.5.tar.gz.sha256`, so nothing triggers it automatically. Therefore: never shell out to a package manager, never fetch-and-build on demand, and never `npx -y` a *third-party* package to make a missing tool appear (the project's own documented `npx -y @henols/vice-mcp anno <verb>` route is an invocation, not an install, and is unaffected). Three things are deliberately **out of scope** and must not be "fixed" by a reader of this bullet: `scripts/ensure-mcp-deps.sh` provisioning the MCP server's *own* `node_modules` via `npm ci` on `SessionStart`, gated on a lockfile sha256 (that is this package's dependencies, not an external tool); CI's `retry_apt install -y acme` in `.github/workflows/ci.yml` (a throwaway runner, never a user machine); and `installer/bin/cli.mjs`'s `npm install -D @henols/vice-mcp`, which runs only behind the explicit `--vendor` opt-in.

Two mechanical properties of that line, both load-bearing:

1. Every path it cites was confirmed present on disk at planning time: `README.md`,
   `src/skills/acme-build/SKILL.md`, `src/mcp/vice/vendor/dxa/`,
   `src/mcp/vice/vendor/dxa/dxa-0.1.5.tar.gz.sha256`, `scripts/ensure-mcp-deps.sh`,
   `.github/workflows/ci.yml`, `installer/bin/cli.mjs`. CLAUDE.md is a scanned normative
   document, so a path that stops resolving is a real defect.
2. It cites **symbol names, never line numbers**. `probeBackend()`, `resolvedBackend()`,
   `findSiblingBinary()` and `findDxaBinary()` were all confirmed to exist at planning
   time. Line numbers drift every phase and there is a standing project note that such
   citations must be re-verified each phase — a symbol name carries no such debt. In
   particular the line must contain no `vice-proxy.ts:<digits>` token, which is
   `docs-linerefs.test.ts`'s `CITATION_RE`.
