# Milestone v1.0.0 "The Rebuild Half" — Audit

**Audited:** 2026-09-16
**Status:** `gaps_found`
**Scope:** Phases 45-57 (13 phases; 9 complete, 1 in flight, 3 never started)

## Verdict in one paragraph

The milestone's *stated* half — the rebuild pipeline — is delivered and holds up
under independent check. Phases 45-50 are complete, verified, and wired end to
end: an annotated store exports to a multi-file ACME tree, real ACME reassembles
it, the hazard report and reassembly gate run over it, and the rebuild is shown
in VICE behaving like the original and being changed. That is 15 of the
milestone's original 15 requirements, satisfied.

What fails the audit is everything the milestone accumulated *after* that
roadmap was written. Thirty-three requirements were added across six later
phases; three of those phases were never started, one is half-executed, and one
closed with no verification of any kind. Worse, an owner-directed quick task on
2026-09-14 deleted the enforcement mechanisms that three separate requirement
families are written against — and its own summary said the roadmap and
requirements would be reconciled afterwards. They were not. The milestone
therefore carries requirements that are not merely unmet but **unimplementable
as written**, still marked Pending, still driving a live phase.

## The central finding: an owner decision the planning documents never absorbed

Quick task **260914-poo** (2026-09-14, commits `276c15c9`, `0b6c394e`,
`e4759250`, `85d13976`) deleted 60 files — 44 test files, one production module,
four CI checkers, one audit gate and ten orphaned `scripts/lib/` files — under
the owner's rule *"only data-driven tests that test production code are kept"*.
Its own SUMMARY states the outcome plainly: **"The planning-vocabulary convention
is retired outright"**, with "no note, seed, or successor document created
anywhere", and closes with *"The orchestrator handles STATE.md / ROADMAP.md /
REQUIREMENTS.md updates and the final metadata commit."*

That reconciliation did not happen. STATE.md's quick-task ledger records the
retirement correctly. The three documents that actually drive work do not:

| Document | Still says | Reality |
|---|---|---|
| `ROADMAP.md` | Phase 51 has nine live plans, 51-09 through 51-17, the last one "all six requirements verified with recorded evidence" | The convention those plans enforce is retired; their guard is deleted |
| `REQUIREMENTS.md` | `VOCAB-01..06` Pending, `[ ]`; `DOCS-04` names `skills-planning-vocabulary.test.ts` | `scanForPlanningVocabulary()` does not exist; that test file was deleted |
| `STATE.md` § Current Position | "Current focus: Phase 51 ... resumes at plan 9 of 17" | Nine plans pointed at a retired rule |

Concretely, per requirement:

- **`VOCAB-01`** requires `scanForPlanningVocabulary()` to report zero across the
  published file set, "and the guard measuring it runs in `npm run
  test:automated`". Measured this audit: that function name appears nowhere in
  the tree.
- **`VOCAB-03`** names `comment-phase-pointers.test.ts` as the one guard of five
  that had to be **moved rather than relaxed**. It was deleted outright. Three of
  the four guards the requirement says "needed none" (`docs-dangling-refs`,
  `docs-absorbed-decisions`, `audit-integrity`) were deleted by the same commit.
- **`VOCAB-05`** requires a planted citation to red "the widened guard". Both the

None of this is an error by the quick task — it executed an explicit owner
decision and recorded its consequences honestly. The gap is that the decision
never propagated into the roadmap and requirements it invalidated.
