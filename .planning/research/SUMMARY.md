# Project Research Summary

**Project:** c64-re-tools — milestone v0.7.0 "Own the Annotation Store"
**Domain:** An owned, persistent, undoable annotation store with per-range interval typing over a 64K address space, reached through a proxy-local MCP surface — plus the removal of the regenerator2000 integration it replaces
**Researched:** 2026-08-26
**Confidence:** HIGH for everything measured against this repository's tree at HEAD (all four researchers measured, none recalled). MEDIUM for store-internals design and the comparable-tool survey. See the confidence table and the unreconciled-disagreements section.

> **Read the "Reconciled facts" and "Unreconciled disagreements" sections before writing requirements.** The four researchers independently corrected the premises this milestone was scoped on, and in three places they corrected them *differently*. Those three are decisions for the requirements conversation, not for a planner.

---

## Executive Summary

v0.7.0 builds an annotation store this project owns — labels, comments, per-range data typing, flat scopes, project enums generated from `memmap.json`, undo, crash-safe persistence, cross-references and an ACME export verified by a real assembler — and then deletes the regenerator2000 integration it replaces. Research says the *store* half is small and well-specified, and the *removal* half is where the milestone's risk lives. The consumers already exist and are already specified: five absorbed analysis procedures in `src/skills/`, written against `r2000_*` calls, with `.planning/phases/19-.../upstream-procedure-manifest.json` classifying every verb each one calls as `curated` / `omit` / `adapt-to-address-input`. The tool surface is therefore a **diff against a committed artifact, not a design exercise** — 18 of the 19 curated verbs have a named consumer; exactly one (`delete_project_enum`) has none and should not be rebuilt.

The recommended approach: **no new runtime dependency.** The heavy machinery is either in the Node runtime already or already owned in-tree. The store registers proxy-locally through `buildViceTool()` exactly as the `r2000_*` family does, which satisfies CLAUDE.md's `rewriteArguments()` interception constraint *by construction* (neither call site is reachable from a `buildViceTool()` runner) and keeps the store backend-agnostic for free. It resolves its file container-side through `repoRoot()` + `resolveStorePath()` and must **never** import `hostpath.ts` — a five-element closed consumer set asserts this. Its type vocabulary should be the twelve members upstream already exposes, not the seven the milestone brief names. Its ACME export must be verified by a real ACME 0.97 spawn plus a byte-diff, never by an exit code and never by the exporter's own string output.

The dominant risks are three. **(1) The "existing `--verify` seam" does not exist as described** — `r2000-verify.ts` parses *regenerator2000's* output, not ACME's, so it dies with the subject; three of the four researchers flagged this independently as the single most dangerous item in the milestone. **(2) The type vocabulary is the milestone's one irreversible decision** — split-table orientation is unrecoverable from data that never recorded it, and shipping seven types re-creates inside this project the exact `da65` expressiveness boundary the project rejected `cc65` for one milestone ago. **(3) The removal produces guards that pass *vacuously***, and the cheap repair (lower the non-vacuity floor, delete the positive control) converts a proven guard into a permanently green one. Mitigation for all three is ordering plus observed control REDs, both collected below.

## Unreconciled disagreements (requirements decisions, not planner decisions)

### D1 — Persistence format: SQLite vs a single JSON document. **This is the largest split.**

- **STACK says `node:sqlite`**, and argues it from live measurement on this host: built into Node since v22.5.0, unflagged since v22.13.0, so already available at the declared `>=22.18.0` floor; **zero new dependencies, zero lockfile change, zero build step, zero tarball bytes**; bundles SQLite 3.50.4; WAL + `synchronous=FULL` measured at **1.16 ms per durable edit** on real NVMe/ext4 against **16.03 ms** for whole-file JSON + atomic rename (which scales with *store size*, not edit size, at 766 KB and rising). It also makes an evidence-quality argument that matters here: the SQLite planted violation ("drop the `COMMIT`") reliably reddens, whereas the JSON planted violation ("remove the `fsync()`") **frequently still passes** because the page cache serves the read — and a guard that cannot be made to fail is not evidence.
- **ARCHITECTURE says one JSON document** at `<workspace>/<name>.c64anno`, atomically rewritten, with the undo journal inside it — argued from the project's "single seam per concern" convention and the tmp+rename idiom already at five sites.
- **PITFALLS assumes the JSON/tmp+rename route** throughout, and independently flags **Performance Trap: "Full-store rewrite on every mutation"** as a real hazard for exactly the designed workload (a `routine-queue-walker` pass setting 200 comments writes 200 full stores).
- **FEATURES says JSON, user data only**, arguing SourceGen's model because it diffs.

**Not resolvable from research alone** — it is a values call between measured throughput/evidence-quality (STACK) and single-seam simplicity plus git-diffability (ARCHITECTURE/FEATURES). **A synthesis worth putting to the requirements conversation:** STACK itself proposes the hybrid — SQLite as the working store, plus a *deterministic, sorted, newline-stable text export* written with the atomic-rename technique as the git-diffable artifact, guarded by a `--check` digest comparison. That mirrors the project's own recorded Key Decision ("make the store canonical and the Markdown memory map a generated view"). Note two SQLite costs stated honestly: on the Node 22 line `node:sqlite` emits an unconditional `ExperimentalWarning` to stderr (so **no test may assert stderr is empty**), and WAL leaves `-wal`/`-shm` sidecars after an unclean exit (so the store is not single-file at rest).

### D2 — Undo: inverse-command journal vs whole-store snapshot vs don't build it

- **STACK:** inverse-command journal, committed in the **same transaction** as the mutation. Notes the real design constraint precisely: *every inverse must be constructible at edit time*, so the handler must read prior state **inside** the transaction before writing — and range typing needs an interval-aware inverse whose payload carries the **displaced rows**, not a single reverse op. Also verified that SQLite's session/changeset extension is exposed but **`sqlite3changeset_invert` is not**, so inverses cannot be derived mechanically (recorded as a named reversal trigger if Node ever exposes it).
- **ARCHITECTURE:** in-document journal, and flags a governance obligation — the Phase 19 manifest classifies `r2000_undo` as **`omit`**, so `anno_undo` is a **deliberate departure** and **the manifest disposition must be updated in the same commit**, or `r2000-upstream-audit.test.ts`'s justification assertion records a reversed decision.
- **FEATURES:** **recommends not building an inverse journal at all.** Measured: no absorbed procedure and no shipped skill calls undo; the manifest's own rationale is that `set_data_type` is idempotent over a range, so "undo it and redo it correctly" collapses to "set it correctly"; an agent has no cursor for "the last action" to be relative to. Recommends satisfying the requirement with the cheapest form that has a consumer — a **whole-store snapshot/restore save-point** — and says plainly that the *durability* half of the requirement has a hard planted-violation test while the *undo* half has no caller.
- **PITFALLS:** agnostic on mechanism, hard on the test: **one combined planted-violation test**, not two.

**Decision needed:** inverse journal, snapshot save-point, or neither. FEATURES' consumer-trace argument is the strongest evidence in the room and is unaddressed by the other three; ARCHITECTURE's manifest-disposition obligation applies to whichever form is chosen.

### D3 — `capability-registry.ts`: entry or no entry?

- **ARCHITECTURE says NO, emphatically**, and calls adding one **"a factual error, not merely an omission."** The registry holds only the *per-backend delta*; a proxy-local family is in neither manifest and so contributes no delta. The registry's own header names `vice_diagnose`/`vice_recycle` as exactly this precedent. An entry would also render a spurious row in the generated `docs/tool-support.md`, breaking its byte-identity guard. Backend-agnosticism is made structural **somewhere else entirely** — in `stock-dispatch.test.ts`'s `BACKEND_SEAM_BYPASS_KEYS`.
- **PITFALLS says the requirement text (`STORE-03`) asks for it**, notes the `r2000_*` family was in neither the manifest nor the registry, and therefore calls it a **new obligation with new consumers, not a carry-over** — advising to check all four registry consumers and the `docs/tool-support.md` drift guard **before choosing**.

**These are not compatible.** Most likely resolution: **amend `STORE-03`** so the backend-agnosticism obligation points at `BACKEND_SEAM_BYPASS_KEYS` (where it is actually enforceable) rather than at the registry. That is a requirements edit and must not be made silently by a planner.

### D4 — Grep-gate exemption unit

- **ARCHITECTURE:** the exempt set is **10 *lines* across 5 blocks in 3 files** (each block carries two `regenerator2000` lines — the `Adapted from regenerator2000.` line and the pinned repository URL), with a non-vacuity counter requiring **exactly 10**. Recommends a **block-scoped, shape-matched** predicate reusing `skill-attribution.test.ts`'s existing `attributionBlocks()` extractor rather than a substring exemption.
- **PITFALLS:** the exempt set is **10 *instances* across 2 trees** (5 in `src/skills/` + 5 synced twins in `installer/skills/`), and adds `THIRD-PARTY-NOTICES.md` in both packages plus `packer-finding.mjs`'s provenance strings as named exemptions with reasons.

**Reconciliation:** both are right about different axes, and a correct gate needs both — block-scoped shape matching (ARCHITECTURE) applied across both trees (PITFALLS), with per-exemption non-vacuity. The exact counter value must be re-measured at plan time rather than copied from either document.

### D5 — Phase count and shape

ARCHITECTURE proposes **six** phases (27–32); PITFALLS proposes **five** roles (27–31, mapping "skill re-pointing" to 30 and "the removal" to 31). PITFALLS states explicitly that its numbers are proposed *roles*, not a roadmap, and that v0.7.0 numbering starts at 27 and numbers are never reused. The roadmapper should map roles, not digits. Their **dependency orderings do not conflict** — see below.

## Key Findings

### Recommended Stack

**No new runtime dependency, and no `npm install` runs in this milestone.** `src/mcp/vice/package.json` keeps the same two `dependencies` and two `devDependencies`, `package-lock.json` is unchanged, so `scripts/ensure-mcp-deps.sh` stays a no-op for every existing user. Both published tarballs gain only source files, so `scripts/check-npm-packages.mjs` needs new `files[]` entries and nothing else. Three concerns stay owned code deliberately because measurement says the libraries are worse.

**Core technologies:**
- **`node:sqlite` (`DatabaseSync`)** — the durable store, *if* D1 resolves that way. Built-in at the existing Node floor; bundles SQLite 3.50.4; WAL + `synchronous=FULL`; `foreign_keys` defaults to `1` (unlike raw SQLite) and FTS5, R*Tree, JSON1, UDFs, generated columns and savepoints are all compiled in — every one probed live on this host. Confine it behind **one seam module** and express the schema in SQL, not driver calls, so a future API break is a one-file fix. Method-heading diff `v22.x` -> `main`: **20 additions, 0 removals.**
- **An owned paint-array interval index, ~60–120 lines** — narrowest-range-wins address lookup. `Int32Array(65536)` of winning range ids plus a parallel width array; **narrowest-wins is resolved at paint time, not query time**; tie-break for equal widths must be explicit (recommend higher range id) and pinned by a test. Measured **0.018 us/lookup** vs 0.31 us (sorted + binary search), 4.6 us (naive scan — the shape `r2000-coverage.ts`'s `classAt()` already has) and 42.6 us (the SQL formulation). Full rebuild for 2,700 ranges costs **7.5 ms**, so **rebuild on mutation** and write no incremental-maintenance code. Cross-validated against an independently written binary-search implementation across **all 65,536 addresses: 0 disagreements.** Every surveyed interval-tree package returns *all* overlapping intervals with no narrowest-wins tie-break, so the deciding logic is yours regardless.
- **Owned, hand-rolled argument validation throwing named `ViceError` subclasses** — because the proxy validates nothing (measured). Address range `0x0000–0xFFFF`, `lo <= hi`, type in the 12-member set, label through `assertLegalAcmeIdentifier()` (`MAX_ACME_IDENTIFIER_LENGTH = 200`). **Not `zod`.**
- **Real ACME 0.97 "Zem"** at `/home/henrik/.local/bin/acme` — the external reassembly oracle. Spawn with an **argv array**, never a shell string; match `src/skills/acme-build/scripts/acme.mjs`'s argv verbatim so the two agree by inspection; never treat an ACME stderr *warning* as failure.
- **Existing owned modules, retargeted not rewritten:** `disasm-opcodes.ts` / `disasm-decoder.ts` / `disasm-renderer.ts` (**1,042 non-test lines** — the seed's "2,555 to reuse" counted tests), `memmap.json` (959 address entries) + `r2000-regbits-gen.ts` + `r2000-enum-gen.ts` (995 lines; only its I/O tail changes), `r2000-acme-ident.ts`, `r2000-confidence.ts`, `r2000-d64.ts` (310, standalone), `r2000-memmap-render.ts`, `r2000-coverage.ts`.

**Explicitly rejected, with dates:** `better-sqlite3` 13.0.3 (11.4 MB / 27.3 MB per consumer unconditionally; ships 8 prebuilt binaries so the "no build step" objection is genuinely *out of date*, but has **no fallback** off those 8 targets -> hard `MODULE_NOT_FOUND` on armv7/freebsd/s390x; changes the lockfile hash so every user's next session runs `npm ci`); `write-file-atomic` 8.0.0 (its `engines` floor is **above** this project's `>=22.18.0` — adopting it forces a breaking prerequisite bump for a ~15-line `node:fs` helper); `lowdb` 7.0.1 (2.7 years stale, *is* the whole-file-JSON route plus a dependency); `lmdb` / `classic-level` / `level` / `sqlite3` (gyp or install scripts); every interval-tree package (`static-interval-tree` has **no `license` field**, two are abandoned, two are 3.7–5.2 years stale, and the one maintained option still has no narrowest-wins semantics); `immer` (in-memory undo dies at process exit — the exact requirement it must satisfy); `zod`; `uuid`/`nanoid` (`node:crypto.randomUUID()` is built in).

### Expected Features

The scoring test applied mechanically throughout: **does a shipped skill call this, or does something a skill calls depend on it?** Result on the current 19-verb curated surface: **18 have a named consumer, 1 does not.**

**Must have (table stakes — every comparable tool has it, every consumer needs it):**
- **Persistence: open / save / survive process death** — 4 of 5 absorbed procedures end with it. Never report "persisted" on the strength of the store's own success text.
- **Label at an address**, with **kind: user / system / auto** — do not collapse to one kind. `routine-queue-walker`'s entire backlog *is* the `auto` set; `export-lbl` exports **user only** (measured — a test asserting an `a_`-prefixed name appears in an export is testing the wrong thing, a trap already documented at `r2000-symbols.ts:16-23`).
- **Comments at an address, `line` + `side`**, multi-line on `line` — consumed by **all 5** absorbed procedures. The `line` comment is also the carrier for the five-grade confidence prefix.
- **Per-range data typing, inclusive both ends**, full 12-member vocabulary, **explicitly stored ranges with no adjacency auto-merge**, even-count validation on split forms.
- **Block enumeration** (`get_blocks`), **cross-references to an address**, **`read_region`** (disasm *or* hexdump, refuse-over-cap **by name**), **`get_binary_info`** (incl. **entropy** — the >7.5 packed gate `analyze-program` relies on after `unpack_binary` was omitted), **`get_address_details`**.
- **Search over labels + comments + instructions** — keep the existing hard decision: **`max_results` REQUIRED with no default** (upstream's silent default of 50 truncated a full-program pass) and return the count so truncation is detectable.
- **`batch_execute`** over the single-owner write path, with **pre-flight validation of every inner name** and **per-item status on execution** — the loop does **not** abort on first failure (measured upstream semantics).

**Should have (differentiators):**
- **Project enums generated from `memmap.json`** — `lda #$1b / sta $d011` -> `lda #D011_YSCROLL3_ROW25_SCREENON_TEXT`, reassembling byte-identical. *"Neither project can do this alone."* `create` + `update` + `apply`; **not `delete`**.
- **Explicitly stored ranges so adjacency never auto-merges** — **the single largest free win from owning the store.** It removes the need for a `toggle_splitter` primitive *by construction*, unblocks `DECOMP-01` and `BUILD-02`, and removes `COV-01`'s predicted over-merge divergence bias. LOW cost if designed in; MEDIUM to retrofit.
- **Store <-> live-emulator symbol round trip** (`export-lbl` / `import-lbl`) — no surveyed RE tool talks to a running emulator's symbol table. Implements the **checkmark-Validated** `R2000-14`/`R2000-15`.
- **ACME export verified by a real ACME**, `=*+$01` idiom, 11 typed prefixes.
- **Derived-from-bytes coverage census the store cannot move** — already built; the *conceptual boundary* (`r2000-coverage.test.ts` rewrites every block entry to one type and asserts no census byte count moves) must survive the port intact.
- **Confidence grade as a queryable axis** — already built (`r2000-confidence.ts`, five grades, zero new storage, typo'd-near-miss parser). Keep it as a comment-prefix convention; promoting it to a column has no caller.
- **`{available:false, reason}` instead of a plausible zero** — existing convention at `stock-cia.ts:494`, `stock-vicii.ts:239`, `incident-record.ts:115`.

**Defer (v0.7.x / v0.8+):**
- **Xref access kind** (`READ`/`WRITE`/`READ_WRITE`/`COMPUTED_JUMP`) — **store the field now** (free at decode time, unrecoverable later), build nothing on it. No shipped skill or skill-called module consumes an access kind today; the *field* is nearly free, the *classifier* is surplus. Trigger: `GHID-05` unheld.
- **`set_immediate_format`** — trigger: `BUILD-03`. **Emitted-vs-non-emitted comment flag** (SourceGen's *note*: a triage note must not reach shipped source) — cheap now, re-typing existing comments later. **Bank-qualified addressing** — defer until `PROOF-03` is actually measured; today it is modelling for an unmeasured requirement. **Cross-release block-classification diffing.** **`delete_project_enum`** — never.

**Anti-features, actively harmful:** a **cursor / current address** (upstream's *own* procedure text says *"**NEVER** use the 'current cursor address'"*); **rejecting no-op writes** (breaks idempotency, and agents retry on timeout — succeed with `changed: true|false`); the **full 5-kind comment taxonomy**; **repeatable comments**; **nested scopes** (`add_scope` has exactly one site in the whole skill tree); **tags/bookmarks as a separate axis**; **local/stack-relative symbol tables**; a **`py_eval`-shaped meta-tool** (the nested-argument smuggling shape `vice.ts`'s `DENY_LIST` exists to close — `batch_execute` is the one sanctioned exception); **destructive in-place unpacking**; **HTML export**; and **byte-or-behaviour parity with regenerator2000's store** (v0.7.0's own requirement text forecloses it — the manifest's per-procedure tool list is the bar, and a procedure that runs is the test).

### Architecture Approach

The annotation family sits **proxy-local**, registered through `buildViceTool()` in a two-line substitution at `vice-proxy.ts:194` (the import) and `:3401-3402` (the loop). Nothing is appended to `vice-proxy.ts` — new code goes in sibling modules, which preserves both `docs-linerefs.test.ts`'s line citations and PROJECT.md's standing instruction about that file's size. Neither manifest is modified (`refresh-manifest.ts` would wipe a hand-added entry from a live *host VICE* `tools/list`), `docs/tool-support.md` is regenerated byte-identical, and the store never touches `vice.ts`, `forwardToVice()`, or `hostpath.ts`.

**Major components (new):**
1. **`anno-model.ts`** (~350) — pure model + invariants: ranges, the 12-member type vocabulary, label/comment/scope/enum records, non-overlap, ACME-legal names. Imports `acme-ident.ts` only.
2. **`anno-store.ts`** (~500) — **THE ONE persistence seam.** open/create, apply-mutation, undo journal, atomic write, `resolveStorePath()`'s six-step containment ladder (reject non-string -> require extension -> `resolve(repoRoot(), ...)` -> `isContained` -> `realpathSync` both sides and re-check -> `resolveViaDeepestExistingAncestor()` on `ENOENT`).
3. **`anno-tools.ts`** (~1,100) — the surface: `ANNO_TOOL_DEFINITIONS`, `CURATED_ANNO_TOOLS`, `assertCuratedTool()` **including batch recursion**, `runAnnoTool()`. Never touches `node:fs` itself.
4. **`anno-xref.ts`** (~400) — xrefs and search over the typed decode. **Derive, never cache on disk** — a cached index inside the store document creates a second truth that can disagree with the block table, the exact failure `COV-01`'s derived-from-bytes census was built to make impossible.
5. **`anno-acme-export.ts`** (~600) + **`acme-verify.ts`** (~250) — the printer and the real-ACME oracle. `acme-verify.ts` is a **deliberate second implementation** of `acme.mjs`'s spawn, because `src/mcp/vice/**` and `src/skills/**` are separate npm packages and cannot import each other.
6. **`acme-test-gate.ts`** (~60, extracted) + **`prg-image.ts`** (~60, extracted `parsePrg`/`flatImageOrigin`) + **`anno-symbols.ts`** + **`anno-cli.ts`** (~900).

**Structural properties to preserve:** the `anno-` prefix must be a **single stable prefix derivable from disk**, because `hostpath-consumers.test.ts` and `r2000-spawn-seam.test.ts` both derive their module sets with `readdirSync` + a name regex precisely because a hand-typed list went stale (INT-01 found four uncovered modules). The `acme-` prefix keeps the assembler-facing half out of the store family's floor count. The removal gate then has a one-line rule: *no shipped module name may contain `r2000`, and no shipped tool name may contain `r2000_`* — prefix-independent, so the `anno_*`-vs-`store_*` naming choice does not affect it.

**Anti-patterns named:** adding the family to `capability-registry.ts` (see D3); hand-adding it to a manifest; routing it through `buildBackendAwareTool()` (on the non-fork arm that calls `dispatchStock()`, which has no table entry for an `anno_*` name and **refuses by name** — the store would be unreachable on stock); importing `hostpath.ts`; an explicit save verb that governs durability (map the procedures' save step onto **`anno_checkpoint`**, an undo boundary that is durability-neutral); narrowing the vocabulary to seven; a grep gate that exempts by file or consults the exemption first.

### Critical Pitfalls

1. **"Reuse the existing `--verify` seam" is impossible as written, and the natural repair reopens the incident the seam exists to prevent.** `r2000-verify.ts` parses regenerator2000, not ACME. The recorded false pass, verbatim: `x ACME — ACME not found in PATH (skipped)` / `ok All roundtrip verifications passed.` / `EXIT=0` — exit zero, an aggregate line reading as a full pass, the one assembler this project cares about never ran. A direct `spawnSync("acme", ...).status === 0` check has the *same hole one level over*: ACME missing -> `status: null`, and a truthiness check reads a missing binary as a pass. **Prevention:** keep the five verdict rules (never derive `ok` from exit status; never trust an aggregate line; require **unanimity** across ACME result lines with the first non-ok driving the verdict; refuse to guess when more than one authoritative line is present; `"skipped"` and `"ok"` are different outcomes and must never be conflated), model "did not run" as a **third outcome** (`AssemblerOutcome = "ok" | "skipped" | "failed"`, which already exists), and make the **byte-diff** the verdict for identity. Re-record `r2000-verify.test.ts`'s two pinned transcripts — the honest pass and the false-pass trap — **from real ACME output**. This is a genuine rebuild cost; do not plan it as a rename.
2. **The seven-type vocabulary is narrower than the store it replaces, and the loss is a confident wrong answer.** A mis-oriented split table **reassembles byte-identically** (the bytes never changed), so an "it reassembles clean" gate passes while every label, xref and memmap join downstream is wrong. And it re-creates inside this project the exact `da65` `RANGE TYPE` expressiveness boundary that got `cc65` rejected one milestone ago. **Prevention:** 12 members, split orientation and element kind as **first-class variants not a flag on "table"**, even-count validation, and carry forward `r2000-coverage.ts`'s **dispatch-context gate** (a split lo/hi pairing is `PROVEN` or `ADVISORY`, never silently promoted).
3. **Guards that pass vacuously the moment their subject disappears.** The highest-value removal pitfall, because its symptom is a **green suite over an undefended invariant**. `hostpath-consumers.test.ts` derives the r2000 family from disk with a `R2000_MODULE_FLOOR = 14` non-vacuity floor and a four-module positive control — so the deletion turns it **red, correctly**. The trap is the *repair*: lowering the floor to 0 and deleting the positive control converts a proven guard into a permanently green one, and the new store modules are then covered by nothing. Same shape in `scripts/check-skill-tool-coverage.mjs` (zero mentions cross-checked against zero curated tools passes trivially) and `skill-attribution.test.ts` (scans `src/skills/` only, never `installer/skills/`, so a sync that drops the headers is invisible to it). **Prevention:** re-point the glob, **raise** the floor to the measured new count, replace the positive control with real new filenames, and **re-run the guard's own planted violation against the new subject.** If you cannot make it fail, you have not re-pointed it.
4. **Two CI gates go red on *registration*, before any deletion happens.** `scripts/generate-tool-support-table.mjs:104`'s `R2000_LOOP_VAR_RE` hard-codes `R2000_TOOL_DEFINITIONS`; rename the collection and the regex matches nothing, the captured `annoDef` identifier falls into the documented **throw** branch, and the failure surfaces as `docs/tool-support.md`'s byte-identity drift guard going red with a confusing message. The identical regex is **deliberately triplicated** ("each is a separate witness proving the other two right") at `src/mcp/vice/tool-support-table.test.mjs:66` and `src/mcp/vice/capability-registry.test.ts:161` — **all three move in the same commit, and none is refactored into a shared helper.** Separately, `scripts/check-skill-tool-coverage.mjs:49` statically imports `CURATED_R2000_TOOLS` and throws `ERR_MODULE_NOT_FOUND` the moment `r2000-tools.ts` is deleted.
5. **A direct contradiction that must be resolved inside one plan.** `scripts/check-skill-fork-honesty.mjs:504` asserts `acme-build/SKILL.md` still contains the literal string `"r2000 export-asm"` ("the deletion must not be 'fixed' by deleting the pointer to the proven route too"). If the skills are cleansed, that `need()` fails; if the string stays, the new grep gate fires on it. **Both halves must move in the same commit.**
6. **Partial overwrite of a typed range must split, not drop or shrink.** "Remove overlapping, insert new" is three lines and passes every test written against non-overlapping fixtures — and silently un-documents a previously annotated region with no message, which is the exact failure the store exists to prevent (`CORE-01`'s reversal condition (a)). **Prevention:** one seam, split-and-preserve, five overlap cases (fully-contained -> 3, left -> 2, right -> 2, exact -> 1 replaced, superset -> 1 replaces), each asserting **total byte coverage is unchanged** — the one invariant that catches all five.
7. **Concurrent writers: the in-process mutex is not a cross-process lock, and the staleness check is the thing most likely to be "cleaned up."** Two real routes write the same store from outside the FIFO mutex today: `vice-mcp r2000 <verb>` (a genuinely separate OS process, invoked by a skill's Bash call — **13 such mentions**) and a second `vice-proxy.ts` process. The recorded consequence was found live, not reasoned about: a held session answered a later read from its now-stale in-memory copy, silently missing the import. Last-writer-wins with tmp+rename produces a **clean** file that has silently lost the other writer's annotations — no corruption to notice. **Prevention:** a monotonic **`revision` counter inside the store file** (stronger than `mtimeMs`, which has coarse granularity on some filesystems and is preserved by `cp -p`), compared on every read-after-cache; **refuse** a write whose base revision is not the current on-disk revision; keep the single-owner check-and-set synchronous with no `await` in the gap, per the standing broker constraint.

Also carried forward and not to be lost: **inclusive-end off-by-one** (name the field `endInclusive`, never a bare `end`; six conversion boundaries and five of them produce plausible output); **address vs image-offset vs `.prg`-file-offset** plus decimal-vs-hex (accept `integer` **and** `$`/`0x`-prefixed strings; **reject an unprefixed numeric string outright** rather than guessing a base — this codebase already contains two opposite defaults, since VICE's monitor reads bare literals as hex); **flat vs banked** (do **not** build bank-aware storage — that is scope creep against held Phase 24/26 — but **reserve** an optional `bank` field plus a schema version, and state that an unqualified annotation on `$D000-$DFFF` or `$A000-$FFFF` is asserted only for the bank state the annotator observed); **label collisions and mnemonic labels** (`LDA`/`INC`/`ROL` are legal identifiers and illegal labels; auto-generated names must live in a separate namespace from user names; **reject, never sanitize** — sanitising `init screen` -> `init_screen` silently collapses two labels into one); **comments orphaned on retype** (return the contradicted-comment list in the retype result — an agent given a list will fix it, an agent given `{ok:true}` cannot); **the enum applied to the wrong operand** (the enum goes on the **immediate operand of the `lda`**, named for the register the *later* `sta` targets — make the attribution a caller-supplied pair, never an inference); **illegal opcodes** (221/256 are ACME-expressible under `!cpu 6510`; the other 35 must emit `!byte $xx` with a naming comment, never an invented mnemonic — this is the instrument that caught 14 wrong entries in an internally-verified table); **reassembly layout** (a label substituted for a zero-page literal changes the addressing mode and the instruction **length**, shifting everything after it — assert `*` equals the original address at the start of **every** block, not only the program start).

### Phase Ordering Rationale — the hard constraints

These are ordering *constraints*, not preferences. Each was derived from code, not taste.

1. **The gate split must precede the deletion gate.** `r2000-test-gate.ts`'s ACME half must be extracted under a non-r2000 name **in the same commit or earlier** as the deletion, keeping `ACME_BIN` / `VICE_REQUIRE_ACME` byte-identical because CI already binds to them by name and a rename there is a second, silent failure mode.
2. **An ACME oracle must exist before the deletion window opens.** The exporter phase (D) must land **before** the phase that deletes `r2000-launch.ts`. Between them there is a window with no working external oracle, and every claim made in it sits at fixture level.
3. **The removal must follow the skill re-pointing.** Otherwise the grep gate cannot distinguish "not yet re-pointed" from "reintroduced", and the milestone's own gate requirement becomes unenforceable.
4. **The registration-time guards must move in the registration phase.** Two CI gates (`generate-tool-support-table.mjs` and `check-skill-tool-coverage.mjs`) break on the **rename**, not on the deletion. Handled anywhere later, the phase closes with a red CI gate. **This is the single most important sequencing fact in the architecture research.**
5. **Build every gate before the thing it gates.** The `4f048bb` precedent — a milestone closed with a guard already red and nothing forcing anyone to notice — is why the grep gate and all guard fates are a *precondition* of the deletion commit, not a follow-up.
6. **The type vocabulary is decided in the store-core phase and never revisited.** It is `DECOMP-01`'s sizing input and the thing a schema migration cannot recover: split-table orientation is unrecoverable from stored data because it was never recorded.
7. **Do not archive phase directories at the close.** `--no-archive-phases`, and the reason has **grown**: the Phase 19 manifest is now a **design input** to this milestone, not merely a guard's fixture. Two surviving guards (`docs-review-disposition.test.ts`, `skill-attribution.test.ts`) force the constraint regardless. Do not treat the deletion as a route to relaxing it.
8. **Pre-declare the expected reds.** Three guards go red **by construction** on the deletion — `docs-linerefs.test.ts` (removing ~120 lines of `vice-proxy.ts` r2000 wiring at `:188-310` and `:3163-3186` shifts all four cited line numbers; the right fix is **re-citing CLAUDE.md**, not loosening the guard), `docs-dangling-refs.test.ts` (its fixed document set **fails if any member is missing**; the right fix is rewriting content, not removing a path), and `docs-r2000-decisions.test.ts` (keep the D-36 decision row as dated history and give the guard an explicit superseded-by fate). Record them as **expected** before the deletion, so an *unpredicted* red is distinguishable from a predicted one.

### "Observe the control RED" requirements

This project accepts a guard only when its planted violation has been observed failing. Every control the researchers named, with the planted violation that must produce the red. *(B/C/D/E/F = suggested phase.)*

| Control | Planted violation that must produce RED |
|---|---|
| **(B) Durability** — mutate -> `SIGKILL` -> **fresh process** reopen -> read the mutation back **by value** | Skip the `rename` (write only to the temp file), or drop the `COMMIT`. **Not** a `close()`-then-reopen (that exercises the flush path the kill is meant to skip), **not** a same-process reopen (the in-memory copy may answer), **not** a hash comparison (a truncated 4-KB-of-40-KB write changes the hash too, and an idempotent save legitimately does not) |
| **(B) Truncation refusal** | Truncate the store file to half its length between kill and reopen; reopen must **refuse**, not return a partial store |
| **(B) Undo across restart — WARNING: ONE COMBINED TEST, NOT TWO** | mutate -> *(undoable)* -> `SIGKILL` -> reopen -> **undo** -> assert the pre-mutation value. Plant: keep the journal in memory only. **If only the two separate tests exist, both stay green over a store that cannot undo across a restart.** This single test cannot be satisfied by in-memory state, by a persisted-position-only log, or by a hash check |
| **(B) Split-table orientation** | A fixture with a known `lo_hi_address` table, typed as `hi_lo_address`, must produce a **differing resolved-target set**. Plant: collapse to one `table` type. **A test that only asserts "reassembles clean" cannot go red here and is not the control** |
| **(B) Inclusive range ends** | A `$0400-$0400` range must report length **1**; switch the model to exclusive and it must fail. Plus a `$FFFF` boundary test that rejects or handles explicitly, never wrapping to `$0000` |
| **(B) Split-on-overwrite** | Total typed bytes **unchanged** across all five overlap cases; plant `filter()`-and-insert in place of split and the fully-contained case must fail |
| **(B) Address domain** | A `.prg` fixture and a flat-64K fixture of the **same program** must produce **identical** annotations; reintroduce the two-byte skew and the equality test fails |
| **(B) Retype comment contradiction** | Comment `$1047` `[confirmed-code] loop head`, then type `$1040-$104F` as `byte`. The call must report **one** contradicted comment; remove the check and it returns clean success — that is the red |
