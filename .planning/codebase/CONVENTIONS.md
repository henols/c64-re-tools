## Scope Note

Code lives in three places, and all three share one hand-maintained style:

- **MCP server** — `src/mcp/vice/` (196 `.ts`/`.mts` files, ~133k lines including tests). The
  largest and most rigorously maintained body of code; every convention below is drawn from here
  first. Run directly by Node's native type-stripping — no build step for the shipped server.
- **Skills** — `src/skills/<skill>/SKILL.md` plus `scripts/*.mjs` (plain ESM JavaScript).
- **Installer** — `installer/bin/cli.mjs`, `installer/scripts/sync-skills.mjs` (plain ESM).

Repo-level guards live in `scripts/*.mjs` (`check-npm-packages.mjs`, `check-guard-fates.mjs`,
`check-no-analyser.mjs`, `check-skill-*.mjs`, `audit-gate.mjs`) and are proven by test
files under `src/mcp/vice/`.

Note: `src/mcp/vice/anno-memmap-render.ts` contains a NUL byte, so plain `grep` treats it as
binary and silently skips it. Always use `grep -a` for any content census over this tree.

## Naming Patterns

**Files:**
- Lowercase, hyphen-separated: `repo-root.ts`, `container-guard.mts`, `broker-launch.mts`,
  `stock-checkpoints.ts`, `anno-store.ts`, `d64-parse.mjs`.
- Domain prefixes are load-bearing and should be continued when adding a module:
  - `stock-*.ts` — the stock-VICE binary-monitor backend (`stock-protocol.ts`,
    `stock-dispatch.ts`, `stock-memory.ts`, ~30 files).
  - `anno-*.ts` — the annotation store and its tools (`anno-store.ts`, `anno-types.ts`,
    `anno-tools.ts`).
  - `disasm-*.ts` — the disassembler (`disasm-opcodes.ts`, `disasm-decoder.ts`,
    `disasm-renderer.ts`).
  - `broker-*.mts` / `vice-broker*.ts` — the host broker and its container-side client.
  - `docs-*.test.ts` — documentation guards (see TESTING.md).
- Tests are co-located, same basename plus `.test.ts` / `.test.mts` / `.test.mjs`:
  `repo-root.ts` → `repo-root.test.ts`; `d64-parse.mjs` → `d64-parse.test.mjs`.
- `.mts` is reserved for modules compiled into a build artifact under `resources/` — the
  `include` list in `src/mcp/vice/tsconfig.build.json` (`vice-broker.mts`, `container-guard.mts`,
  `backend-detect.mts`, `broker-state.mts`, `broker-launch.mts`, `broker-kill.mts`,
  `broker-epoch.mts`, `broker-control.mts`). Plain `.ts` is consumed as source, type-stripped at
  runtime. Never rename across `.ts`/`.mts` without checking that build `include` list.
- Compiled output lives in `src/mcp/vice/resources/*.mjs`, generated by `build.ts`, banner-marked,
  committed, and never hand-edited (`resources-sync.test.ts` fails CI on drift).

**Functions:**
- `camelCase`, verb-first, one job: `repoRoot()`, `containerPath()`, `containerizeRecord()`,
  `ensureResourcesInstalled()`, `shippedTsModules()`, `buildViceArgs()`.
- Boolean returns read as predicates: `isInsideContainer()`, `isLoopbackHostname()`,
  `isValidRequestId()`, `isLaunchInFlight()`.
- `handle<Thing>` is the convention for a stock-backend tool handler: `handleMemoryRead()`,
  `handleMemoryWrite()`, `handleMemoryBanks()` (`src/mcp/vice/stock-memory.ts`).
- Test-only state resets are exported explicitly with a `ForTest` suffix — never reached via
  module internals: `resetBankCatalogsForTest()` (`stock-memory.ts`),
  `resetRunStateTrackersForTest()` (`stock-runstate.ts`), plus
  `resetCheckpointStateForTest()`, `resetRegisterCatalogsForTest()`,
  `resetSymbolStoreForTest()`, `resetTimingStateForTest()`. Any new module holding
  module-level caches should follow this exact naming.
- Unexported helpers are declared `function`; public API is `export function`.

**Variables:**
- `camelCase` for locals and mutable module state (`warnedEnvOutsideFrom`, `reqId`).
- `SCREAMING_SNAKE_CASE` for module constants, especially env-var or protocol contracts:
  `HERE`, `WORKSPACE_ROOT`, `CONTAINER_WS`, `STOCK_DERIVED_TOOLS`, `MANUAL_ONLY_TESTS`,
  `ACQUIRE_TIMEOUT_MS`, `HOST_BOUND_ARTIFACTS`.
- `HERE` is the idiomatic name for `dirname(fileURLToPath(import.meta.url))`, used across nearly
  every module and test in the tree.
- Frozen exported constant lists use `Object.freeze([...])` with a comment stating that the list
  is the single source of truth and must not be duplicated elsewhere (see `MANUAL_ONLY_TESTS` in
  `src/mcp/vice/test-gate.mjs`).

**Types (TypeScript):**
- `PascalCase` for interfaces, types, classes: `RepoRootOptions`, `StockConnectSession`,
  `StockDispatchDeps`, `ViceError`, `BrokerState`, `InstanceRecord`.
- Options objects are `<FunctionName>Options`, destructured in the signature with defaults:
  `function repoRoot({ from = HERE, env = process.env }: RepoRootOptions = {})`.
- Result shapes are `<FunctionName>Result` (`HostRootCandidatesResult`,
  `ContainerizeRecordResult`).
- Enum-like protocol constants are const objects, not `enum` — `erasableSyntaxOnly: true` in
  `tsconfig.json` forbids `enum` and constructor parameter properties. `CommandType`, `ErrorCode`
  (`stock-protocol.ts`) follow this.
- Error subclasses end in `Error`.

## Code Style

**Formatting — no formatter config exists anywhere in the repo.** No `.eslintrc*`, `.prettierrc*`,
`biome.json`, or equivalent. Style is maintained by hand; match the surrounding file exactly.
- 2-space indentation throughout (`.ts`, `.mts`, `.mjs`).
- Double quotes, always.
- Semicolons used consistently.
- Generous line width (~100–120 cols common, wider inside dense comments). Do not aggressively
  rewrap; break at logical operator / ternary boundaries.
- Template literals for all interpolation.
- `#!/usr/bin/env node` shebang on every standalone script (`.mjs` and CLI-capable `.ts`/`.mts`).

**Static checking:** `npm run typecheck` in `src/mcp/vice` (`tsc --noEmit -p tsconfig.json`,
TypeScript 7.0.2, `strict: true`) is the only static gate, and it runs in CI before tests. Treat
strict TS as the linter. Relevant `tsconfig.json` flags that constrain how you may write code:
`strict`, `isolatedModules`, `verbatimModuleSyntax`, `erasableSyntaxOnly`,
`allowImportingTsExtensions`, `noEmit`, `module`/`moduleResolution: nodenext`, `target: es2022`.

**Runtime floor:** Node >= 24 for `@henols/vice-mcp` (`src/mcp/vice/package.json` `engines`);
Node >= 18 for the installer (`installer/package.json`).

## Import Organization

**Order (consistent across `src/mcp/vice/*.ts`):**
1. Node built-ins, always with the `node:` prefix: `import { existsSync } from "node:fs";`
2. Blank line, then local relative imports with explicit `.ts` / `.mts` extensions:
   `import { ensureResourcesInstalled } from "./install-resources.ts";`
3. `type`-only imports use `import type { ... }`, or an inline `type` keyword inside a named
   list: `import { spawn, type ChildProcessWithoutNullStreams } from "node:child_process";`
   (`verbatimModuleSyntax` makes this mandatory, not stylistic).

**Path style:**
- No path aliases; every local import is an explicit relative path with its real extension.
  Never extensionless, never a bare specifier for a local file.
- `.mts` files destined for the `resources/` build have their own sibling-import extension rule —
  read the header comment in `broker-launch.mts` before changing an import extension in that set.
- The runtime dependency set is pinned to exactly `@mastra/mcp` + `@mastra/core` (DISASM-07,
  enforced by `scripts/check-npm-packages.mjs`). Do not add a runtime dependency — including a
  dev-only convenience like a YAML parser for a guard — without going through that decision.

## Error Handling

**Custom error hierarchy, rooted at one base:**
- `class ViceError extends Error` (`src/mcp/vice/vice-errors.ts:158`) carries optional `code`/`data`,
  mirroring the JSON-RPC error shape.
- Transport/state subclasses extend it and add domain fields as plain public properties:
  `MachineRestartedError { baselineEpoch, currentEpoch, where, lastToolCall }`.
- The annotation store defines a whole sub-tree rooted at `AnnoStoreError extends ViceError`
  (`src/mcp/vice/anno-types.ts`): `AnnoStoreCorruptError`, `AnnoStoreStaleRevisionError`,
  `AnnoRevisionArgumentError`, `AnnoTypeError`, `AnnoRangeShapeError`,
  `AnnoSplitRemainderError`, `AnnoAddressError`, `AnnoStorePathError`, `AnnoLabelError`,
  `AnnoCommentError`, `AnnoCommentGradeError`, plus `AnnoDeriveArgumentError` /
  `AnnoDerivedTargetError` in `anno-derive.ts`. A new failure mode gets its own class here when
  it carries fields the nearest existing class cannot hold — that reasoning is written into the
  class's JSDoc.
- The stock backend has `StockProtocolError` (`stock-protocol.ts`) for wire-level failures.
- A handful of leaf classes extend `Error` directly when they must NOT be a `ViceError`
  (`AnnoSymbolsError`, `AnnoCoverageInputError`, `AnnoConfidenceGradeError`,
  `PathOutOfWorkspaceError`) — the "directly, not via ViceError" choice is commented at the
  declaration; preserve it.
- Constructor pattern: `constructor(message: string, { ...fields }: XOptions = {}) { super(message);
  this.name = "ClassName"; ... }` — `this.name` is always set explicitly so `error.name` is stable.

**Throwing:** messages name the exact offending input and the exact remedy, so
`assert.throws(fn, /regex/)` can match on content, not just type. Range errors embed the value and
the valid range.

**Never-throw contracts are explicit and load-bearing:** e.g. `ensureResourcesInstalled()` "never
throws (D-3)", and callers still wrap it in `try { } catch { /* belt-and-suspenders */ }` with a
comment saying so. Pure transforms return `{ result, changes, untranslated }`-shaped records
instead of throwing on partial failure (`containerizeRecord()` in `containerpath.ts`) — prefer that
shape when a caller needs to know WHICH fields succeeded.

**Silent-but-observable failure is an actively-designed-against bug class.** `repo-root.ts` carries
a header comment describing an incident where a wrong-but-non-throwing path resolution caused
silent data loss, and forbids reintroducing that shape (fixed `".."` hop counts instead of
marker-based resolution). `vice-proxy.ts`'s `containerizeGrant()` documents a matching incident of
its own: a host-rooted epoch path that "simply never resolved, so every broker-granted instance was
silently unreachable" until the container/host boundary was fixed at that seam. New fallback
branches emit a one-time `console.error()` warning (see the `warnedEnvOutsideFrom` /
`warnedNoMarkerFound` guards) rather than succeeding on a guess.

**Fail-closed over degrade-quietly** is the standing rule for guards: a guard whose input set is
missing must fail, not fall back to a smaller, correct-looking set. `.github/workflows/ci.yml`
checks out with `fetch-depth: 0` specifically because `check-guard-fates.mjs` fails closed on a
missing pinned git object.

**CLI error convention:** CLI entry points catch at the top level, print
`` `error: ${(e as Error).message}` `` to stderr, and `process.exit(1)`.

## Comments

**Decision-record-style header comments are the house style, not an exception.** Non-trivial
modules and nearly every test file open with a multi-paragraph block covering:
- **WHY THIS FILE EXISTS** — the incident, constraint or requirement that motivated it, stated
  as a *reason a reader can act on*, not as a pointer. Write "a second broker launch raced the
  first and killed a live capture, so this check is synchronous with no `await` inside it" —
  not "plan 02-03 (BROK-03, D-14)".
- What this file is the ONE authoritative place for (the single-seam pattern).
- **WHAT NOT TO DO**, naming the specific past mistake — e.g. "do not re-list these nine file
  names in a CI workflow, an npm script, or a second test runner anywhere else"
  (`test-gate.mjs`), "do not reintroduce a fixed `\"..\"`" (`repo-root.ts`).
- What the file deliberately does NOT do, and why the cheaper alternative was rejected (see
  `ci-suite-coverage.test.ts` on not parsing YAML).

**Planning vocabulary does NOT belong in these comments.** `.planning/*` paths, `/gsd-*`
command names, phase and plan numbers, `D-NN` / `G-NN-N` ids and `ROADMAP`/`REQUIREMENTS`/
`RE-FINDINGS` cross-references stay inside `.planning/`. `src/mcp/vice/*.ts` ships verbatim to
npm and `src/skills/**` ships to every plugin user; neither reader has a planning tree. See
`.planning/ENGINEERING_RULES.md` § 21 for the full rule, its measured justification, and the
two named exemptions. `src/skills/**` is mechanically enforced by
`skills-planning-vocabulary.test.ts`.

The one citation that survives is a decision id that resolves OUTSIDE `.planning/`, cited with
its document named so a consumer can follow it: `` `docs/stock-vice-parity.md` D-03 ``. A bare
`D-03` resolves nowhere for a reader who has only the package.

NOTE FOR A FUTURE `/gsd-map-codebase` RUN: this section is normative, not descriptive. A large
population of legacy `Phase N` / `plan NN-NN` / `D-NN` comments still exists in
`src/mcp/vice/**` (1659 occurrences across 95 of the 103 shipped modules, MEASURED
2026-09-11); it is a known backlog, not the house style, and must not be re-described as one.

**Comments are mechanically checked.** Several test files assert on comment content and on line
references, so a careless comment edit fails the build:
- `docs-linerefs.test.ts` — verifies every `vice-proxy.ts:<N>` citation in `CLAUDE.md` AND
  `.planning/PROJECT.md` actually points at the claimed construct.
- `comment-phase-pointers.test.ts` — no stale phase pointers in shipped comments.
- `hop-chain-comments.test.ts` — path-reference correctness in hop-chain comments.
- `assumption-label-discipline.test.ts` — an `[ASSUMED]` row's label must be consistent at every
  source site that names it.
See TESTING.md for the full documentation-guard set.

**JSDoc** (`/** ... */`) on every exported function, type, and class, written as prose explaining
purpose, parameter semantics, and edge-case behaviour — not terse `@param`/`@returns` tags.

**Section divider comments** break long files into named regions:
```ts
// ---------------------------------------------------------------- round-trip
// ============================================================================
// repoRoot() ladder (D-2) and the last-resort path-anchor hop count ...
// ============================================================================
```

## Function Design

**Size:** single-purpose, with comments long relative to code — a 15-line function may carry 30+
lines of rationale. Do not shorten the comments to "clean up" without preserving the WHY.

**Parameters:** destructured options objects with inline defaults, never positional booleans.
Required vs optional is expressed in the type. Dependency bundles are passed as an explicit deps
object (`StockDispatchDeps`) so tests can inject stubs.

**Return values:** prefer structured results (`{ candidates, exact?, reason? }`,
`{ record, changes, untranslated }`) over throwing or returning `null`. `reason` fields are
human-readable prose meant to be surfaced verbatim, not codes to be mapped later.

**Predicates that guards depend on return findings rather than asserting internally** — so a test
can drive the REAL rule against an in-memory document instead of re-implementing it (stated
explicitly in `docs-linerefs.test.ts`).

## Module Design

**Exports:** named only. No default exports anywhere in `src/mcp/vice/`, the skill scripts, or the
installer.

**One authoritative seam per concern (the "D-N single source of truth" pattern):** exactly one
module owns each piece of derived knowledge — `repo-root.ts` for the project root,
`stock-connect.ts`'s connect handshake for the binary-monitor session, `hostpath.ts`/`containerpath.ts`
for path translation, `test-gate.mjs`'s `MANUAL_ONLY_TESTS` for the manual test set,
`shipped-modules.ts` for what the structural guards scan, `stock-dispatch.ts` for the tool dispatch
table (there is no second, per-backend capability table left to own — FORKRM-01). Import the
existing function instead of recomputing it inline; duplicating that logic is the primary defect
class this codebase's comments warn against, and several tests exist purely to detect a second
copy appearing.

**Barrel files:** not used. No `index.ts` re-export layer; every module is imported by filename.

**Dependency injection for testability:** functions that touch environment, time, spawning, or
I/O accept an optional override defaulting to the real thing (`repoRoot({ from, env })`,
`superviseChild({ spawn })`, `StockDispatchDeps`). Prefer adding an injectable parameter over
reaching for a mocking library — the suite has no mocking framework.

**Host/container boundary:** any host-facing path or hostname must go through `hostpath.ts`,
`containerpath.ts`, or `container-guard.mts`. Never `spawnSync` an external binary directly from a
skill script — the app lives on the host, so it must go through a container-out seam.
