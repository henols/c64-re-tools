### INT-01 (test-coverage) — the R2000-02 guard stopped growing with the family

`hostpath-consumers.test.ts:106-118` enumerates 10 r2000 modules. The production family is
now **14**. Uncovered: `r2000-acme-ident.ts`, `r2000-regbits-gen.ts`, `r2000-symbols.ts`,
`r2000-test-gate.ts`.

I verified directly that none of the four imports `hostpath.ts` or `containerpath.ts`, so
R2000-02's runtime guarantee holds today — **by luck, not by the test**. `r2000-symbols.ts`
is the module implementing R2000-14/R2000-15 and the highest-value target for an accidental
host-path import. This is precisely the failure mode the guard exists to prevent, recurring
one phase after the original five modules.

Fix: derive the list from `readdirSync` filtered on `/^r2000-.*\.ts$/` minus test files, so
it cannot silently under-cover again.

### INT-02 (doc-accuracy) — two file headers disagree about the spawn seam

`r2000-launch.ts:2,12-13` claims to be "the ONE authoritative place in this repo that
spawns regenerator2000 … No other file may shell out to the `regenerator2000` binary
directly." `r2000-mcp-client.ts:332` calls `spawn(bin, argv, …)` directly — necessarily,
since `withR2000Session()` needs a long-lived async child while `runR2000()` is blocking
`spawnSync`. `r2000-mcp-client.ts`'s own header correctly says "both spawn call sites in
this repo," so the two files contradict each other.

**R2000-01 is not compromised:** `r2000-mcp-client.ts:330` calls the shared
`assertNoViceFlag(argv)` immediately before every spawn, covering both
`buildMcpServerStdioArgs()` and 11-08's `argv` override (which is fed only by
`buildImportLblArgs()`, never hand-built). Verified by source read.
